与前篇的关系
Day 05 Data Turnstile 是在合成时分角色验证、把错误拦在数据外面；Day 06 反过来，把“失败场景”本身当成训练资产——专门合成 agent 最容易翻车的对话。Day 02 AED 是从真实 rollout 里挖失败（事后挖），ToolRACER 是用三个模拟器合成失败场景（事前造）；Day 04 ToolLoop 是“出错就带着错误原因重生成”，ToolRACER 是“失败轨迹喂回模拟器再生”，都靠反馈循环救样本，但一个救的是单条样本、一个救的是整条对话轨迹。

2一句话总结

只会练“合作用户”的 agent，一遇到摇摆、漂移、含糊、或根本办不到的要求就翻车——而真实用户大多不合作。ToolRACER 用三个模拟模型配合（用户模拟器、助手、工具模拟器），显式生成三种轨迹：Happy（合作 + 可满足）、Unhappy（摇摆、漂移、含糊）、Impossible（工具满足不了，Agent 应该识别并拒绝）；失败轨迹喂回模拟器再生，救回了 65.4% 一开始失败的轨迹；最后得到 5.6K 条多轮对话，约 66% 是容易失败的场景。Qwen3-4B 在 τ²-bench 上从 32.20% 升到 39.20%，和 APIGen-MT 叠加能到 41.25%；只训 Impossible 子集，能把 BFCL 的 Irrelevance 检测从 85.83% 拉到 95.50%。但不同路径会互相干扰：H+I 合起来反而比单路径差，不能简单拼接。

33 个问题

  1. 三种轨迹为什么不能简单拼接——干扰到底出在哪一层？论文只报了“H+I 合起来反而比单路径差”，没拆干扰的来源。设计一个实验：固定同一个基座（Qwen3-4B）与同一总样本量，七臂——A 只训 Happy、B 只训 Unhappy、C 只训 Impossible、D H+U、E H+I、F U+I、G 三者全拼（比例与单路径臂的混合比例一致）。评 τ²-bench（多轮成功率）与 BFCL Irrelevance（拒绝无关调用）两个指标。判据：若 E 在 Irrelevance 上 ≈C、但在 τ² 上 ≪A → 干扰是“拒绝”行为与“坚持完成”行为在策略层冲突（模型分不清什么时候该坚持、什么时候该拒绝）；若 E 在两个指标上都 ≪ 单路径 → 干扰在数据层（Impossible 的“拒绝”模板污染了 Happy 的完成轨迹）。再预测一个 2×2 格子：{Happy 为主，Impossible 为主} × {先训 Happy 再训 Impossible，混合一起训}，哪个格子在 τ² 上最高并写理由。漏洞：七臂的混合比例与训练顺序都没控制——“拼接差”可能只是比例不对（Impossible 占比过高把模型训成了“动不动就拒绝”），而不是路径本身冲突；另外 τ² 与 BFCL 的量纲不同，一个臂在一个指标上赢、另一个指标上输时，没有事先定好的加权规则，结论可以随权重翻盘。
  2. Impossible 训练的泛化边界在哪里——“会拒绝”能跨过工具边界吗？只训 Impossible 子集把 BFCL Irrelevance 从 85.83% 拉到 95.50%，但 Irrelevance 只是“识别无关工具调用”这一种拒绝。设计一个实验：把 Impossible 按失败原因分层——工具不存在、权限不足、参数不可满足、目标本身自相矛盾——只训其中一层（例如只训“工具不存在”），测其余三层上的拒绝准确率，再测 τ²-bench 的 Unhappy 轨迹（用户含糊但可澄清）。判据：若只训一层、其余三层也跟着涨 → Impossible 训练教的是通用的“核查可满足性”能力；若只涨被训的那一层 → 教的只是该层的话术模板。构造一个具体反例：用户说“帮我把这份文件发给上周开会那个人”——表面看像 Impossible（缺收件人、缺文件），实际是 Unhappy（可澄清）；若模型直接拒绝而不是追问，说明 Impossible 训练把“先澄清”挤掉了。漏洞：四层的难度本来就不等——“目标自相矛盾”比“工具不存在”难得多，跨层比较可能只是在比难度；而且拒绝准确率的判定本身需要 judge，judge 对“拒绝 vs 澄清”的边界判错会直接污染结论。
  3. 救回的 65.4% 是真救回，还是模拟器自己放了水？失败轨迹喂回模拟器再生，救回了 65.4% 一开始失败的轨迹——但再生用的还是同一套模拟器，模拟器完全可以把任务改简单（用户变合作了、工具变好调了），然后宣称“救回”。设计一个实验，对照 Day 02 AED 与 Day 04 ToolLoop 的两种失败处理：三臂——A 失败轨迹直接丢弃（只留一次通过的）；B 失败轨迹喂回模拟器再生（ToolRACER）；C 失败轨迹只做 citation-first 诊断、不再生（AED 式：诊断进 SFT，轨迹本身不进训练集）。同时记每臂“救回轨迹的任务难度”（用独立 verifier 或人工抽查：再生后的任务与原任务相比，约束条件少了几个？）。判据：若 B 在 τ² 上 ≫A、且救回轨迹的难度基本不变 → 再生是真救回；若 B ≫A、但救回轨迹的难度系统性下降 → 收益来自“任务被改简单了”，不是模型变强了。再预测一个 2×2 格子：{失败轨迹用，弃} × {再生，诊断} 在 τ² 上的排序并写理由。漏洞：难度判定本身就是个模型判据——独立 verifier 与模拟器可能共享同一种“简单化”偏见；而且三臂的最终样本量不等（B 比 A 多 65.4% 的救回量），“B 更好”可能只是样本更多，不是再生机制更好——必须把总样本量对齐再比。

Motivation：只练 Happy path 的 agent 见不得真用户

agent 训练数据几乎全是 Happy path——用户配合、需求清晰、工具够用。真实用户摇摆、漂移、含糊，还会提工具根本办不到的要求；只在 Happy 数据上训出来的 agent，遇到这些场景要么硬着头皮乱调工具，要么直接崩。缺的不是更多成功轨迹，是系统性的失败场景数据。

只训 Happy vs 三轨迹显式合成

老路：只训 Happy path

  • 用户配合、需求清晰、工具够用
  • 真实用户摇摆、漂移、含糊、提办不到的要求
  • agent 要么硬着头皮乱调工具，要么直接崩
  • 失败轨迹直接丢掉，等于把最值钱的信号扔了

反直觉点：“多一种数据”不是单调收益——H+I 合起来反而比单路径差，Impossible 教的“拒绝”和 Happy 教的“坚持完成”会互相打架。但只训 Impossible 子集，Irrelevance 检测反而能从 85.83% 拉到 95.50%：拒绝是一种可以单独练、也值得单独练的能力，只是别把它和“坚持完成”搅在同一个锅里。

5边界

  • 三种轨迹互相干扰：H+I 合起来反而比单路径差——“多一种数据”不是单调收益，拼接比例、训练顺序、混合方式都可能翻转结论；论文没有给出最优配比。
  • 模拟器即是数据生产者又是裁判：三个模拟模型配合生成轨迹，失败轨迹的再生也靠同一套模拟器——模拟器的偏见（什么样的用户算“摇摆”、什么样的要求算“办不到”）会直接进数据，没有独立的外部 verifier 把关。
  • 评测只有两个点：τ²-bench（多轮）+ BFCL Irrelevance（单点拒绝检测）；Unhappy 场景的真实用户分布（摇摆、漂移、含糊各占多少）没有外部统计对照，5.6K 条对话里的比例是模拟器自己定的。
  • 救回率 65.4% 的口径不清：注释没有说救回的轨迹是否保持了原任务难度——再生可能把任务改简单了，这个数字本身不能直接读成“模型能力提升”。

6迁移

  • “失败场景当主资产”可搬到任何 agent 训练：办公 agent（Day 09 Agent-R² 的真实附件场景）、计算机操作（Day 12 CUA-Master）、机器人（Day 15 PyRUA-DataFarm）——关键是先把失败分类（Happy / Unhappy / Impossible 这三类是通用骨架），再按类合成，而不是只堆成功轨迹。
  • 与 Day 02 AED 构成对照：AED 从真实 rollout 里挖失败（真实但稀少、要 citation-first 诊断才敢用），ToolRACER 用模拟器合成失败（量大但分布由模拟器定）——真实失败 vs 合成失败，哪个更值得当主资产，取决于你的场景有没有真实 rollout 可挖。
  • 与 Day 04 ToolLoop 构成对照：ToolLoop 的反馈再生救的是“单条样本里出错的那一步”，ToolRACER 的再生救的是“整条对话轨迹”——反馈循环的粒度不同，ToolLoop 修错、ToolRACER 救轨迹；两篇都证明了一件事：失败样本丢掉是浪费，喂回去才有价值。
  • 如果复现，第一步先定三类轨迹的判定标准（什么算 Unhappy、什么算 Impossible，各写 5 条可操作定义 + 正反例子），再搭模拟器；没有判定标准就开合成，Impossible 和 Unhappy 会互相串味——这正是 H+I 拼接会干扰的根源之一。
