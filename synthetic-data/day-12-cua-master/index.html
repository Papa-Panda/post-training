2一句话总结

电脑操作 agent（CUA）缺的不是模型，是数据：交互数据的多样性、可控性、可靠性都跟不上，而且常规优化 pipeline 没有迭代反馈，递归改进又只靠自生成经验，越练越窄。CUA-Master 搭了一个嵌套双循环：外层是世界–数据–模型飞轮，按模型的能力缺口不断从开放世界语料里再采集；内层是开放世界播种 + 自催化传播——从教程视频里挖真实工作流当种子任务，用视觉–语义双路重建轨迹，再把种子抽象成可复用原语，组合出多样、复杂、可验证的新任务；轨迹采集时用反馈引导的快照回滚重试，失败了不从头再来，而是回到最早偏离点接着试。27B 模型在 OSWorld Verified 上拿到 80.2 分；长任务同重试预算下，全重启成功率 14.6%，快照回滚 49.8%。

33 个问题

  1. 快照回滚的收益里，有多少是“少走回头路”，有多少是“避开了难状态”？——取 papers.md 的思考题。49.8% 对 14.6%，约 3.4 倍，听起来是回滚的功劳，但回滚同时做了两件事：省掉了重新走一遍前缀的步骤，也把 agent 直接放回了一个“还没走错”的状态。三臂——A 全重启（论文基线：长任务 14.6%）；B 快照回滚到最早偏离点（论文方法：49.8%）；C 回滚到最早偏离点、但强制清空已走过的前缀动作、只复用恢复后的状态（状态复用，路径不复用：agent 站在偏离点那个状态上，但不知道之前是怎么走过来的，得自己重新想下一步）。指标：长任务成功率（同重试预算）、平均成功步数、同一难状态被重复进入的次数、每轮重试里“偏离点之前的状态”被重新走过的步数占比。判据：若 B ≫ C 且 C ≈ A → 收益基本全是“少走回头路”——前缀复用才是真功劳，状态本身不值钱；若 C ≈ B ≫ A → 收益基本全是“避开了难状态”——只要把 agent 放回正确状态，前缀爱走不走都行；若 B ≫ C ≫ A → 两者都有份，各占一半左右，14.6% → 49.8% 要拆成两段才说得清；若 C ≪ A → 清空前缀反而有害——回滚恢复的状态里藏着前缀才能提供的上下文（比如已经打开的窗口、已经填了一半的表单），光有状态没有路径，agent 比从头来还懵。再预测一个 2×2 格子：{回滚，重启} × {保留前缀，清空前缀}，哪个格子的长任务成功率最高、哪个最低，并写理由。再构造一个具体反例：最早偏离点本身可能就是错的——agent 在第 3 步选错了应用窗口，第 20 步才偏离；回滚只回到第 20 步的偏离点，前面那个错窗口还在，agent 再怎么重试都是在错窗口里打转，49.8% 里混着“在错误前提下反复试错”的水分；更糟的是快照只恢复了界面状态、没恢复后台状态（文件已经改了、表单已经提交了、购物车已经下单了），回滚后状态不一致，越重试错得越离谱。漏洞：14.6% vs 49.8% 是“长任务、同重试预算”，但“长任务”多长、重试预算是多少、偏离点定位的准确率是多少，注释都没给数字——如果偏离点定位本身只有 60% 准，49.8% 里有一部分是“恰好滚对了地方”的运气；而且只报了成功率，没报步数——回滚可能用更多的步数换成功率，49.8% 的代价没说。
  2. 原语组合的合成任务，是真可控，还是“看起来可控”？——综合 Day 10 ToolSpace。CUA-Master 把种子任务抽象成可复用原语，再组合出多样、复杂、可验证的新任务；Day 10 ToolSpace 也做工具数据合成，教训是“执行见证的边胜过 LLM 判定的边（45.8 对 37.8）”。三臂——A 原语组合合成（论文方法：种子 → 原语 → 组合出新任务）；B 直接用教程视频的整条原始轨迹（不抽象成原语、不组合，原汁原味）；C 原语随机组合（不按依赖关系组合，随便拼）。指标：合成任务的可验证率（能自动判定对错的占比）、任务多样性（不同原语组合数）、agent 在合成任务 vs 真实任务上的成功率差距、幻觉工具调用占比（调了不存在的工具、或调了与任务无关的工具）。判据：若 A 的可验证率和真实任务成功率都 ≥ B，且 C 的可验证率大跌 → 原语抽象 + 有约束的组合是真本事，组合不是随便拼；若 A ≈ B ≫ C → 原语抽象没带来什么，真正起作用的是“种子任务本身真实”，组合只是锦上添花；若 C ≈ A → 组合的约束是摆设，随机拼也能拼出可验证的任务，那“可控合成”这个卖点就是假的；若 A 的合成任务成功率 ≫ 真实任务成功率 → 合成任务系统性地比真实任务简单，agent 在合成数据上练出来的本事搬到真实任务上要打折。再预测一个 2×2 格子：{原语组合，整轨迹} × {可验证，不可验证}，哪个格子的 agent 成功率最高并写理由。再构造一个具体反例：原语是从视频里挖的，视频里的原语自带隐含前置条件——比如“发邮件”这个原语默认已经登录了邮箱、已经打开了写信窗口；组合时丢了前置条件，合成的任务第一步就走不通，表面上可验证、实际上无解，agent 练的全是无解题；或者两个原语在真实环境里互相冲突——一个要改系统设置、一个依赖默认设置，组合任务在真实环境里根本不存在，agent 再怎么练都是在练假任务。漏洞：原语组合的“可组合性”由谁判定，注释没说——如果是 LLM 判定，Day 10 的教训（LLM 判定的边 37.8 < 执行见证的边 45.8）直接适用，CUA-Master 的原语边可能有一大批是 LLM 编出来的假边；而且“多样、复杂、可验证”三个形容词都没有数字——多样是多少种组合、复杂是几步、验证通过率是多少，全没给。
  3. 外层循环按能力缺口再采集，是真的在扩能力，还是只在收割“差一点就会”的任务？——综合 Day 01 SPADE 与 Day 04 ToolLoop。Day 01 SPADE 用 hint-regret 把环境卡在 agent 能力边界上，30B 一轮 400 步生成 3310 个环境；CUA-Master 的外层循环按能力缺口再采集，论文说“在递归迭代中持续增益”。三臂——A 按能力缺口再采集（论文方法：外层飞轮按当前模型的弱项采下一轮数据）；B 均匀采集（不按缺口，教程视频随机采）；C 只采模型已经会做的任务（反向对照：采集“已掌握”区间）。指标：OSWorld Verified 分数随迭代轮数的曲线、每轮新增原语数、失败模式多样性（失败原因的分布熵）、每轮新增数据的边际收益。判据：若 A 的分数逐轮上涨、B 很快平台、而 C 基本不涨 → 缺口引导是真功劳，外层循环在扩能力；若 A ≈ B → 涨分靠的是“数据越来越多”，不是“按缺口采”，外层循环的引导机制是多余的；若 C ≈ A → 模型只是在把已经会做的事做得更熟，根本没有扩能力，所谓“持续增益”只是熟练度上涨；若 A 在第 3 轮后就平台、而 B 还在涨 → 缺口引导反而把采集范围收窄了，均匀采集的探索价值更高。再预测一个 2×2 格子：{按缺口采，均匀采} × {早期迭代，后期迭代}，哪个格子的边际收益最大并写理由。再构造一个具体反例：能力缺口由“当前模型在哪些任务上失败”定义，但失败可能是环境噪声——网络抖动、弹窗、页面加载慢——不是能力缺口；外层循环会不断采集“噪声任务”，越采越多，模型在噪声上浪费预算，分数不涨反跌；或者缺口评估用模型自己判（自评缺口），模型不知道自己不知道什么，缺口清单永远缺最关键的那一块——最该补的能力永远不在采集列表里。漏洞：“持续增益”没有每轮数字——涨了几轮、每轮涨多少、第几轮开始收益递减，注释没给；而且 80.2 的 OSWorld Verified 是第几轮的成绩、基线模型是多少分，也没说——不知道外层循环到底贡献了几分。

Motivation：CUA 缺的不是模型，是数据

电脑操作 agent 缺的不是模型，是数据。交互数据的多样性、可控性、可靠性都跟不上：多样性不够，agent 只会几种固定操作；可控性不够，任务难度、工具组合没法按需调；可靠性不够，轨迹里混着错步、脏步。更麻烦的是常规优化 pipeline 没有迭代反馈——训完一轮，下一轮数据还是老样子；已有的递归改进又只靠自生成经验，模型自己教自己，越练越窄，收益递减。CUA-Master 要的是一个能“越练越宽”的数据飞轮：从开放世界不断 import 新东西，按模型的弱项补数据。

失败利用 vs 失败记录：回滚不是重试，是接着试

老路：失败了从头再来

  • 全重启：长任务成功率 14.6%
  • 前面走对的步骤全部作废
  • 同一难状态反复进入、反复失败
  • 失败样本只被记录下来当数据

CUA-Master：失败了回到偏离点接着试

  • 快照回滚：长任务成功率 49.8%，约 3.4 倍
  • 定位最早偏离点，恢复快照接着试
  • 只保留成功且更高效的分支
  • 失败从“被记录”变成“被利用”

长任务重试：全重启 vs 快照回滚（同重试预算，示意，非论文公式）：

$$\frac{P_{\mathrm{rollback}}}{P_{\mathrm{restart}}} = \frac{49.8\%}{14.6\%} \approx 3.4$$

其中 $P_{\mathrm{rollback}}$ 是快照回滚的长任务成功率， $P_{\mathrm{restart}}$ 是全重启的长任务成功率——约 3.4 倍的差距，是这篇最硬的数字；但“长任务”多长、重试预算多少，注释没说。

轨迹重建与原语组合（示意，非论文公式）：

$$T = \mathrm{reconstruct}(V, S), \quad \tau = p_1 \circ p_2 \circ \cdots \circ p_k, \;\; p_i \in \mathcal{P}$$

其中 $T$ 是从教程视频重建的轨迹， $V$ 是视频画面、 $S$ 是语义理解——视觉–语义双路对上才算重建成功； $\tau$ 是合成的新任务， $p_i$ 是可复用原语、 $\mathcal{P}$ 是原语库——原语是合成单元，组合是放大器。

失败定位与快照回滚（示意，非论文公式）：

$$t^* = \min \{ t \mid s_t \neq \hat{s}_t \}, \quad \text{rollback to } S_{t^*}$$

其中 $t^*$ 是最早偏离点， $s_t$ 是实际状态、 $\hat{s}_t$ 是期望状态， $S_{t^*}$ 是偏离点处的快照——失败了不从头再来，从 $t^*$ 接着试；只保留成功且更高效的分支。

反直觉点：80.2 的 OSWorld Verified 很好看，但 Agents' Last Exam 只有 25.0 分——最难的长程考试型任务上，CUA-Master 的办法还远没够。快照回滚的 49.8% 也一样：它救的是“差一点就成功”的长任务，不是“根本不会”的任务。

5边界

  • 14.6% vs 49.8% 只有一个对照、没有细节：长任务多长、重试预算多少、偏离点定位准不准、回滚的步数代价是多少，注释都没给——约 3.4 倍的差距不能直接外推到短任务、别的预算、别的定位准确率。
  • 80.2 / 36.9 / 43.9 / 25.0 是四个基准、一个模型规模：CUA-Master-27B 一个模型，别的规模怎样、基线模型是多少分、外层循环贡献了几分，注释没给——四个分数里有多少是方法、有多少是 27B 这个规模，分不开。
  • Agents' Last Exam 只有 25.0 分：四个基准里最低的一个，说明在最难的长程考试型任务上，CUA-Master 的办法还远没够——80.2 的 OSWorld Verified 不能代表“电脑操作问题解决了”。
  • “持续增益”没有每轮数字：涨了几轮、每轮涨多少、第几轮开始收益递减，注释没给——外层循环是真在扩能力，还是前两轮涨完就平台，分不开。
  • 教程视频的覆盖面就是种子任务的覆盖面：视频里没有的工作流，种子库里就没有；冷门软件、内部工具、非英文界面，视频本来就少——原语库从一开始就偏向“热门应用的常见操作”。
  • 快照回滚依赖“状态可恢复”：界面状态能恢复，后台状态（文件已改、表单已提交、订单已下）不一定能恢复——回滚后状态不一致的任务，回滚反而是错上加错；注释没说哪些环境支持快照、哪些不支持。
  • “只保留成功且更高效的分支”没有效率数字：更高效是少了多少步、省了多少时间，注释没给——过滤掉的“成功但低效”分支里，可能恰恰藏着更稳健的做法。

6迁移

  • “从教程视频 import 工作流”可搬到任何“人已经会做、机器还不会”的领域：客服对话（从真实客服录音里挖工作流）、数据分析（从屏幕录制里挖分析步骤）、机器人操作（从示教视频里挖动作原语）——关键是种子必须来自真实人类操作，别自己编；而且要像 CUA-Master 这样先做“视觉–语义双路重建”，两条路对不上就别当种子。
  • 与 Day 03 WorkForge 构成对照：WorkForge 说“16.7K 真实工作空间，真实感是学会探索的原因”；CUA-Master 把真实感从“真实工作空间”升级成“真实人类操作”——一个信环境真，一个信轨迹真。两篇合起来才是完整的真实感故事：环境要真，操作也要真；只真一半，agent 学到的探索可能是假探索。
  • 与 Day 02 AED 构成对照：AED 把 50228 条 error–diagnosis 对当主资产，失败样本第一次被当成主资产；CUA-Master 更进一步，失败不只留下来当数据，还要定位最早偏离点、回滚、只留成功且更高效的分支——失败从“被记录”变成“被利用”。但两篇的教训是通的：失败数据的价值不在“有多少条”，在“定位准不准”——AED 的诊断准不准，CUA-Master 的偏离点准不准，都是同一个问题。
  • 与 Day 04 ToolLoop 构成对照：ToolLoop 说“无反馈合成数据比不训还差 2.17 个点”；CUA-Master 的反馈引导快照回滚重试、和按能力缺口再采集的外层循环，是同一条闭环在 computer-use 上的落地——反馈从“数据合成时”挪到了“轨迹采集时”和“下一轮采集什么”。但 ToolLoop 的反馈是“动态自反馈”，CUA-Master 的反馈是“失败定位 + 缺口引导”，两者的反馈信号不一样：一个是“这条数据好不好”，一个是“这一步错在哪、下一步采什么”。
  • 与 Day 10 ToolSpace 构成对照：ToolSpace 以可执行工具依赖为合成单元，执行见证的边胜过 LLM 判定的边（45.8 对 37.8）；CUA-Master 以可复用原语为合成单元——原语组合的“可组合性”如果只靠 LLM 判定，Day 10 的教训直接适用：假边会混进合成任务里。搬过去要改的第一件事，就是给原语组合加上执行见证：组合出来的任务先在真实环境里跑一遍，跑通了才算数。
  • 如果复现，第一步先拿 10 个教程视频，用视觉–语义双路重建轨迹，人工抽查 20 条重建轨迹，量“重建准确率”——如果重建准确率低于 80%，种子库从一开始就是脏的，后面原语、组合、回滚全是白搭；再拿 20 个长任务，全重启和快照回滚各跑一遍，量成功率和平均步数——如果回滚的成功率涨了、步数也涨了一大截，先算清楚“多花的步数换来的成功率值不值”，再决定要不要上外层循环。
