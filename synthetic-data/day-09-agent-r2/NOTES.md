## 一句话总结

办公 agent 常犯的错不是不会调工具，是不读附件、不验算就交文件——交出来的东西看着像回事，细看全是没落地的空壳。Agent-R² 的判断是：这个问题不是模型能力问题，是数据问题——现有的办公 agent 训练数据里没有“真实工作意图 + 真实多格式附件 + 交付级评判”这三样东西。做法是全程用真实来源打底（real-source）：O*NET 职业活动播种任务意图，从 10k 个网络语料候选里蒸馏出 4k 个任务实例，每个实例配真实多格式附件和细粒度交付级 rubric；附件经过检索验证，交付物经过沙箱校验，再由专家执行 + verifier 核对；然后先 SFT、再按交付 rubric 做 RL，训出 Agent-R²-4B。GDPval Pass@1 从 32.4% 经 SFT 到 45.3%、RL 后到 51.0%；只用 4k 条实例训出的 4B 模型，在 GDPval 上 51.0% 对 48.0%、OfficeQA 上 14.8% 对 13.8%，都超过了 Qwen3-235B-A22B-Thinking-2507。

## 3 个问题

1. Rubric RL 的功劳，到底是 rubric 细，还是 RL 本身？三臂——A SFT only（基线）；B SFT + 二值结果奖励 RL（只按交付物过/不过给 0/1）；C SFT + 交付 rubric 奖励 RL（论文方法）。指标：GDPval Pass@1、OfficeQA、捷径率（不读附件/不验算就交文件的比例）、平均步数。判据：若 C ≫ B ≈ A → 细粒度 rubric 是真功臣，二值奖励学不到“先 grounding 再交件”的顺序；若 B ≈ C ≫ A → 功劳在 RL 不在 rubric，rubric 只是个昂贵的包装；若 C 的 Pass@1 高但捷径率也高 → rubric 被 hack 了，模型学会了“在 rubric 项上刷分”而不是“真把活干对”。再预测一个 2×2 格子：{rubric 细粒度，二值} × {真实附件，合成附件}，哪个格子的捷径率最低并写理由。再构造一个具体反例：rubric 里有一项“引用附件中的关键数字”——模型在交付物里堆一堆从附件抄来的数字，每项都沾一点边，rubric 分刷满了，但数字之间的逻辑关系全是错的；若 C 臂里这类交付物占多数，51.0% 的 Pass@1 就是 rubric 本身在放水。漏洞：B 臂的二值奖励本身也可能被 hack（交个空文件碰运气过 checker）；捷径率没有标准定义，得自己先定“什么算没读附件”（比如交付物里引用的数字在附件里查无此数）——定义一变，结论跟着变；而且 C 臂的 rubric 是谁写的没有交代——如果是 LLM 写的 rubric，rubric 质量本身就是变量。
2. 真实附件到底是“真实”重要，还是“多格式、带噪声”重要？三臂——A 真实附件（论文方法）；B LLM 按任务生成的合成附件（格式、内容都仿真）；C 任务文本 only，无附件（附件信息由 LLM 自己编）。指标：GDPval Pass@1、交付物数字与附件的一致率（grounding 率）、幻觉率（交付物里出现附件中不存在的数字/事实）。判据：若 A ≫ B ≈ C → “真实”本身是关键——合成附件再像，也缺真实文件那种“信息藏在犄角旮旯、格式不规整”的难度；若 B ≈ A ≫ C → 关键是有附件这个训练信号，不必非得真实来源，合成附件够便宜就能规模化；若 B 的 grounding 率 ≫ A → 真实附件反而带了噪声和无关信息，合成附件更干净、更好学。再预测一个 2×2 格子：{真实附件，合成附件} × {rubric RL，SFT only}，哪个格子的幻觉率最低并写理由。再构造一个具体反例：真实附件里有一份 40 页 PDF，关键数字在第 37 页脚注里——模型如果只读前两页就交件，交付物数字大概率是编的；若 A 臂的模型在这个任务上仍然不翻到第 37 页，说明“真实附件”并没有教会它“读完再交”，只是让它记住了“附件里有答案”这个先验。漏洞：B 臂的合成附件是 LLM 生成的，生成时可能无意中把答案“泄露”进附件的显眼位置——合成附件的难度分布和真实附件根本不同，直接比 Pass@1 是在比任务难度；而且真实附件经过“检索验证”筛过一轮，被筛掉的任务可能恰恰是最难的那些。
3. SFT 扩探索、RL 收可靠——这个两阶段曲线在别的 agent 任务里也出现吗？——综合 Day 08 Harness-S。注释说 SFT 后步数暴涨但完成率跌，RL 后回升：SFT 把“多走几步、多试几种做法”学进来了，但“一次交对”的可靠性反而掉了，RL 按交付 rubric 把可靠性拉回来。Day 08 的 Harness-S 也有类似的张力：救援组带来方差（探索），但要靠回原 harness 校验（可靠）。设计一个实验：三臂——A 在 AppWorld 上复现 Agent-R² 的两阶段（SFT → rubric RL），每 100 步记一次 checkpoint 的步数与完成率；B 只 SFT 不 RL，看步数与完成率的曲线是不是一直“步数涨、完成率跌”；C 只 RL 不 SFT（基线直接上 rubric RL），看没有 SFT 扩探索，RL 能不能把完成率拉起来。指标：分 checkpoint 的步数、完成率、Pass@1。判据：若 A 的曲线复现“先跌后升”而 B 一直跌、C 涨不动 → 两阶段分工是真规律：SFT 负责把探索空间撑开，RL 负责在撑开的空间里挑可靠路径；若 C 的完成率也涨 → RL 自己就能扩探索，SFT 那一步是多余的；若 A 在 AppWorld 上没有“先跌后升” → 这个曲线是办公任务特有的（办公任务的“交件”动作本身就是个容易提前触发的捷径），不是 agent 训练的通用规律。再预测一个 2×2 格子：{SFT 后，RL 后} × {步数，完成率}，哪个格子最反直觉并写理由。漏洞：步数暴涨可能不是探索，是 SFT 把模型训“啰嗦”了——多走的步数可能全是无意义的重复查询和自我纠错，拿步数当探索的代理指标会高估 SFT 的贡献；而且“完成率跌”是相对哪个基线跌的，注释没给数字——SFT 后的完成率跌到多少、RL 后回升到多少，都得自己跑出来才能下结论。

## 核心机制

1. **Motivation**：办公 agent 的失败模式很具体：不读附件、不验算就交文件。交出来的交付物表面上格式齐全、数字俱全，但数字是编的、结论没根据——“看着像回事”是这类任务最危险的失败，因为用户一眼看不出来。根子在数据：现有办公 agent 训练数据没有“真实工作意图 + 真实多格式附件 + 交付级评判”——任务是人工编的、附件是 LLM 生成的、评判是过/不过的二值。模型在这种数据上训出来，自然学会“先交件再说”，因为数据里从来没有因为“没读附件”而被扣分的例子。
2. **方法**：Real-source 全程打底。O*NET 职业活动播种任务意图（工作意图来自真实职业活动清单，不是人工拍脑袋）；从 10k 个网络语料候选里蒸馏出 4k 个任务实例，每个实例配真实多格式附件（检索来的真实文件）与细粒度交付级 rubric；附件经过检索验证、交付物经过沙箱校验；专家执行 + verifier 核对交付物（人类专家做一遍，verifier 按 rubric 核对交付物是否真达标）。训练分两段：先 SFT 学会“照着附件把活干完”，再按交付 rubric 做 RL——奖励不是“交没交”，是交付物按 rubric 一项一项的得分。
3. **关键数字**（论文自报，出自 papers.md 注释与论文摘要）：GDPval Pass@1 从 32.4%（基线）经 SFT 到 45.3%、RL 后到 51.0%（+18.6 个百分点，三阶段顺序按注释）；10k 候选 → 4k 任务实例；Agent-R²-4B 只用 4k 实例，在 GDPval 上 51.0% 对 48.0%、OfficeQA 上 14.8% 对 13.8%，均超过 Qwen3-235B-A22B-Thinking-2507（235B 思考模型）。

把交付级 rubric 想成加权和（示意，非论文公式）：

$$ R = \sum_{i=1}^{n} w_i \cdot r_i $$

其中 $r_i$ 是第 $i$ 项 rubric 的得分， $w_i$ 是权重——与二值奖励只给 0/1 不同，rubric 奖励把“交件”拆成可逐项得分的交付标准：读没读附件、算没算对、格式对不对，每一项单独计分。

## 边界

- 4k 实例很小：整个方法建立在 4k 个任务实例上——O*NET 播种 + 检索验证的 pipeline 能不能从 4k 扩到 40k、400k，注释和摘要都没给数字；4k 规模下“真实附件”的多样性（行业、文件格式、语言）覆盖面有限，换一个没覆盖到的职业，效果可能直接掉。
- “SFT 后完成率跌”没有数字：注释只说步骤暴涨但完成率跌、RL 后回升，没给 SFT 阶段完成率跌到多少、步数涨到多少——这个反直觉现象的幅度没法从注释里核实，RL“回升”回升到多高也不清楚；Pass@1 的三段数字（32.4% → 45.3% → 51.0%）是净效果，中间的波动曲线是黑的。
- Rubric 的质量没有交代：交付级 rubric 是谁写的、怎么验证 rubric 本身是对的，注释里没有——如果 rubric 是 LLM 写的，RL 就是在优化 LLM 写的标准，标准错了模型越训越偏；而且 rubric 逐项得分天然可 hack：模型可以学会“每项都沾一点边”而不是“把活干对”。
- 真实附件经过筛选：10k 候选只留下 4k，筛掉的 6k 是什么？检索验证和沙箱校验筛掉的可能恰恰是最难、最脏、最真实的任务——留下的 4k 是“真实来源里最好训的那部分”，评测数字可能高估了在未筛选真实任务上的表现。
- 评测可质疑处：GDPval 51.0% 对 48.0% 的优势只有 3 个百分点，OfficeQA 14.8% 对 13.8% 只有 1 个百分点——两个 benchmark 的绝对值都很低（OfficeQA 只有 14.8%），“超过 235B 思考模型”的标题在绝对值上仍然是“都不会做”；而且对照的 Qwen3-235B 是零样本还是同等 SFT 后的，摘要没说——如果 235B 没经过办公数据 SFT，这个比较是在比“训没训过”，不是比“方法好不好”。

## 迁移

- “真实附件 + 交付 rubric”可搬到任何“交件型”任务：写报告、做表格、编代码——只要交付物是文件，评判就可以从“过/不过”改成“按交付标准逐项打分”；关键是先有“真实来源的输入材料”（真实文件、真实代码库、真实数据表），没有真实材料，rubric 再细也是在真空里打分。
- 与 Day 02 AED 构成对照：AED 是把真实失败样本当主资产进 SFT，Agent-R² 是把真实附件当主资产进 SFT+RL。两者都拒绝合成数据当建材，但 AED 的真实来自“失败轨迹”，Agent-R² 的真实来自“工作材料”——失败样本教你“别这么干”，真实附件教你“按这个干”。
- 与 Day 08 Harness-S 构成对照：Harness-S 是“训练信号不够，换环境造信号”；Agent-R² 是“数据里没有交付标准，加 rubric 造信号”。一个在 RL 采样环节补信号，一个在数据环节补信号——但两者都面临同一个问题：补进来的信号是不是真的？Harness-S 靠“回原 harness 校验”，Agent-R² 靠“专家执行 + verifier 核对”。
- 与 Day 07 Spotify 构成对照：Spotify 用合成对话当测试集、修规划层而不动模型权重；Agent-R² 用真实附件当训练集、动模型权重（SFT+RL）。合成数据当测试集是便宜的，但当训练集会把模型的“交件习惯”带偏——Day 07 和 Day 09 合起来看，合成与真实的分工是：合成搭架子、做测试，真实当建材、做训练。
- 如果复现，第一步先定“什么算没读附件”：写一个自动检查——交付物里的每个数字、每个引用，在附件里能不能找到出处；没有这个检查，rubric 的“grounding 项”没法自动打分，RL 的奖励就落不了地；再拿 100 个任务人工跑一遍，量一量“不读附件就交件”在你的任务上占多大比例——如果不到 10%，这套方法解决的不是你的主要矛盾。
