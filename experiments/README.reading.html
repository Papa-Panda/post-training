把"读论文"转成"做研究"的回路。每周固定 1 个 claim，不必每篇论文都做。

11. 四步法

  1. 抽 claim，改写成可证伪句。 从论文/笔记里抓一句话，改成"如果…那么…"， 并且必须能说出"什么样的结果算我错了"。写不出证伪标准 = 还没想清楚，重写。
  2. 只测机制，不复现全文。 缩到最小可测单元：toy 数据、小模型、论文自己的 数字做二次分析。目标是几小时内能跑完，不是发 paper 级别。
  3. 先写预测再跑。 跑之前写下预期看到什么、为什么。防 hindsight bias， 这是 researcher 和爱好者的分水岭。
  4. 记录三档结果：证实 / 证伪 / 模糊。每档写一句"下一步是什么"。 证伪了也是产出，而且往往更有价值。

22. 小实验分三档

  • Tier 0（纸上，~30 分钟）：推导边界、构造反例。 例："这个结论在非凸 / 小 batch 下还成立吗？"
  • Tier 1（toy code，2-3 小时）：NumPy/PyTorch，几百个样本验证机制。
  • Tier 2（小规模实证，半天）：公开小数据集或论文开源代码跑一个 ablation。

32.1 知识图谱（Roadmap）

学东西要有体系：每个 claim 必须挂到知识图谱的一个节点上。 详见 ROADMAP.md —— 核心地图是 model-in-the-loop 数据策展的 十条线（归因 / 目标化选择 / 无梯度估值 / 多样性覆盖 / 集合协调 / 主动生成 / 安全/持续学习 / 可学性门 / 系统实现 / coding 闭环）， 外围是 ai-infra 补充和 physical AI 背景音（不设 claim 指标）。

找下一个 claim 时先看图找空白节点；每月自测时对着 claims/ 检查覆盖。

43. 文件组织

  • 每条 claim 一个文件，放在 claims/ 下，命名 YYYY-MM-DD-<slug>.md （例：2026-09-12-less-gradient-vs-bm25.md）
  • 用 templates/claim.md 做起点，直接复制改写
  • 跑之前必须先填"我的预测"一节，跑完再填"结果"

54. 节奏

读保持每天，实验固定每周 1 个（建议周六上午）。 攒够 10-20 条，这里就是 idea pool：白天工作里哪个 ablation 值得做、 内部 paper 缺哪块证据，直接从这里取。
