## 一句话总结

上半场讲两件事：把 desktop agent 推向「AI 协科学家」的科学发现基准——关键工程是给科学软件开 RESTful 接口拿确定性中间状态做 verifier；以及一套面向 mobile agent 的安全评测——把安卓系统层 trace 引入检测，用形式化校验 + 上下文化 VLM judge 的混合方法守住隐私底线。

## 核心

1. **背景/问题**：当前 AI 在科研工作流里还只是「分析师」（出 idea、写代码、做审稿辅助），当不了能从 0 到 1 操纵科学软件的「执行者」。科学任务的评测比日常办公难得多：同一个分子可视化任务有多种合法风格与角度，像素级 matching 验不了对错。安全一侧的问题同样尖锐：agent 跑在用户自己的电脑上，良性指令也可能出事——讲者举的例子是让 agent 把会议日程截图发到群里，结果整个日历连同里面的就诊安排一起被截了出去。

2. **方法/设计**：
   - 科学发现基准（讲者称 ScienceBoard 一类，字幕转写作「3sport」，待核）：在 Ubuntu 虚拟机里预装生物信息、天文、代数/定理证明、地理、报告写作等科学软件，观测给 screenshot、accessibility tree 与 Set-of-Mark。核心招数是「魔改」开源软件（如生物信息可视化软件 ChimeraX），通过类 RESTful API 暴露运行时中间状态，从而对每一步拿到确定性 state 做 verifier（状态匹配、数值容差校验），而不是看最终画面像不像。任务由有学科背景的标注者先读软件 tutorial 再构造，标注 easy/medium/hard 难度与 GUI/CLI/混合标签，标注者之间交叉复核，强调任务必须能在环境里被准确执行、尽量避免一题多解。
   - 安全评测：先做 live 环境 MobileRisk-Live（原生安卓模拟器），除截图、accessibility tree、Set-of-Mark 外，额外从系统层抽取 system traces——文件系统元数据、权限、网络信息等，对语义层看不见的敏感信息触达做留痕。再考虑到不可逆风险、流媒体内容漂移、超级 App 反虚拟机三件事，又把环境信息冻结采集成 MobileRisk 基准（含真机事件驱动采集来对付反虚拟机），轨迹带 safe/unsafe 标注与安全场景分类。检测方法是混合式：formal verifier 从系统状态里查完整性与敏感模式，给一条低成本的安全底线；contextual judge 则在传统 VLM judge 之上喂入 Android runtime 信息判断轨迹语义；两者可单步或多步组合，输出轨迹级判定。

3. **实验/实战**：科学基准上整体成功率仍然低，更新到 Claude、GPT-5 等最新模型后最好也只有约 25%。分领域差距明显：代数、生物化学类做得较好，讲者分析是因为模型学过这些软件的 tutorial；定理证明这类需要开软件、写代码、高阶逻辑推理的任务则明显挣扎。两个值得记的负面/正面结果：科学 UI 元素密集时，把 Set-of-Mark 框全部打满反而成为 agent 的认知负担，不是越多越好；把有 planning 能力的大模型与小规模 action model 做模块化组合，能实打实提升表现。安全一侧，混合检测在不同 backbone 上、step 级与轨迹级都明显优于 rule-based verifier 与传统 VLM judge，且离线冻结版与在线 live 版结果接近。

4. **结论/观点**：讲者明确的判断有二。一是想让 computer-use agent 迈向更高阶应用，光有 planning 与 action 能力不够，还要补 domain knowledge——高阶任务里缺的是领域能力本身。二是安全上，「这不只是 agent 的 safety，也是人的 safety」：检测必须同时看语义层与系统层，只靠 VLM judge 看屏幕会漏掉系统层面的敏感信息触达。关于科学基准里模型「熟悉 tutorial 所以做得好」，讲者不认为这是基准被 hack，反而认为 tutorial learning 是走向自动化科学家的一条可行路线。

## 可迁移

- **Verifier 设计**：科学基准的做法——给被测软件开接口、暴露确定性中间状态做校验，而不是对最终产物做模糊匹配——可以直接迁移到 coding agent 与 GUI agent 的评测 harness：凡是能拿到结构化中间状态的地方，都优先用它做 verifier，LLM judge 只补语义层。
- **评测数据纪律**：任务构造流程（标注者先读 tutorial、难度分层、GUI/CLI/混合标签、多人交叉复核、刻意避免一题多解）是一套现成的 benchmark 构建规范；另外「界面标注不是越多越好、密集标注反成认知负担」这条负面结果，对 GUI grounding 的数据合成与观测设计有直接参考价值。
- **安全护栏**：给 agent 的安全检测同时接语义层（截图/轨迹）与系统层（文件、权限、网络 trace），并留一条规则化的形式底线，是 agent infra 里可落地的 guardrail 结构。
