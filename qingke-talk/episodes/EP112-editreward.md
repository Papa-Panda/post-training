## 一句话总结

针对图像编辑领域缺一个与人类对齐的评价器，讲者团队做了三件套：200K 人类偏好数据（EditReward-Data）、在 VLM 基座上用双头 + 不确定性感知排序损失训出的奖励模型（EditReward），以及用多图组全排序判定来压位置偏置的评测基准（EditReward-Bench）；这个小开源模型在多个基准上与 GPT-5、Gemini 2.5 相当或更好（字幕口径），并用一个数据过滤实验证明：筛后的 20K 数据训出的编辑模型优于 46K 全量——数据质量比数量更关键。

## 核心

### 动机：闭源编辑模型拉开差距后，缺的是评价器

工作构思于 2025 年 6 月前后，当时 GPT-Image 一类强闭源编辑模型刚出现，开源与闭源的差距明显拉大。讲者把差距拆成两个可动手的点：其一，训练数据质量有差，需要一个能做 data filter 的高质量图像编辑 evaluator；其二，文生图领域 Flow-GRPO 一类 diffusion RL 已成范式，图像编辑要跟进 RL，同样先得有一个好的 reward model。传统路线（CLIP/LPIPS 特征匹配、通用 VLM 直接 prompt 打分）噪声大、不连续、与人类对齐程度存疑；社区共识已转向用 VLM 做 reward model，利用其图像理解先验——EditReward 沿这条线做全。

### EditReward-Data：200K 偏好数据怎么造

数据构造分三步。第一步选指令：尽量取人工选出的高质量 instruction，压低「输入图与指令本身不对齐」的噪声。第二步生成候选：用当时 SOTA 的编辑专家模型与通用统一模型（字幕专名误差较大，以论文为准），每组生成 12 个 candidates；为防「强模型候选总是更好」带来的偏差，随机抽其中 7 个进入标注，并引入随机种子等随机性。编辑类型覆盖多样。

标注只设两个尽量正交的维度，各按 1–4 分制、专家标注并交叉核验：

1. **Instruction Following（IF）**：是否严格执行指令，其中明确包含对背景与「不需要编辑区域」的保持能力——编辑任务里「不该动的地方别动」被讲者列为一等公民。
2. **Visual Quality（VQ）**：传统意义上的视觉质量与美学（模糊、畸变、不一致等）。

### EditReward 模型：双头 + 把打分建模成分布

模型设计（借鉴 HPSv3 一类工作的 head 结构，字幕口径）：输入为 source image、instruction、edited image 三元组，在 Qwen2.5-VL 等 VL 基座（字幕另提一个基座，专名不清）上挂两个 reward head，分别管 IF 与 VQ。关键设计是每个 head 不输出点值、而是输出一个高斯分布（mean 与 variance），用 uncertainty-aware ranking loss 训练、取 mean 作分数。动机是人标注本身带误差，真实好坏与标注之间存在偏差，把输出建模成分布等于给模型一个「信赖度」，能压低它在不确定样本上的幻觉式排序。

两个训练细节被讲者点名有效：其一，加入「tie 数据」——总分相同、但一个在 IF 更好另一个在 VQ 更好的样本对——训练明显更稳定；只喂完全分大小的数据，模型容易陷在局部、学不好。其二，双维度聚合策略做过消融（average / min / max 等），结论是平均策略最好，因为它综合了两维度的相互关系（字幕口径）。

### EditReward-Bench：多图组全排序，专治位置偏置

旧基准（GEdit-Bench 一类，字幕作「g AI bench」）多是两图比较。讲者的观察是：VLM 做排序有 position bias，会偏向某个位置，未必反映真实好坏。Bench 因此把一组扩到 2 / 3 / 4 张图，要求模型对组内全部图给出完全正确的排序（如 A>B>C），整组才算对——难度与判别力都更高。构建上从总标注池里撇出 500 个 case，专挑 3 位标注者之间平均分与极值高度对齐的样本作 ground truth（字幕口径）。

### 结果与三个用途

结果（字幕口径，未给逐项数字）：在多个 benchmark 上与当时最好的闭源模型 GPT-5、Gemini 2.5 相比，有更好、有持平，整体相当或更优；且是开源小模型，推理速度快得多。

讲者给了三个用途，其中第一个有完整实验：

1. **数据过滤**：取 ShareGPT-4o-Image 的 46K 图像编辑数据，用 EditReward 打分排序、只留 top 20K 训练编辑模型，结果比 46K 全量训练更好，分数与当时的 VLM 方案相当（字幕口径）。讲者由此下判词：数据质量比数量关键。
2. **RL 后训练的 reward**：本工作因算力有限没有自做 diffusion RL，但讲者称后续多个工作已采用 EditReward 做 RL 训练、指标不错（专名以各论文为准）。
3. **Test-time scaling**：推理阶段打分选 best-of-N。

定性 case 上，模型能识别「remove 任务只把杯子模糊化、没清掉」「六根手指」一类细粒度失败（字幕口径）。

### Q&A 要点

- **IF 与 VQ 冲突时标注者怎么权衡？** 不做权衡：两维度按各自标准独立打分（IF 看指令完成度与背景保持，VQ 看美学与畸变）；讲者补充两者并不完全独立，VQ 很低时往往意味着图被改坏，IF 通常也不会好。
- **VQ 更主观、噪声更大，有无特殊处理？** 一条数据找 3 人分别打分取平均，代表大众口径。
- **pairwise 还是 pointwise？** 各有好坏：pairwise ranking 有工作证明对 RL 训练更友好；pointwise 直接出分，用起来方便（单图评价、数据过滤都有现成参考），且能看出样本在标尺上的大致范围。本工作是 pointwise 出分、Bench 侧再做多图排序判定。
- **为什么不用生成式 reward model？** 讲者认为 VLM 式 reward 能用上语言侧的感知与 reasoning，可解释性更好，是当前主流路线；纯蒸馏闭源模型的 CoT 造数据，上限会被教师锁死，他更看好带空间定位（如先框出应编辑区域再评估）的 reward 设计。
- **公认难做的编辑任务**：structured data（infographic、chart、diagram）与复杂文本渲染，目前编辑模型处理得都不好。
- **中文指令编辑**：数据以英文为主，未专门考察，讲者建议使用者自测。

## 可迁移

- **Reward model 先当 data filter 用，是投入产出比最高的验证方式**：46K→20K 还涨点的实验说明，先拿评价器筛数据、再谈 RL 接入，能用很低的成本验证评价器与人类偏好的对齐程度；这条「评价器→过滤→训练」的链路对 coding data 的质量筛选同样成立。
- **偏好标注把维度拆正交、且把 tie 样本喂回去**：总分相同但维度互有胜负的样本对能显著稳定排序训练——做人类偏好/LLM judge 数据时，与其只收「明显一好一坏」的对子，不如刻意保留难分对子并给模型不确定性出口（分布输出而非点值）。
- **评测端用多样本全排序压位置偏置**：任何 pairwise judge（代码评审、回答质量评估）都可借这个办法——扩大组规模、要求全序正确，比反复交换位置取平均更能暴露 judge 的真实判别力。
