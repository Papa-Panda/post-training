2一句话总结

四位一线从业者（模型、基建、产品、学术四种视角）的共识是：CUA 的「操作层」（grounding、点击执行）基本已经解决，真正的瓶颈是环境与数据的规模化、长时程的推理与决策逻辑，以及可靠性与可验证性；所谓 ChatGPT 时刻不会由单一因素触发，它更可能以「某个子领域先出现像 Claude Code 之于 coding 的爆款形态」的方式到来，而开源社区最该补的位是中立评测、轨迹数据与可靠性研究。

3核心

谷雨：被高估的是「把 RL scaling 直接搬到 CUA」，被低估的是操作之外的决策逻辑

谷雨的判断：operational 层面的 grounding 已经「解决差不多了」，不值得作为长期追求的目标；真正难的是操作背后的决策逻辑——遇到各种 case 到底应该怎么处理，这是非常长尾的问题。他据此认为把数学/coding 上 RLVR 的 scaling 思维定式迁到 CUA 被高估了：数学与 coding 是相对封闭的世界，CUA 面对的是开放世界，对环境的要求与成本完全不同。

他给「ChatGPT 时刻」下的定义偏终局形态：一个像生活秘书一样的通用数字助理，你把问题说给它，它能自己想办法解决（他举了自己用虚拟卡买礼品卡导致亚马逊账号被封、至今没解决完的真实经历——这类事纯靠点击解决不了，需要理解申诉流程的决策逻辑）。除能力外，他强调入口因素：他看好 OS 级入口（AI PC / AI 手机），但这背后牵涉的商业与生态问题很难预测。

在 self-improving（自进化）问题上，谷雨给出全场最体系化的一段：当前最大的瓶颈是数据。已文档化的数据很大程度已被挖掘，但大量知识是 undocumented 的——过程知识、办公场景里的交流与软件使用痕迹，这些从未进入训练。他 bet 的范式转移是：从「人被动准备数据训练模型」转向「模型在部署中主动从 interaction 里获取并决定学什么」。表征上他认为短期非参数化方式能立刻产生迭代，但长期更有效的还是压进参数。落到 CUA，他认为 grounding 与操作层可以靠被动学习解决，self-improving 真正的战场是让模型进入真实场景、理解业务的决策逻辑并不断自我改进。

陈周俊：瓶颈不在学习范式，在 environment 如何 scale up

周俊自陈是做 RL 的，但同意「learning paradigm 至少不是现在的 bottleneck」：环境与数据没被 grounded 地拉起来之前，讨论哪种学习算法学得更好体现不出来。他还补充了人机分工的建模问题：agent 需要一个 belief state——知道自己处在什么状态、什么时候该停、什么时候该求助人。现在的做法把一切都压进 policy，没有显式建模，部分可观测性（partial observability）下就会出现「点了搜索框但截图里没高亮、于是反复点」这类行为。

他介绍的组合式 benchmark（computer use + coding + deep research 三种能力组合在同一任务里，因为真实任务往往每样都要沾一点）给出两个关键数字与观察（字幕口径）：最好的开源模型（Kimi K2.5）只有约 11 分，而闭源模型可达四五十分；但在 OSWorld 这类单一 benchmark 上两边差距远没有这么大。也就是说，开源与闭源的真实差距藏在组合式、长时程任务里，error analysis 显示差距主要不在 grounding，而在 reasoning / planning。他还发现：不规定解法时，闭源强模型明显更偏好用 code 来解题（读 HTML、写脚本），效果也确实更好；能不能用 coding 往往取决于基础设施是否暴露 API，没有 API 才只能读截图。

关于开源，他以 LLM360（字幕作「LM360/M360」）为例：这个组织从数据到 70B 模型全程开源（pretrain、mid-training、SFT、RL、全部 checkpoint 与日志），填补的是「完整训练 recipe 的 revealing」这一空白——学生能看到真实训练中发生了什么（如 loss spike），这些日志与 checkpoint 长期看本身就是研究语料。代价是流程变慢、快迭代与全面公开之间要做优先取舍。

彭冲：大厂的优势在基建与算力，短板在组织灵活度；被低估的是数据与环境

彭冲与周俊判断一致：被高估的是算法层面的花活（很多 agent 论文的 RL 增益不可复现、无法推广），被低估的是数据与环境。OSWorld 过去两年指引了领域进展，但已经开始饱和，而且它总共只有 369 条数据，做 RL 实验时不得不拆成两半一半训练一半评测——这就是训练数据与环境稀缺的缩影。他列举的新进展包括静态轨迹数据集、动态环境在持续开源。

谈到大厂视角：CUA 极吃沙盒基建与算力，资源是大厂相对创业公司与社区的真实优势；劣势是组织灵活度（他本人在 2025 年三四月就想全职转 CUA，组织到七月才放行）。

他对 EvoCUA 开源的复盘很具体：最大的支撑来自工程团队——两周内搭起平台、后来做到上万并发沙盒 rollout，且 Linux、Windows、macOS 都能跑；模型只用 Linux 环境数据训练，在 Windows 任务上表现也好过先行工作，说明数据做得精细时泛化性不错。但部署到自己 Mac 上「还是干不了啥」：数据的真实性与多样性不够，缺真实用户的文件系统与输入回流——在没有 C 端产品的公司里，这类数据根本拿不到。他给开源社区开的药方排第一位的是评测：开源社区立场天然中立，而好评测需要前瞻性、本质是对问题的定义，这件事特别值得社区去做；其次是非英语、长尾 app 场景的评测覆盖。

林雨：hybrid 路线被低估；开源对模型厂是「触达」与生态补充

林雨认为过去一年纯 GUI 路线被高估、hybrid（GUI + API/code 等混合）方式被低估。MiniMax 约 400 人，模型、工程、产品物理距离近、决策链短，这是偏创业型公司的优势；劣势是资源受限，只能把资源集中在当前最有价值的方向。其 CUA 产品上内部模型已有实际上线使用，后续计划扩展到 mobile 等全平台。

对开源的看法分两层：对模型厂，开源核心模型是一种触达——让更多人本地用起来，雪球滚出影响力与口碑，并吸引人才；反过来，开源社区的训练框架等基建也会被大厂吸收优化，是互相补充的过程。

共识与分歧

共识：

  1. 操作/grounding 层基本解决，不再是主要矛盾（谷雨、周俊、彭冲三人明确同调）。
  2. 瓶颈在环境与数据的 scale、以及长时程 reasoning/planning；算法花活的边际收益被高估。
  3. 开源与闭源长期共存：林雨从「涉及个人文件系统与隐私、必然存在只能信任自部署模型的场景」论证开源模型的市场；谷雨用两个关键词总结协作关系—— complementary（互补：评测、数据、可靠性这些闭源不愿做的）与 revealing（揭示：把前沿 recipe 公开给研究社区）。
  4. 人的 taste/审美与判别力在执行被自动化后反而增值（谷雨称最高层级的 taste 是使命感；彭冲举文生图为例；林雨举做 PPT 为例——初稿不错，但不好看且难以靠文字描述改好）；分歧只在 taste 的边界会不会随模型能力上移而被逐步吞掉（主持人提出，周俊认为 taste 决定「不做什么」，即任务优先级本身）。

分歧：

  1. ChatGPT 时刻的形态：谷雨认为是通用数字助理 + OS 级入口；彭冲更保守地认为「永远不会出现以通用 computer use 为核心卖点的爆款产品」，CUA 只会作为一种执行媒介被吸收进通用智能体；林雨则预测一年内会出现某个子领域里真正取代人一部分工作的 computer use 产品（如 coding 之于 Claude Code）；周俊的定义最朴素：报税这类繁琐表单，每个格子都能可靠填对，填完人只需 check。
  2. 可靠性优先级：周俊把「不够可靠、太慢」列为第一、第二位（computer use 任务的性质决定了慢而错不可接受，因为人自己填只要十分钟），价格与隐私在其后；彭冲则从产品方视角指出可靠性与可验证性恰恰是大厂不 care 的——刷榜只需秀能力上限，不需要「这次做对、下次还做对、做错了自己知道」。

可证伪预测环节（字幕口径，一年为限）

  • 彭冲：benchmark 一定会被刷爆——OSWorld 2025 年初还只有 20 多分，现在已 80 来分，新版 benchmark 一年内会被刷到 80 分水平。
  • 林雨：一年内会出现一个大家都在讨论的 computer use 产品，在某个小子领域真正取代人的一部分工作。
  • 周俊（相对激进）：未来一年在常用主流 app/网站上，用户可以不用手动操作，看着它干。
  • 谷雨（反向押注）：永远不会出现以通用 computer use 为卖点的爆款产品，CUA 会被吸收进通用智能体；并玩笑称其公司会在 12 个月内被以 100 亿美元收购（明确自称开玩笑，不计入预测）。

5可迁移

  • 评测设计：单一维度 benchmark 会掩盖真实差距——组合式任务（多能力 compose、长 horizon、解法不预设）才暴露开源与闭源在 planning 上的代差。给自己的 agent 评测留一类「不规定解法、只给问题描述」的组合任务，比多刷一个单项榜更能测出上限。
  • 数据飞轮的先决条件：彭冲的教训是，没有产品就没有真实用户文件系统与输入回流，合成数据再精细也补不上真实性与多样性这一课。做 agent 数据时，先想清楚回流通道从哪来。
  • 可靠性作为独立维度：把「重复运行一致性」与「做错时自知」做成单独指标（而不是混在成功率里），这是大厂激励下被系统性忽略、社区与小团队能建立差异化的点。
