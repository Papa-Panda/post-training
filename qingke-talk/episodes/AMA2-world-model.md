## 一句话总结

五位自动驾驶/具身背景的世界模型研究者达成一个基本判断：世界模型的价值不在「生成更长更清晰的视频」，而在它能否作为 data engine、simulator 和 policy 本身三件事真正落到真机与下游任务上；表征（pixel / latent / 3D-aware）、失败数据从哪来、以及如何评测，是三个仍未解决的核心问题。

## 圆桌问答

### 开场：每位嘉宾的入行路径与「踩过的坑」

主持人请每位嘉宾介绍自己为何关注世界模型、以及最重要的认知转折。

- **王晓峰**：2023 年夏天从自动驾驶起步做 DriveDreamer。Sora 出来后曾想把自驾积累迁去做通用 world simulator，结论是通用世界模拟对算力需求极大，「这个事还是非常非常难」；转折点是意识到世界模型必须找到具体 application 才能「做得更实在、更扎实」。目前在做 action-conditioned 的 GAIA-World 新版本。
- **王雨琪**：2023 年夏天听了特斯拉的世界模型 talk 后做 DriveWM。三次认知迭代：先以为 diffusion 能生成就够了，但数据有限时 rare 场景不行；再去补数据，发现「就算你哪怕有这个数据，diffusion 由于它是一个 joint 的优化，它很多因果性也学得不好」；于是转 AR 架构，又发现「用 pixel 的表征方式去学世界模型本身就是一件很困难的事情」，落点是表征比架构更根本。近年的冲击来自 R1 之后的 RL 浪潮：世界模型作为物理世界的 reward / planning 轨迹生成器开始变得可行。
- **贾肖松**：从 RL 一侧切入。在 CARLA 2.0 这类「过于困难」的仿真里没人愿意手采困难场景数据，PPO 直接上不行，23 年初 DreamerV3「挖到钻石」给了启发，于是做 model-based RL（Think2Drive）。他点出世界模型 + RL 的工程之痛：训不动时「你不太清楚到底是 reward 不对，还是 policy model 不对，还是 world model 有问题」。他判断具身领域的 reward model 还停留在抓取等简单任务，长时程任务的 reward 工程是巨大挑战。
- **廖康**：3D 重建出身（重建、位姿估计）。他认为现在世界模型「更多是一个 generation」，缺少内在理解；他想在统一模型里把理解与生成一起做，让物理/3D 的先验在内部就建好，而不是像 DreamZero 一类工作那样「潜在地学习、并不知道怎么去学习 action 与世界的交互」。他的经验教训是方向切换要快：「以半年为时间节点算的话，你如果不 follow 一些比较新的技术，你可能就掉队了。」
- **佳智**（补充反思）：Sora 的 demo 是否把学术圈带偏了——「大家所追求的就是生成的特别特别长、resolution 非常非常大、所有东西都特别清晰，其实反而忽略了到底我们应该关注这个视频里面的什么东西……导致我们对下游的探索都变轻了」。王雨琪部分同意：大家被 Sora 带得往生成质量上靠了很多，「但他的爆火也确实让大家把生成的能力做得很好，不完全是说给带偏了」。

### Q：生成与理解的统一，背后的 motivation 是什么？真的能互相促进吗？

佳智向廖康发问。廖康给出两点：一是 AGI 必然是全能的，理解与生成（及重建）不应是割裂的专家；二是两者是「不同粒度上的监督信号」——理解提供 high-level 表征，生成本质是 low-level 的仿真，能补上理解做不到的精细几何知识。他自述在空间智能统一大模型项目中验证过：在中低层面的几何/物理类任务上，生成确实能反哺理解。但他也承认当前统一模型在纯文本理解榜单上仍与专用理解模型有差距，需要物理、空间、几何这类「中间粒度的 task」去连接两端。

### Q：在大模型已被验证的今天，为什么还需要世界模型？（主持人总起）

王晓峰借一篇世界模型 survey 的框架给出三种 application：

1. **Data engine**：主机厂不缺普通数据，缺 corner case（极端天气等）；具身更是「整个发展被数据 bottleneck 住了」。世界模型可以低成本补这类数据。
2. **Simulator / environment**：借 Shunyu Yao「下半场」的说法——语言模型接下来重要的是怎么打分、怎么给 reward、怎么给可交互环境；physical AI 的 policy 迭代更需要一个能替代真机测试的仿真器（呼应 Sora 自称 world simulator）。
3. **Policy generator（WAM）**：从 OpenAI 的 transfer scaling law 出发，结论是 pretraining 与 post-training「最好是做同一件事」知识迁移才最高效；而 VLA 继承 VLM 的 next-token 语言预测，与下游连续 action 监督之间 gap 很大，并不符合这条规律。用视频预训练对齐下游 action prediction，可能是一个更好的范式（他个人 believe，但承认需要更 solid 的 scaling 实验）。他还补了一个直觉：没有语言系统的动物靠视觉+触觉就能做精细动作，所以「更加值得 scaling 的恰恰是 video data」。

讨论随即转到一个尖锐的子问题：**世界模型能不能学会「失败」？** 佳智提出：想要的是当 policy 给出坏 action 时，世界模型能生成 failure 的未来，而不是永远生成完美轨迹；但失败数据极度稀缺，这件事是不是本质上 data-hungry？王晓峰回应：他们办的 CVPR 比赛就是验证这件事——给一半纯成功的遥操数据、一半有成功有失败的 rollout 数据让选手自己配 recipe，结果前几名模型与真实世界的匹配（成功/失败一致性）「真的可以到 70% 以上」，上百支队伍统计下来是个正向信号。工程上他给出两条经验：一是高效利用模型自己的 rollout 数据；二是 action condition 的形式——把语言当 action 做 cross-attention（implicit，如 Ctrl-World 一类）容易训、相关性高但控制不精细（抓笔差 1–2 cm 就抓不起来），显式的 pixel-aligned 控制（把机械臂动作渲染出来作条件，如 Embodied Dreamer，或 Google 用关键点表征机械臂）目前更适合做 simulator。

贾肖松则借 π0.7 的做法提另一个角度：视频先生成一个确定性的未来、policy 再去执行它，可以在训练时消掉多模态行为带来的「数据的诅咒」；更一般地，世界模型若能「利用任意 quality 的数据——只要能准确描述这条数据是什么质量、该不该模仿」，就有独特价值。

### Q：学 video 为什么会比直接学 action 更好？（可达性/泛化之争）

这是全场争得最细的一问。佳智与贾肖松共同质疑：一条轨迹既有对应视频也有 action，diffusion 本有能力学多峰分布（往左、往右都合法），凭什么说先学生成的未来图就「更可达」、更确定？

- 佳智（Vista 经验）：关键不在可达性，在视觉泛化性。VLA 只学语言到 action 的映射，在训练场景里很好，换了东西视觉泛化就断；视频生成模型有很强的视觉泛化，先把未来「想象」出来，再从被缩小了的视觉空间 decode 出轨迹，事情就变容易了。
- 补充机制：只用 action 做 supervision 信号太稀疏，模型容易 shortcut 甚至「不怎么看图」就训出不错的 policy，其实是过拟合塌陷；预测 video/image 是稠密监督。
- 廖康：DreamZero 的强泛化给了他们启发——WAM 把 video token 与 action token 一起训练时，海量 video token 相当于正则项，把 action 的过拟合「拉远」，这是 WAM 与 VLA 泛化性差异的一个可能解释。

顺带抛出一个空白地带：VLA 领域几乎没人做 representation learning——大家只顾着把 backbone 做大，没人看 policy 学到的特征到底长什么样、是否可迁移。王晓峰提到美团 Larry Bench 的消融结论：semantic embedding 比重建/视觉预测类的 embedding 学到的 representation 更适合做 policy generation。共识是：谁能真正解释「为什么 WAM 比 VLA 更好」，谁就推进了这个领域。

### Q：应该在 pixel 上做世界模型，还是 latent / JEPA / point-cloud / flow？

这是「预测 pixel 是否有必要」的路线之争，回应的是 LeCun「生成视频是死路一条」的说法。

- **廖康**：看下游——要高保真 3D 世界就用 pixel；但 pixel 太贵、容易把容量浪费在无关细节上。latent 更优雅、可接各种头，但缺可解释性、控制准确性难保证。他还提到 thinking-with-camera 类工作给世界模型补「绝对物理关系」（如绝对水平线）作为锚点，可缓解长时程漂移。另一个共识性的吐槽：现在大部分工作对 future 的监督非常直接、缺少显式 3D 约束，生成视频里「手一靠近苹果就自己贴上来」——因果与物理都是错的，模型只是模仿 VAE latent，并不知道什么是物理。
- **王雨琪**：倒未必是 pixel——pixel 是最容易拿到数据、能 scale 的方案，但代价贵，且 policy 未必需要这么精细的表征。难点在于 pixel 与 language 都有现成监督，而中间态 latent「怎么定义、怎么监督」非常难做。她引自动驾驶的 BEV/occupancy 经验：数据受限时，引入 3D-aware 表征可能比 pixel 更好用；现在大家还多用 pixel，只是因为「视频这边的基模还是太强大了」，缺一个可用的 3D foundation model。
- **贾肖松**：提出「一大一小双世界模型」——policy 侧用小而快的模型做局部推演，另训一个几十 B 的大模型做高保真世界还原（造数据、做 RL 环境）。佳智接话：这其实就是分层——Figure 的 System1/System2 式结构用在世界模型上同样成立，因为世界表征本就不是定长的一秒或五秒。
- **王晓峰**：还是看 application。自驾做 data engine 要输出 RGB 与点云，就得在 sensor 空间建表征；做 simulator 要产出 observation 喂给 VLA，也在 RGB 空间；至于所谓 latent space，「这个词对我来说还是太 latent、太 implicit 了」，他更愿意叫它 action space——把多源信号映射到与 action 相关的视觉 embedding 空间，只预测与 action 相关的视觉 embedding。但他承认 action space 如何定义本身是 open problem。

佳智补了个历史注脚：Dreamer 系列（V1–V3 都在 latent 里小打小闹）的作者 D. Hafner 后来转去用 World Model 在 Minecraft 里做 RL，「他自己也没有选择在 latent space 一直做」，学术是螺旋上升的；现在大家用视频生成，很大程度是因为有现成的预训练 backbone 可以直接拿来收敛，latent/point 一侧没有等价物可用。

### Q：世界模型与 policy 要统一架构、统一训练吗？AR 还是 diffusion？

- **王雨琪**（UniVLA 经验，基于 Emu3）：把 action 经 FAST 编码成离散 token，做成纯离散三模态自回归模型，先训出一个发现——哪怕第一阶段只是 text-conditioned 的视频预训练，在其 checkpoint 上「反推」一个 policy、迁移效果也很好。他的判断是「统一架构非常优雅，但并不那么关键，关键还是怎么把多模态串联起来；数据可能会比架构更重要」。个人偏好 AR：「AR 天然更适合建模因果关系，而因果关系对物理世界的应用非常关键。」
- **王晓峰**（GAIA-Policy 的 joint pretraining）：小数据、简单场景下 video+action 联合监督确实加速 policy 收敛；但换更大规模自有数据后「这个结论目前还没有收敛到和刚刚说的那个结论一致」，他归因于 data recipe 与数据分布，并重申「数据怎么构建、训练范式怎么设计，才是最重要的」。
- **廖康**：AR 与 diffusion 可以在同一架构里分工——high-level planning 用 AR、连续动作建模用 diffusion，不必二选一；AR 更好 scale，全转 diffusion 可能有上限问题。肖松的保留意见：真正做到原生生成-理解一体化的可能只有最前沿实验室那个 scale，学术界在现有数据量与模型尺寸下收益确实有挑战。

### Q：世界模型的数据从哪来？failure case 怎么造？仿真数据到底能不能吃到收益？

- 自驾侧的经验（佳智与贾肖松合作的工作）：把仿真里的 failure case 与真实世界的不安全 case 混在一起训，最后能生成出真实世界的 failure case——仿真数据确实能产生价值。原因：真实世界里 failure case 不可规模化采集（不能让 500 个人每天撞 10 次），而仿真里「随便乱撞」得到的 action-state pair 恰恰是世界模型需要的任意 action 想象能力。
- 王晓峰：纯机器人数据训出的世界模型在场景泛化（室内→室外）上容易遗忘视频基模的知识，所以预训练阶段要混 web data、遥操/真机数据、跨本体数据、egocentric 数据；越往后，模型自己的 rollout/exploration 数据对「world model as simulator」越重要。
- 数据筛选经验（佳智在美团做 DrivingDojo 的做法）：按三个维度筛——自车轨迹多样性、交互数据（车车/车人交互）、世界知识数据（红绿灯、升降杆等难以描述但对仿真重要的数据）；更 diverse 的数据确实让模拟变好，但「始终无法解决真实世界」的问题。
- 有人提到 Simulation Distillation 一类工作：完全不用真机数据、只在仿真里训世界模型，数据足够 diverse 时能较容易地迁移到真机领域（展示任务偏简单）。
- 仿真 vs 真机的产业分歧（佳智转述 CES 上两家公司的对谈）：一方几乎不用仿真（测试在真实场景，训练就采真实数据）；Skild AI 则把高度 diverse 的仿真数据当核心资产（光照、桌面高度、物体大小在仿真里可控且便宜）。
- 一个被多位认同的框架：仿真容易 scale 的是 environment diversity，真机容易 scale 的是 task diversity，两个轴框出的泛化空间比单轴大，两者不互斥。但贾肖松泼冷水：manipulation 的很多任务本身极难仿真（柔性物体、抓取精度），搭一个仿真的成本不亚于真机采集。肖松补一刀经济学：如果真机遥操/UMI/egocentric 的采集成本降到低于仿真建场成本，仿真的价值就会下降，纯仿真越往后价值越低；且仿真里的动作分布多是单一模态（规则生成），与人手的多模态动作分布有本质差别。

### Q：评测世界模型应该看什么？哪些能力对 policy 真正有帮助？

- **贾肖松**：现有从常识稳定性、物理一致性出发的视觉评测都合理，但「对策略的有效性」这一维度社区做得很不充分，而且本身就难——policy 在世界模型 A 里 30 分、B 里 40 分、真实世界 50 分，不能就断言 B 更好，可能只是 B 生成的东西更贴合这个 policy 训练时的分布。他设想的办法是把路径与 policy 轨迹都「固定死」再反过来评世界模型，但承认还没想清楚。
- **王晓峰**（企业内部标准）：只看 benchmark 刷分的版本「内部同行评议是不会通过的」。三条落地标准——做 data engine 就看造的数据能否让真机泛化场景成功率上升；做 environment 目前主要用人工评测（真实 rollout 的成败由三个人看同一批数据判定，不信任模型打分，因为现阶段模型打分 bias 很大）；做 WAM 最终还是看真机成功率与数据/算力效率。
- 佳智顺势问了一个常见质疑：训世界模型本身就需要泛化数据，那为什么不直接拿这批数据训 policy？王晓峰用语言模型类比回答：GPT-3.5 到 o 系列之后，大家大量用模型造的结构化数据训自己；世界模型泛化到一定程度后也能「组合出世界中难以采集的数据，左脚踩右脚让自己上天」。王雨琪同意：核心是组合泛化——模型能自己出题、自己 evaluation，就能造出泛化数据反哺自己。
- **廖康**：重点看两个维度——物理真实性（多视角生成接到一起要能对应一个真实物理，而不是各画各的）与 memory 的时空一致性（镜头移开再移回来，history 不能丢）。实现上已有两类方法：一类是 lift 到 3D 空间再投影回 2D 用一致性做约束/损失，另一类是直接把 depth 等 3D 信息一起训、隐式同时建模两个空间。
- 物理能不能靠 scaling 数据学出来？佳智的怀疑很直白：视频模型已经把 YouTube 和各家私有数据训遍了，人和人还是会「连到一起」、抓取的因果还是乱的，碰撞、摩擦这类细粒度物理连 caption 都很难写，「这个成本是完全不可估量的高」。廖康确认：深度、重力这类可由大模型标注的属性相对成熟，但细粒度物理的 caption 是目前的大问题。

### Q：世界模型需要 long-horizon 的想象能力吗？

佳智自陈曾反思：优化 local action 时似乎只需要 local 想象，卷生成长度是否必要？多数意见偏向「不需要为卷而卷」：核心能力是状态间的 transition 学得准，action 能作用多久就推多久，单步准了自然可以 AR 式地滚下去；long horizon 只在任务本身需要长程决策、或要在世界模型里多次 rollout 做 planning 时才成为必需。但 inference-time 用几 B 的模型在世界模型里反复 rollout 再执行，「好像是一个做不了的事情」——佳智自述做 RISE 时想过各种做法，最后认为做 RL 更实际，inference-time planning 目前太慢。

### Q：工业界到底有没有落地的世界模型？

王晓峰（不点客户名）：自驾的 data engine 落地较多——主机厂缺的主要是 perception 训练用的 corner case；simulator 需求同样强，但「现在应该没有一家（敢说）纯生成式的世界模型仿真方案可以量产交付」，实际跑通的是生成式与 3DGS 结合的方案：把 3DGS 场景建得足够大，在里面开车、做 evaluation，2024 年以来主机厂持续有需求。机器人侧目前还在早期趋势阶段。

### Q：学术界资源远不如大厂，还能怎么做研究？

- **贾肖松**：不要硬卷 Wan14B 或几十 B 的视频模型，也不要立「洗多少 B 数据」的大 project。他相信的方向：把物理世界里 object 的 state 抽出来做锚点——从一段 robot video 里把 object/robot 的 asset 提出来（object level 或 VGGT 点级别重建），再渲染、再结合生成，而不是 pixel-to-pixel 映射。怎么提合理的 asset、怎么端到端做好、怎么从视频直接估物理属性，都还没有被很好地回答。算力要用在真正做交互的主体上，别浪费在背景渲染上。
- **廖康**：与导师（字幕作「KEVIN」）常聊此事——大厂有数据有管线、千卡训一波就走，学界的优势是有时间想工业界没时间想的问题。他举多智能体方向：现有世界模型几乎都是 single agent，多个 agent 在同一个世界里共享 memory、实时交互更新，是探索不多又不需要太多卡的方向。他还认为 benchmark 是低算力高杠杆的事——但好 benchmark 不能只给数字，要能给出 insight（比如某个新维度能让某些模型失效的原因）。数据上他提醒：很多学生任务时长很长但任务特性很低，真正缺的是任务数量与多样性而不是时长。
- **王晓峰**：可以做 training-free 的工具型工作（他举了 TeaCache 类视频生成加速的例子），关键是把工具做到当前市面最好的 foundation model 上让大家用起来——训练代价小，但影响力上升，自己也把先进模型摸了一遍。
- **王雨琪**：在确定性道路上跟大厂卷确实很难，学界更擅长找新路、做分析和探索，比如「什么样的表征对下游 policy 更有效」就很适合学界、工业界未必愿意做。他最后讲了 DiT 的往事：DiT 在公司内部起初被认为没用、太简单，但坚持做下来成了 Sora 的 scale 管线——「即使和当时主流 pipeline 都不一样，还是可以做一些非常 fundamental 的尝试」。

## 观众问答（评论区）

**Q：世界模型里面怎么用 RL 的 reward？**
佳智：两条路。一是 reward 可以学出来——标 +1/-1 用模型学出连续值；二是把 episode 的 progress 当 reward 来源：episode 起点 value 为 0、完成时为 1，学一个 reward prediction 模型，之后世界模型里每个 state 都能过这个模型得到对应 value。

**Q：NVIDIA Cosmos 的应用也有限，真的能做到实时推理、提升模型性能吗？**
王雨琪：看推什么——推图片仍然很难；推 latent 表征就有可能。而且更可能的形式不是时时都推，而是「在有些场景它会激活它的推理」，按需触发。

**Q：从 DriveDreamer 一路做下来，实现了哪些突破？**
王晓峰自述脉络：DriveDreamer/2 做单视角到多视角视频生成与 perception 的 data engine；DriveDreamer-4D、ReconDreamer 把生成模型与 3DGS 结合建更完整的 3DGS 驾驶仿真；ReconDreamer-RL 在建好的场景里让车做 RL；UniDriveDreamer 做多视角 RGB + LiDAR 的多模态生成；最近的 DriveDreamer-Policy 是自驾场景的 WAM。

**Q：怎么看 3D-aware 世界模型路线，比如和 VGGT 这类 backbone 结合？**
廖康：短期内接一个 3D 重建 backbone 是直接且 make sense 的（现在的 VLM/VLA 没有 3D prior）；长期看会收敛，因为下一代视频模型本身可能就在 3D 重建数据上训，届时只需把 depth/camera 头接出来即可。

**Q：物理的 hidden states（密度、易碎性等）如何通过仿真模拟？／symbolic world model 可做吗？／脉冲神经网络会是具身智能的未来吗？**
前两问现场无人认领深入回答。贾肖松对 symbolic 路线表态：他老本行是轨迹预测，觉得在像素世界模型之外、背后有一套 agent/object 的博弈推演是 promising 的路线，「生产出来他们有趣的博弈」本身就值得研究。脉冲神经网络一问全场明确表示不在专业范围内、无法回答。

中间还穿插了一个未被追问完的发现（佳智）：在世界模型里控制自车去撞前车，前车居然会自己避让开——模型学到的是数据里「车与车没什么交互」的统计，你硬让自车乱开，它会把周围车躲避掉。这指向 multi-agent control 的必要性：不控制其他 agent，世界就会按数据的先验把冲突消解掉。

## 共识与分歧

达成的共识：

- 世界模型的成败最终要落在真机与下游任务上评判，只看生成质量刷分的版本没有价值。
- 失败/failure 数据是世界模型当 simulator 的前提，且只能靠仿真生成与 rollout 数据配比解决，没法从真实世界规模化采集。
- 数据（recipe、分布、来源构成）比架构更决定成败；仿真与真机数据不互斥，分别 scale environment diversity 与 task diversity。
- 「卷更长、更高清的生成」对大多数下游任务不是必要的；单步 transition 的准确性更根本。
- 学界的机会在表征、benchmark、多智能体、training-free 工具等低算力高杠杆处，不在硬拼规模。

保留的分歧：

- 表征路线未收敛：王晓峰主张按 application 选（甚至把 latent 改名 action space），王雨琪赌中间态/3D-aware 表征，贾肖松主张一大一小分层并存，廖康认为 generation 与 understanding 终将在一个统一模型里收敛。
- 物理规律能否靠 scaling 数据学出来：佳智明显怀疑（细粒度物理连标注都写不出来），廖康相对乐观（部分属性已可标注、路线在收敛）。
- 世界模型当 simulator 的产业成熟度：王晓峰认为纯生成式方案离量产还远（现实是 3DGS 混合方案），而学界讨论的版本要超前得多。
- RL 与 inference-time planning 之争：佳智认为当前阶段在世界模型里做 planning 不现实、RL 更实际；无人明确反对，但 long-horizon planning 的价值在特定任务上被保留。
