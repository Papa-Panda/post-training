2一句话总结

图像与视频扩散模型的推理 FLOPs 甚至远超 LLM，算力账不解决，再好的生成质量也普及不了。SANA 系列的路线是四个方向一起抠：VAE 把图像压得更狠（深度压缩 32 倍）、DiT 用线性注意力把序列复杂度从 $O(N^2)$ 降到 $O(N)$ 、蒸馏把推理步数从约 20 步压到 1–4 步、再把自回归与扩散结合生成分钟级长视频——四篇合起来，是把 GenAI 视觉模型的价格打到笔记本 GPU 与消费级显卡能跑的工程答案。

3核心

背景/问题：视觉生成的 FLOPs 比 LLM 还夸张

按官网预告，本讲分四段：先讲视觉生成模型的计算瓶颈与四大加速方向，再讲 SANA 与 SANA-Sprint 的高效图像生成，然后是 SANA-Video 的长视频生成，最后 AMA。问题定义（官网口径）：GenAI 视觉模型（Sora 2、Nano Banana 一代）效果惊人，但单次推理的 FLOPs 甚至远超 LLM，部署成本高昂难以普及。四条成本曲线各有解法：高分辨率下 latent token 数爆炸（VAE 压缩率）、长序列下注意力平方复杂度（DiT 架构）、采样步数多（步数蒸馏）、长视频的 KV 内存随长度线性增长（Block Diffusion 与恒定内存缓存）。

方法/设计之一：SANA —— 压缩率与线性注意力各砍一刀

SANA（arXiv:2410.10629，ICLR 2025 Oral）的两把刀：第一，深度压缩自编码器把图像压缩倍数提高到 32 倍，latent token 数直接降一个量级；第二，Linear DiT——用线性注意力替换所有传统 softmax 注意力，复杂度从 ， $O(N^2)$ ， 降到 ， $O(N)$ ， （官网口径）。结果：Sana-0.6B 比大型扩散模型小 20 倍、吞吐快 100 多倍（官网口径），能在 16GB 显存的笔记本 GPU 上部署，生成一张 1024×1024 图像不到 1 秒（官网口径），最高支持 4096×4096 高分辨率生成（官网口径）。

方法/设计之二：SANA 1.5 与 SANA-Sprint —— 训练、剪枝、推理时扩展

SANA 1.5（arXiv:2501.18427）解决「怎么长大」：深度增长范式（depth-growth）把模型从 1.6B 平滑扩到 4.8B，配内存高效的 8-bit 优化器压显存；基于 block 重要性分析的深度剪枝可把训好的大模型裁到任意目标尺寸、少量微调即恢复质量；推理时扩展用重复采样以推理算力换等效容量。结果：GenEval 0.81，加推理时扩展后升至 0.96（官网口径，称刷新当时 SoTA）。

SANA-Sprint（arXiv:2503.09641）解决「怎么变快」：把预训练的 flow-matching 模型零额外训练地转成连续时间一致性蒸馏（sCM）的可蒸馏形式，再做混合蒸馏——sCM 保全局分布一致、潜在对抗蒸馏（LADD）保单步细节；步数自适应的单一模型在 1/2/4 步下都能出图，还集成了 ControlNet 做实时交互（H100 上 ControlNet 模式延迟 0.25 秒，官网口径）。结果：1 步推理 FID 7.59、GenEval 0.74，优于 FLUX-schnell 的 FID 7.94、GenEval 0.71（官网口径）；H100 生成一张 1024×1024 图 0.1 秒 vs FLUX-schnell 1.1 秒、约 10 倍（官网口径）；RTX 4090 文生图延迟 0.31 秒（官网口径）。

方法/设计之三：SANA-Video —— Block Linear + 恒定内存 KV 缓存

SANA-Video（arXiv:2509.24695）把 SANA 的两件武器搬到视频：Linear DiT 继续做核心算子；面向块线性注意力设计恒定内存 KV 缓存——利用线性注意力的累积特性构造固定内存占用的状态缓存，让 Block 自回归生成在固定内存下拿到全局上下文，支撑分钟级长视频（最高 720×1280、时长达一分钟，官网口径）。数据过滤与训练方案把总成本压到 64 块 H100 训练 12 天，约 MovieGen 训练成本的 1%（官网口径）；性能与 Wan 2.1-1.3B、SkyReel-V2-1.3B 一类小型扩散视频模型可比，实测推理延迟低 16 倍（官网口径）；RTX 5090 上用 NVFP4 精度生成 5 秒 720p 视频，从 71 秒缩短到 29 秒（2.4 倍，官网口径）。

结论/观点

按官网预告的表述，团队的判断是：视觉生成的普及瓶颈在成本不在效果——FLOPs、显存、步数、内存四本账都得算（这是预告页框定的讲授主旨）；线性注意力被明确表述为「处理超长序列的关键」（官网原文），复杂度从 $O(N^2)$ 到 $O(N)$ 不只是数学优化，而是长视频分钟级上下文的前提。讲者陈俊松为该系列核心作者（港大 MMLab、NVIDIA 实习），本讲按「四大加速方向」组织——DiT 架构、VAE、步数蒸馏、Block Diffusion——四篇论文恰好各占一格，SANA-Video 与 LongSANA 是第四格的最新进展。

5可迁移

  • 对 post-training / RL infra 的可试点：步数蒸馏与「训推成本前置」的账目框架——VLA/LLM 的多步生成同样可以做「sCM 式免训练转换 + 混合蒸馏」的同构移植评估，先在小模型上验证单步退化幅度，再决定是否蒸馏专模；SANA-Sprint 的混合蒸馏分工（一个损失管分布、一个管细节）对 RL 蒸馏目标设计有直接参考。
  • Infra 视角：SANA-Video 的恒定内存 KV 缓存与 Block 自回归，本质是把「上下文长度」与「显存」解耦——这正是 agentic RL 长轨迹 rollout 的同一个瓶颈（KV 随轮次线性涨、GPU 被占满后吞吐塌陷）；线性注意力的状态累积在长程 agent 里同样值得一轮对照实验。
