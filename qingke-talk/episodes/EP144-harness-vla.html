2一句话总结

端到端 VLA 的局部接触技能其实够强，坏就坏在部署扰动下：指令换个目标、物体挪个位置，模型还会照着训练分布的老轨迹走完，一次接触失败整条 rollout 就废。本期的工作 Harness VLA 不动 VLA 一根参数：把冻结的 VLA 封装成一个可重试的接触密集原语 $vla\_act$ ，再配一小组固定的解析原语（移动、旋转、夹爪、导航）负责非接触的走位与摆位；上层由 LLM 规划器（Codex / Claude Code 一类 coding agent）以 JSON 调用方式回合制地编排，配两层记忆——成功轨迹沉淀为 Task-Specific Memory、跨任务的成功规则与失败模型沉淀为 Global Memory。结果是：在 LIBERO-Pro 扰动基准上整体成功率从直接调用同一冻结 VLA 的 50.0% 提到 82.4%（Claude Code 规划器），比此前最强基线 RATS 高 38.6 个百分点；真机双 Franka 上同一冻结 VLA 还能做目标重定向、抓取恢复与新任务组合。

3核心

背景/问题：VLA 刷爆了 Benchmark，却搞不定真实世界的细微变化

官网预告把问题抛得很直白：VLA 在标准基准上分数很高，但真实部署里「语义重定向、目标重绑定、空间布局漂移、局部接触不稳定」四类扰动一来就垮。论文 §1 给出机理：端到端 VLA 是在分布内任务轨迹上训出来的，它把「语言 grounding、长程组合、低层控制」全压进一个策略里；部署时指令换了目标，视觉场景还长得和训练时差不多，策略会直接复放熟悉的旧行为，而不是听新指令——语言通道某种程度上是摆设（论文引 OpenVLA/π0.5 的观察原话是语言通道 "largely vestigial"）。一次不稳定的接触失败又会沿单体 rollout 一路传导，没有恢复机制。

另一条路线是 LLM coding agent + 解析原语（Code as Policies、ProgPrompt 一系）：语义与组合推理强，但纯解析控制器（IK 搬运、腕部旋转、夹爪开合）做不来不规则抓取、紧公差放置、铰接物体操作。论文的判断是两个范式各自「让错误组件承担了过多责任」：单体 VLA 被迫吸收全部组合与 grounding；coding agent 被迫用手工 API 实现精细物理交互。Claude Code 这类数字 Agent 的经验是另一条路：突破不只来自更强的模型，还来自模型之外的执行组织系统（Harness Layer）——模型负责思考，Harness 负责维护上下文、调度工具与纠错容错。本期就是把这套搬到具身：不扩原语库，而是让规划器学会用好一小组固定原语。

方法/设计：冻结 VLA 当原语，规划器回合制编排

论文 §2 的形式化：环境是刚体物理引擎（MuJoCo/Robosuite 一类），每步观测 $o_t$ 包含 RGB 图像、深度图与本体状态（末端位姿 + 夹爪状态），任务由语言描述 $\ell$ 与二值完成谓词 $\mathcal{G}$ 定义。所有低层控制——冻结的预训练 VLA 与全部确定性解析控制器——统一收进一个预定义原语库 $\mathcal{P}$ 。每一回合，规划器 $\Pi$ 读当前观测、任务描述与两层记忆里检索到的上下文，输出一个 JSON 序列化的原语调用 $c_t \in \mathcal{P}$ ，物理引擎执行到该原语的内部后置条件满足为止，再返回新观测。一直循环到 $\mathcal{G}$ 满足或步数预算耗尽。

原语库刻意保持小而固定（论文 §2.3、附录）：

  • $vla\_act$ ：唯一的学习型原语，把冻结 VLA 封装为「接触密集专家」，负责抓取、不规则物体操作、紧约束放置、按钮按压、水龙头/抽屉/咖啡机等接触丰富的局部阶段；
  • 解析原语： move_to（世界坐标笛卡尔目标搬运，后端可为操作空间伺服/Jacobian/IK，暴露的语义一致）、 move_pose（位置+俯仰联动）、 rotate_wrist / rotate_pitch（原地调姿）、 set_gripper / release（夹爪开合）、 navigate_to（移动底盘走位）。

关键在于调用语义： $vla\_act$ 不是一次性黑盒调用，而是一次「可重试的局部接触尝试」。规划器先用解析原语把机器人摆到有利于接触的预接触位姿（staging），再触发 VLA，观察接触结果；若抓空或放置不稳，就重新摆位、再调用一次。失败被局域化在这一个接触子任务里，不会污染整条长程 rollout。论文把它总结为一句话：harness 教的是每个固定原语的「工作范围」——哪类子问题该解析地解、什么时候该调用 $vla\_act$ 、失败后如何重摆位——而不是靠往库里加新技能扩张。

Harness 本体是 REPL 式运行时契约（论文 §2.2）：暴露原语 schema、把决策序列化为 JSON 命令、执行并刷新 RGB-D 与本体观测、记录轨迹、检索记忆、执行重置与预算策略、用基准谓词检查进度。本质上就是 coding agent 的执行-反馈闭环搬到机器人上，所以规划器可以直接复用现成的 Codex、Claude Code 作为骨干，只换提示与工具面。

记忆机制：两层记忆 + 两阶段生命周期

讲授提纲第 3 点对应论文 §2.2 的两层记忆：

  • Task-Specific Memory：探索式自举阶段在单个参考 seed 上成功解出的原语调用序列，序列化为 JSONL 轨迹存档；部署时按当前任务检索，做 few-shot 的重新 grounding（把旧轨迹里的目标、位置重新绑定到当前观测，而不是机械复放）。
  • Global Memory：从探索轨迹里提炼的跨任务可复用的成功规则与失败模型（哪些摆位容易抓空、哪类布局要先退后等），以启发式形式注入规划器上下文。

生命周期分两段：探索式自举——规划器在参考实例上被给予 reset 原语与宽松时间预算，反复试摆位次序、预接触位姿、 $vla\_act$ 调用时机与提前终止阈值，成功后把轨迹与规则写入记忆；部署评估——在扰动后的新实例上检索记忆、重新绑定目标与状态后执行。注意部署阶段会根据当前 RGB-D 观测重新绑定目标、位置与状态，而非复现旧轨迹，这是它能抗布局扰动的关键。

还有一个部署形态 Flash Mode（论文 §4.1）：把成功运行编译成「任务卡」（动作顺序、VLA 提示、非空间参数；空间航点相对任务相关物体存储），部署时由 VLM 在 RGB 里定位目标、反投影成 3D 坐标更新航点，顺序复放，不再做在线规划。Flash 在 LIBERO-Pro 上达 72.63% 成功率（581/800），介于 Codex 高推理与无推理两档之间。论文也明说 Flash 目前只适用于子目标顺序固定、目标可直接定位的简单任务；新子目标、动作重排或意外恢复仍需在线规划。

实验/实战：同一冻结 VLA，换上 Harness 前后

评测覆盖三类仿真基准 + 真机（论文 §3）：

  • LIBERO-Pro（桌面操作，指令重定向 T 与位置交换 S 两类扰动，Spatial/Object/Goal/LIBERO-10 四套件）：冻结后端是 RLinf 发布的 π0.5-SFT 检查点 $\pi_{\mathrm{RLinf}}$ 。直接调用该 VLA 整体成功率只有 50.0%，端到端 VLA 基线在扰动下普遍塌陷（π0.5 整体 11.0%、OpenVLA 0.0%）；此前最强的 agent 式基线 RATS 为 43.8%。Harness VLA 以 Codex 规划器达 72.1%、Claude Code 规划器达 82.4%，对 RATS 的 +38.6 个百分点就是官网与摘要的口径（82.4 − 43.8，非增幅百分比）。同表的消融对照说明增益不是来自后端更强：同一个 $\pi_{\mathrm{RLinf}}$ 检查点，直调 50.0%，套上 harness 后 82.4%。
  • RoboCasa365（家居厨房、移动底盘、长程复合任务）：直接冻结 VLA 基线 RLDX-1 整体 30.0%；Harness VLA（Codex）达 57.1%（+27.1 个百分点，v5 口径），Claude Code 版 48.6%。
  • RoboTwin C2R（clean→randomized 零样本迁移，记忆只从 clean 设置探索得到，不在随机化设置里再探索、也不微调 VLA）：冻结后端换成 LingBot-VLA，直调 50.4%，Harness VLA 提到 58.0%（Codex）/ 58.4%（Claude Code）；对照 GR00T-N1.7 的 20.7%、π0.5 的 47.9%。
  • 真机（双 Franka，两套装置，论文 §4.2）：Codex（GPT-5.5）调用冻结 π0.5 桌面清理策略做抓取、交接与放置，展示目标重定向、抓取恢复与新任务组合。

机制分析（论文 §3.3 三个 Key Finding）：第一，语义重 grounding 在规划器层完成——解析任务描述、从实时 RGB-D 里解出当前接触目标，让 VLA 只在规划器给定的绑定下做局部接触；第二，staging 决定成败——扰动后原始预接触位姿往往不再把目标暴露在 VLA 熟悉的局部构型里，规划器绕当前场景重新摆位，等于「学会让 VLA 从哪里开始动手」，而不是要求策略自己吸收分布漂移；少量规划器选定的 $vla\_act$ 调用就能越过直调基线，随后饱和（Fig. 4）；第三，解析原语把非接触结构（自由空间搬运、预接触摆位、腕/底盘调姿、撤退、接触后重新定位）从 VLA 身上剥离，LIBERO 里 $move\_to$ 占全部调用的 61.8%、 $vla\_act$ 只占 15.8%（论文附录 F 用量统计）——VLA 用得很稀疏，但可重摆位与可重试是鲁棒性的来源。

零样本消融能分离记忆的贡献（论文 §3.2，LIBERO-Pro Goal）：不检索任何自举记忆时，指令重定向（Goal-T）还有 79.0%（few-shot 为 87.0%），但位置交换（Goal-S）从 87.0% 掉到 31.0%——语义重绑定主要靠规划器在线推理，而空间扰动下的原语组织方式最依赖探索阶段沉淀的任务级记忆。

结论/观点

  • 论文结论（§6）：可靠操作不只来自训更强的策略，也可以来自给冻结策略套一个可审计的执行环：固定原语契约、记忆、反馈与任务级验证。把语义与空间绑定从 VLA 身上抽象出去，能避免单体部署里常见的灾难性失败。这正是官网预告的问题意识：与其继续堆参数与数据，不如承认具身智能的下一站可能是给 VLA 装上 Harness Layer。
  • 作者自陈的三个限制（论文 §6，按原文）：（1）规划器与低层 VLA 之间是开环反馈——规划器看不到 VLA 内部状态，只能事后看接触结果；（2）没有用环境奖励与人类偏好做联合微调，后续需要样本高效的强化学习（原文举例 GRPO）；（3）缺少细粒度图像描述，高度杂乱的长程任务里结构化推理受限。未来方向提了与 ASPIRE 一类自动技能发现系统结合：当重复的原语组合暴露出缺失的抽象时，允许 agent 提议、验证并接纳新技能，但保留可审计的原语接口。
  • 本期的讲授侧信息（官网提纲第 5 点「应用价值与未来技术趋势」）在论文里对应 §6 与 Flash Mode 一节：样本高效（一个参考 seed 探索即可自举）、跨场景迁移（记忆重绑定）、长期自主执行（失败局域化 + 重试）。讲者现场如何展开、AMA 问了什么，无书面材料可核，本纪要不代拟。

5可迁移

  • 「冻结模型 + 可重试原语 + 小型固定工具库 + 两层记忆」是 agent 系统的一套通用骨架（直接可试）：把手头任何不稳定的生成式组件（代码生成、检索、VLA、数据构造模型）封装成带明确后置条件的可重试原语，上层用回合制 planner 编排，失败局域化到单个原语再重排/重试，而不是让单次长链生成承担全程。本期实测里非接触（非核心生成）部分用确定性代码兜底、核心生成只占 15.8% 的调用，这个比例感对 coding agent 的工具设计同样成立：能解析解的别让模型生成。
  • 记忆分两层存：轨迹级与规则级（Infra / 评测视角）：成功轨迹按「可重绑定的参数化模板」存（存相对锚点而非绝对坐标），失败模式与成功规则单独蒸馏成全局启发式。对应到后训练数据管线：SFT/RL 里跑通的解法与典型翻车模式也可以这样分账——轨迹进样本库，规则进系统提示/工具说明/过滤器；本期的零样本消融给了量化依据（空间类扰动最吃轨迹记忆，语义重绑定更吃在线推理）。
  • 评测要单独测「扰动轴」而非只测标准集（评测自动化）：LIBERO-Pro 的 T/S 双扰动 + 「同一冻结后端直调 vs 加 harness」的同后端对照，把增益干净地归因到系统组织而非模型变强；给自己的 agent/RL 评测加指令改写、目标替换、布局随机化三类扰动列，并固定后端做 harness 前后对照，才能分辨涨分来自模型还是来自脚手架。
