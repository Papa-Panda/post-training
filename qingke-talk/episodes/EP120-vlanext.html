2一句话总结

VLA 领域各家在不同框架、不同 benchmark、不同 loss 下自称更强，无法公平比较；本期工作以最原始的 RT-2/OpenVLA 为起点，在统一框架内沿一条「从最早 VLA 走到现代 VLA」的路线逐步消融，最终给出 12 条可直接照抄的设计准则：分出独立 policy head 并放大成 policy network、用 action chunking、用 flow matching 等连续 loss、用更强的 VLM backbone、用软连接（soft connection）连接 VLM 与 policy、当前别直接喂 video、多视角优于单视角、自感知（proprioception）加到 VLM 一侧且用一层 linear 就够、预测未来几帧图像的世界建模目标有用但慢、频域正则（低频加权）提升泛化。判词：设计选择大多不是质变，胜负在强 baseline 上能否仍然成立。

3核心

引入：为什么需要一份"配方"

讲者对现状的描述是「原始汤」状态（字幕口径）：工作很多，但每家用不同的测试、框架、benchmark、loss 与 setup，无法在完全公平的环境下对比，「A 组说 A 组的模型好，B 组说他的模型也更强」，单个设计到底有没有效、有多有效，没有客观评价。本工作的办法是搭一个统一框架，从 VLA 的起源 RT-2（及其开源版 OpenVLA）开始，一步步把现代设计逐个加上去，形成一条可复查的演进路线；其中有些结论是新的，有些是把机器人社区已有共识在统一环境下重新确认（讲者明说这一点，不冒充新发现）。探索分三组：基础组件（架构与 loss）、感知输入（video / 视角 / 自感知怎么进）、多任务学习目标（额外 loss 能否帮 action 学习）。前半程 benchmark 用 LIBERO，后半程因 LIBERO 已接近饱和、波动太小看不出差异，切换到同源但专测泛化的 LIBERO-Plus（在 LIBERO 任务上加 7 种扰动，训练集不变、只测没见过的扰动）。

第一组：基础组件（policy head、chunking、loss、backbone、连接）

起点架构：Llama 纯语言模型 + SigLIP 视觉编码器，输入一张当前帧图像 + 文本，输出下一帧 action；RT-2 的原始做法是把词表里最少用的几个 token 替换成 action token，用与文本完全相同的交叉熵分类来学。在此之上逐步替换：

  1. 要分出独立的 policy head，不要复用 token。直接把词表尾部 token 当 action 输出，会破坏文本空间本身的学习；把输出特征接一个独立的小 head，效果远远好于复用 token（讲授口径）。直觉：分出 head 等于把 action 学习的压力从语言空间里卸下来。
  2. 把 policy head 放大成 policy network。借 MetaQuery 的做法：用一组可学习 query 经一个 connector（transformer）把 VLM 特征整理成 policy 能用的条件，再以 cross-attention 注入；policy 从 2 层加深到 12 层后，性能又远远超过小 head。结论是 policy 要独立、且要给足容量。
  3. Action chunking 必开，长度至少 4。一次只预测下一帧 action（约零点几秒）信息量太小；一次预测未来 4 / 8 / 16 / 32 帧（约覆盖 1 秒）能让模型学到连续运动过程，同时还能加速推理。实测 4 以上差别不大，4 以下性能骤减（字幕口径）。讲者明说这是机器人社区已有定论，此处是重确认。
  4. Loss 用连续的，不要离散分类。把 action 值域（如 −1 到 1）切成 256 个 bin 做分类、或用 VQ-VAE 式离散化，学起来慢、收敛差；回归、diffusion、flow matching 这类连续 loss 明显更好、更稳，因为 action 本身就是连续过程。还有一层随性能水平翻转的细节：性能还低时回归反而好于 diffusion（action 分布简单，回归够用且好学）；性能上去之后 diffusion / flow matching 胜出，因为它能表达精细的 action 过程。本工作最终选 flow matching。
  5. VLM backbone 越强，VLA 越强（数据足够时）。对比 Llama、PaliGemma、Qwen-VL 三种 backbone，排序是 Qwen-VL 好于 Llama、再好于 PaliGemma（字幕口径）。讲者补充最近试了 Qwen3.5 的 0.8B 版本：参数量比论文里用的 2B 版本小得多，性能几乎一致，「可以考虑用 3.5 作 backbone」。
  6. VLM 与 policy 之间用软连接（soft connection）。三种接法：松连接（MetaQuery 式，只在最后一层把 VLM 输出特征接给 policy）、紧连接（π0 式，VLM 每一层特征逐层连到 policy 每一层）、软连接（在两者之间加一个缓冲区，先把有效信息蒸馏进缓冲区再传给 policy）。结论：软连接好于紧连接、好于松连接。理由是 VLM 的输出空间是文本、policy 的输出空间是 action，两者完全不同，紧连接硬连很难把知识迁过去；缓冲区给了文本空间到 action 空间一个过渡。讲者在 Q&A 中坦白：软连接「不是一个质变」，只是更好学一点、轻微提升，偏工程而非飞跃。

第二组：感知输入（video、视角、自感知）

  1. 历史 video 直接喂进来，目前无效。Qwen-VL 本身在视频理解上大规模训练过，把单帧图像换成历史几帧 video 是最自然的选择，但实测没有收益。讲者的解释：学的是 action 不是文本理解，action 需要 3D 空间理解，video 理解任务里学到的信息很难直接抽象成对 action 有用的东西。他个人仍相信未来有更好的方式能用上 video，但当前直接加不行——这是本期少数让他「一开始比较惊讶」的负结果。
  2. 多视角好于单视角，但真机上收益小于 benchmark。第三视角（高处俯瞰机械臂）+ 腕部相机视角（装在机械臂上）两路输入，在 benchmark 上提升巨大，因为仿真数据干净，腕部视角给的抓取边缘信息非常准；真机数据本身噪声大，收益就没有那么大。方向有效，幅度打折。
  3. 自感知（proprioception）要加，而且加到 VLM 一侧。自感知即机器人自身状态（字幕中称「自感知」，讲授里也混用 action state 指代）。四种接法对比：不加、加到 VLM、加到 policy、两边都加，排序是加 VLM 最好，其次不加，再次两边都加，加 policy 最差（字幕口径）。机制解释很关键：加到 policy 一侧会让 policy 的学习变得太简单——loss 下降极快，但模型就不愿再从 VLM 那里取知识，容易收敛到局部最优；加到 VLM 一侧则强迫 VLM 在长期训练中慢慢蒸馏出 action 信息再传给 policy。
  4. 自感知的注入方式越简单越好：一层 linear 就够。对比 linear、transformer、先用 MAE 式 masked autoencoder 预训练 action 表征再注入三种：linear 与 transformer 性能大差不差（linear 更稳），MAE 明显最差、掉了约 7–8 个点（字幕口径）。与上一条同构的解释：MAE 预训练出的特征已经自带 action 还原信息，模型又容易偷懒收敛到局部最优；linear 把融合的压力留给本来就很强的 VLM，反而学得更好。讲者的归纳：关键在学好融合，不在把 action 表征提前做深。

第三组：多任务学习目标（世界建模与频域正则）

  1. 预测未来图像的世界建模目标有用，但要预测"未来几步"而不是"最终目标"，且代价是慢。为了公平，他们不用预训练的图像生成器，而把图像 token 化后从头训一个 generator，用 next-token 分类学生成（讲者明说这不算完全公平，但至少没引入外部预训练模型的知识）。两个目标对比：预测任务完成时的最后一帧（目标帧）vs 预测未来几步之后的帧——后者好得多；直接预测目标帧收敛虽快，却容易记住训练集的目标长相、收敛到局部最优，新任务目标一变就学不好。整体结论：世界建模目标能带来提升，但要额外背一个生成模型，速度确实慢。
  2. 频域正则（frequency regularization）：便宜的泛化增益。灵感来自讲者与一位做时序预测的朋友的聊天：VLA 本质上就是带条件的时序预测，而时序预测领域频域流派已近乎「压榜」。把轨迹做频域分解后加一个频域 loss，实测主要涨的是 LIBERO-Plus 上的泛化而非 LIBERO 本身分数，讲者把它理解为一个正则化。细节结论：低频成分更有效——机器人轨迹采集里有直行、突然大拐弯和抖动，带来很多高频噪声；适当加大低频权重，泛化更好。这个方案的好处是不用背大模型，加一个很小的 loss 就行。

讲授末尾的两条实操经验（不在 12 条内，但讲者特别点名）：其一，warmup 非常必要；其二，当前 VLA 训练基本是一个过拟合过程——「不过拟合性能就上不去」，所以有利于过拟合的尝试对性能提升比较大。Q&A 中他把"训到过拟合"说清了：不是数据量大，而是同一批数据训很多遍、把 loss 降到足够低。

讲者的路线判断（观点，非实验结论）

  • 机器人数据的结构性问题：真实机器人数据永远在数据金字塔顶端、最稀缺；互联网上有大量带 action 的视频（自动驾驶、人体运动），但没标签、且与机械臂 action 差很多。讲者看好的解法是 latent action：不直接学 action 本身，先学一个 action 表示，用大规模视频预训练把 latent action 提出来，再拿这个预训练模型做机器人微调，让模型"提前见过类 action 的东西"。
  • 第二个方向是 VLA + reaction model（字幕词，按上下文即在 VLM 旁联合学习视频生成/反应模型再接 action 的多任务结构）：VLM 主干终究是语言模型，其表征空间源于人类语言，而 video 是更原始、更反映现实世界的数据，可能更有利于 action 学习。他判断未来更可能是 VLA 与视频建模联合学，而不是二选一。
  • 对 video model + imagination planning 路线：不冲突。那是用视频模型生成数据给 policy 学的数据增广；他看好的是把视频建模与 action 一起学的 reaction model，两者不同。VLANeXt 本身是 reactive policy（不断从环境取新输入、输出、再反馈），且很容易扩展到世界模型——把多任务部分的世界建模 generator 换成预训练初始化即可，他自己后续的世界模型工作就搭在 VLANeXt 基础上。

Q&A 要点

  • 组件之间有强交互效应，且不小。最典型的就是 loss 那条：regression 在低性能时有效，性能拉高后比不过 diffusion / flow matching 的泛化与精度。讲者由此给出一条方法论判词：探索要在强 baseline 上做——「基于一个很强的 baseline，如果还能有效，那这个东西就确实是可以的」；弱 baseline 上有效的东西未必可信。
  • 为什么 flow matching 在高性能段赢：到了高性能段，好与不好就差在抓杯子时偏一毫米还是几毫米这种细粒度偏差上；flow matching 通过多步细化的连续表达能刻画这种精细过程，回归给不出。连续 loss 整体胜分类，则因为 action 本来就在连续空间里表示。另外他明确确认：机器人动作本质上是多模态分布（抓杯子可以抓杯柄也可以抓杯身、可以从左绕也可以从右绕），不是确定函数。
  • 真机长时任务上结论还成立吗：他们没做太多长时任务消融，但最近在 clean table（抓多个物体放好，算稍长任务）上做过消融，结论一致。他的判断是长短任务差别没有想象中大——机器人反正过拟合在任务上，每个 step 的成功率差不多，步数多了综合成功率自然低一些。
  • Scaling 与 recipe 之争：不冲突。机器人的 scaling 确实慢（话题火了一年多，连大公司也还在秀 demo、难落地），但探索好 recipe 本来就是为后面的 scaling 铺路，两件事互相帮助。
  • "删掉 80% 设计只留本质"：讲者答得很实在——他自己在搭新框架时一点都没删，只把 backbone 换成了 Qwen3.5；试过删，删了性能就掉，而且这些设计的代价也没那么大，所以删 80% 他做不到。这个回答本身是对"哪条准则最重要"的一种回避式诚实：配方是整体生效的。
  • 软连接是本质优势还是更好调参：他承认更像后者——借鉴松、紧两种连接的直接延伸，性能只是轻微提升、没有质变，他试了很多变体后感觉 soft 还是好一些，「偏 engineer 一点」。
  • 对同行工作的态度：被问到某个同行 VLA 工作（如 MoVA，字幕音译）时，他说方法跟自己的「blow（框架）也比较相似」、性能挺好，但补了一句「好不好你自己做了才知道，说不定他调的时候才有 bug」——建议是把别家的 recipe 拿到自己的框架里直接试，这是最可靠的判断方式。他还提到一个学术取向的工作（字幕作「FASTONE」，未核对）把视频生成的部分直接去掉、训练时换一种身份，推理快很多、效果只差一丢丢，「想做的话可以看他公开的代码库」。
  • 最后一个问题（更强的 VLM 提升性能，靠的是理解任务、更会猜答案、还是别的）讲者答「他其实也不是理解任务，也不是猜答案，更多是更好的去拟合这个 action」——此答在字幕截断处中断（末条「我个人觉得」），后半句未收录，以上只记已播部分。

5可迁移

  • 「强 baseline 上再验证」是本期最可迁移的方法论：讲者明说组件间交互效应不小（regression 与 flow matching 的优劣随性能水平翻转），弱 baseline 上跑出的消融结论不可外推。做 post-training / RL 实验设计时，消融应在已调好的强 baseline 上做，并预期结论会随性能段翻转——这与本仓库 OPD 线「实施细节先于换目标」的经验同构。
  • 「把信息加在强模型一侧、用最简注入、把融合压力留给强模型」是一条跨域的设计启发式：自感知加在 VLM 侧 + linear 注入胜过加在弱 policy 侧 + MAE 预深加工，因为过强的现成表征会让下游偷懒、收敛到局部最优。对照 LLM 侧：给小模型/适配器喂过加工的特征、或让 loss 太容易降，都可能买到快速收敛但学不到真东西——loss 降得太快本身就是一条警报信号（讲者正是从 loss 曲线上看出 policy 侧注入的问题）。
  • 频域视角处理轨迹噪声：机器人轨迹的高频多来自采集抖动与突然转向，低频才是运动意图。对任何序列建模（包括 agent 轨迹、rollout 数据清洗），先做频域分解再决定平滑/加权，比时域硬过滤更可控；且这类正则便宜、无需额外大模型，值得先试。
  • 消融组织方式可抄：统一框架、从最原始 baseline 出发沿一条时间线逐步加设计，每步只换一个变量，benchmark 饱和后换同源泛化版继续测。这套「演进路线式消融」比散点式对比更容易让读者（和自己）看清每个设计的边际贡献。
