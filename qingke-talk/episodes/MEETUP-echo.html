2一句话总结

ECHO 把 RL 的 rollout 与训练彻底解耦：训练端只感知参数更新（体验上等同 SFT），rollout 交给去中心化异构推理引擎 Parallax 在全球消费级显卡/Mac/CPU 上弹性组装，权重更新再经蜘蛛网式广播同步到推理节点；实测在多个模型尺寸上精度与中心化 verl 对齐，证明消费级异构算力可以承接 RL 的生成阶段。

3核心

  1. 背景/问题：垂直行业用 LLM 需先 SFT 再 RL 提升泛化，但 RL 的 rollout 时间远大于参数更新时间（长思维链下生成可达万级 token），业务验证周期被拉长；同时 RL 训练成本高（讲者引不完全统计：A100 级显卡存量约千万级、消费级显卡上亿级），而现有开源框架（verl、slime 等，字幕口径）对异构/消费级设备支持不友好。讲者提出两个目标：让 RL 训练在体验上变成 SFT（训练侧不感知 rollout），让闲置消费级算力（白天打游戏、晚上跑 rollout）加入训练。
  2. 方法/设计：三层产品栈。① Parallax：去中心化异构推理引擎，上层做与模型无关的调度/路由，中层承接硬件优化，底层是分布在全球的消费级设备，支持请求量变化时动态扩容与新设备无缝加入；内置算子融合、缓存与通信优化。② ECHO 框架：训练端用 verl，rollout 端由 Parallax 承接，训练侧每次把 query + 模型参数发给 Parallax，推理结果（及 reward 计算）回传训练端；第二种模式下多个 Parallax 集群并行持续生成、结果进 buffer，训练侧只做 data load 与参数更新的循环，与推理完全无关；参数更新通过蜘蛛网扩散广播（先广播到离训练集群近的推理节点，再由推理节点向外同步）。③ 通信层（字幕作「拉提卡」）：面向去中心化环境的 P2P 通信架构，处理设备上下线、网络不稳定与设备间多跳通信。
  3. 实验/实战：Parallax 推理 235B 模型：1 台 5090 或 3 台 Mac M4，input 约 1K 时 output 接近 10 token/s（字幕口径）；其 chatbot 演示显示调用集群分布在东京/大阪等地、延迟 10ms 内，用 6 台 5090 跑 235B。ECHO 与中心化 verl 对比：在 3B/4B/7B 与 32B LoRA 等设置（字幕口径，尺寸识别可能有误）下精度基本一致；在推箱子、数学、逻辑任务上亦跑通多轮 RL。广播实测：约 60GB 模型（30B 级）在 60Mbps 家庭宽带、1 个训练端对 30 个推理端，单点广播约 17 分钟，全量经两跳扩散共约 170 分钟完成。
  4. 结论/观点（讲者判断）：广播耗时虽长但证明可行；若只训 LoRA（参数约 1% 量级），广播成本可降数十倍，只要「推理 + 参数广播」时间短于训练时间，整个 RL 在体验上就等同 SFT。后续方向：继续压缩广播的通信频率与参数量，并把数据端也解耦——让用户贡献显卡、数据与自设计 reward，共建模型。

5可迁移

  • Rollout 外包给弹性异构推理池：把生成与训练解耦、用 buffer 衔接的模式可直接借鉴到 agentic RL 的 rollout 扩容——训练侧只管消费样本，推理侧独立弹性伸缩（讲者的同步问题本质是我们做异步 RL 时的 off-policy 程度问题，他们用「广播必须快于训练」给出判据）。
  • 权重同步成本决定架构可行性：全参广播 60GB/170min 不可用、LoRA 1% 参数立即可用——评估任何训推分离方案时，先算「参数量 × 更新频率」这笔账，再看推理吞吐。
