2一句话总结

通常说强模型带弱模型，第一反应是蒸馏/OPD：更新弱模型的参数。本期问了一个更本质的问题：完全不改参数，强模型能不能在测试时直接给弱模型"搭好思考方式"？ 工作把强模型设为 builder、弱模型设为 target：builder 只拿到 5% 的验证集，在多轮迭代里为 target 自动构建一个 inference-time harness（任务路由、结构化抽取、确定性代码、校验、输出格式控制），target 本身零训练。四个 Theory-of-Mind（ToM）基准、3900 道隐藏测试上，最佳 scaffold 把 GPT-5.4-mini 的宏平均准确率从 0.488 抬到 0.912（+87% 相对提升），且 72 次运行里每一组 builder 配置都正向。机制分析表明，收益主要来自把弱模型不稳定的隐式推理"卸载"成确定性代码与规则，而不是让弱模型想得更久——强模型的推理被一次性编译成了可复用的推理时结构。

3核心

背景/问题：能力迁移除了改权重，还有第二条路

官网预告把问题抛在一句话上：「我们能否在不更新任何模型参数的情况下，把强模型的能力迁移给弱模型？」论文 §1 给了理论支点（借 Sweller 的认知负荷理论）：小模型在任务上失败，未必全是内在能力不足，也可能是任务的呈现方式给它压了过高的认知负荷。于是改进有两条路：让模型更能干（蒸馏路线：数据蒸馏、rationale 蒸馏、on-policy distillation，都是改参数），或者让任务对模型更容易（harness 路线：路由逻辑、提示模板、校验、记忆与工具使用，改的是模型 reason 时的条件）。

第二条路缺的恰恰是系统账本：现成的 agent 系统里小模型早就被包在管线里用了，但为什么 harness 有效、何时稳定、哪些设计真正起作用、增益里有多少是真实推理支持而多少是基准特定的捷径，此前没人系统测过。这就是本期工作的切入点：把 strong-to-weak scaffolding 形式化为一个独立的测试时能力迁移设定，并做大规模受控实验。

方法/设计：builder 写脚手架，target 只管执行

设定（论文 §1、§4）：强模型 builder 构建一个 scaffold，即 task routing、prompt 模板、确定性求解器、few-shot 例证、校验过程与答案格式约束的任意组合；目标是提升一个固定的弱模型 target 在隐藏测试集上的表现。规则有三条硬约束：

  1. target 不做任何训练，参数与提示外的一切都不动；
  2. builder 永远看不到完整测试集，只能用一个 195 题（5%）的验证样本迭代改进 scaffold；
  3. scaffold 必须迁移到未见样本上，所以它被迫捕获可复用的技能与任务结构，而不是背实例答案。

换个说法：builder 要做的不是解题，而是把自己的解题方式外化成 target 能执行的程序——论文的原话是把 builder 比作 "compiler of task competence"：花一次性推理预算，把任务的决策程序编码进 harness；之后每道题上 target 的认知负担被摊薄，它只处理规则编译不掉的残余情况。

实验设计（论文 §4）：测试床选 ToM（心智理论）推理——需要追踪嵌套信念、视角切换、隐藏信息与贝叶斯目标推断，对小模型难，但结构上又有可路由、可分解、可符号化求解的空间。四个基准合成 3900 题隐藏测试集：BigToM 1200 题（智能体是否观察到世界变化的二值问题）、Hi-ToM 1200 题（0–4 阶递归的嵌套信念，含欺骗设定）、MMToM-QA 600 题（从动作轨迹做贝叶斯目标/信念推断）、MuMA-ToM 900 题（三选多智能体信念问题）。主 target 是 GPT-5.4-mini，另以 Gemini-3.5-flash 做 target 对照；builder 阵容包括 GPT-5.5、Opus-4.7（四档推理强度）、Sonnet-4.6、Gemini-3.5-flash、Gemini-3.1-Pro、GPT-5.4-mini、Codex-5.3、Grok-0.1，且 builder 自己也跑在三种平台之一（Cursor、Claude Code、GPT Codex）里——builder 的 harness 也是变量。总计 72 次运行，每个配置重复 3 次测稳定性。参照系有两个：Vanilla（target 裸调用，GPT-5.4-mini 宏平均 0.488、Gemini-3.5-flash 0.761）与 Human-Inspired Harness——特意用了讲者自己先前的工作 UserHarness（Qian et al., 2026）作为人类手工 harness 的上限参照（同一 GPT-5.4-mini 上达 0.939）。

实验/实战：0.49 → 0.91，且每次运行都正向

主结果（论文 §5、Table 1）：57 次以 GPT-5.4-mini 为 target 的运行，scaffold 后的宏平均准确率均值 0.763（相对基线 +0.275），100% 的运行超过裸调用基线，11 个 builder 配置无一例外正向。最佳单次运行是 GPT-5.5 在 GPT Codex 平台上构建的 scaffold：0.912，即 +0.423、相对 +87%——官网预告所说的「仅仅改变模型外部的 harness，就能让 GPT 在不同 Benchmark 上的准确率提升将近翻倍」指的就是这个口径（0.488 → 0.912）。

三个值得记的对照：其一，最佳 scaffold 后的 GPT-5.4-mini 在四个基准上全面超过裸调用的 GPT-5.4（0.619）与 GPT-OSS-120B——「给小模型配好脚手架」在这些任务上胜过「直接换大一号的裸模型」；其二，与人类手工 UserHarness 比，自动 scaffold 在结构最显式的 BigToM 上打平甚至反超（1.00 vs 0.95），但在 Hi-ToM（0.80 vs 0.87）、MMToM-QA（0.84 vs 0.98）、MuMA-ToM（0.88 vs 0.96）上仍有清晰差距——差距集中在不容易编译成确定性结构的部分；其三，换 target 的对照说明增益看余量：Gemini-3.5-flash 本来就强（裸调用 0.761），scaffold 的增益几乎全集中在 BigToM 一项（占其宏平均涨幅 0.42 的 96%），弱 target 从脚手架里拿到的东西系统性更多。

机制层面的量化（论文 §5 后段，这是全篇最有价值的部分）：

  • 确定性卸载是主因。定义 determinism fraction 为 scaffold 中由确定性代码/规则直接作答、无需 target 模型推理的题目比例；它与最终准确率的相关达 $r = 0.72$ ——builder 把越多工作编译成可执行结构，target 剩的推理负担越少。而 scaffold 代码量本身与准确率只有 $r \approx 0.22$ 的弱相关：写得多没用，卸载得对才有用。
  • 每个基准的"可编译度"不同：BigToM 几乎全可编译（determinism 均值约 0.94，因为题目常直接暴露"观察到/未观察到"这个判别）；Hi-ToM 约 0.51（常靠符号化信念状态追踪）、MMToM-QA 约 0.44、MuMA-ToM 只有约 0.36（自由对话式推理最难编译成规则）。论文称之为四个基准的 compilability 排序。对应地，BigToM 上 builder 经常直接写出确定性求解器或混合规则，MuMA-ToM 几乎总是模型中介的提示式 scaffold。
  • 收益不是靠验证集刷出来的：builder 平均只用 5 次验证评估（中位数 5，范围 2–15）；最佳验证分与最终全集分的相关 $r = 0.96$ ，验证→全集的乐观偏差均值仅 0.021；而验证迭代次数与最终分数的相关只有 $r = 0.17$ ——builder 本身的质量远比它探验证集的次数重要。
  • 稳定性与强弱排序：同一配置重复构建的宏平均标准差均值 0.036，比主涨幅小一个数量级；但方差集中在确定性求解器策略上——一条规则里的逻辑错误能在一个 1000+ 题的基准上摆动几十分。builder 身份是主要变量、平台只是二阶效应；Opus-4.7 的推理强度与其 scaffold 质量单调正相关（Spearman $\rho = 0.77$ ）。实务配方由此很清楚：用最强 builder、高推理强度构建、只花少量验证评估、优先卸载可证明子任务，有预算时多建几个独立 scaffold 再按验证分选或集成。
  • 残差错误的形状：最强的 8 个 scaffold 平均修复了基线答错题的 83%、只弄坏基线答对题的 7%，接近帕累托改进；剩下错误集中在最难编译的核：Hi-ToM 随递归阶数下降（0 阶 0.999 → 4 阶 0.700，欺骗设定再降）、MMToM-QA 的贝叶斯目标推断子类、MuMA 的 social-goal 与 belief-of-goal 标签。

结论/观点

  • 论文结论（§6）：scaffolding 不替代原始推理能力，而是重新分配它——"scaffolding does not replace raw reasoning capability; it reallocates it." builder 做一次性的结构推理，target 处理残余的模型依赖部分。能力不必只以权重形式存在，也可以外化成 tools、code、routing、verification 与 harness；这正是官网预告里 AI4AI 视角的落点：未来的 AI4AI 不只是有一个更聪明的模型，而是让 AI 学会为 AI 构建更好的思考环境。
  • 一个反直觉但被数据支持的细节：让弱模型"想得更久"（更长推理、更多采样）不是增益来源；增益来自结构外化、确定性卸载与严格的答案格式约束。讲授提纲第 4 点「一个有效 Harness 由什么组成」在论文里对应的配方是：近乎普适的可靠性地板（格式强制、路由、贪心解码）+ 高价值的任务结构利用（极性逻辑、结构化抽取、确定性求解）。
  • 作者对适用边界有明示（论文 §7）：目前只在 ToM 这一类测试床上验证，它是有意选的——同时包含可脚手架化的结构与残余推理难度，能区分浅层提示优化与真正的任务结构发现；更广的基准族（不同的符号结构/歧义/开放推理配比）是未来工作。论文还提出把这个设定本身做成 builder 的标准基准：测的不是 builder 能不能答题，而是它能不能让另一个模型答得更好。
  • 本期与已完成期次的坐标：讲者钱成的 UserRL 是他先前的一作工作（本仓库已有相应期次），本期的参照系 UserHarness 同样出自其团队——三期连起来看是同一条线：从"训 agent"（ToolRL/UserRL）走到"不训模型、训环境"。另外本期与 EP144 是同一批的 Harness 双联：EP144 把 Harness Layer 装到冻结 VLA 外面，本期把 Harness 装到弱语言模型外面，机制同构（固定被服务对象、外层确定性结构兜底、残余难题留给模型）。讲者现场如何展开第 6 点「AI4AI 的未来」、AMA 问了什么，无书面材料可核，本纪要不代拟。

5可迁移

  • 把"写脚手架"当成后训练的一种廉价替代，先于蒸馏试一轮（直接可试）：在 coding-data / agent 工作里，当小模型在某类任务上系统性翻车，先让强模型（或自己）把判别规则、结构化抽取、确定性求解与输出格式控制编译成 harness，再测增益；本期的量化结论是：卸载质量与准确率的相关为 $r = 0.72$ ，写更多脚手架代码的相关只有 $r \approx 0.22$ 。若 harness 后残差仍大，再考虑把这些失败模式蒸馏进权重——两条路线互补而非互斥（论文 §7 的定位）。
  • Builder 配方可直接抄到 agent 基础设施（Infra 视角）：最强 builder + 高推理强度一次性构建、少量验证评估迭代（本设定 5 次中位数即够）、按 5% 验证分选 2–3 个独立 scaffold 再集成；验证→全集相关 0.96 说明小验证集足够当选型信号，不必为调 harness 烧全量评测。这套同样适用于自动生成评测检查器、数据清洗规则、工具路由策略等"一次性构建、长期复用"的工件。
  • "可编译度"是一把给任务/评测分层的尺（评测自动化）：先测一个任务有多少比例能被确定性规则覆盖（本期四个 ToM 基准从 0.94 到 0.36），再决定资源押注：高可编译任务用代码求解+弱模型兜底，低可编译任务才值得上大模型或 RL；给自有基准做这个分层，能避免在规则可解的题型上白白消耗推理预算，也能解释为什么同一脚手架在不同基准上增益差一个数量级。
  • 与 EP144 合看的组织原则：两期是同一个 Harness 模板的两个实例——冻结被服务对象（VLA / 弱 LLM），外层用固定原语与确定性结构兜住可解析部分，模型只处理残差；且两边的记忆/规则都是"一次探索、多次复用"。做 agent 系统时先问哪部分可编译、可路由、可校验，往往比先问换哪个模型更划算。

6疑问 / 下一步
