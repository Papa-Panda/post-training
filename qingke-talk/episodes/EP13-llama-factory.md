## 一句话总结

这一期前半程是高效微调方法的一次系统盘点（部分参数微调、LoRA 家族、全参数显存优化三条线），后半程讲 LLaMA Factory 如何把这些方法连同预训练/SFT/RM/PPO/DPO 全流程收进一个框架：一份基座权重 + 可插拔 adapter + 统一的训练/推理/导出接口，让 7B 模型在 16GB 甚至 4–5GB 显存下完成微调。

## 核心

### 背景：高效微调方法的三条线

讲者先把常见高效微调方法归为三类，作为理解框架设计的前提：

1. **部分参数微调（partial fine-tuning）**：冻结大部分参数、只训小部分。早期做法训模型前几层或后几层；代表作 LLaMA Pro（腾讯 AI Lab）把原模型的若干层复制出来，新层初始化为恒等映射、冻结原始参数只训复制层——原有能力保留、新知识写进新层，还适用于继续预训练与领域适配。
2. **Adapter 方法（以 LoRA 为核心）**：冻结原权重，只训低秩增量。LoRA 的秩 $r$ 通常取 8 或 16，相对原矩阵 4000 甚至上万的维度，只训不到 1% 的参数。讲者按改进点分了三支：
   - **重参数化**：DoRA 把权重分解为幅度（magnitude）与方向（direction）两个分量，冻结幅度、只对方向做低秩微调，更逼近全参数微调的拟合能力，且可合并回原权重不改变推理结构（ICML 2024）。
   - **更新策略**：LoRA+ 不动结构，只把 LoRA 中 $B$ 矩阵的学习率提高到原来的约 16 倍——讲者转述其理论分析： $B$ 的最优学习率本就应远高于 $A$ ，改优化器初始化即可。
   - **初始化**：PiSSA 对原权重做 SVD，取最大特征值对应的主成分初始化 LoRA 的 $A$ 与 $B$ ，其余部分作为残差矩阵冻结。好处有二：收敛更好；量化微调时重要信息留在高精度 LoRA 里、不重要的残差被低比特量化，量化误差更小。
3. **全参数微调的显存优化**：更新仍是全参数，但用技巧压显存。代表作 GaLore 把**梯度**（而非参数）投影到低秩空间，优化器状态的显存降到与 LoRA 相近的量级，同时保留全参数更新的特性。

### 框架设计：一套接口装下全部方法

LLaMA Factory 的结构按讲者的划分是三层：底层硬件（英伟达 GPU、华为 NPU）与既有框架（PyTorch、Hugging Face、DeepSpeed），中层做模型集成（FlashAttention、位置编码插值、量化等适配，已支持 100 多种开源文本模型）与数据集成（填充、packing、多轮对话处理），上层是统一的训练器，把预训练、SFT、奖励模型训练、PPO、DPO 全部实现。讲者强调的三个卖点：效率（速度与显存）、首个面向文本大模型的可视化 WebUI 微调界面（零代码）、结合 DeepSpeed 后可微调 70B 乃至 100B+ 模型。

显存账（字幕口径）：7B 模型全参数微调约需 120GB 显存；换 GaLore 或 LoRA 后降到约 16GB；再叠加 4-bit 量化（QLoRA 式）可到 4–5GB；70B 模型量化加 LoRA 约 48GB（两张 24GB 卡）可训。

### 实现细节：四个值得抄的工程点

1. **Packing 的 mask 分场景**。预训练用 sequence packing 把不等长样本打包成等长序列，但**不做样本间 mask**——预训练就是要让模型尽量多见文本；SFT 阶段则必须做块对角的 attention mask（子样本长度为 2、3、4 时，mask 是 2×2、3×3、4×4 对角块拼成的大矩阵），防止模型在算第二个样本时 attend 到第一个样本，讲者明确说不做 mask 会拉低训练指标。
2. **SFT 只对回答算 loss + 坚持原厂 chat template**。多轮对话里只在回答部分计算损失；格式化必须用模型原本的特殊标记符。讲者的理由值得记：「我们在微调的时候保持（与预训练）一样的格式，可以继承训练时候的能力……间接地减少过拟合或者遗忘。」
3. **奖励模型取 EOS 位置的标量分**。RM 用 pairwise ranking loss 训练；打分取解码器最后一个隐藏向量（即 EOS 位置）过 value head 得到标量——选 EOS 是因为它在序列末尾、能 attend 到全部内容，信息量最大，且每个样本都有、不会过拟合到某个特定标记符。
4. **多 LoRA 权重共享的 RLHF**。PPO 需要 policy、reward、reference 三个模型，显存压力大；框架的做法是只载入一份基座权重，靠挂不同的 LoRA adapter 切换角色（RM 一套 adapter、policy 一套），绝大部分参数共享只载一次。DPO 同理只需两个模型、同样共享。另一个细节是把 SFT loss 与 DPO loss 用超参数 $\gamma$ 融合，防止 DPO 训练中的遗忘。

工具调用在框架里只是数据格式问题：工具名、描述、参数写进 system prompt，数据按「用户问题 → 工具调用 → observation 回填 → 最终答复」的多轮对话构造，模型就学会该调工具时不硬答。

### 效率技术与实测口径

- **FlashAttention**：讲者给了直观对比——序列长度从 1000 提到 8000，不用 FlashAttention 显存从 15GB 涨到 45GB（近二次增长），用了之后只多约 5GB、8000 长度约 20GB 即可训完；机制是 K/V 分块 + softmax 可分次更新，整个过程不生成 $N \times N$ 大矩阵，还能算子融合提速。
- **量化**：16 位参数约 14GB 显存，量化后可降到约 5GB；但量化后的权重本身不可训练，必须配高精度 adapter 一起优化（即 QLoRA 路线）。
- **位置编码插值**：上下文从 4K 扩到 2–3 倍时能力不显著下降，训练推理都可用。
- **LoRA 自定义算子**：框架为 LoRA 写了融合算子，把反向传播的计算量降到原来的约 0.5%，速度约翻一倍（字幕口径）。

### 结论与边界（讲者自述）

- 还没实现的：pipeline parallel、tensor parallel 等改模型结构的并行策略，实现难度大，后续会考虑 4D/5D 并行（含 expert parallel）。
- Q&A 中的明确边界：RAG 不支持、以后也不会（那是推理范畴）；内置评估只有 C-Eval、CMMLU 这类多项选择集，其他形式的评估建议用别的框架；支持从零训练但建议用 GPT-2 量级的小模型练手；「评估时显存不够」多半是 eval batch size（默认 8）或 `max_new_tokens` 太大。

## 可迁移

- 「一份基座 + 多个 adapter 切换角色」是省显存做 RLHF 的通用招：policy/reward/reference 显存爆炸时，先想参数共享、只训小 adapter，而不是先加卡。
- Packing 的 mask 分场景原则可直接迁移到自己的 SFT 数据管线：预训练可以不管样本边界，SFT 必须块对角 mask，且坚持基座模型原厂 chat template——这两点是讲者用「会拉低指标」背过书的。
- 方法选型坐标：要拟合能力先看初始化（PiSSA 式主成分初始化）和学习率分配（LoRA+ 式 $B$ 放大），这两招不动结构、不加参数，是 LoRA 调参前应先试的。

## 疑问 / 下一步

- 讲者说 LoRA 融合算子让反向计算量降到「原来的 0.5%」——这个口径（是对 LoRA 分支本身还是整网反向）字幕没有展开，值得去 repo 里核对实现再引用。
- 多 LoRA 共享基座做 PPO 时，不同 adapter 切换的调度开销与数值一致性（尤其 reference 模型与 policy 共享基座时 logprob 的计算路径）talk 里没细讲，是自己复现时要先验证的点。
