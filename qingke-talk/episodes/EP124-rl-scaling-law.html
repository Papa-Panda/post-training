3一句话总结

32B
以后边际增益

预训练有成熟的 Scaling Law，RL 后训练此前没有。本篇在 Qwen2.5 全系列（0.5B–72B）上用 63 个模型、5 万多道数学题系统实测：测试损失（ $L = 1 - \mathrm{PassRate}$ ）与后训练资源 $X$ （算力 $C$ 或数据 $D$ ）之间是统一的对数线性幂律 $\log L(N,X) = -k(N)\cdot\log X + E(N)$ ，且学习效率 $k(N)$ 随模型规模按饱和曲线增长——大模型效率更高，但 32B 以后边际增益明显递减。数据受限时，高质量数据重复用 25 遍以内几乎不掉点，性能主要由训练总步数而非样本独特性决定。

4核心

背景/问题：RL 后训练缺一张资源分配地图（论文 §1 及官网提纲）

o1/R1 之后 RL 后训练是推理能力的主通道，但工程上关键问题都悬而未决：固定算力下该用多大的模型、数据不够时该复用还是扩充、堆参数的效率收益有没有上限。论文把这些问题形式化为三组约束优化——算力受限（固定 FLOPs 找最优 $N$ 与 $D$ ）、数据受限（固定唯一数据量 $D$ 找最优 $N$ ）、数据复用（固定总数据量 $D_{\mathrm{total}} = D_{\mathrm{unique}} \times \tau$ 找最优复用因子 $\tau$ ）——然后用大规模实证逐个回答。

方法/设计：统一幂律 + 效率饱和项（论文 §1、§2）

核心公式（Eq. 1）：

$$\log L(N,X)=-k(N)\cdot\log X+E(N)$$

其中 $L$ 是测试损失（定义为 $1 - \mathrm{PassRate}$ ）， $X$ 可以是算力 $C$ 或数据量 $D$ ， $k(N)$ 是该模型规模下的学习效率， $E(N)$ 是资源为 1 时的截距。关键的第二步（Eq. 2）是： $k(N)$ 不随规模线性涨，而是按饱和函数走：

$$k(N)=\frac{K_{\mathrm{max}}}{1+\frac{N_{0}}{N}}$$

即规模越大效率越高，但渐近趋于理论上限 $K_{\mathrm{max}}$ 。实验台：Qwen2.5 稠密系列 0.5B/1.5B/3B/7B/14B/32B/72B（同架构、只有参数量一个变量），VeRL 框架跑 GRPO，训练数据为 guru-RL-92k 的数学子集（去重与难度过滤后按难度升序课程排列），共微调 63 个模型、5 万多道数学题；评测用 500 道同分布留出题算 $L$ ，另有 GSM8K/MATH500/AMC2023/AIME2024 等域内与 HumanEval、Zebra Puzzle、SuperGPQA 等域外基准。验证公式可预测性用了两种协议：模型间外推（用 0.5B–32B 拟合、预测 72B）与模型内预测（只用早期步数拟合、预测后期轨迹）。

实验/实战：四个发现（论文 §3）

  1. 大模型算力与数据效率都更高，且公式可外推：算力与数据两种口径下 $L$ 与资源均呈对数线性，两种拟合协议的 $R^2$ 都大于 0.99 ；用小模型拟合出的系数能准确预测 72B 的效率，只用早期步数也能外推后期收敛（论文 §3.1、§3.2、Figure 2–4）。
  2. 效率饱和与性能交叉： $k_{C}(N)$ 与 $k_{D}(N)$ 都在 32B 以后增益明显放缓（Figure 5）。直接后果是一个反直觉的交叉现象：同等算力预算下，32B 模型在训练早期反而跑赢 72B——因为小模型每步便宜、能跑更多步（论文 §3.1）。「RL 里大模型总是更好」在固定算力下并不成立，规模与步数存在真实的权衡。
  3. 跨架构同形式：同一协议搬到 Llama 3 系列（1B–70B），算力律与数据律拟合 $R^2$ 同样大于 0.99 ，饱和结构不变；只是绝对水平不同（Llama-70B 留出集准确率约 50% vs Qwen-72B 约 59%），论文据此判断这套缩放动态由优化过程本身而非底座架构决定（论文 §3.3、Figure 6）。
  4. 数据复用便宜有效：固定总数据量、变复用因子 $\tau$ ，最终测试损失对 $\tau$ 基本不敏感， $\tau \le 25$ 无显著退化； $\tau = 100$ 才出现明确过拟合。结论是数据受限时性能主要由总优化步数（ $D_{\mathrm{total}}$ ）驱动，而非样本独特性（论文 §3.4、Figure 8）。域迁移则偏保守：数学 RL 只在数学域内（不同难度）稳定泛化，对代码、科学、逻辑等域外任务几乎无迁移，大模型在逻辑谜题上甚至变差（论文 §3.5、Figure 9）。

结论/观点（区分事实与作者主张）

事实层（论文实验口径，数学推理、Qwen2.5/Llama 3 两族、0.5B–72B 范围内）：RL 后训练的损失-资源关系可被一条带饱和效率项的幂律高精度拟合与外推；大模型的效率优势在 32B 后饱和；中等程度的数据复用（ $\le 25$ 遍）不损害泛化。作者主张（观点层）：RL 后训练可以像预训练一样做事前的资源规划——先用小模型拟合 $k(N)$ 曲线，再决定目标规模与预算分配；且在高质量数据稀缺时，「把好数据多训几遍」是被实证支持的策略而非凑数。论文 §5 也自陈边界：测试损失依赖评测集难度构造，不同任务的系数（ $K_{\mathrm{max}}$ 、 $N_{0}$ 、 $E$ ）不可跨任务直接解读。

6可迁移

  • 对 coding data / RL infra 的可试图：在开一轮大模型 RL 之前，先用小模型（同家族 2–3 个尺寸）跑短程、拟合 $\log L$ 对 $\log C$ / $\log D$ 的直线斜率 $k(N)$ ，再外推目标规模的收益与步数预算——论文证明这在数学域内误差很小（ $R^2 > 0.99$ ），可直接用于 RL 训练的资源申请与排期，而不是每轮都从头试。
  • 数据策略：高质量可验证数据不足时，优先保证总优化步数——同一批数据复用到 25 个 epoch 以内有实证护航；但要给复用次数设上限（100 遍明确过拟合），且复用时保持难度课程顺序（论文 §3.4 的对照设置）。
  • Infra 视角：效率饱和意味着 RL 预算的最优点不在「尽可能大的模型」：固定 FLOPs 下 32B 早期能跑赢 72B 的交叉现象提示，中等规模 + 更多步数往往是固定预算下的更优解——做 RL infra 的容量规划时，rollout 步数与模型规模应联合排，而非先定模型再塞步数。

7疑问 / 下一步

  • 全部证据来自数学推理（二值奖励、难度明确）；代码 RL 的奖励更稠密（部分通过率）且任务异质， $k(N)$ 的饱和点与复用上限是否同量级，论文没有覆盖——这是把这张地图用到 coding-data RL 前最想先自证的一点。
