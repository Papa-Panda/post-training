## 一句话总结

OpenClaw-RL 想解决的是：个人 agent 在真实使用中没有现成奖励信号，怎么边用边学。它的做法是只从「下一状态」里挖信号——用户或环境的下一句反馈既可以被 PRM 判成好/坏的二值奖励（Binary RL），也可以被总结成一句提示塞回原 prompt、构造出带特权信息的教师来做 token 级蒸馏（OPD）；讲者发现两者缺点互补，于是把两个 loss 直接相加成 Hybrid，并用一套异步 RL server 让收集、打分、训练全部离开用户对话的关键路径。

## 核心

### 系统形态：训练藏在对话背后

项目被讲者拆成两部分共用同一目标：对 personal agent（以本地运行的 OpenClaw 为代表）做个性化强化学习，以及对通用 computer-use agent（Terminal、GUI、SWE、工具调用四类）做大规模 GRPO。系统侧是一台独立的 RL server，内部再分 policy、PRM、训练引擎三块：用户在任何地方调用部署在 server 上的 policy 模型，PRM 在下一状态到达后立刻异步收到打分任务，攒够一条完整训练数据（回复加奖励）就入队，数量达到阈值后自动在后台开训。整个过程与用户交互解耦，只有模型权重更新的那两三秒会有短暂影响（字幕口径）。

讲者反复强调的设计约束是：不要求用户做任何显式打分。现实产品里让用户给偏好对、给整场对话打分、给 0–3 分都是负担，OpenClaw-RL 要的是完全从对话本身提取训练信号。

### 信号从哪来：next-state feedback 的两种读法

两种基础方法都建立在同一个观察上：policy 回复完之后到来的下一状态（用户的下一句话、环境的报错或执行结果）天然携带对上一步的评价。

**第一种是 evaluative 信号（Binary RL）**：PRM 读下一状态，判断上一步回答是好是坏，输出 1、-1 或 0（0 表示中性或判断不明确，相当于一道数据质量控制）。为提高准确性，PRM 独立判很多轮、每轮带思考过程，最后用 majority voting 的结果作为奖励。这里有个结构上的特殊点：每个状态只有一个样本，没有 GRPO 式的组内多回答，所以 advantage 直接等于 reward，这也是它需要靠 0 分与中心化倾向来控制噪声的原因。

**第二种是 directional 信号（OPD）**：用户的下一句反馈往往不止于好坏，还指明了该往哪改（比如「讲得太 AI 了，换个说法」「评语要更具体友好」）。PRM 把这类反馈总结成一句 hint，拼回上一步生成时的原 prompt，得到一个「带后见之明」的完整 prompt；同一个模型在这个增强 prompt 下就是教师，原 prompt 下就是学生，两者的对数概率差就是 token 级 advantage，再用标准的 PPO-clip 式 ratio 目标优化。教师与学生是同一个模型、只差一段 hint，这正是 OPD 在此处的含义。

两种信号的取舍被讲者讲得很直白：Binary RL 没有方向性，只知道好坏，但数据密度高——只要有反馈甚至情绪反应就能收，用户跳过某个问题直接问下一个，PRM 也能据上下文猜测任务是否已完成；OPD 有方向性、是 token 级信号，但数据收集苛刻得多，必须能从反馈中提取出明确的 hint 才收得到一条。讲者给的经验数字是，Binary/Hybrid 的数据收集速度大约能达到 OPD 的四倍左右（字幕口径）。

### Hybrid：把两个 loss 直接相加

技术报告阶段的核心发现就是把两者加权相加，权重默认都设为 1（字幕口径，讲者称尚未尝试其他取值效果就已经很好）。实现上很统一：无论是 sequence 级的二值 advantage 还是 token 级的 OPD advantage，最终都是 advantage 乘上 probability ratio 的同一类目标函数，所以 Hybrid 只是逐 token 把两边算出的量按权重合并；哪一边能收集到信号哪一边就生效，两边都有就同时优化。讲者认为这也说明 OPD 与 RL 在此框架下本就是同一个 loss 的两种 advantage 估计。

### 个性化实验：36 道题改变输出风格

个性化部分没有标准基准（讲者直言 RLHF 式任务主要看输出风格的肉眼变化），实验用 LLM 模拟两类带明确偏好的用户：一名用 OpenClaw 写作业、且不想被看出在用 AI 的学生；一名用 OpenClaw 改作业、希望评语具体友好的老师。每个作业题是一个对话 session，用户第一条消息是固定写死的 prompt，以便事后在完全相同的输入下比较输出风格的变化；评分由模拟用户按偏好打 0 到 1 的五档分（0、0.25、0.5、0.75、1）再聚合（以上均为字幕口径）。

同等训练时间下三方对比的结论是：Hybrid 效果显著，Binary RL 基本没有可见优化，OPD 刚开始效果低、后面才追上来，主因就是数据收集太慢。定性效果上，学生场景大约 36 道题的优化后，输出从满是加粗标记与步骤编号的「AI 腔」变得随意自然；老师场景更快，大约 24 道题后评语就明显更具体友好（讲者还提到后期模型甚至开始自发输出表情，偏好被学得有点过头）。工程参数上，每攒满 16 条数据就在后台触发一次更新（字幕口径）；讲者后来发现把每批数据的训练轮数提高、不拘泥于严格 on-policy，优化速度还能明显加快，大约二十几道题就能见效。

实验模型为 Qwen3-4B（字幕作「千万 34B thinking 2507」，应为 Qwen3-4B-Thinking-2507）；算力口径是 A100 上 4 卡训练、2 卡 policy 推理、2 卡 PRM 推理，H100 或消费级卡可以更少（字幕口径）。

### 通用 agent 部分：stepwise reward 与按步索引标准化

第二部分面向 computer-use agent 的长程交互（GUI/Terminal 场景正常要交互约 30 轮），此时只有终局 outcome 奖励会过于稀疏。讲者的改法是把 PRM 的逐步打分与 outcome 结合成 stepwise reward（PRM 打分取 -1/0/1，与 outcome 合并），再解决 advantage 怎么算的问题：标准做法要么对同一状态采样多条轨迹做组内标准化，要么训一个 value model；但在 Terminal、GUI 这类环境里连「两个状态是否相同」都难以判定，状态聚类不现实。他们的经验性解法是按 step index 标准化：同一轨迹位置附近的 step 状态近似相似，直接对相同 step index 上的 reward 做标准化得到 advantage，实测能稳定训练且效果明显好于只用 outcome 的 GRPO（字幕口径）。环境侧则把 Docker/VM 环境部署到云上以提高大规模训练的交互效率。

### Q&A 要点与讲者自陈的边界

- **稳定性是这个方向最难的问题之一**：给模型喂天马行空的数据、或学习率开太大，输出会逐渐「变怪」；如何平衡优化效率与长期稳定性，讲者认为这是 lifelong learning 里值得做的学术问题。相对而言，他承认当前最立竿见影的自进化手段仍是 skills 与 memory（不改权重、最稳定），权重级训练胜在能容纳的信息量大得多。
- **奖励全为正会漂移**：如果某个用户给的反馈恒为正，advantage 不中心化必然不稳定；缓解靠数据筛选与正负样本平衡等质量控制。讲者也说理论上最正确的是训 value model，但这个场景数据太少、不适合。
- **闭源模型无法用这套方法更新参数**，只能走 skills/memory 路线；权重更新只适用于开源模型（包括部署到推理平台上的开源模型）。
- **灾难性遗忘尚未测试**：讲者坦承目前先测的是稳定性，遗忘问题还没测；他预期 RL 因相对温和会比 SFT 好一些。
- **与同类工作的关系**：AREAL 团队在他们开源约两周后也做了一个 OpenClaw 版实现；讲者称自己主要用 SLIME 框架，胜在灵活、适合多人协作。仓库整体定位仍是 computer-use agent 的大规模 RL，OpenClaw 个性化是后加进来的一部分。
- **评估短板**：个性化 RLHF 没有合适的公开基准，现用的是自设的模拟用户加固定 prompt 前后对比；PRM 打分的波动较大，只有当方法间差距明显超过标准差时结论才可靠。

## 可迁移

- 「下一状态即反馈」是一个可直接搬的信号挖掘范式：凡是 agent 与用户/环境有多轮交互的系统，都可以让一个 judge 模型异步地把下一轮输入读成二值奖励或一句 hint，前者做 RL、后者做带特权信息的自蒸馏，两者共用同一个 PPO 式目标函数合并训练，不需要用户显式打分。
- Hint 式 OPD 的构造值得单独借用：教师不需要更强的外部模型，同一个模型加上「事后信息」就是教师，token 级对数概率差直接当 advantage——这给没有教师模型可用时的稠密监督提供了一个便宜实现。
- Infra 视角：把 policy、judge、训练引擎拆成异步解耦的三块、攒够小批量（如 16 条）就后台更新，是把 RL 训练塞进在线服务而不打断交互的可行形态；代价是 off-policy 程度与数据质量控制（中性样本丢弃、正负平衡）必须在数据入队时就做掉，事后补救很难。

## 疑问 / 下一步

- Hybrid 两个权重默认都取 1 的敏感性如何、step index 标准化的窗口与分组细节、以及技术报告中 Hybrid 相对两单项的完整定量曲线，讲授只给结论，需查项目技术报告核对。
- 个性化实验依赖模拟用户与自设评分，讲者自己也承认 PRM 评分波动大；真实用户、长周期下风格漂移与灾难性遗忘会到什么程度，目前没有数据。
- 多用户共用一个模型一起优化（讲者提到的组织级部署场景）会放大数据收集效率，但不同用户偏好冲突时信号如何隔离，本期没有展开。
