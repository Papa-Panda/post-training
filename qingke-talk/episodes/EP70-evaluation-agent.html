2一句话总结

Evaluation Agent 把视觉生成模型的评估从「固定 benchmark 全量跑分」改造成一个多智能体对话式流程：plan agent 把用户的自然语言查询分解为子方面，prompt agent 动态生成最有信息量的测试提示词，生成模型采样后由可扩展的 evaluation toolkit 打分，多轮迭代收敛后输出一份可解释的报告。它用不到 1% 的样本与时间（讲者口径：VBench 评估 VideoCrafter-2 需 4355 个样本、4000 多分钟，Evaluation Agent 只需 23 个样本、24 分钟）达到与完整 benchmark 高度一致的结论，并支持传统 benchmark 做不到的开放式查询。

背景：评估危机，与 agent 的理论框架

讲者的研究目标是构建能像人类一样感知、推理、预测的多模态智能体；智能体的三项核心能力是感知（从复杂环境提取有意义表征）、推理（理解因果、做逻辑推断）、预测（规划长程轨迹）。他先用 POMDP（部分可观测马尔可夫决策过程）框架给 agent 下了个形式化定义：隐藏的环境状态空间、动作空间（自然语言输出、工具调用、API 调用等）、观测空间、状态转移函数、记忆（存到当前时刻的全部交互历史），以及要优化的策略函数与最终目标（隐式 reward）。agent 的关键是在不完全观测下维护历史记忆、学最优策略——这也是 Evaluation Agent 的设计基础。

为什么是现在做评估 agent：视频生成模型从 2023 年的 Runway/VideoCrafter 一代，到 2024 年 Sora/Kling，再到 2025 年 Veo 3 等，迭代速度爆炸，但评估方法没跟上。讲者引 Andrew Ng 的说法：现在存在「评估危机」——现有指标要么过于狭窄、要么容易被 hack，而 vibe checking（直觉抽查）又太主观、样本量太小。需要从 vibe checking 走向 transverse（系统化）evaluation。

他顺带区分了 model 与 agent：LM/VLM 是 model-level、stateless、无动作接口；agent 是 system-level、有长期记忆、能与环境交互。从 LM 到 agent 获得的是自动化——端到端自主执行。他团队的 Ego-R1 就是例证：训练小参数 LM 的工具调用能力 + 分层检索，能处理长达 7 天的第一人称视频推理；这个能力与视频形态无关，所以在第三人称 Video-MME 上同样迁移得动。

现有评估的三个问题

  1. 贵：VBench 评测一个模型需要 4730 个样本，T2I-CompBench 需要超过 18000 个样本（字幕口径），一次评估通常要几十个小时。
  2. 固定：指标与流程预先设定，无法适配用户需求——有人关心艺术风格，有人关心物理准确性，固定 benchmark 只能给固定维度。
  3. 黑箱：只输出一个分数（如 87.5），不解释分数背后的含义：模型哪些方面好、哪些要改进，无从得知。

方法：两阶段、多轮迭代的评估 agent

框架的目标是「让评估像日常对话一样自然」：用户用自然语言提问（如「VideoCrafter-2 生成对象及其属性的能力如何」），系统自动完成理解意图 → 设计方案 → 执行评估 → 给出解释与 summary report。流程分两个阶段：

  • Proposal stage（提案阶段）：plan agent 把用户问题分解为具体子方面（如空间关系拆成上下关系、左右关系的理解）；prompt agent 据此动态生成测试提示词（如「一只猫在桌子上」「汽车停在房子面前」）。提示词是按用户意图动态生成的，不是静态题库。
  • Execution stage（执行阶段）：提示词送入被测生成模型采样，结果交给 evaluation toolkit 打分——toolkit 里既有现成 benchmark 的工具，也有专为 open query 设计的工具。每轮结果以 observation 形式反馈给 plan agent，它据此推理、决定继续探索还是停止，并调整子方面与提示词。多轮之后，agent 把全部观测整理成包含总结与深入分析的报告。

被测生成模型是外接的：系统只关心它 sample 出来的图片/视频，任何架构、开源闭源都可接入。

实验：效率与「能不能反映真实能力」

效率对比（讲者口径）：以视频生成为例，VBench 评估 VideoCrafter-2 需要 4355 个样本、4000 多分钟；Evaluation Agent 只需 23 个样本、24 分钟即可达到相等或类似的评估效果——不到 1% 的样本、不到 1% 的时间。图像生成（T2I-CompBench）上提升同样显著。

准确性验证：与 VBench、T2I-CompBench 的原始结果逐维度比匹配度。关键发现：

  • 单次运行已经很准：如 VideoCrafter-2 在 subject consistency 维度上单次即达到 100% 匹配（字幕口径）；
  • 多次运行普遍更准：评估 5 次后，美学、apparent style 等维度可达 90%–100% 匹配；
  • 有些维度天然难：human action、color、spatial relationship、场景这几类维度，即使评 5 次匹配度仍偏低——讲者归因于这些维度本身生成 variation 大、区分性差，需要更特别的设计。

讲者把这总结为三点：少样本能得出与完整评估高度一致的结论；模型间优劣关系与关键能力差异被保留下来；这不是随机减样本，而是智能采样选了最有信息量的 case。

开放式查询：传统 benchmark 做不到的事

user study 发现用户更关心「模型能否满足我的特定需求」，而非通用指标——比如能否保持原始风格生成现有艺术作品的变体、是否理解焦距/光圈/ISO 等摄影概念。为此他们构建了一个开放式查询评估数据集（open-ended query evaluation dataset）。

讲者用艺术风格案例完整演示了渐进式探索：第一轮查「复制基础艺术风格」（莫奈印象派风景：是否反映印象派的光线色彩强调、笔触纹理是否像莫奈）→ 第二轮查风格一致性（梵高《星夜》变体加城市天际线）→ 第三轮查风格混合（把澳大利亚土著点画元素融入莫奈睡莲——这轮暴露了模型局限：只用了印象派技巧、没有系统性点阵）→ 第四轮查复杂风格整合（浮世绘 + 非洲部落图案，保留部分浮世绘特征但整合不足）。最终报告：模型生成单个对象熟练，但在保持空间关系等混合生成上挑战大。这个案例展示了四点：渐进式探索（按每轮结果调下一步）、深度分析（不仅判对错、还解释为什么）、能力边界发现（强弱项画像）、全过程对用户可见的可解释报告。

Q&A 要点

  • 多次评估会因 LLM 不确定性而不稳定吗：恰恰相反，多次评估会逐渐收敛到原始 benchmark 的结果——可以把 Evaluation Agent 理解为对原始 benchmark 的一种更聪明的采样，测得越多越 converge。开放查询部分由 LLM 生成提示词与评估，确实存在不确定性，但实测 qualitative score 还不错。
  • 少量样本的样本偏差风险：存在，这是效率与偏差的 trade-off；大部分维度上影响小，generation variation 大的维度（human action、color、spatial relationship）偏差风险更大。
  • 为什么只需要少量样本：传统方法要测全部维度是因为只输入了「一个模型」；他们先分析用户 query，用户关心的层面往往不需要把十几个维度全测一遍就能回答。
  • promptable 如何实现、通用吗：plan agent 把自然语言 query 投射到评测维度上（如「空间关系生成能力」→ spatial consistency 类维度）；toolkit 可编辑可扩展，目前集成了常用视频/图像 benchmark + open-ended query 工具，换上图表/流程图类评估工具即可评测图表生成（直接评视觉质量则现成可用）。
  • 评测问题是 yes/no 形式吗：不是。评测问题是「在某维度上好或不好、好到什么程度、不好在哪里出问题」的更复杂形式。
  • 能否做多模态数据的 reward/评估：可用 toolkit 中个别维度或 open-ended query 工具做，但框架整体是 model-level 的生成模型评测。
  • 可解释性怎么评估：讲者坦言没法用数字指标衡量，可解释性是 qualitative 层面的——报告里包含各维度具体表现与原因，用户能理解得更深入，这本身就是可解释性的提升。

5可迁移

  • 评测即采样问题：把「全量跑分」改成「按 query 投影维度 + 智能选最有信息量的 case + 多轮收敛」，直接对应 RL 评测自动化——eval 预算有限时，先想清楚用户/训练真正关心的维度，再设计采样策略，而不是把 benchmark 全量刷一遍。
  • Toolkit 注册表模式：评估工具可插拔扩展（换 toolkit 即可评图表生成），对内部 eval infra 是个干净的抽象——评测维度与工具解耦，agent 只负责编排。
  • 报告而非分数：评估产物从单个分数升级为带原因的能力画像，对 post-training 的意义明确——模型迭代需要的恰恰是「哪里不行、为什么」，而不是又一个总分。

6疑问 / 下一步

  • 可解释性无法量化：当评估结论要用于模型选型或上线决策时，「报告写得好」与「结论可信」之间还缺一个可验证的锚点；讲者给出的收敛性论证（测得越多越接近原始 benchmark）依赖一个前提——原始 benchmark 本身是对的。
  • 开放式查询中 LLM 既出题又判卷，其 qualitative score 的可靠性在分布外查询上还没有系统验证。
