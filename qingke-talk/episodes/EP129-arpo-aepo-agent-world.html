2一句话总结

讲者从 token 熵这个最底层的行为信号出发，先量化出"工具调用后熵急剧上升"这一智能体推理独有现象，并据此提出 ARPO（在高熵工具步自适应分支 rollout + 软优势归因）和熵平衡版 AEPO（采样端与更新端双端平衡，保住高熵 token 的有效梯度）；随后把问题从算法推进到环境：Agent-World 用深度研究智能体从真实 MCP 服务器锚点自动挖掘近两千个可执行环境，以图合成与程序化合成生成可验证任务，再把训好的智能体放回环境竞技场做诊断—补短板的多轮自进化，三段工作构成"算法—环境"协同进化的完整叙事。

3核心

引入：三段工作，各解一层问题

本期是一条递进线：ARPO 与 AEPO 是智能体 RL 的算法层工作（怎么采样、怎么更新），Agent-World 是环境层工作（训练场从哪来、怎么不一次性用完就扔）。讲者的总判断是：智能体 RL 至今仍是开放问题（他举 OpenAI o3/o4-mini、Kimi K2、豆包 UI-TARS 等为例背书），现有工作大多只优化 reward 与数据筛选，很少从模型推理行为本身（熵变、长度变化、工具调用模式）找机制层面的问题与解法。三段工作因此都从"先看行为、再改机制"起手。

ARPO：工具调用后的熵尖峰，与自适应分支采样

现象（出发点）。讲者先做了一个纯观测实验：跟踪工具使用智能体推理过程中的 token 熵分布，发现工具调用后的前 50 个 token 熵急剧上升，且问题本身带来的熵低于工具调用带来的熵，搜索结果带来的不确定性高于代码编译器（编译器反馈通常是确定性的数字，搜索内容则信息丰富得多）。他的解释是分布转变：外部工具返回的信息与模型内部 token 分布对不上，于是在工具步产生超出原始分布的不确定性。而 GRPO、DAPO 等轨迹级算法只从问题起点 rollout、只在起点分支，系统性地忽略了工具调用步的分支探索——这是把 LLM 的 RL 直接搬进 Agent RL 的核心错位。

方法：entropy-based adaptive rollout。总预算仍是 $M$ 条链，但先只从问题起点 roll 出 $N$ 条，剩余 $M-N$ 条预算留给工具调用步：在每轮工具调用后计算该步的熵变（记 $\Delta H_t$ ，即工具带来的熵相对问题基准熵的变化），超过阈值就在该步分支 $Z$ 条新链，直到预算用完。整体 rollout 因此是一棵共享前缀的树，工具调用轨迹被大量复用——这正是后面"工具调用次数远低于 GRPO"的来源。

优势归因：硬估计 vs 软估计。树状 rollout 天然产生"共享推理段 + 分支推理段"混合的链，优势怎么分？硬优势估计对独立段按原 GRPO 计算、对共享段取两条链优势的平均（原话举例：共享段优势取 $\frac{1}{2}(A_1+A_2)$ 式平均）；软优势估计则不做显式拆分，直接沿用 GRPO 的更新——讲者的洞察是 GRPO 的重要性采样比率天然能区分共享 token 与独立 token，软估计对比下来稳定性远好于硬估计，故 ARPO 默认软估计。

reward 与实验。除答案正确性与工具调用格式外，ARPO 额外给"同一轨迹同时调用搜索与代码等多种工具且答对合规"一个多工具协作奖励 $+0.1$ 。评测覆盖三类：计算推理（MATH、AIME24/25、GSM8K、MATH500 等 5 个数学集）、知识型（WebWalker、HopQA、2Wiki、Musique、Bamboogle 等）与深度搜索（GAIA、HLE、XBench 等）。字幕口径的结果：仅 RL 1000 条高质量深搜样本、Qwen3 小模型即可在 HLE 与 GAIA 上分别拿到约 10 分与 43 分（字幕口径，原话含混）；ARPO 在 GAIA、WebWalker 上比 GRPO 约 $+6\%$ ；pass@5 口径下 GAIA 61.2、HLE 24、XBench 59；工具调用准确率高于 GRPO 而调用次数远低于 GRPO。讲者还强调 prompting 很难稳定激发工具能力（有时甚至低于不用工具的直接 instruct），说明当时的模型内部并不具备工具熟练度，必须靠 RL 训。

AEPO：熵是双刃剑，要平衡不要最大化

两个失败模式。做 ARPO 时讲者就意识到高熵驱动探索是把双刃剑：其一，高熵轨迹过度探索——某条轨迹从一开始就是错的，高熵只驱动模型在错误 solution 里越挖越深，"在错误上探索依旧也是错误的"，而正确轨迹反而得不到探索预算；其二，高熵 token 的梯度丢失——传统算法对高熵 token 做无差别裁剪（DAPO 把阈值从 0.2 提到 0.28 也只是治标不治本），有价值的采样信号被整批丢弃，直接伤泛化。

方法：双端平衡。采样端是动态熵采样：先用一条预推链做熵预监控（估计这条问题轨迹大概要调用多少次工具），据此在整个 rollout 集合层面自适应分配"全局采样 vs 分支采样"的预算；同时对同一条链上连续高熵的分支做惩罚抑制，防止分支预算被单条链吃光、坍缩在一条轨迹上。更新端是熵平衡策略优化：在 GRPO 的熵—优势更新中引入 stop-gradient 操作（借鉴 MiniMax M2 的 CISPO 一系做法），在二阶导意义上更合理地缩放高熵 token 的有效梯度；再加熵感知优势估计——把熵值融进优势计算，不确定且正确的行为要额外鼓励。

实验与那条 recipe。在同样的 14 个基准（深度搜索、知识密集、计算推理）上（字幕口径）：pass@5 下 GAIA 65 分、HLE 26 分、WebWalker 70 分；在 10 个通用推理任务中比 GRPO、ARPO 等 7 种主流算法约提升 $5\%$ ，且全程避免熵崩溃。讲者花了不少篇幅讲训练动力学：GRPO 的熵随训练飙升但性能并不高，CISPO 的熵一路下降性能也低，唯有 AEPO 把熵维持在"高且稳定"时换来的性能最好。他把这条作为本节的 take-away：希望大家都能训出一个熵"高且稳定"的智能体 RL recipe（Q&A 中再次重申：熵降下去意味着探索空间已经没了，accuracy 不会涨）。

Agent-World：把环境做成会自我进化的训练场

问题设定。ARPO、AEPO 用的都是固定工具环境（搜索、代码执行器）——环境只返回信息、不被行动改变。真实世界不是这样：下单会让库存减一、余额减少，订机票会让余票减一，智能体的每个 action 都在改环境状态。讲者把环境构建的两条已有路线摆出来对比：可执行工具 + 真实数据库（反馈真实、状态可建模，但每个环境构建成本高、规模与复杂度受限）与 LLM 模拟环境（world model 扮演环境返回反馈，扩展性强但致命地易幻觉——初始只有一张票，订完还返回"订票成功"）。在此之上他指出两个瓶颈：真实环境难以扩展（要么靠 LLM 生成与真实逻辑不匹配，要么靠人工从 trace 反向映射、难以大规模且状态浅）；更根本的是没有环境持续学习机制——费力造出几千个环境，只生成一批数据训一轮就丢弃，不经济也不合理。

环境与任务探索（合成底座）。第一步是从真实世界锚定：从真实 MCP 服务器上收集约 2000 个环境主题，辅以开源工具文档的接口定义与行业需求文档（PRD，如订机票系统"必须具备什么功能"的行业标准）。然后派一个配了搜索、browser、代码编辑器、文件系统四类工具的深度研究智能体，自主从网页信息中挖掘主题相关的数据库（讲者现场展示了它挖出的航班 CSV——航班号、经纬度、国家代码一应俱全），并通过迭代式复杂化持续扩库。工具接口则由代码智能体逐环境生成，并过三重规则过滤：可编译性、测试准确性、环境最小性。最终沉淀 1978 个环境的数据库与工具接口，再聚类成 50 个二级、20 个一级类别；统计上每个环境平均有 10–20 种工具、单个工具入参常大于 9 个，任务交互轮次大量在二三十轮以上，用豆包 Seed 2.0 去解有大量任务 pass 率为零——难度与真实性都有据。

任务合成：两种可验证策略。其一是基于图的合成：按工具间依赖（强依赖、弱依赖、随机关系）构建 DAG，在图上随机游走出可执行的工具链，再反向映射出任务、标准答案与 rubric——保证任务可解且有校验标准。其二是程序化合成：面向更复杂的非线性推理，直接写一段代码串联工具的函数定义（设计好入参出参），由 solution code 反向映射出问题与答案，并天然带 verify function。两条路共同点是都自带可校验矩阵：图任务用 rubric 打分，程序化任务直接执行验证代码，校验最终答案或数据库状态的变化。由此产出 SFT 数据约 4 万条、RL 数据约 5000 条（Q&A 口径）。

多环境 RL 与自进化竞技场。多环境 rollout 是整篇最关键一环：智能体、工具、数据库三方真实交互，订票就真的让底层 JSON 里的余量减一；算法底层用 GRPO，讲者明确说算法本身不是关键、"如何让这个 rollout 转起来才是最关键的"。奖励是结构化验证 reward shaping（图任务走 rubric 评分、程序化任务走验证代码）。训练之上再套自进化循环：从环境池按 20 个一级类别动态采样、生成与训练任务分布不同的动态评测任务，诊断智能体当前在哪些环境、哪些工具使用行为、哪些状态更新上出错，对弱点环境排序并生成 targeted 的任务生成 guideline，再在弱点环境上合成更难的任务做定制化训练——环境、评测、训练三者形成飞轮，环境从"数据工厂"变成"训练场"。

实验。对比面拉得很满（字幕口径）：16 个 baseline（含 GPT-5.2、Claude Sonnet 4.5、Gemini 3 Pro、豆包 Seed 2.0、Kimi K2.5、DeepSeek-V3.2 等闭源与开源模型），23 个 benchmark、五个领域。长程多轮有状态交互任务很难：闭源模型在 MCP-Mark 上也只有约 50 分。Agent-World 14B 模型在 BFCL-V4 上拿到 55.8 分，反超 685B 的 DeepSeek-V3.2 的约 54.0 分；8B 模型相比 EnvScaler 8B 全面提升且数学推理不退化、微涨。讲者最喜欢的是环境规模 scaling 实验：环境从 0 扩到 2000，性能与环境数量呈清晰正相关，10–100 个环境时增长最迅猛（关键交互模式覆盖至关重要），之后放缓但持续。自进化消融：Agent-World 14B 进化一轮、两轮均有明显涨点，把开源 EnvScaler 8B 放进同一套"评估—诊断—针对性训练"流程也能明显涨——机制本身可迁移，而非只对自家模型有效。

Q&A 要点

  • 熵阈值怎么定？ ARPO 做了敏感性消融：阈值定在 0.5 左右比较好（字幕口径）。
  • 分支预算怎么定？ ARPO 里就是一半——rollout 32 次、初始分支 16 次；AEPO 才进一步做了自适应分配。
  • 熵高且 accuracy 高就是好吗？ 讲者明确回"并不是"：熵降低意味着探索空间消失、策略已崩，accuracy 不会涨；RL 的 recipe 里熵绝不是单调下降才对。
  • 数据规模：SFT 约 4 万条、RL 约 5000 条（强模型根据问题与工具做推理生成链条，较难的放 RL 侧）。
  • 任务质量与多样性怎么保：质量靠难度把控（用强模型 pass@k 衡量：pass@10 只对一两次即为复杂任务）；多样性来自环境锚点本身的多样（约 2000 个真实 MCP 服务器 + 工具文档 + 行业 PRD），全程无人参与，讲者称用他们内部的 GPT-OSS 流程生成、开源模型也可走通这套流程（"它只是一套流程"）。
  • 生成工具的正确性：挖掘出的环境数据本身不涉及对错；工具接口生成后有三重校验并生成 test case 确保可执行。
  • 代码为什么没开源：Agent-World 已被用于豆包 Seed 基座模型训练，paper 曾被打回两三次才 release 出来；代码会尽力争取，但基座相关工作如今很少放代码与数据。
  • 跨环境任务：Agent-World 本身不覆盖（一个任务不跨多个环境），讲者说这是关键方向、业界基座团队都在做但没公开；当前这批环境仍只支持文本 agent，多模态是下一步。

5可迁移

  • 对 Agentic RL infra 的直接启发：采样预算不该平均撒在起点。ARPO/AEPO 的共同结构是"先观测哪一步不确定性最高，再把分支预算投到那一步"——rollout 引擎若能暴露每步的熵（或等价的不确定性）并按阈值自适应分支，等于在不增加总采样量的前提下把探索集中到工具边界上；树状共享前缀还直接省工具调用次数，这对工具调用昂贵（真实 API、沙盒）的场景是成本项而非精度项。
  • 熵是训练健康度的一等观测指标：讲者的三方对比（GRPO 熵飙性能不高、CISPO 熵降性能也不高、AEPO 熵高且稳最好）给出了一条可落地的告警规则——监控熵曲线的"水平 + 斜率"组合，而不是只看 reward 曲线；高熵 token 被裁剪丢弃的比例也应单独打点，它是泛化损失的先行指标。
  • 环境即资产的思维：Agent-World 的闭环把环境从一次性数据工厂变成可复用的诊断与再训练设施（动态评测 → 弱点排序 → 定向合成 → 再训练）。做 coding agent / 工具调用训练时，优先把"环境 + verify function + rubric"作为可版本化资产沉淀，而不是只沉淀轨迹数据；任务可验证性要在合成时就内建（图游走保证可解、solution code 自带校验），别指望事后过滤。

6疑问 / 下一步

  • ARPO 的熵阈值（约 0.5）是在搜索/代码工具上消融出来的，换成状态会变的真实环境（Agent-World 那类）后，工具步的熵分布会不会因为状态反馈更长而整体漂移？讲者在 Agent-World 部分直接用了 GRPO，没把 ARPO/AEPO 的熵机制接回有状态环境——两套工作的合流效果未验。
  • AEPO 的 stop-gradient 处理在二阶导意义上缩放高熵 token 梯度，讲者只给了直觉解释；熵感知优势把"不确定且正确"额外加权，与 ARPO 的多工具协作奖励这类手工 shaping 叠加时是否会双重计数，talk 未展开，需查论文公式与消融。
  • 环境持续学习目前只演示了两轮进化；环境池本身会不会随着任务定向合成而分布收窄（只练弱点导致灾难性遗忘）？讲者说实验里性能"比较稳定的提升"，但长轮次（5 轮以上）的遗忘曲线未给出。
  • Agent-World 的代码、数据都因豆包 Seed 基座训练而未释放，社区复现只能靠论文细节；其可验证 reward 里图任务的 rubric 由大模型打分，与程序化任务的执行验证相比可靠性如何分工，讲者只并列介绍未做对比数字。
