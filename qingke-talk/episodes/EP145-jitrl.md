## 一句话总结

JitRL 让冻结权重的 LLM 在部署后「边用边学」：维护一个存了 $\langle$ 状态, 动作, 折扣回报 $\rangle$ 三元组的非参数经验记忆，推理时检索相似历史轨迹在线估计每个候选动作的优势 $\hat{A}(s,a)$ ，再把更新 $z'(s,a)=z(s,a)+\beta\cdot\hat{A}(s,a)$ 直接加到输出 logits 上。论文证明这正是「最大化优势 + KL 惩罚」目标的精确闭式解（定理 4.1，论文口径），因此零梯度、零遗忘，还能给闭源 API 模型用；字幕口径下，WebArena 与 Jericho 上超过所有 training-free 基线并击败微调方法，货币成本约低 30 倍以上。

## 核心

### 背景/问题：部署即冻结，持续学习的两条老路都不通

讲者的出发点：LLM agent 一旦部署，权重冻结，基本失去继续学习的能力——「就像一个刚入职却永远不接受在岗培训的新员工，会在同一个地方反复犯同样的错误」。两条现成路线各有硬伤：

1. **标准 RL 微调**：要持续收集数据、频繁做梯度训练，计算成本高；动权重还有灾难性遗忘风险；且已有研究显示传统 RL 在持续学习场景下提升相当有限。
2. **In-context learning（把经验写进 prompt）**：agent 任务的交互序列很长，上下文一长性能就掉；更本质的是，很多真正有用的策略是隐性的，写不成一段文字，而 RL 靠奖励信号优化策略、不受「能不能说清」限制。ICL 缺的正是 RL 那种通用的优化能力。

核心问题：**能不能借 RL 的形式化框架拿到它的优化能力，同时彻底避开梯度更新？**

### 方法：把学习搬到测试时——记忆、检索估值、logit 更新三步

1. **构建经验记忆（reflective stepwise rewards）**。测试时没有训练好的价值网络，回报只能靠历史数据估。每条轨迹跑完后，用一个 LLM 评估器回看整条轨迹（带着后见之明，知道每步之后发生了什么），给每一步动作打一个标量奖励 $r_t$ ，再聚合成折扣回报：

$$G_t=\sum_{u=t}^{T}\gamma^{u-t}r_u$$

原始观测先抽象成紧凑的结构化状态，三元组 $(s_t,a_t,G_t)$ 存入动态记忆 $\mathcal{M}$ ——记忆不是文本日志，而是一个非参数的经验分布。

2. **测试时检索估值**。当前观测抽象成结构化状态 $s$ 后，从记忆中检索最相似的 top-k 三元组构成局部邻域 $\mathcal{N}(s)$ ：

$$V(s)=\frac{1}{|\mathcal{N}(s)|}\sum_{(s_i,a_i,G_i)\in\mathcal{N}(s)}G_i$$

$$Q(s,a)=\frac{1}{|\mathcal{N}(s,a)|}\sum_{(s_i,a_i,G_i)\in\mathcal{N}(s,a)}G_i$$

$V(s)$ 的直观是「跟当前处境差不多的状态平均能拿多少回报」；动作价值分两种情况：记忆里见过的 (s,a) 用同上均值；**没见过的动作**以概率 $\gamma$ 给一个乐观价值（在 $V(s)$ 上加 $\alpha/|\mathcal{N}(s)|$ ），以 $1-\gamma$ 概率设为 0 防过度探索——邻域越稀疏越值得试新动作，经验攒够了探索项自动衰减。优势就是相对局部基线的中心化：

$$\hat{A}(s,a)=Q(s,a)-V(s)$$

3. **闭式 logit 更新**。「最大化期望优势、同时约束新策略相对冻结策略的 KL」这个标准 RL 目标有闭式解，映射到 logits 空间就是一条加法：

$$z'(s,a)=z(s,a)+\beta\cdot\hat{A}(s,a)$$

讲者强调这不是启发式：论文里有完整证明（定理 4.1，论文口径），它在理论上等价于做了一次 KL 约束的策略改进，但全程不产生任何梯度。整个系统是持续闭环：推理时检索估值改 logits，每跑完一条轨迹就评估、打分、回写记忆，经验越攒估计越准。

### 实验：四个研究问题（字幕口径）

设置：Jericho（纯文本交互式文字冒险游戏）与 WebArena（模拟真实网页操作）两个 benchmark；每任务多次尝试（Jericho 每游戏 50 个 episode），看平均成功率与最终成功率——持续学习要看的正是「做多了会不会变好」。对比分两类：training-free（Static、Memory、Reflection、AWM、EvoTest，字幕名称口径）与权重更新类（SFT、WebRL、GRPO）。

- **RQ1 对比**：WebArena 上 JitRL 的平均与最终成功率都领先——超过所有 training-free 方法，也超过花大代价训练的 SFT/WebRL；Jericho 三个游戏的学习曲线全程最高。三条曲线规律（字幕口径）：前 10~15 个回合就学到有竞争力的水平、与基线的差距随回合数越拉越大（经验在有效积累）、后期方差小（策略收敛稳）。对照组里 GRPO 在 50 个 episode 下全程方差大（数据饥渴 + 奖励稀疏），Memory/AWM 类很早就停滞（依赖已有模式、抑制探索）。
- **RQ2 泛化**：主结果是 Gemini 2.5 Flash，另在 GPT-5 mini、DeepSeek V3.2（字幕口径名称）上绝大多数仍是 SOTA——logit 更新机制模型无关。跨任务冷启动（做新任务时只能用其他任务的记忆）依然稳定领先，讲者的解读是：迁移的是抽象的过程性知识，而不是死记某个任务的答案。
- **RQ3 定性机制**：本质是「用真实经验校正模型的语义先验」。字幕给的具体例子：找用户评价的任务，base 模型给 catalog 的 logit 0.9、marketing 0.7，记忆更新后 catalog 压到 0.4、marketing 抬到 1.4；导航任务里把全局 search 的 logit 压低、click forums 抬高；界面操作里发现 hover 比 click products 更高效，把 hover 抬上去。
- **RQ4 消融**：检索邻居数 $K$ 在 8~14 区间稳健（太小证据不足方差大，太大引入不相关历史拖慢收敛）；最关键的对照是「同样的检索信息，一种估计优势改 logits，一种塞进 prompt」——logit 更新明显更好，因为长上下文里模型可能注意不到提示信息或不严格遵循，而 logit 直接作用在输出分布上。
- **成本**：RL 类方法要在 7B 模型上训练，约 \$9900（字幕口径；论文口径同为该量级）；JitRL 约 \$290（主要是 API 开销），与 training-free 方法（\$200~300）同量级，但性能更好——相对传统 RL 成本低 30 倍以上。

### 结论/观点（讲者明确表达的判断）

1. 测试时优化 logits 可以实现等价于一次 KL 约束策略改进的持续学习，权重冻结、零遗忘，且闭源模型可用（见 Q&A 的 confidence 替代方案）。
2. 讲者对上限的判断很坦白（Q&A）：靠外部记忆的学习存在上限——如果环境固定、可以充分训练，传统 RL 学得更充分、泛化也更强；JitRL 的主场是部署后环境持续变化的持续学习场景。
3. 适用边界（Q&A 自列）：动作空间要有限、动作要可检索——GUI 精细坐标操作不支持，开放式生成任务（如故事生成）不适用；search agent 这类需要持续适应的场景很合适。

## 可迁移

- **对 RL infra 的直接启发**：JitRL 把「策略改进」从参数空间搬到 logit 空间，意味着 rollout 侧的经验（成功/失败轨迹）可以先以非参数记忆的形式即时生效，再考虑要不要回训。对自己的 agentic RL 流水线：长周期训练之外，可以加一层「经验记忆即时生效」的快路径，特别适合部署后环境漂移快的场景。
- **信用分配的低成本做法**：reflective stepwise rewards 用「轨迹结束后带后见之明的 LLM 评估器逐步打分」替代训练价值网络，再多轨迹重复采样摊薄噪声。这套（后见之明 + 多次采样平均）在 coding agent 的轨迹打分里可以直接试，比逐 step 在线打分稳。
- **检索估值的防坑清单**（来自 Q&A）：状态最终用文本而非 embedding（embedding 语义相似会检索到表面像但实质相反的状态）；状态要包含历史上下文（不只是当前帧）；未见动作的乐观价值要随邻域密度衰减，且保留置 0 的概率分支防过度探索。
- **闭源模型的后训练接口**：拿不到 logits 时让模型输出 confidence，排序一致即可驱动同一套更新（讲者在 Gemini/GPT 上即如此，字幕口径）——这是给 API-only 模型做「类 RL 持续改进」的可用协议。

## 疑问 / 下一步

- 记忆管理目前是全量存储（Q&A 口径：三元组数量尚不多），讲者设想未来加时间戳做遗忘；记忆规模与检索质量的权衡（邻域污染、旧经验过期）在长周期部署下没有实验覆盖。
- step reward 的正确性没有保证（讲者坦承）：靠评估器的后见之明 + 同一 (s,a) 多次采样平均来摊薄，但评估器本身的系统性偏差会直接写进记忆并被 logit 更新放大。
- 「存在上限」之外没给量化边界：记忆驱动的学习在什么任务规模/时长下会饱和、饱和后与继续 RL 训练的差距有多大，只有定性判断。
- 动作空间必须有限且可枚举/可检索——对开放动作空间（如自由文本生成）讲者明确说不适用；中间地带（大但结构化的动作空间，如工具调用组合）能否靠状态抽象撑住，未展开。
