2一句话总结

RLVR 的判定靠规则验证器或者外置判分模型：规则覆盖不了自然语言的表达多样性，判分模型要标注、拖慢系统。RLPR 换个思路——把参考答案拼到模型自己的推理链后面，用策略模型本身对这段参考答案各 token 的平均概率当奖励：正确答案在模型自己「想通了」的推理后面概率更高，错误的推理会让概率塌陷至一个「sink」。在这个连续奖励上再做两件事——减掉空推理基线消掉风格与模型偏好造成的系统偏差、用组内奖励标准差替代 0/1 准确率做样本过滤——拿到一条不需要验证器、不需要判分模型、只用模型自己 next-token 预测能力的通用领域 RL 奖励管线，效果与稳定性全面超过同期 likelihood 奖励路线（VeriFree）。

3核心

背景：为什么 RLVR 推不出数学代码之外

讲者把 RLVR 的三种既有验证方式各判了一遍：

  1. 规则验证器（正则抽取 + 符号等价匹配）：每个领域都要单独编写规则，数学要处理 5.0 与 5、代码要跑编译与测试；且规则本身有长尾覆盖问题——比如「A×B 与 B×A 等价」这条，在矩阵乘法里是没有交换律的，规则写不对就误判；
  2. 外置判分模型（General Reasoner 一类）：需要大量人工标注训练一个判分器，判分器一进系统，RL 管线的复杂度与时延都被抬高；
  3. 共同问题：两者都处理不好自然语言表达的灵活性与多样性。讲者现场给了一个例子：一道酸碱强弱排序题，正确答案可以用 < 分隔、逗号或顿号——都对，但规则和判分模型会把与参考字面不同的正确输出判错（字幕中记作「CBAD 式输出被判错」）。

核心洞察随之而来：语言模型自回归地给整个序列打概率，「模型在想通之后、输出正确答案的概率」本身就是一个连续的正确性指示。讲者在白板上演示了酸碱排序例子：推理顺序排对的那条回答，参考答案的概率平滑；排反了的那条，在参考答案对应的位置出现一个明显的概率 sink——这个下降就是信号。

方法：参考概率奖励 + 纠偏 + 标准差过滤

奖励定义。给定题目 $x$ 、模型生成的思考过程 $z$ 与最终答案，把答案替换成参考答案 $y^*$ ，整段序列送回策略模型本身，取参考答案每个 token 概率的算术平均作奖励 $R$ 。

为什么是算术平均而不是 likelihood（乘积）？讲者给了个三 token 的小例子：第一个 token 经常是「冒号」一类的不可控低概率 token（0.001 与 0.05 在直觉上是同样的「不太可能说」，但乘积会把两个回答的奖励拉出 5 倍差距），likelihood 被单个低概率 token 主导，既不鲁棒又高方差；而算术平均对离群 token 天然钝感。消融里把算术平均换回 likelihood，掉点明显——讲者解释说奖励质量指标上差异不大，但训练跑几百步，一次坏奖励就足以污染一轮更新。

纠偏（减基线）。概率得分不只受 $z$ 的好坏影响，还受答案风格、模型当下表达偏好等「未观测潜变量」影响（有的模型爱列点、有的爱长句）。处理方法：把 $z$ 拿掉、直接算参考答案在空上下文下的得分 \$R'\$ ，两式相减才得到最终奖励 $\hat{R}$ —— $z$ 的贡献被从风格基线里剥出来。公式骨架：

$$\hat{R} = R(x, z, y^*) - R(x, \varnothing, y^*)$$

标准差过滤。PRIME 的 prompt filtering / DAPO 的 dynamic sampling 靠「一组 rollout 全对或全错就丢」保 batch 里有学习信号，但那依赖 0/1 奖励。RLPR 的奖励是连续的，于是把过滤标准换成组内奖励的标准差：std 太小（大家都高或都低、题目过易过难）就丢掉，保留难度适中的样本持续学。

奖励计算的职责最终还是策略模型自己承担：讲者建议不用额外引入大模型打奖励，「0.5B 模型就用 0.5B 自己打，7B 就用 7B」，零新增系统开销。另外 Q&A 中交代实现细节：think 用尖括号、最终答案用 <answer> 标签包住，正则抽出答案段做替换，计算成本只是一次前向。

实验：三个模型家族 + 与 VeriFree 对比 + 奖励质量

主实验（字幕口径）。在 Gemma、Llama、Qwen 三个系列上与 RLVR 同超参对照训练：RLPR 在通用能力上比 RLVR 额外多涨点，其中一个系列 +1.4 点、Llama +4 点、Qwen 亦约 +1.4 点（字幕口述略有含糊，此处按其顺序记录），计入数学能力后结论一致。

与同期工作 VeriFree 对比（同训练规格）：某个 QA 任务上高约 8 个点，Minerva Math 高 7.5 个点；平均通用任务高 3.5 个点，通用+数学共 7 个 benchmark 高出近 4 个点。稳定性对比更有意思：双方都换三组不同提示词（如 R1 式、Qwen-Math 式）重跑，RLPR 的三条训练曲线挤在窄带里而 VeriFree 明显发散；答案长度行为上 VeriFree 出现「三组平行线」、RLPR 一致——讲者归因于 likelihood 建模的乘积结构对低概率 token 的敏感，以及 VeriFree 需额外辅助损失维持训练。

奖励质量（ROC-AUC）（把奖励当「对/错」分类器、用人工复核标签测其排序能力）：规则奖励在数学上做到 0.95 左右但通用域大幅衰减；通用验证器经训练能比规则在通用域高约 8~10 个点但数学上并无优势；likelihood 数学 0.95、通用约 0.8；RLPR 在通用域把奖励质量做到 0.9 以上（Q&A 口径作「90 多」），且 0.5B 的小策略模型已经足够、7B 更高、72B 边际收益有限。评测协议上所有 benchmark 报告 avg@k，AIME 这种 30 题的小集测 16 次取平均——讲者称这样做之后先前文献里那种 AIME 涨跌剧烈的现象消失了，结果是稳定抬升。

与 RLVR 互补性的一个小实验：在 PRIME 数据上把连续的 PR 信号与 0/1 VR 相加融合，SimpleQA（字幕作「sim m q a」）约 +4 点、Minerva 约 −1 点——简单的 advantage 相加融合不是全面提升，讲者判断融合方向有空间但需要更好的融合方式。

讨论：三个「更本质的问题」与 Q&A 要点

讲者在主讲末尾把工作放回更大的问题清单，有三个值得记：

  1. Data scaling：现在 RL 训练常常几千步跑十几个 epoch 的固定 prompt 集，「瓶颈到底在数据不够，还是数据的作用没被发挥出来」未定；RLPR 能 unlock 数学/代码/rules 覆盖不到的数据，这个问题在 RLPR 之后更值得重问。
  2. Effective exploration：用 pass@1024 这类严格标准去衡量，RL 训练后模型「能解决的题集」几乎不变，涨的全是 pass@1。原因是探索被模型先验约束——训练得 loss 越低越采不出新路径。先验与探索的矛盾是公开的争议点，讲者未给解法，明说这是个值得讨论的方向。
  3. 效率：RL 继承了预训练与 SFT 的低效又加上同步开销，数据可 scale、exploration 可放宽之后，训练速度会先撞墙。

Q&A 中讲者明确给出的边界：依赖参考答案是方法的固有限制，没有参考答案的任务（如 deep research 报告）RLPR 不适用，无监督路线（TTRL、entropy reward 一类）上限目前不高；参考答案长几十到一百词都能训，关键看其是否唯一、是否有指示价值；完全没见过的垂直领域 RLPR 训不动（模型拿不到正奖励），需要先补 mid-training；chain-of-thought 的思考过程在 RLPR 里不直接提供奖励信号（只有最终答案被评估），讲者认为刻意约束过程好比「手把手教小孩骑车，可能学得更慢」；关于「和 SFT 的本质区别」：RLPR 与 RLVR 同构，都是序列级 outcome reward 做策略更新，完全不需要 $z$ 的逐 token 标签——需要高质量数据的只有 $y^*$ 这一个点。

5可迁移

  • 对 coding data / RL infra 工作的直接可试点：
  • 「把参考答案拼到自己推理后面、取概率均值减空推理基线」是一条极廉价的通用域奖励管线——只多一次前向（还可与训练前向合并），且不需要养任何外置判分模型。在自家领域里先按讲者的方法测一下 ROC-AUC：若奖励质量能到 0.9 上下，再考虑上 RL；
  • 标准差过滤是 prompt filtering 在连续奖励世界里的等价物，已有的 GRPO 训练里只要组内 std 太小的 prompt 换个实现就能丢，是一行级改造；
  • 评测协议直接抄：小 benchmark reporting avg@k（AIME 测 16 次）能消掉很多「涨跌剧烈」的假象，做 RL 实验时尤其值得。
  • Infra 视角的启发：
  • 奖励计算零新增组件（策略模型自打）意味着 verl 里 RLPR 只是把 reward function 从「规则函数」换成「模型内嵌前向统计」，对现有 RL infra 改造成本最低；对比之下外置判分模型要付常驻推理服务与版本对齐的成本；
  • likelihood 类连续奖励的稳定性风险值得注意：如果自己在训通用域 RL，用乘积形式前先想好低概率 token 的钝化（算术平均、clip、或 top-prob 截断），不然每次坏奖励都可能污染掉一整轮更新。

7原文金句（1-2句）

「我们并没有把语言模型当成一个特定任务的实施模型——评估概率这件事，就是语言模型从随机初始化起、一直在优化的统一任务。」

「你把这道题解出来，靠的不是模仿别人怎么写解答，而是让模型自己探索出他输出得出来的路径，再用这个能力教他这道题该答 A 还是答 B。」
