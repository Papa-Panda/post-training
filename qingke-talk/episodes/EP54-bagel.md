## 一句话总结

BAGEL 用一套 Mixture-of-Transformers（MoT）架构把「理解」和「生成」放进同一个 decoder-only Transformer：理解与生成各用一套独立参数、只在 attention 层共享上下文，从而既绕开外挂 diffusion 解码器的信息瓶颈、又避免单套参数的任务冲突；再配上大规模交错（interleaved）图文数据与只在 SFT 阶段构造的推理增强数据，模型在训练后期涌现出 free-form 图像编辑、世界知识生成与 3D/导航类操作能力。这期 talk 的价值不在报 benchmark，而在讲者把「为什么选这条路线、四阶段怎么训、哪些能力何时涌现、哪些坑（EMA、CFG）怎么避」完整摊开。

## 核心

### 路线之争：五类统一架构，BAGEL 为什么选参数分离

讲者先用近年的综述图谱把统一理解+生成模型的路线分成几类，并逐条给出否决理由，这部分是整场最有信息量的「选型论证」：

1. **纯 AR + 离散视觉 token**（Chameleon、Emu 一系）：好处是完全复用 LLM 基建、天然支持图文交错生成；但离散化同时伤生成质量与理解性能，且逐 token 生成大图慢、内存开销大——「目前沿着这条路线做还稍微有点尴尬」。
2. **双 encoder**（连续 ViT 管理解、离散 VAE 管生成）：缓解了理解差的问题，但生成质量仍差、双编码内存开销大，且两个任务在同一个 LM 里存在语义冲突。
3. **单一专用 tokenizer**（VILA-U、TokenFlow、Muse 一系）：把高低层语义压进一个 vision encoder，交错场景下省 token，但理解与生成效果都还不够好，讲者定位为更适合学术界探索。
4. **冻结理解模型 + 外挂 diffusion 解码器**（BLIP-Diffusion、MetaQuery 一系）：从训好的多模态理解模型接 learnable query 去条件化 diffusion，训小模块、一两天见效，两个任务都「守得住」。但讲者团队一开始考虑后放弃了：query 压缩等于显性信息瓶颈，单图生成无碍，一旦做超长文本、图文交错输入就会丢信息。讲者并据此反推 GPT-4o 的图像编辑容易丢细节（风格转换后眼镜、长发、背景灯消失）「很有可能就是用的这种外挂一个 decoder 的结构」——这是猜测，但给出了从结果反推架构的方法论。
5. **单 Transformer 同做 next-token prediction 与 flow matching**（Transfusion、MonoFormer、Show-o 一系）：不做高层信息压缩、交互无损、可扩展到长上下文；但共享参数导致高层语义归纳（文本）与低层生成（图像）的任务冲突，且要从头训扩散模型，学术界算力做不动、训练不稳定。
6. **参数分离、共享注意力**（LLaMA-Fusion/LM-Fusion、Seed 的 Mogao、Janus-Pro、BAGEL）：理解与生成各用一套参数、共享同一套 attention。这样既保留第 5 类「无瓶颈、可长上下文」的好处，又用独立参数消掉任务冲突；代价仍是训练开销大、稳定性差——「我们今天要介绍的也是这一套架构」。

此外讲者提到一条更新的路线：把文本生成也改成 diffusion 目标（字节 Duo Diffusion、Princeton/CA 的 MMaDA 一系），生成质量已不错，但文本理解离自回归模型还有差距。

### 架构细节：MoT 的 token 如何流动、attention mask 怎么切

BAGEL 的具体做法（以两轮交错输入为例）：第一轮输入图像+文本，文本 token 走理解分支；若任务是文生图，噪声 token 走生成分支。第二轮的文本与图像需要看到第一轮的图文信息，所以训练时把第一轮图像的 **clean VAE 特征** 喂给生成分支、**ViT 特征** 喂给理解分支，后续轮次重复这一过程。attention mask 整体仍是 causal 的：后续文本/图像能看到前面所有轮次的图文内容，但**看不到前面轮次的 noise token**；每张图像（或每个噪声块）内部是 bidirectional 的。对视频训练做了变体：上下文太长，不再喂 clean 特征，而是借 diffusion forcing 的做法，让后续帧看到前面帧的带噪特征。

为什么生成与理解必须分参数？讲者给了小模型消融：在 dense、只共享 QKV 的 MoE、QKV 与 FFN 全分离的 MoT 之间比较，理解任务的几条曲线差异不大，但生成任务的 MSE loss 能差出 0.01 甚至 0.04——「这个差距对生成任务影响非常大」，故最终选 MoT。不过讲者也留了口子：模型放到非常大的规模时，MoE 与 MoT 的差别未必还有这么大，这一点他们并不确定。

### 数据：开源没有现成的交错生成数据，只能自己造

BAGEL 与其他统一模型最大的不同，是不用纯 image-text pair 训，而用大量 interleaved 数据激发 free-form 生成。理解侧交错数据现成（主流理解数据本身就是交错形式），生成侧交错数据开源生态里几乎没有，他们为此搭了两条构造管线：网页图文交错数据（从 OmniCorpus 过滤）与把开源编辑数据改写成交错形式；视频数据天然适合构造交错（帧间变化即编辑指令），另有 3D 数据支撑 rotation 类能力（字幕作「MB image net」，应为 MVImgNet 一类多视角数据集）。需要推理的生成数据（文生图推理、free-form manipulation、智能编辑）最难构造，只做了 SFT 规模，用开源的 VLM/thinking 模型辅助生成推理过程。

配比实验结论很干脆：**生成 : 理解 ≈ 4 : 1**。增大生成数据比例对生成 MSE loss 影响非常大；而理解的 CE loss 虽然曲线波动大，从 benchmark 看影响不大——理解数据比例可以不用太大，生成数据比例一定要够。讲者补充：这里还有很多可做的 ablation，论文里没有放太细。

### 四阶段训练：分辨率与 pack 长度逐阶段放大

1. **对齐**：类似 LLaVA 的做法，先用简单的 image caption 数据把 ViT 与 LM 对齐，开销小，在较小的 ViT feature 上快速做完。
2. **预训练**：原生分辨率训练——生成侧图像最长边约 512，理解侧最长边约 980。所有样本 pack 成长序列训练，**没有严格的 batch size 概念**，靠控制 pack 序列长度与卡数来控制样本吞吐（这是 GitHub 上被问最多的点之一）。
3. **继续训练（CT）**：借鉴文生图模型的经验把生成侧长边放大到约 1K，token 量涨幅大，最长 pack 序列相应增加约 10K token。
4. **SFT**：筛更高质量数据并加入推理增强数据；随阶段推进，纯文生图数据占比逐步下降、交错数据占比上升，以换取 free-form 生成能力。

讲者顺带给了三个实战参数经验（都来自被坑过的复现者提问）：优化器 epsilon 要设得非常小以防崩溃（某篇论文的小发现）；**EMA 是最常见的翻车点**——默认 EMA 衰减设得太大时 EMA 模型几乎不更新，会出现「训了几万步 loss 降了很多但模型没效果」，解法是先测普通权重、或把 EMA 调小；生成发糊/过曝主要是 CFG 引入的，开 CFG renorm/rescale 或调小 CFG scale 可明显缓解（Flash 模型的做法是直接做 CFG 蒸馏）。

### 涌现顺序：理解先到，智能编辑最后

讲者用「达到最终性能的 85% 即算饱和」的口径画了能力随训练的涌现次序：理解任务收敛最快（几百 B token 量级即可达到不错性能，与 LLaVA 时代的经验一致）；生成约到 700B token 才有像样的基础 matching；之后才慢慢长出基础编辑；**最后涌现的是「智能编辑」**——需要理解与生成真正互相促进的那类任务（如推断毛线织完的形状、水果加牛奶搅拌后的颜色、视角转换），可视化上要到约 4.5T token 才与人的预期对齐。文生图很早就与 prompt 对齐、后续只是质量与文字渲染变好；简单编辑在训练早期（约 2T token）就可以了，后面是润色。另有一个推理侧消融：简单增删改查用纯 VAE 推理与 VAE+ViT 推理差距不大，但**需要智能推理的编辑，VAE+ViT 明显更好**——ViT 的语义特征是这类任务的关键输入。

### 效果与边界：self-CoT 是统一模型独有的招

benchmark 讲者只做定性交代：主流理解 benchmark 与同规模纯理解模型 comparable，但比不过自家专门的理解模型——这里他主动澄清了参数口径问题：MoT 虽然总参数翻倍，但理解任务只流经理解分支的那套参数，「另外 7B 参数其实是完全没有用的」，所以按 7B 理解参数与别人比是成立的。生成侧两个自研要点：一是 **self-CoT**——让模型先对输入文本/图像做文本推理、再按推理结果生成，在需要世界知识的生成与智能编辑上都有明确增益（如「由小车拼成的大车」这类构图，直接生成做不对、先想一想就对了）；二是文字生成能力是规模涌现的，中小模型学不好，英文场景迁移尚可、中文明显弱。编辑 benchmark 上，中英文编辑与专用模型 Step1X-Edit 相差不大；智能编辑明显强于开源模型，但与 GPT-4o 仍有距离。

失败案例讲者也不藏着：特殊 IP/动漫形象、复杂文字生成、交换两个瓶子、deblur（会幻想不存在的内容）都做不好——并指出这些是目前几乎所有模型的共同短板。

### Q&A 要点

- **为什么不直接用 Agent 调外部生图工具？** Agent 现在确实很强、是很多任务的高上限做法，但统一模型的追求是模型自身在「生成帮助理解、推理帮助生成」之间自我循环，冲更高的智能上限。生成促进理解目前还很初步：用简单 transform/visual CoT 帮理解「提升非常慢」，甚至不如直接函数调用；图像的 2D 表达与文本的 1D 表达差异何在，是讲者认为值得想的方向。
- **输出模态怎么决定？** 目前靠人工指定的 special token 切换文本/图像输出，不像 GPT-4o 那样自动调用生图；要模型自判只需补一版 special token 预测的 SFT，「非常好训练」，主要难在应用端交互工程。
- **训练数据是多任务混合、任务间不可见吗？** 是混合训练，样本间由 attention mask 隔离，样本内另有特殊 mask 设计。
- **文字生成除了数据量还靠什么？** 字符级 encoder 是关键一招（可看 Seed 的文生图技术报告）。
- **理解指标还会不会涨、会不会打架？** 打架肯定有，只是 MoT 里程度小；理解在 CT 之前就已到 90%–95%，后续涨幅有限。
- **生成扩图：先升分辨率还是先升参数？** 先升分辨率，收益更大。
- **编辑能商用吗？** 还有距离（瑕疵率要求高）；讲者认为 Flash 一类闭源模型已接近商用水准，这条路线要靠更大规模与更好数据长期演进。

## 可迁移

- **选型论证框架可直接复用**：把「离散 AR / 双 encoder / 单 tokenizer / 外挂解码器 / 共享参数 / 参数分离」按信息瓶颈与任务冲突两条轴排一遍，是做任何理解+生成统一系统时的第一张图；尤其「外挂解码器=显性瓶颈、长上下文交错场景必丢信息」这条，对评估闭源模型（GPT-4o 编辑丢细节）也是可操作的反推线索。
- **infra 视角**：MoT 是「共享 attention、分离 FFN/参数」的静态路由，它的部署形态介于 dense 与 MoE 之间——理解流量只激活一半参数，成本模型要按激活参数而非总参数算；原生分辨率 + packing、无固定 batch size 的训练方式，对变长多模态数据的吞吐管理是现成参考。
- **训练坑位清单**：EMA 衰减过大导致「loss 降了模型没变」是隐蔽的静默失败，任何带 EMA 的生成训练都应先验普通权重；CFG 的糊/过曝优先查 renorm/rescale 而不是先怀疑模型。
- **self-CoT 值得在 RL 数据构造里借鉴**：生成任务先出文本推理再执行，与 post-training 中「先想后做」的轨迹设计同构；且 ViT 语义特征对推理型编辑不可替代，提示多模态 RL 的状态表示不能只用像素 latent。

## 疑问 / 下一步

- MoT 与 MoE 在超大规模下是否趋同，讲者明确表示不确定；小模型上 0.01–0.04 的 MSE 差距能否外推到 7B 以上，没有给出证据。
- 生成数据 : 理解数据 4 : 1 只是「中间结果看着不错」的经验值，讲者承认不是最优、ablation 未放全；交错生成数据的两条构造管线细节（过滤规则、编辑数据改写方式）在 talk 中一句带过，须查论文与 GitHub。
- 「生成促进理解」讲者自认尚无好形式（visual CoT 太弱）——这恰是统一模型相对 Agent+工具范式的立项理由，目前仍停留在愿景层，缺可量化证据。
- 智能编辑与 GPT-4o 的差距被多次提及但未量化；论文口径的 benchmark 数字（理解/生成/编辑）需另行查 arXiv:2505.14683 核对，不能只凭 talk 口径引用。
