## 一句话总结

Mini-Gemini 在「学术界可接受的算力与数据规模」内从三条线提升视觉语言模型：一是 patch-informing——用低分辨率 ViT 特征作 query、CNN 高分辨率特征作 key/value 做一层 cross-attention，在不增加视觉 token 数的前提下把高清细节注进每个 token；二是数据侧三件套（GPT-4V 蒸馏的细粒度指令数据、OCR/文本相关数据、少量纯文本生成数据）；三是应用侧把理解与生成打通——模型以纯文本形式生成 Stable Diffusion 的 prompt，再由扩散模型出图，全程只做文本训练就得到图文交错的对话生成能力。讲者的经验结论很克制：视觉编码器两端要匹配且不必过大、token 数扩到约 8K 即收敛、生成质量主要由理解模型的规模决定。

## 核心

### 出发点：在可接受范围内把 VLM 做得更好

讲者先给整场 talk 定调：这份工作探索的是在学术界能接受的资源范围内（而不是大厂式海量数据与 GPU）把多模态视觉语言模型做得更好，三条线是高分辨率、更好的数据、可扩展的应用。Teaser 展示的是一个由 9 张小图拼成的做面包流程图：模型不仅能理解图的顺序，还能答出切块后应放在温暖处发酵约一小时这类细节，并能做需要 reasoning 与 instruction following 的细粒度 OCR。

### 高分辨率困局：token 数随分辨率平方涨

现行 VLM 的做法是把图像转成视觉 token 与文本 token 拼接后送入语言模型。两类编码器讲者都点了一遍：

- **query-based**（BLIP-2、InstructBLIP、Flamingo）：用少量预定义 query（字幕口径：Flamingo 64 个、BLIP-2 32 个）从图像里抽取与文本相关的信息，问题是细节必然丢失，64 个 token 装不下一张文字丰富的图；
- **projector-based**（LLaVA）：直接把图像转成 token 再用简单 projector 映射进语言模型空间，问题在分辨率一升 token 数就失控——字幕给出的量级是输入 224 时约 256 个 token，336 时约 576 个，672 时直接涨到 2000 多个，而语言模型训练是逐 token 算交叉熵的，成本随之线性涨。

多图与视频场景让问题更尖锐：单图放到上万 token 还能忍，8 张图就是 8 万到 10 万 token。所以 Mini-Gemini 的问题设定是：不增加视觉 token 数，只提升每个 token 的质量。

### 方法一：patch-informing 双分辨率 cross-attention

做法拆成两支：

- **低分辨率支**承担 token 的「骨架」：用 ViT 处理低分辨率图。讲者强调 ViT 的 patch 间已做充分交互、感受野好，且 token 数可控（24 × 24 输入约 256 个量级）；
- **高分辨率支**承担细节：用 CNN 处理放大 2–3 倍以上的高分辨率图。相对 ViT，CNN 的局部细节更丰富。

衔接方式：把低分辨率特征图 reshape 成如 4 × 4 的空间网格，低分辨率中的每个区域对应高分辨率中的一块区域；以低分辨率特征作 query、高分辨率对应区域的特征作 key 与 value，做一层 cross-attention。这样每个 token 只看自己对应的高清区域，计算量不大；可训练参数极少（三个 projector，cross-attention 本身是固定计算），不需要大数据与大算力就可探索。讲者点明这一取向正是为学术界设计的：改动小、上限高。

可扩展性也顺带解决：注意力机制里低分辨率 token 数与高分辨率区域数是解耦的。高分辨率输入可以在空间上放大到 1000、2000 量级（按算力封顶），也可以扩展到时序维做视频；低分辨率 token 数也可以像 LLaVA-NeXT 那样切块拼到 5 倍。

### 实验一：高分辨率侧的消融结论

- **只加一层 cross-attention 就有明显收益**：在 token 数不变（256 个）的条件下，对分辨率敏感的任务直接有 4 个点以上的提升（字幕口径，基线为 LLaVA-1.5）。
- **把高分辨率输入升到 768 × 768** 还能进一步涨，文本相关任务收益最明显，MME 与 MMBench 一类则以波动为主、增益不大。
- **编码器必须两端匹配**：高分辨率侧若换成 ConvNeXt-Base 这类较弱编码器，cross-attention 不仅没用，在一些数据上还会大幅掉点；ViT-Large 配 ConvNeXt-Large 才有好结果（字幕给出的对比是 59.8 → 61.5，MME 31.9 → 34.6，均为字幕口径）。
- **再往上堆编码器没用**：升到 XXL 后涨点不再明显——两端匹配即可，过大只会收敛到同一水平。
- **token 数也有天花板**：把 $N$ 扩到约 3K（低分辨率输入 672）收益显著，但继续扩到 8K 左右即进入收敛，1 万以上基本没增益（字幕口径）。

### 数据侧：三类数据各自的作用

1. **细粒度视觉指令数据**：讲者用了三套 GPT-4V 回复蒸馏的数据（字幕作 ShareGPT-4V、LLaVA-GPT-4 与另一套 ASR 不清的数据集，原文以论文为准），在 instruction tuning 阶段加入（pretraining 阶段仍混 LLaVA 数据）。结论是更好的数据带来更好的效果，三套都有明显提升，其中一套约 700K 指令数据带来非常明显的涨点（字幕口径），且回复风格更接近 GPT-4 的体验。
2. **OCR / 文本相关数据出奇地重要**：文字本来就是语言的视觉表示，与语言模态强相关。把 text caption 一类数据删掉（仅约 21K 条）不只 TextVQA 掉点，其他数据集也明显掉；讲者又收集了约 334K OCR 相关数据（图表理解、文字问答等；数字为讲者凭记忆口述、字幕口径存疑）加入训练，带来显著提升。
3. **纯文本数据不能缺**：他们生成的 13K 条纯文本生成数据加入后，多模态指标不降反升，部分指标 3 个点以上（字幕口径）。讲者的解释是纯文本防止语言模型过拟合到「输入必须有图」的模式、保住语言能力本身；他引用 Apple MM1 报告称 text-only 数据保持约 10% 的比例对多模态性能更好。

训练方式上讲者也给了经验：两阶段训练对这个工作更划算——第一阶段只训 $N$ 个 token 的配置，第二阶段复用已训好的 projector 切换到高 token 配置，省算力；但他强调实际选型要看效果，不同语言模型对学习率的需求不同。

### 方法二：用文本作桥梁把理解与生成打通

直接让语言模型输出 embedding 再接扩散解码效果不好，还会反过来伤 VLM。Mini-Gemini 的做法是最直接的一条：用文本连接两个模型，关键在训练数据怎么造：

- **recaption 数据**：从已有 GPT-4 回复数据集中取回复，让 GPT-4 在给定若干 Stable Diffusion 指令示例的上下文里反推「这个回复对应的生成 prompt 应该是什么」，训练时就把模型目标设为生成这种 prompt。整个链路全是文本，不需要配对图像。
- **in-context prompt 数据**：用 Lima 一类高质量纯文本对话数据，把高质量 prompt 嵌入对话上下文，让模型学会从上下文判断该生成什么样的 prompt 去调 Stable Diffusion，使图片能跟着对话走。

效果上有两个讲者自己觉得有意思的点：一是纯文本训练出的生成能力能泛化到图文输入——给一张「冰湖中的仙人掌」照片让它生成相似图，模型抓住主体与环境的对立关系，生成了「北极熊在热带雨林」这类逻辑对应的图；二是能做多轮对话中的故事式连续生成。他同时坦承短板：开源 Stable Diffusion 本身质量弱于 DALL·E 3；细节保留差（如小白鼠毛发颜色会漂移）是下一步要解决的问题。

### 生成质量由理解规模决定

讲者专门做了一组规模对比：同一设定下把 VLM 从 34B 换到 13B、7B、2B，生成的逻辑质量逐级下降——34B 能抓住图像的主体-环境矛盾并生成逻辑自洽的新图，13B 开始出现背景残留（如北极熊在沙漠但身后还有雪山），7B 只剩字面对应（仙人掌就生成仙人掌、环境都往寒冷上靠），到 2B 连指令跟随都不足、直接生成不出可用的 prompt。结论：这条「理解生成 prompt、扩散模型出图」的链路上，瓶颈在理解侧模型的规模与能力，而不是绘画模型。

### Q&A 要点

- **与 LLaVA 的上下文**：LLaVA 本身支持 4K 上下文，2.8K token 可以输入；要更多可换 16K 以上的语言模型。
- **与 token 压缩类工作（如 LLaVA-Vid 系）的区别**：那类工作为处理超长视频不得不压缩 token，研究重点是压缩时保留关键 token，关注效率；Mini-Gemini 不需要输入超长序列，关注的是固定 token 预算下的质量上限。两者可结合，但更直接的路是扩上下文。
- **text-only 数据为何能涨多模态指标**：它涨的不是 caption 本身，而是保住语言模型不陷入「输入必须有图」的模式；想看系统对比建议读 MM1。
- **几何与深度信息**：CLIP 本质是语义对齐、不具备几何能力，讲者直言「哪怕把 CLIP 再 finetune 也做不到」，更看好用 agent 式方式把光流、深度等信息引进来，而不是强行都对齐进 CLIP。
- **离散视觉 token 会不会取代连续特征**：目前把理解与生成统一起来的论文（如 Google 的大模型工作）都没有显示出对 VLM 的提升；连续特征胜在与语言的大规模对比对齐。若将来 VAE 式编码能真正打通生成与理解，它会是更好的选择，但目前还没看到做得很好的。
- **是不是世界模型**：讲者明确说他不认为现在的 VLM 或 Sora 一类算「真正的世界模型」——世界模型应从数据中学到世界规律、编码进参数去预测未知，而「怎么把这份知识提取出来用于任务」至今没有显式解法。

## 可迁移

- 对数据工作的直接借鉴：这场 talk 给了三个低成本杠杆的优先级参考——少量高质量蒸馏指令数据（约 700K 量级即可见效）、不起眼的 OCR/文本对齐数据（21K 量级就能影响全局）、以及约 10% 比例的纯文本数据防语言能力退化。做多模态 SFT 数据配比时，这三项都值得先于「堆更多通用图文对」验证。
- Infra 视角：patch-informing 的本质是把「 token 数」与「有效分辨率」解耦——固定送入 LLM 的 token 预算，用一次区域对齐的 cross-attention 把高频细节按需注入。这与长上下文里「固定预算 + 按需取回细节」的检索式做法同构，且对多图/视频的 token 爆炸是结构性解法。
- 评估纪律：讲者多处主动限定数字口径（「波动」「讲者凭记忆」），且指出生成质量的瓶颈定位在理解侧而非生成侧——做图文生成系统时先升级理解模型、再换扩散模型，这个排障顺序可以直接沿用。

## 疑问 / 下一步

- patch-informing 目前只在空间维验证过；讲者说 $M$ 可以扩到时序维做视频，但视频场景下区域对齐（运动导致低清区域与高清区域不再静态对应）如何处理，讲授中没有展开。
- 编码器「两端匹配」的判据仍是经验性的（弱一档掉点、升到 XXL 无增益），缺少可预先计算的匹配度量；实际选型时如何低成本预判，值得深挖。
- 纯文本生成桥接的细节保真问题（同一角色跨轮毛发颜色漂移）讲者列为待解；这与多轮图文生成里的一致性保持是同一类问题，后续工作如何解决值得对照看。
