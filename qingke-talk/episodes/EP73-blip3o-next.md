## 一句话总结

这期讲 BLIP3o 系列如何在统一多模态模型里安排「理解」与「生成」两个任务：BLIP3o 的结论是把图像表示放进 CLIP 语义空间、用 diffusion（flow matching）目标而非回归目标去建模连续图像特征，并用「先训理解、冻结骨干、再训生成」的顺序训练避开多任务配比难题；其续作 BLIP3o-NEXT 再在同一骨干上加一路离散图像 token 的交叉熵监督——离散信号负责打好画面结构（尤其文字渲染与空间关系）、diffusion 负责渲染细节——并由此把语言模型那一整套 GRPO 式 RL 原样搬到图像生成上，拿到明显的 prompt 对齐与文字渲染提升。

## 核心

### BLIP3o 的表示选择：为什么在 CLIP 空间里生成

统一模型的高层结构是「自回归模型 + diffusion」：自回归骨干产出中间的连续特征，diffusion 模型以此为条件生成真实图像。第一个设计问题是图像用什么表示。老做法是 VAE latent：低层像素特征，重建质量好，但与理解侧的表示不在一个空间。BLIP3o 选择 CLIP 特征作图像编码——理解侧本来就用 CLIP，生成侧也用 CLIP，两个任务就被统一到同一个语义空间里操作。代价是 CLIP + diffusion 解码器的重建质量可能略逊于 VAE，讲者认为为了统一性这个交换值得。

讲者把三种架构并排做了对照实验（在 GenEval、DPG、FID 三个常用生成基准上、每 3–4 千步画一次曲线）：

- 架构 A：自回归模型直接回归 CLIP 特征（MSE 一类目标），无 diffusion 模块（Emu、SEED、MetaMorph 一系）；
- 架构 B：自回归模型 + Diffusion Transformer 对 CLIP 特征去噪（BLIP3o 的方案）；
- 架构 C：自回归模型 + Diffusion Transformer 对 VAE latent 去噪（MetaQuery 一系）。

两个结论：其一，B 对 C 说明**语义特征比 VAE latent 更容易与自回归骨干对齐**；其二，B 对 A 说明**连续图像特征的分布要用 diffusion 式目标（flow matching）来建模**，样本多样性与图像质量都好于直接回归。附带一提：他们后期弃用了 FID——FID 可以很低但图完全不跟指令，GenEval 与 DPG 更可信。

### 训练策略：顺序训练代替多任务混合

理解与生成同训有两条路：多任务混合（两个任务的数据按配比混着训），或顺序训练（先训理解、冻结自回归骨干、再单独训 diffusion 部分）。讲者选了后者，理由很实际：混合训练必须仔细调两个任务的数据配比，配比一错某个任务就掉；顺序训练每个阶段只专注一个任务，不存在配比问题，且能最大程度保留原有理解能力。

代价是放弃了探索「理解与生成能否互帮互助」。讲者对此给了少见的坦白：他们实际试过，结论完全取决于数据配比、数据规模与架构三件事——小规模下用 MSE/余弦相似度目标（如 MetaMorph）时互助似乎成立，但一旦换上 diffusion 式损失，互助基本消失、两任务甚至互相冲突。所以这不是「统一模型没有意义」，而是在当前框架下观测不到；他猜测本质问题可能在于两个任务还没被放进同一个 tokenizer 之下。

数据与开源：BLIP3o 开源了模型、训练代码与 3000 万条预训练数据（用 Qwen-VL 重新标注，dense caption 平均约 120 个 token）；另蒸馏了约 6 万条 GPT-4o 的高质量指令数据。讲者的经验是蒸馏数据比真实图像**更容易学**，消除生成伪影也更快。预训练数据主要用 CC12M 与 SAM 并做 recaption；SFT 数据则是先看预训练模型的具体毛病（如人体姿态差），再针对性构造 prompt 生成数据补齐。

### BLIP3o-NEXT：给连续生成加一路离散监督

NEXT 的唯一大改动是加一路离散信号。骨干的 hidden states 之上挂两个头：一个还是 Diffusion Transformer 用 flow matching 损失建模连续 CLIP 特征；另一个是 LM head，用交叉熵预测离散图像 token。离散 token 来自 VQ-SigLIP2：不用 VQ-VAE，而是把 SigLIP2 的语义特征量化成 codebook——理由与 BLIP3o 一以贯之：一切都放在语义空间里操作。

关键澄清：**推理时生图仍然只靠 diffusion 那一路**，离散头只在训练时注入监督，不参与出图。离散与连续的分工来自他们的观察：连续/diffusion 的视觉保真度高，但离散自回归在需要空间结构的任务上更强——文字渲染、物体间位置关系（「A 在 B 左边」这类构图）都明显更好。讲者的比喻是：离散 token 先把图的结构蓝图打好，diffusion 再在蓝图上填细节、做渲染。

### 离散信号的真正红利：把 LM 的 RL 整套搬过来

加离散 token 还有一个架构外的重要好处：图像生成可以**原样复用语言模型的 RL 基础设施**。他们的做法是冻结 diffusion transformer、只更新自回归骨干：骨干采样出不同的离散序列，冻结的 diffusion 部分据此渲染出不同的图，可验证的 reward 给图打分，信号回传给骨干——整个训练 pipeline、代码与 infra 与语言模型 RL 一模一样。选的两个任务都因为 reward 可验证：文字渲染用 OCR 模型核对图中文字，prompt 对齐用 GenEval 的 evaluator 打分。

结果（字幕口径）：GenEval 类任务上 reward 约 500 步从 0.80 涨到 0.991；文字渲染准确率从 0.55 左右涨到约 0.9（不到 1000 步，后期 reward 出现下滑，他们停了，讲者说学习率与 KL 系数还要再调）；GenEval 总分从 0.81 提到约 0.91。做这件事的模型总共约 3B（约 1.7B 语言骨干 + 1.5B diffusion 部分），且用的是原始 GenEval prompt、没做长 caption 改写。讲者对 RL 价值的概括有两层：一是让每次采样更大概率一次就出对图（少抽几次奖）；二是把 text token 与 image token 并进同一个词表后（16 万文本 + 5 万图像 ≈ 21 万），推理时的搜索空间被实质放大，这对 reasoning 类任务是很有前景的方向——当然，Q&A 中他也承认实际解码时文本与图像词表需要隔离、交错生成怎么做还没落地。

### Q&A 要点

- **算力**：两个项目都只用了 32 张 H200；BLIP3o 的数据在 1–2 亿量级。讲者自评这是「学校与公司之间的地带」。
- **参数口径**：BLIP3o 的 8B ≈ 7B 自回归骨干 + 1.xB diffusion 部分，不含 CLIP。
- **生成能力来自谁**：冻结骨干后，生成能力基本来自 Diffusion Transformer，骨干只提供条件。
- **NEXT 还做不做理解**：放出的版本没做理解任务。讲者的观点是理解 benchmark 与最终需要的能力（比如图像编辑里的理解）之间有 gap，与其刷 benchmark，不如「需要什么能力就用那方面的数据去训」。
- **双 CLIP 的代价**：生成侧实际用了 EVA-CLIP 配套的 diffusion 解码器（借自 Emu），与理解侧的 CLIP 不是同一个——理想情况应统一，但自己训这个解码器并不 trivial。影响主要在图像编辑的一致性上，相当于给能力定了个上限，数据可以逼近上限但消不掉这个 gap。
- **为什么 CLIP 特征训得动**：CLIP 特征池化成固定 64 个 token、每 token 约 1000 维，与分辨率无关；1024×1024 出图的压力全在第二阶段的 diffusion 解码器上，不进主训练。这是 CLIP 相对 VAE 的最大好处：压缩比高、训练效率高。
- **对 GPT-4o 架构的猜测**：讲者认为大概率是「BLIP3o + NEXT 式结构」——AR + diffusion 且带离散 token。理由有二：有离散 token 时训练/推理 infra 与语言模型零差别，公司会喜欢；且 OpenAI 擅长 RL，离散化后所有 RL 算法能直接继承到图像生成。
- **统一模型 vs 纯文生图**：讲者的判断是 GPT-4o 之后统一模型已无明显短板（文字渲染、prompt 对齐都不差），GenEval 上的提升很大；剩下的短板主要在图像编辑一致性。

## 可迁移

- **「冻结渲染器、只训策略」是把 LM RL 搬进生成任务的最小改动路径**：只要生成链路里有一段可采样、可打分的离散决策层，就能复用现成的 GRPO 框架、infra 与调试经验，连续渲染部分完全不进训练图。做多模态 RL 时先找这个离散决策层在哪，比先改 RL 算法更重要。
- **任务合并先问「表示是否同一空间」**：BLIP3o 的经验是理解与生成能否共存，先取决于表示是否统一到同一语义空间，其次才是数据配比；配比调参救不了表示层面的错位。反过来，顺序训练（训一个、冻结、再训下一个）是配比敏感场景下的保底方案，代价是放弃任务间互助，需要显式接受。
- **评测口径**：生成质量别只看分布距离类指标（FID 可以很低而图不跟指令）；优先用可验证的任务型评测（OCR 核字、evaluator 打分），这类评测同时还能直接当 RL 的 reward，一套设施两用。

## 疑问 / 下一步

- 离散监督到底帮了多少：讲者说不做 RL、只 SFT 时 NEXT 的文字渲染已明显好于 BLIP3o，但这是跨模型对比（架构、数据都变了），缺同一骨干上「有/无离散头」的干净消融；离散头对理解任务有无影响也未提。
- RL 后期 reward 回落的原因只归到学习率与 KL 系数，没有展开：是 reward hacking（OCR/GenEval evaluator 被钻空子）还是优化不稳定，值得看论文或后续版本。
- 文本/图像词表隔离与交错（interleaved）生成的具体解码方案未落地；「搜索空间扩张有助于 reasoning」目前是方向性判断，没有实验支撑。
- 双 CLIP 空间不一致对图像编辑一致性的实际损失有多大、数据能补回多少，讲者只给了定性判断（决定上限、数据逼近），没有量化。
