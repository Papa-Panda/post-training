2一句话总结

USER 是在 RLinf 框架上为真实世界机器人在线策略学习补的一层系统：统一硬件抽象让机器人像 GPU 一样被调度，自适应通信平面解决异地训练与点对点数据传输，全异步学习框架加持久化 buffer 则把「交互」与「训练」彻底解耦；实验显示异步化使总训练时间缩短到同步版的 1/5 ，跨域分布式 channel 使交互时间变为原来的 1/3 。

背景：真机在线策略学习难在哪

讲者先界定场景：真实世界（相对仿真）+ 在线（相对 offline，训练中持续与环境交互）。仿真里可以并行上千环境，但 sim-to-real gap（视觉与物理规律）使仿真训出的 policy 直接部署会掉性能；直接在真机上学是另一条路，但有三重困难：

  1. 硬件种类与接口不统一。仿真里只有 GPU/CPU 这类封装规范的硬件；真机引入机械臂后，不仅多了一类硬件，Franka、方舟无限等不同机械臂的控制接口、通信接口还各不相同。「能不能像平时分卡一样，选 0 到 4 号卡那样去用机器人」成为系统问题。
  2. 真机数据昂贵，样本效率是第一约束。仿真并行上千环境只需算力，真机并行上千环境需要上千台机械臂，成本高得多。这要求算法侧选高样本效率的方法。
  3. reward / success 信号不明确。真实任务里「是否成功」没有仿真里现成的判据，reward 设计本身要改。

在算法答案未统一的阶段，系统的价值是把多种算法集成到同一框架里公平比较——USER 的定位就是「系统层与学习层之间的桥梁」。

系统层之一：统一硬件抽象——像使用 GPU 一样使用机器人

整个训练流程拆成三个组件：环境（机械臂本身）、rollout（模型推理并与真实世界交互）、actor（训练节点，负责参数更新）。推理与训练主要吃 GPU，环境是机械臂。配置方式是给资源打 label 组节点组：例如 GPU 标为 4090 节点组、Franka 作为一个节点组，在右侧配置文件里写明各自落在哪个节点上。连多台机械臂只需补机械臂的 IP；异构混训也只需在环境节点组里写上两种机械臂（如某个代号 TL2 的机械臂与 Franka）的名字与所在机器，代码侧无痛切换。讲者称这套抽象的好处是「改好配置文件，就可以在代码中无痛地使用多个机械臂和多种类型的机械臂」。

系统层之二：自适应通信平面

通信层做了三件事：

  1. 穿越组网支持异地训练。借助开源工具 EasyTier：北京节点与深圳节点不在同一局域网时，两边都连上一台有公网 IP 的中继机器（如租一台云服务器只提供公网 IP），即可在节点 A、B 之间建联。这样可以「北京放训练集群、深圳放机械臂」地组织实验。
  2. 分布式 data channel。最朴素的实现是所有数据经 master 节点转发，master 带宽压力巨大、效率低。USER 的做法是让推理节点与机器人节点 P2P 直传，不走 master 转发，极大减轻 master 的传输负担。
  3. 权重同步的 SM 感知。训练后要把新权重经 NCCL 发给推理节点，但 NCCL 会占用 GPU 的 SM 资源，导致同步期间推理卡顿。对策是在配置里设置 NCCL_MAX_CTAS 这类参数，限制通信占用的 SM 数量，剩下的 SM 留给推理计算。

学习层之一：全异步训练流程

同步版在线策略学习的流程是「交互攒数据 → 发给训练节点 → 训练 → 同步权重 → 再交互」，交互与训练互相阻塞，两次网络更新之间的间隔被拉得很长。USER 的全异步流程让交互持续进行：攒到一点数据就发给训练节点，训练节点数据一够就不间断训练，每次训练结束即向推理节点同步权重。交互与训练互不等待，同时不间断运行。

异步对算法有要求：on-policy 算法（如 PPO）要求数据新鲜度，天然更配同步；off-policy 算法与 DAgger 这类模仿学习算法对数据新鲜度没有要求，可以直接吃异步加速。讲者在 Q&A 中补充：RLinf 主分支已经集成了异步 PPO，数据不太旧时仍可用，且系统支持策略版本隔离（控制采集数据与训练策略之间的版本差）。

学习层之二：持久化 buffer

off-policy 算法要把交互数据存进 buffer 供采样，buffer 越大算法上限越高，但内存有限。USER 的 buffer 设计把三层存储拼起来：

  • 内存只存 index：所有数据的 ID 常驻内存；
  • 磁盘存全量：每份数据在磁盘上都有一份备份，「磁盘有多大 buffer 就有多大」；
  • 内存 cache：新数据优先驻留内存 cache，cache 满了淘汰较旧数据（磁盘仍有备份，随时可取，只是慢些）。

这样 buffer 容量不再受单机内存限制。实验验证了 cache 的作用：以 $R$ 表示数据在内存中的占比（字幕口径）， $R$ 越大，被 cache 住的数据越多，采样效率明显越高。

学习层之三：多样的模型、算法与 reward

  • 模型：大小模型都支持，大模型主要支持 π0 这类 VLA 模型；
  • 算法：SAC、RLPD 等 off-policy RL 算法，以及 HG-DAgger 这类带人类干预的模仿学习算法；
  • reward：三类来源——rule-based（如按到目标点的距离判定）、人类给的 reward 信号、reward model 接口。

实验一：正确性与大模型验证（5 个真机任务）

验证用了 5 个真实任务：peg insertion （把 3D 打印插块插入指定孔）、插插座（开场演示的任务）、拧瓶盖（对力控有要求，拧到最后很紧）、pick & place（把鸭子从紫色侧抓到红色侧）、长流程任务（把笔放进橙色盒子 → 抓起橙盒塞进白色大盒子 → 扣上盖子，用来验证大模型能力）。

小模型侧：peg insertion、charger 等任务很快收敛，pick & place 与拧瓶盖效果也好，reward model 给信号时同样能正常收敛。大模型侧用 π0 + HG-DAgger + 人类 reward 的配置验证成功率：先做一个简单 SFT，SFT 后 pick & place 成功率 23% 、table cleanup 成功率 45% （字幕 28:19–28:23），再做策略学习后两者都达到更高成功率——讲者坦言「当时因为时间所限，这个实验没有完全做完」，但趋势已经 promising。

HG-DAgger 的配置下成功率本身没有意义（要保证收集的每条数据都成功），所以看的是人类干预步数：只有模型行为不符合预期时才干预，干预步数越少性能越高。训练全程人类干预步数呈下降趋势；buffer size 增长也越来越慢，说明模型接近收敛、不再需要更多数据。

多机与异构训练也做了验证：两台 Franka 分别做插插座与 peg insertion，两条成功率曲线都涨得很快、短时间内收敛；异构侧一台 Franka（较稳定）加一台方舟无限机械臂（造价便宜），做按按钮任务，也在有限时间内收敛。

实验二：通信平面的跨域验证

实验 setting 把 master 节点放在北京（同时承担训练），机械臂与推理节点放在深圳。先验证穿越组网本身 work（京深两地确实可以训练），再对比集中式通信与分布式 data channel：跨域 setting 下，用 distributed channel 后，无论发送 observation 还是发送 action 的时间都大幅变短，使整个与环境交互的时间变为原来的 1/3 （字幕 32:55）。讲者还跑了同城对照：跨域与同城在数据发送时间上已达到几乎相近的数量级，证明推理与机器人节点确实走了本地网络。

实验三：异步的收益

同一实验里蓝线是异步流程、红线是同步流程：整个训练时间缩短到原来的 1/5 （字幕 34:09）。这个数字在两个 setting 上都成立——大模型 π0 + DAgger 与小模型 SAC，从同步改到异步，两次模型更新之间的间隔基本都是约 5 倍提升，与成功率曲线上的 1/5 提速正好对应。讲者的判断是：只要算法支持异步流程，「把整个训练流程改成异步，绝对是没有损失的」。

Q&A 要点

  • 异步会不会导致 policy drift？取决于算法：off-policy / DAgger 不受数据来源影响，不太会导致性能下降；on-policy 需要考虑新鲜度，原始实现同步更好，但 RLinf 主分支已集成异步 PPO，数据不太旧时好用。
  • 真机 RL 能否完全替代仿真 RL？讲者认为不能：仿真便宜太多（一张卡并行上千甚至上万环境），适合训基础的、common knowledge 式的技能；sim-to-real gap 靠真机 RL 做最后一步，把性能冲到接近 100% 。两者并存，真机 RL 是落地的最后一步。
  • 论文里用了几台机械臂？论文结果只用了 2 台（时间赶 + 实验室机械臂数量有限），现在已试过 3–4 台同时训练。扩展瓶颈不在通信（网线直连时通信不是主要瓶颈），而在各台机械臂 setup 不尽相同、收敛速度不一，能否同时收敛还需要实验。
  • 与 offline RL + sim-to-real 比样本效率有定量优势吗？讲者直言「事实上我觉得未必」。但 real RL 是目前看到能把落地成功率调到最高的方法——各种工作中能到接近 100% ；sim-to-real 只能缓解 gap，做不到 100% 。
  • 在线 RL 的 exploration cost 会不会让训练时间不可接受？「是的，这肯定是真机 RL 里面最主要的一个问题。」缓解角度：从成功率已经较高的 checkpoint 起步（奖励信号明确、exploration cost 小）、算法改进（off-policy / offline 技巧结合）、以及 USER 本身想做的事——把机械臂数量 scale 上去摊薄 cost。
  • 云边协同如何保证推理延迟？建议训练上云、推理放边端与机械臂实时交互；推理若只能上云，latency 要靠各种 trick，不是 USER 关注的重点。
  • 灾难性遗忘？「目前还没有探索到这一步」，真机 RL 还没发展到考虑环境分布变化的阶段，落地场景更多是对单一场景 overfit。
  • 机器人到 100 / 1000 台时瓶颈在哪？调度、通信、数据聚合都会成为挑战，需要持续调试与硬件场地支持。
  • 不同任务能否共享 replay buffer？当前设计就是共享的、暂未区隔；区隔也简单，加个 label 即可。算法角度上，仿真多任务 RL 的经验是混在一起训就能训得很好，未必需要分开（讲者注明这是个人感受，不是严格结论）。
  • RL 更新会不会破坏 VLA 的语义泛化？讲者引了组里去年的工作（字幕作「what can RL brings for VLA」一类标题）：RL 相比 SFT 在行为泛化上好很多，对预训练获得的泛化能力有很大程度保留，「当时比较超乎我的认知」。
  • demonstration 数据与 rollout 数据如何区分？RLinf 的 RLPD 实现分两个 buffer：demo buffer 放预先采好的数据与训练过程中的人类遥操数据，replay buffer 放交互数据；不想区隔就直接去掉 demo buffer。目前还没特别支持不同的采样策略，真实场景有需要再酌情添加。

5可迁移

  • 「像使用 GPU 一样使用机器人」的抽象方式对 RL infra 是通用模板：把异构执行体（GPU、机械臂、仿真器）统一成带 label 的节点组 + 配置文件声明拓扑，env / rollout / actor 三组件解耦——这正是 LLM 侧 RL 框架（如 verl 的 resource pool）已经在做的分工，USER 把它推广到了物理执行体。
  • 异步化的前提是算法对数据新鲜度不敏感：off-policy / DAgger 可以直接把交互与训练解耦拿到 5 倍提速；on-policy 要异步就必须配策略版本隔离与新鲜度控制。这个判据在 LLM post-training 里同样成立（异步 PPO / off-policy 修正的取舍）。
  • buffer 的三层存储（内存 index + 磁盘全量 + 内存 cache）是 replay buffer 容量突破内存上限的标准解，cache 占比 $R$ 直接决定采样效率——做大规模 rollout 数据管理时可直接借用。
  • 权重同步的资源隔离：NCCL 通信会抢 SM 拖慢同卡推理，用 NCCL_MAX_CTAS 限制通信占用——这是 colocate 训练/推理时容易被忽略的卡顿来源。

6疑问 / 下一步

  • HG-DAgger + π0 的大模型实验未做完：策略学习后 pick & place 与 table cleanup 的最终成功率字幕未给，后续可从论文（arXiv:2602.07837）补齐。
  • 多机扩展的真正瓶颈被讲者定位在「各机 setup 与收敛速度不一致」，但 3–4 台之后的实验数据尚未给出；100+ 台时调度/聚合的解法仍开放。
  • 灾难性遗忘与环境分布变化在真机 RL 里尚无人探索——USER 的持久化 buffer 理论上能支持跨任务数据复用，但与遗忘问题的关系未展开。
  • 不同任务共享 replay buffer 目前是「混训即可」的经验判断，缺少真机上的对照实验。
