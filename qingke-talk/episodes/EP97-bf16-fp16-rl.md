## 一句话总结

RL 微调里 rollout 引擎与训练引擎算出的策略分布数值上并不相等，这个训练-推理不匹配会让策略梯度变有偏、还会留下部署差距；讲者团队的结论是病根不在算法而在 BF16 本身——它只有 7 位尾数，舍入误差随自回归步数累积放大。做法只是把 RL 微调的精度从 BF16 换回尾数 10 位的 FP16（配合框架标配的 loss scaling），mismatch 基本消失：最朴素的无偏策略梯度在 FP16 下就跑赢了 BF16 下所有重要性采样补丁，还省掉补丁所需的那次额外前向（约 25% 训练成本）。

## 核心

### 背景/问题：两个引擎，两个策略

按官网预告，本讲分四段：先讲 RL 为什么会出现训练-推理不匹配，再讲为什么 FP16 反而更一致，然后是效果验证与启发，最后 AMA。论文 §2 给出问题的形式化：现代 RL 框架为了效率，rollout 用高度优化的推理引擎（如 vLLM）采样，梯度计算用训练引擎（如 PyTorch FSDP / DeepSpeed），两者数学上应是同一个策略，数值上却不是。记训练策略为 $\pi$ 、推理策略为 $\mu$ ，目标本应是对 $\pi$ 求期望收益：

$$J(\theta) = E_{x \sim p_X}\left[ E_{y \sim \pi(\cdot|x,\theta)}[R(x,y)] \right]$$

但样本实际从 $\mu$ 采出，若直接套 REINFORCE 的梯度形式，得到的是有偏梯度，优化方向被系统性带偏（论文 Eq. 3）。第二个问题更隐蔽：**部署差距**——我们优化的是对训练引擎最优的参数 $\theta$ ，上线跑的却是推理引擎，两个引擎各自的最优参数并不重合，训练再好部署也会掉点（论文 Eq. 4）。已有的算法补丁都只修第一件事，修不了第二件。

### 现有补丁：重要性采样为什么不够

论文 §2.1 梳理补丁路线。用序列级重要性比率把期望从 $\mu$ 重加权回 $\pi$ ，可以得到无偏估计：

$$\nabla_{\theta} J_{\mathrm{pg-is}}(x) = E_{y \sim \mu(\cdot|x,\theta')}\left[ \frac{\pi(y|x,\theta)}{\mu(y|x,\theta')} \nabla_{\theta} \log \pi(y|x,\theta) \cdot A(x,y) \right]$$

但长序列上这个比率方差极大，于是有了截断（TIS，上限 $C$ ）与掩码（MIS，超限整条丢弃）两个拿偏差换方差的变体（论文 Eq. 6、Eq. 7），以及把它们嫁接进 GRPO 的 token 级 TIS（Yao et al.）与序列级 MIS（Liu et al.）实现。论文指出这类实现的两个硬伤：一是都要为算比率多跑一次前向，按反向约为前向 2 倍成本折算，约多花 25% 训练成本；二是部署差距原样保留——补丁只在训练期校正梯度，最终模型仍是为训练引擎优化的。工程对齐路线（手工对齐两端实现、FP32 lm_head、强制推理确定性）也被点名：要么不足以防崩，要么需要深领域知识逐框架定制、难泛化（论文 §2.2）。

### 根因：BF16 的尾数太短

论文 §3 是本讲的核心论证。FP16 与 BF16 同为 16 位，分法不同：FP16 是 5 位指数 + 10 位尾数，动态范围小（最大约 $6.6 \times 10^{4}$ ）；BF16 是 8 位指数 + 7 位尾数，范围与 FP32 相当（最大约 $3.4 \times 10^{38}$ ），代价是精度低。1 附近相邻可表示数的间隔，FP16 是 $1 + 2^{-10} \approx 1.000977$ ，BF16 是 $1 + 2^{-7} \approx 1.007812$ ——FP16 的尾数分辨率是 BF16 的 8 倍（论文 Table 1、§3.4）。

BF16 当年胜出靠的是免调 loss scaling 的省心：范围大、不易溢出，预训练里这是决定性优势。但在 RL 微调里，两个引擎的 kernel 实现、并行策略、MoE 的 top-k 专家选择等细节差异，会在 BF16 的粗尾数上产生不同的舍入结果，再沿自回归生成的成百上千个 token 累积， $\pi$ 与 $\mu$ 就此分叉。FP16 的细尾数相当于给实现差异留了吸收垫：两端输出更可能数值一致，误差不累积。FP16 范围小的老问题则由 loss scaling 解决——这正是混合精度训练早期的标配技术（动态 loss scaling 自动升降缩放因子），PyTorch、Megatron、DeepSpeed 都内置，开启只需一处配置（论文 §3.2）。讲者团队的判断可以压缩成一句：**RL 微调阶段权重与激活的数值范围已由预训练定型，BF16 的大范围用不上，它牺牲掉的精度反而成了主导矛盾**（论文 §3.4、§6）。

离线分析先验证了这个归因（论文 §3.5）：在 DeepSeek-R1-Distill-Qwen-1.5B 上，三种精度纯推理的分数基本相当（AMC23 8K 下 BF16 50.38 / FP16 50.60 / FP32 51.54；AIME24 32K 下 29.90 / 30.94 / 28.44），说明精度本身不直接涨推理分；但序列级对数概率比 $\frac{\pi(y|x)}{\mu(y|x)}$ 的分布显示，BF16 的不匹配随生成变长指数级恶化，FP16 把它压到约 24 分之一（论文 Fig. 2）。

### 验证一：sanity test——先造一个「算法理应满分」的考场

论文 §4 提出一个方法论贡献：sanity test。从 MATH 中筛出初始模型准确率在 20%–80% 之间的题目（太易浪费算力、太难分不清是算法错还是模型不行），得到 1460 道「可解但不平凡」的 perfectible 数据集，判据是可靠的 RL 算法应能把训练准确率推到 95% 以上。在 VeRL 与 Oat 两个框架、R1-Distill-1.5B 上的结果（论文 §4.2、Fig. 3）：

- BF16 + 原版 GRPO（Dr.GRPO 变体）：早期崩溃，峰值训练准确率仅 73%（VeRL）/ 84%（Oat）；
- BF16 + token 级 TIS：多撑一阵，最终仍崩，峰值 82% / 88%；
- BF16 + GSPO：比 token-TIS 更稳，但 VeRL 实验里 1200 步后梯度范数变 NaN；
- BF16 + 序列级 MIS：唯一不崩的补丁，但收敛慢，且峰值训练准确率 95%、AIME24 34%，明显低于 FP16——这就是部署差距的实测形态；
- FP16 + 最朴素的无偏策略梯度（Eq. 5，不带任何补丁）：训练准确率 99%、AIME24 39%，跑赢 BF16 下全部补丁。

论文 §4.3 还有一个值得注意的现象：换到 FP16 后，各算法之间的表现差异几乎消失——mismatch 被压下去之后，优化问题近似回到 on-policy，复杂校正就没有额外收益了。训练动态里还有一个可作监控信号的规律：将崩的 run 在崩之前 mismatch 会先持续放大（论文 §4.2），这为 RL 训练加了一个廉价的早期预警指标。

### 验证二：精度消融与跨场景泛化

精度组合消融（论文 §4.4，VeRL + vLLM + FSDP）回答了「到底哪端要高精度」：BF16 训练时把推理端精度往上提能延长稳定期，配 FP32 推理甚至完全不崩——但 FP32 推理慢约 3 倍，不可用；训练与推理同用 FP16 时 mismatch 最低、训练最稳，perfectible 集上接近 100% 训练准确率且不损失速度。

跨场景验证（论文 §5）覆盖四类设置，结论一致：MoE（Qwen3-30B-A3B-Base，三种算法）FP16 更稳、训练与验证分数更高；LoRA（Qwen2.5-Math-1.5B，rank 32）BF16 约 600 步崩溃、FP16 全程稳定；大 dense 模型（Qwen3-14B-Base + DAPO）FP16 奖励涨得更快、AIME24 验证更高；换模型家族（OctoThinker-3B，自 Llama3.2-3B 中训而来）BF16 约 150 步后失稳、FP16 平稳训完。

### 结论/观点

- 论文的立场很克制：不宣称 FP16 普适最优。讨论部分明说效率方向可能走向 FP8，超大模型用 FP16 有溢出管理等工程挑战，但认为这些是可解问题；真正的主张是**社区应重新审视 RL 微调阶段的精度默认选项**，而不是把 BF16 从预训练一路惯性带下来（论文 §6、§7）。
- 对 BF16 下算法补丁的评价是一个偏差-方差权衡的诊断：低方差高偏差的方法（GRPO、token-TIS、GSPO）起步快但终局崩溃，低偏差高方差的方法（序列级 IS/MIS）稳但慢；FP16 同时压低两端，这个权衡随之失效（论文 §6）。换句话说，此前一部分「算法之争」其实是精度问题穿了算法的外衣。
- 提纲第 3 节标题里的「启发探讨」在论文中对应 §6 的两点：精度是训练栈的地基级选择，值得按训练阶段（预训练 vs RL 微调）分别定默认；以及 mismatch 指标本身可作训练健康度的先行指标。讲者现场如何展开这一节、AMA 问了什么，无书面材料，本纪要不代拟。

## 可迁移

- **自建或改 RL 训练栈时，精度是比算法补丁更先该动的一格**（直接可试）：在 verl 类框架里把 rollout 与训练两端统一切 FP16（训练端记得开框架标配的动态 loss scaling），先测 mismatch 指标与崩溃步数，再决定要不要上 TIS/MIS 类补丁——论文口径下这能省掉约 25% 的额外前向成本，且同时关掉部署差距这一补丁修不了的洞。MoE 的 top-k 专家选择等精度敏感算子切换前先小规模实测溢出。
- **把训练-推理 mismatch 做成训练看板的先行指标**（Infra 视角）：序列级对数概率比的分布、两端 policy difference 的极值，都是论文实测中先于崩溃发散的量；比起盯 reward 曲线事后救火，这类指标能在 run 早期给出「这个配置要崩」的信号，适合做自动 kill/告警与配置回归测试的判据。
- **sanity test 是现成的框架回归测试模板**（评测自动化）：用一批「当前模型可解但不平凡」（初始准确率 20%–80%）的小数据集作算法/框架改动的验收集，判据明确（理应冲到 95%+），比在真实混合难度数据上看曲线涨跌更能隔离出实现与算法的问题；改精度、换 rollout 引擎、升级框架版本时都可以先过这一关。
