两位讲者用两篇早期探索回答同一个问题——推理模型的 test-time 算力还能怎么 scale：TinyZero 先证明「基座能力与任务难度要同步下调」时，3B 模型、约 \$30 就能在 Countdown 上复现长思维链的涌现；而 APR 进一步把串行长 CoT 拆成可端到端学习的并行搜索：给模型 Spawn/Join 两个类似操作系统线程的原语，先用符号求解器的演示做监督初始化、再用 GRPO 端到端优化何时并行、开多少线程，在 200M 小模型上以不到串行基线一半的算力追平其 pass@8，并诚实地指出当前 RL 的增益主要来自「测试时用更多算力」，而非同等算力下更聪明的决策。

3核心

背景：两条新 scaling law 与一个未解的问题

第一位讲者先立坐标：预训练 scaling law 已在对数坐标上走了近十个数量级，经济与工程上都越来越难（GPT-4 这一代已停滞近两年）；推理模型打开了两条刚起步的新曲线——train-time compute（RL 投入越多、性能近似 log-linear 提升）与 test-time compute（推理时算力越多、回答越好）。o1 只给了结论没给方法，DeepSeek R1-Zero 才把配方公开：强 base model + RL + rule-based reward，长 CoT 与「aha moment」（自我反思、回溯）自然涌现，RL 步数从 0 到 8000 的过程中精度与每回答 token 数同步爬升。她的问题是：如果想在学术规模上研究这套训练科学，怎么把 R1-Zero 的门槛降下来。

TinyZero：最小化实现的关键是任务与模型同步降配

TinyZero 的定位是推理模型的最小化实现：不用 671B 的 V3 base（讲者引业界对 R1 训练成本的估算为 10 万到 100 万美元），而是用 3B 模型、约 \$30 成本（约租 10 小时 H200）在 Countdown 任务上复现核心现象——给几个数字（如 19、30、6、55、7）和一个目标数（65），让模型拼出算式；GRPO 训练约 100 步后，模型自发出现先试一个公式、不对再换一个的搜索与回溯行为。

核心观察有二：

  1. 涌现需要基座能力门槛。在 Qwen2.5 家族上做规模消融：0.5B 只学会输出格式、拿约 0.1 的格式分就直接给答案；1.5B 起 RL 才能持续涨分并逐步演化出复杂思维链，3B/7B 更明显。所以在 3B 上做 R1 的原始任务不会有涌现，但同时降低任务复杂度，涌现性质就回来了——这正是最小化实现能成立、便于快速实验迭代的原因。她引 John Schulman 在 MIT 演讲《Don't Teach, Incentivize》的观点互相印证：RL 能激发什么能力，取决于模型大小能否 pick up 那些启发式模式。
  2. RL 自己找策略。不同任务上模型学到的 test-time compute 用法不同：Countdown 上是逐个试候选式子，复杂乘法上是学会用结合律/分配律把式子拆小——不需要人告诉它怎么做。

下一步的判断：推理模型的训练科学（RL 算法、数据配比）远未定型；RL 框架与基础设施仍欠缺（TinyZero 借用 verl）；多轮工具使用、更多训练环境、从易验证任务走向难验证任务（创意写作类）是明确方向；以及——长 CoT 只是 test-time 算力的一个维度，还有没有别的维度。这直接引出 APR。

APR：把串行搜索树拆成可学习的并行线程

第二位讲者的问题设定：长 CoT 是串行的，动辄数万 token（举例 Claude 3.7 Sonnet thinking 支持 32K 思维链），延迟高且 context window 永远有上限。自一致性、best-of-n、树搜索等 test-time 并行方法都是推理时拼凑的：各路径互不协调、冗余计算多、没有端到端优化。APR（Adaptive Parallel Reasoning）要让模型端到端学会自适应编排串行与并行。

方法分三层：

  1. 视角：推理是一棵中间步骤构成的搜索树（沿用 Countdown 上的 Stream of Search 范式，CoLM 2024 oral）；串行 CoT 只是把整棵树序列化展开，于是又长又慢，甚至窗口耗尽还找不到答案。
  2. 原语：借操作系统多线程概念引入 Spawn 与 Join。模型在需要时生成子线程：主线程把一段上下文（一条待探索路径的状态）传给每个子线程，子线程只看这部分、彼此独立地用同一个语言模型并行搜索；找到解的子线程通过 Join 把这条简洁的成功路径返回主线程，失败子线程不返回任何内容。主线程最终上下文里只多出「发起点之前的内容 + 成功路径」，大量并行计算被折叠掉，既省窗口又降延迟。子线程可多次发起、无人为障碍（Q&A 确认）。
  3. 训练两阶段：先 监督初始化——在 Countdown 上从零预训练一个 200M 的小模型，用符号求解器合成两类演示：串行版（讲者称 SoS+，对原始 Stream of Search 的改进版）与带 Spawn/Join 的并行混合演示；同时训练条件化变体（给 token 预算条件或子线程数条件），以便做计算量控制变量实验。再 GRPO 端到端 RL：在监督检查点上以最终答案对错的 0/1 outcome reward（RLVR）继续优化，让模型自己学「何时串行、何时并行、开多少线程」；Q&A 确认这是多智能体式的联合优化——主线程与所有子线程一起做 RL，而非只训主线程。

实验：并行的收益能拆成哪几块

  • 随算力扩展：APR 在低算力区（约 2 条子线程）反而略差，讲者归因于「并行性开销」——Spawn/Join 等协调原语本身要生成 token、不直接参与搜索；算力升到 8000 量级后优势显著：用不到串行基线一半的计算量，就达到 SoS+ 做 8 次采样（pass@8 量级）的水平，同等算力下精度增幅很大。串行基线则被 4096 的 context window 卡死，自一致性/pass@n 能涨但幅度有限。
  • 随窗口扩展：在每一种 context window 限制下 APR 都优于 SoS——并行把总计算量摊到多条线程各自的窗口里，串行基线必须把整条搜索路径塞进一个窗口。
  • RL 的真实作用（讲者最坦白的消融）：RL 之后精度、总计算量、子线程数全面上升；但当子线程数条件固定在最高档（10 条）时，RL 带来的增益很小。结论原话：RL 的提升「主要是源于它让 supervised training 的 checkpoint 用了更多的在测试时用了更多的计算资源，而并没有让他在相同计算资源的时候做出了多么更优化的更好的决策」（字幕 48:30–48:52）——让 RL 真正搜得更聪明而非只是搜得更多，是他明说的待解问题。
  • 延迟实测：理论指标用「最长不可并行段」（所有路径中必须串行执行的最长部分）估计延迟下界；真实部署测在 8×A6000 上（主线程占 1 卡、子线程分到其余卡，模拟 API 服务式并行），基于 SGLang 引擎、未做 KV cache 共享等专门优化；在约 5000 ms 的延迟下成功率大幅提高（具体百分比字幕识别不清，本纪要不收录）。

Q&A 要点

  • RL 是激发还是赋予能力：讲者明确站乐观派——pass@k 在 k 极大时趋同是概率模型的必然（pass@∞ 本来就是 100%），RL 把原本 pass@1000 甚至 pass@1000 万才出现的东西提前到一次采样里，这就是能力提升；且 TinyZero 的规模消融与 SoS 作者后续关于 Llama/Qwen 基座差异的工作（Qwen 预训练里见过带 verification 结构的数据，Llama 微调补上后 RL 增益同样可观）都证明增益强依赖基座。
  • 难验证任务怎么办：两条路——只在数学/代码上训、期待泛化（R1 已有初步迹象，但与 in-distribution 训练有明确 gap）；或回归 reward model，且看好 generative reward model（让模型先 CoT 再打分）的大规模回归。
  • 简单问题省算力：本工作未做，但给现成菜单——reward 里加长度惩罚、模型自学会少想、用 length condition 前缀给预算（他们试过效果很好），或外挂分类器给简单题开低预算。
  • PRM：讲者直接表态不看好，「用 PRM 跟 PPO 里面用个 value function 差不多」。
  • 公平性：APR 与 SoS 两边模型 context window 都是 4096 且相同（子线线程各自一个同样的 4096 窗口），对比无窗口作弊；实验在 paper 中可查（talk 当天正 release）。
  • 对下一步的猜测：工具使用（代码解释器、搜索）接入长 CoT 是确定方向（o3 路线）；并行化这种范式要等长 CoT 的延迟不可忍受时才会成为主流，他们先占位探索。

5可迁移

  • 对推理/RL 实验设计的直接清单：小规模复现大现象时，任务难度要与模型规模同步下调（TinyZero 的方法论）；任何「RL 带来提升」的结论都应配一条固定 test-time 算力的消融，否则分不清是搜得更聪明还是搜得更多（APR 的自拆台消融）。
  • Infra 视角的启发：APR 的 Spawn/Join 本质是把 test-time compute 从「单序列长度」扩展到「序列数 × 长度」的二维预算，且只有成功的子线程回写主上下文——这与 rollout 侧的并行采样、部分结果回收是同一种资源观；在推理引擎层他们直接站在 SGLang 上测延迟，fork/join 的 KV 前缀共享是他们明说还没做、留给 infra 的优化点。
  • 奖励设计菜单（难验证任务）：generative reward model 回归论 + 长度惩罚/length condition 的预算控制，都是可以先在小实验里试的低成本项。

6疑问 / 下一步

  • APR 只在 Countdown 单任务、200M 从零训练的小模型上验证；迁移到预训练大模型与通用任务、以及减少对符号求解器合成演示的依赖（讲者的下一步清单），是这条线能否成立的关键，待 paper 与后续工作确认。
  • 子线程数超过 10 条后的曲线、以及更丰富的线程间通信范式（讲者提了 auction、p2p 等设想）都未探索。
  • 讲者预告 APR paper 在 talk 当天/次日 release，本纪要未收录链接；待公开后应回补论文出处与延迟实验的准确百分比。
