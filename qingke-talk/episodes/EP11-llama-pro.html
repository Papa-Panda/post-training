2一句话总结

针对「继续预训练学领域就掉通用能力」的 trade-off，LLaMA Pro 的解法是结构上隔离：把原模型分成若干组、每组恒等复制新增一个 block（输出侧投影清零使新块初始为 identity）、冻结全部原始参数、只在纯领域语料上训练新增块。这样新增容量专门装领域知识、主干通用能力原样冻结，Llama2-7B 只用 80B token 就在代码/数学上超过用 500B token 的 Code Llama，同时通用能力几乎不掉。

问题：继续预训练的两难

通用模型（Llama、Mistral）直接在代码/数学上推理效果不好；在领域语料上继续训练（Code Llama 路线）则通用能力下降。散点图上横轴领域性能、纵轴通用性能，两类模型各占一端。从数据侧出发、构造通用+领域平衡数据集 from scratch 预训练（CrystalCoder 路线）可以绕开，但计算成本大，而且构造数据集时无法预知未来会关心哪些新领域（生物医药、法律都可能后到），所以「怎么在继续训练阶段既保通用又涨领域、还省算力」才是真问题。

方法：恒等块扩展（block expansion）

三步：

  1. 分组复制：把原模型 block 分成 $N$ 组，每组复制其中一个 block 插入，得到新增层；
  2. 恒等初始化：把新块中 attention 的 output projection 与 FFN 的 down projection 清零，两个模块的输出都为零，只剩残差流通过，新块初始即 identity——扩展前后同一输入的输出严格一致，起点不掉点；
  3. 冻结主干：原始参数全部冻结，只训练新增块。

为什么清零点选在输出侧而不是 norm 侧，讲者给了梯度推导：若把两个模块前的 norm 权重清零，进入模块的 hidden state 为零，经 SwiGLU 后激活对 norm 权重的梯度恒为零，梯度消失、块根本训不动；输出侧清零借鉴 adapter 的做法，梯度不消失。附带的好处是即插即用：主干冻结不变，代码领域训出的新增块可以整组丢掉、换法律数据重训一组，同一 backbone 服务多领域。

为什么不用 LoRA 这类层内 PEFT：讲者的判断是容量问题。LoRA 大约只动 1% 参数，在新领域语料上很难真正学进知识；后面的法律语料消融里，LoRA 把 rank 拉到 1024（与新增块参数量相近）仍明显学不动。加深层数则直接给模型新增容量，loss 能压得更低、scaling 曲线更陡。

训练流程与 SFT 衔接

  • 主实验：Llama2-7B（32 层）分 8 组、每组 +1 块 → 40 层、7B → 8.3B 参数；
  • 继续预训练数据：Proof-Pile-2 与 The Stack 的 Python 子集，共 80B token，刻意不混通用数据做平衡——讲者把「保通用」的责任完全交给冻结+恒等初始化的结构，而不是数据配比；
  • 指令微调阶段改为全参数微调：目的是让扩展出的模型无缝接入标准 SFT 及后续 pipeline，不需要用户指定哪些是新增层这类 ad hoc 操作。SFT 数据含 ShareGPT 多轮对话、MetaMath、Evol-CodeAlpaca 等（约 80M token，论文口径）；
  • 部署无特殊要求：架构本身没变（只是层数变多），vLLM 等推理框架无缝兼容。

结果

  • GSM8K、HumanEval 上显著超过 Llama2 与 Code Llama，通用基准（Open LLM Leaderboard 一组）相对 Llama2 几乎不掉，预训练版与 SFT 版结论一致；
  • 需要「通用+领域」结合能力的基准上优势更明显：MT-Bench 综合对话胜过对应 Llama/Code Llama 版本；MINT-Bench（字幕作 mind/my bench，多轮对话+工具使用）与 Mistral-Instruct 打平。讲者给的 case 里 Llama2-7B 在需要按指定格式输出并调用程序执行的题目上失败，LLaMA Pro 能完成；
  • 分布漂移探针：让 Llama2 生成文本、逐 token 比对两模型预测，92.6% 的 token 是 top-1 一致（unshifted），仅 0.7% 连 top-3 都不匹配（shifted，多为 for 循环、数学符号等关键操作 token）——量化说明主干的语言分布基本没被动过。

消融：层数、LoRA 对照与「真学到了吗」

  • 法律语料上的 scaling 分析对比 LoRA/adapter/MoE：新增块越多 loss 越低；LoRA 在通用保持上最好，但法律 benchmark 比 LLaMA Pro 低约 10 个点（rank 1024、近参数量对照）。+8 层是在通用/领域平衡下选定的默认设置；
  • 知识注入验证（借 LIMA 的直觉：SFT 主要是激发、知识在预训练阶段编码）：用同一份指令数据分别对 Llama2-7B 与 LLaMA Pro 做 SFT，后者各项仍更好，说明继续预训练确实把新知识写进了新增块，而不是 SFT 阶段的激发差异；
  • 同样的方法在 Mistral 上复现也能在保通用的同时提升代码/数学（字幕口径，具体对照模型名识别不确）。

Q&A 要点

  • 与 SOLAR、深度扩展类工作（字幕作「E9B」）的区别：那两家没有清零操作，扩展后初始测 benchmark 是掉点的；LLaMA Pro 靠恒等初始化保证起点不掉。两家在「复制哪些层」上有系统研究（按层输入输出余弦相似度选层），且共识是头尾不动、只动中间——讲者承认自家当初的分组复制位置没做实验，这是可结合的改进点；
  • 加 16 层为何反而变差：低资源设定下训练不充分；数据量与新增层数如何匹配的 scaling law 没做，是他自己点名的开放问题；
  • 资源边界坦白：全部实验只在 7B 上做（当时只有 16 张 H800）；更大模型按比例扩 25%–50% 层数是他的估计（本工作 25%，SOLAR 类 50%），未实测；
  • 显存：比全量微调省（只有新增块有梯度与优化器状态），比常规小 rank LoRA 贵；LoRA rank 拉到 1024 时两者显存差不多；
  • 继续预训练要不要混 10% 通用数据：没做过实验。他的看法是关键在数据是否已被 backbone 见过——见过的数据重复预训练可能导致 memorization 问题；没见过的高质量新数据则按 scaling law 应该有益。

5可迁移

  • 防遗忘的两种路线之争：业界默认靠数据配比（领域数据里掺通用数据）防遗忘，LLaMA Pro 给出结构路线——冻结主干 + 恒等初始化新容量。做领域继续预训练/post-training 时值得先问：遗忘到底来自参数被改写，还是数据分布偏移？前者用结构隔离更便宜、更可组合。
  • 恒等初始化的一般原则：任何「往已训好模型里插新模块」的方案（adapter、新增层、side network），起点应先保证函数不变（输出侧清零），再谈训练；norm 侧清零会梯度消失这个坑有明确的推导证明，不必再踩。
  • 低成本遗忘探针：用原模型生成文本、统计新旧模型 top-1/top-3 token 一致率，比跑全套通用 benchmark 便宜得多，可做继续预训练每步的漂移监控。
  • 「激发 vs 学到」的对照实验：同一份 SFT 数据训 base 与继续预训练后的模型，是区分「知识真注入了」与「SFT 把已有知识激发出来」的干净消融，评估任何 continued pretraining 收益时都可复用。

6疑问 / 下一步

  • 数据量 ↔ 新增层数的 scaling law 缺失：多少 token 配多少新增层最划算，讲者明确没做；+16 层变差只是用「训练不充分」解释，未给曲线。
  • 只在 7B 验证：更大模型上冻结主干的收益/代价、以及 25%–50% 扩展比例的说法都是外推。
  • 复制位置的选择无自家实验，借用的是 SOLAR 类工作的余弦相似度判据与「头尾不动」经验，能否与恒等初始化叠加增益未验证。
  • Q&A 中被问到 PiSSA（本系列 EP10 的主题，SVD 主成分初始化）时讲者表示没看过——两条初始化哲学（恒等/零初始化保起点 vs 主成分初始化加速收敛）正好对照，后续可比读。
