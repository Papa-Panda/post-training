2一句话总结

受 DeepSeek-R1 启发，讲者团队把"只给问题、只给 0/1 结果奖励"的 rule-based RL 直接搬到 VLA 上：策略就是 OpenVLA-OFT，轨迹级二元奖励广播到每个 action token 做组内相对优势（GRPO 系），再加三件探索设计（升温采样、动态采样过滤、调高 clip 上限）。结果是仿真是本已很高的 LIBERO 仍从 91 提到 99、RoboTwin 从约 40 提到 70，只用 2% 演示数据（每任务 1 条轨迹）加 RL 能反超全量数据 SFT（50→96）；且全程只在仿真训练、零真机数据，真机成功率仍从 17% 涨到 38.5%。

背景/问题：VLA 的模仿学习困在数据上

VLA 的主流范式是遥操收集数据 + SFT 模仿学习，有两个病灶（讲者举例：锅的位置因食物分量不同而偏低，SFT 训出的铲子只会在空气里挥舞）：① 空间理解不足——只学到"看到这个画面就挥铲子"，没理解为什么；② 泛化差——换锅的颜色、食物、背景，任务就可能完全失败。根源是模仿学习严重依赖数据多样性，而机器人数据极度稀缺：讲者对比了数据规模量级——π0 的数据比 GPT-2 少约 50 倍，GPT-2 又比 Llama-3 少约 2000 倍（字幕口径）；遥操要专业人员一对一带设备演示，难以 scale。讲者的解法不是继续降数据成本，而是换学习方式：像 R1 那样让模型自己交互、自己采数据，只给最简单的 0/1 结果奖励——RL 恰好同时治"要人遥操"和"泛化差"两个痛点。

方法/设计：简单到刻意与 R1 同构

算法流程就是 GRPO 的原样移植：

  1. Rollout：在 GPU 上并行开 8 个仿真环境（组大小 8），同一初始状态出发，OpenVLA-OFT（Llama-2 主干 + 视觉编码器 + 动作头）按温度采样生成 action token，环境执行、状态更新，单任务最多 200 步，超时判失败。
  2. 奖励：轨迹成功则整条轨迹每个 action token 奖励为 1，失败全为 0——轨迹级二元奖励直接广播成 token 级奖励。
  3. 更新：组内算相对优势，做 GRPO 式更新。讲者强调"simple"就是刻意不引入过程奖励、不手写 reward 函数：所有任务都有成功/失败标准，省掉逐任务 reward 工程（手写 reward 单个任务不难，但多任务持续扩展时工程量不可承受）。

三个探索导向的小设计（讲者明确点名）：

  • 采样温度从 1.0 提到 1.6 ，效果明显上升；
  • 动态采样（dynamic sampling）：过滤全对/全错的无梯度组，直到收集到的都是有对有错的组；
  • 调高 clip 上限（字幕口径：区间由 0.8–1.2 改到上限 1.3），鼓励给低概率动作更多提升空间。

框架建在 verl 之上二次开发：继承其 HybridFlow 通信与训练框架，新增多仿真环境并行采样与交互式生成，从"训练+推理"变成"训练+推理+渲染"一体。训练配置口径：7B 的 OpenVLA-OFT 用 8 张 A800/A100 可训。

实验/实战：关键数字（字幕口径）

  • 仿真主结果：LIBERO 从 91 提到 99（基线已很高的情况下基本拉满）；RoboTwin 1.0 从 40 提到 70，2.0（按任务长度分短/中/长程）总体同样 40→70。讲者诚实标注：任务越长，仅靠结果奖励的提升幅度越低。
  • 真机 sim-to-real：全程零真机数据——仿真收集 1000 条轨迹做单任务 SFT，再在 1000 个场景中做 RL；部署到松灵 Piper 双臂平台实测：SFT 模型真机成功率约 17% ，RL 后 38.5% ，超过 RDT 基线的约 23.5% （而 SFT 起点本身还不如 RDT）。另有一组未上 slide 的实验：每任务仅 20 条真机数据 SFT，效果与 1000 条仿真轨迹相当，仿真 RL 的最终效果甚至更好。
  • 数据效率：LIBERO-Long 上模拟数据稀缺——每任务只用 1 条轨迹（总量 2%）做 SFT，再加 RL： 50 → 96 ，反超用全部 500 条轨迹 SFT 的效果。
  • 泛化对比：留一任务设定（9 个任务训练、1 个未见任务测试）：继续 SFT 会灾难性遗忘到成功率 0，RL 则未见任务性能不降甚至略升。
  • RL 何时失败：讲者给出明确判据——上限由初始模型能力决定，不由数据量或训练时长决定。0 条轨迹的 base 模型在 RoboTwin 五个任务上成功率全为 0，RL 提升也是 0（roll 不出成功轨迹就无从学起）；100 条轨迹 SFT 的弱模型 7.3 → 25.4（+18.1），1000 条的强模型 28.2 → 50——初始越强，RL 后上限越高。

行为涌现：探索"意外"学到的推送策略

Case study：演示数据里"把罐子放到锅旁"从来都是先抓起再移动，但 RL 训练中模型偶尔没抓准、把罐子碰着推了过去，任务照样完成、奖励同为 1，于是"推"这个演示数据之外的策略被学了下来。讲者强调机制不黑箱：温度采样产生多样轨迹 + 二元奖励不区分完成方式 = 探索能发现演示外解法。但也有边界：SFT 数据越多、模型越"记住"标准动作，探索性越低、越不涌现；且当前 base（OpenVLA-OFT）能力弱，只出现"推"这类低级泛化，更高级的涌现要等更强的 base model。

结论/观点（区分事实与判断）

  • 事实：上述成功率变化、数据效率与泛化对比均为字幕口径的实验陈述。
  • 判断（讲者立场）：① 仿真中大规模 RL 再迁移真机是可行路径——真机 RL 的真瓶颈是采样效率（并行 8 个环境只要多开进程，真机并行 100 台机械臂不现实）；② RL 不会无限训下去：持续 online RL 会收敛在约 60%–70%，瓶颈不在"某些 seed 永远采不到成功"（实测几乎所有 seed 都采出过成功 case），更像是模型容量与轨迹质量问题，"某种程度上仍是黑箱"；③ 过程奖励不是必需，结果奖励"优化起来其实还好"。

Q&A 要点

  • Diffusion 动作头怎么做 RL：论文版没做，但团队已在对 π0.5（flow matching 动作头）做：难点是 ODE 过程除初始噪声外无随机性、log-prob 是常数没有梯度；解法照 Flow-GRPO，把 ODE 改成 SDE、每步加高斯噪声， log-prob 即该正态密度，均值是模型输出的速度场。talk 时代码已写完、实验在跑，尚未推送，之后会更新到框架。
  • 交互式/迭代 RL（SFT→RL→再 SFT 交替，如 RL-100）：可以用且有持续提升价值；逆强化学习（IRL）在 VLA 领域目前没人做，但讲者认为值得试（反推出的稠密过程奖励正对长程任务的胃口）。
  • 温度调大不会格式崩坏：VLA 只生成 256 个 action token 中的采样，格式被天然锁死；动作不合理只会换来 0 奖励被压低概率。
  • 同步 rollout 的等待成本：同步训练下先完成的 episode 要等未完成的；但任务步数上限 200、多数 140–160 步完成，等待不久。
  • 效率瓶颈：rollout 的仿真渲染——A100 上 GPU 光追/渲染效率不如 4090，大部分时间花在渲染而非训练。
  • 没有机械臂能不能发论文：纯仿真可发 ICLR/ICML 类会议；机器人浓度高的会议（如 RSS 一类）通常要求真机实验。
  • 同步 vs 异步框架的计划：后续会补 PPO、离线 RL 等算法支持。

5可迁移

  • 对 coding data / RL infra 工作的 1-2 个直接可试的点：
  • "初始能力决定 RL 上限"值得当体检项：开 RL 前先测 base 在目标任务的非零成功率分布；roll 不出成功轨迹的任务，加数据量、加训练时长都没用，先补 SFT 把能力垫到能偶尔成功。
  • 二元轨迹奖励广播到 token 级 + 组内相对优势是长程稀疏奖励下最省工程的基线：先证明结果奖励能学动，再考虑过程奖励的增量价值——讲者的长程退化曲线（任务越长、结果奖励提升越低）正好给出"何时该上过程奖励"的经验判据。
  • Infra 视角（扩展性 / 成本 / 评测自动化）的启发：具身 RL 的 rollout 瓶颈不在训练而在渲染吞吐，且同步训练的等待被任务步数上限天然收敛——对照 LLM 侧的长尾 straggler 问题，具身侧用"步数上限 + 同步屏障"的简单组合就把问题压住了，代价是截断长任务的学习信号。
