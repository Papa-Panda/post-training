2一句话总结

MLA 把计算强度精心压在 H100 的 roofline 拐点上，但换到算力被砍的 H20、开 MTP 多 token 解码或开 tensor parallel 时就会掉进算力瓶颈；GQLA 的改动只有一处——压缩后的 latent 表示还原时不还原成 MHA 形态、而是还原成 GQA 形态——于是同一个权重可以等价地在「省显存的 MQA 吸收形态」与「省计算的 GQA 形态」之间自由切换，再配一套把市面 GQA / MLA 模型低损转成 GQLA 的转换方法（相似度分组 + 损失感知低秩压缩 + RoPE 位置信息分离），做到不从头训练、按硬件选形态。

3核心

为什么只盯着显存与带宽：roofline 视角

讲者先立坐标系。LLM 推理分 prefill（并行处理整段输入，计算瓶颈）与 decode（逐 token 生成，每步要把全部历史 KV 调出来，访存瓶颈）两阶段；KV cache 必须存下来，FlashAttention 只能压计算过程中的显存、压不掉 KV cache 本身。过去约 20 年里 GPU 浮点算力涨了约 1 万倍、带宽涨了不到 100 倍（字幕），所以优化的主战场是访存。用「算力除以带宽」得到计算强度，即每搬一个字节要做多少次浮点运算；把模型的计算强度标在 roofline 图上，就能看它先撞带宽墙还是算力墙。MHA 的 KV 太多、先撞带宽墙；GQA 靠多 query 头共享 KV 头缓解；MLA 进一步把 KV 压成一个低维 latent 表示，训练时还原成 MHA 形态保证表达力，推理时把升维矩阵吸收进 query、退化成 MQA 形态省显存——两种形态等价切换，是 MLA 的关键。

MLA 在 DeepSeek V2 / V3 的典型配置下（字幕口径：128 个头、latent 维度 512、每头 128 维、RoPE 部分 64 维），计算强度约 242 ，恰好压在 H100 约 295 的拐点下方（字幕）。问题是「压得太准」：硬件一变，拐点就变。

MLA 的三个不适配：H20、MTP、TP

讲者列了 MLA 的三处硬伤。第一，H20 这类卡带宽与 H100 相近、算力被砍约 7 倍、拐点只剩约 37（字幕），MLA 吸收形态把每头维度从 128 撑到 576 ，计算量翻数倍，直接撞算力墙。第二，开 MTP / 投机并行解码时，几个 token 的访存几乎不变、计算量翻几倍，MLA 在 H100 上理论 2 倍加速缩到约 1.2 倍（字幕）。第三，tensor parallel 按头切分时，每个头都要用一份完整 latent 表示，切得越多、MLA 省显存的优势越消失，而 GQA 的每组 KV 独立、天然适配 TP。

GQLA：还原成 GQA 形态，多一条推理路径

GQLA 的改动被讲者称为「非常简单」：latent 表示升维还原时，不还原到与 query 同样多的头，而是还原成更少的 KV 头（即 GQA 形态）。训练好的同一个模型因此有两条等价推理路径：强算力卡用吸收后的 MQA 形态（与 MLA 在 H100 上完全重叠、同样压住拐点），算力受限卡用 GQA 形态（计算强度与 GQA 一致）。以 H20 实测口径，GQLA 用 GQA 形态比 MLA 吸收形态快约 3.4 倍（字幕）。配置上讲者推荐 128 个 query 头、8 个 KV 头、并行解码 2 个 token（字幕作「128 / 8 / MTP 开 2」），理由是还原的头越多、表达力保持越好；代价是 GQA 形态比原生 GQA 多了 RoPE 维度（64 维 RoPE + 128 维 NoPE 共 192 维），计算与访存都略大、会慢一些，但多出的容量可经后训练转成能力——讲者举蚂蚁模型从 2.0 到 2.5 用很少 token、省约 15 倍训练开销而能力更强为例（字幕，Q&A 口径）。

转换方法一：头合并 + 相似度分组 + 损失感知压缩（MLA → GQLA）

从头训不可接受，所以要把已有模型转过来。第一步是「头合并」：把多个头拼成一个维度更大的头，用分块对角的 0/1 投影矩阵把每个 query 组只取回自己那份 KV，这一步严格等价；但合并后维度变大、计算强度虚高、显存没省，所以必须接着做低秩压缩，去掉头之间的冗余——压缩有损，目标是把损失压到能靠少量微调恢复。两个关键 trick：按 KV 头相似度分组（越相似的头压到一起损失越小），以及不用纯参数 SVD / PCA 、而用考虑全部 token 对最终 loss 影响的方式定压缩（字幕提及 Hessian 一类做法）。实验在 GLM 30B-A3B 与 DeepSeek 3.1 上做（字幕）：直接转会掉点，每加一个 trick 都有明显提升；讲者强调在大模型上不用这两个 trick「完全无法接受」。对提问「不压缩行不行」，讲者答得很明确：不压缩则计算量涨、缓存不变，任何卡上都没有速度收益，压缩是必需的。

转换方法二：跨过 RoPE 做压缩（GQA → GQLA）

GQA 转 GQLA 的难点是 RoPE：矩阵吸收要求中间不能有非线性 / 旋转操作，而 GQA 每个头每个维度都带位置编码。解法分三步。先是重排（字幕作「roll rope」）：利用「query 与 key 相乘对顺序不变」这一性质，把相同频率的维度聚到一起——同一频率内乘一个矩阵再乘其逆可以跨过 RoPE 做等价压缩，于是位置信息被集中到第一个头，其余维度去掉位置信息后与 NoPE 部分联合低秩压成 latent 。再是频率折叠：只按相同频率压缩时、高压缩率下损失反而大，把相邻频率一起折叠压缩，引入少量频率损失换更大的压缩损失下降，讲者给出经验点是约四个频率折叠成一个时效果最好（字幕）。最后是 KV 范数平衡：去掉位置信息后 K 与 V 的 norm 差异大、低秩分解会被大的一方主导，用 query 乘系数、key 乘其倒数（结果不变）把两者 norm 拉平。这条线的前身工作（字幕作 TransMLA）把 LLaMA 转 MLA 时，同期另一方法初始掉约 20 个点、他们只掉 1 点几个（字幕）；该方法已被蚂蚁 2.5T 模型采用把 GQA 转成 MLA（字幕）。

稀疏注意力：从 DSA 的 indexer 瓶颈到分层选择 HSA

后半讲换到 token 维度的稀疏。DeepSeek 的 DSA 逐 token 选 top-k 、粒度细、效果好，但 indexer 本身是 $O(N^2)$ 开销（字幕）：64K 上下文下 indexer 占 5.6 毫秒、真正打分只占 1.6 毫秒（字幕），长上下文里 indexer 成为瓶颈。讲者的 HSA 做两阶段分层选择：先按块粗选出重要块，再把入选块内的 token 汇到一起逐 token 精选出 top 2048 ；无论序列多长，后段都固定成「8K 选 2K」，对硬件优化友好。无训练直接套用时，HSA 选出的 token 与 DSA 逐 token 选出的重叠度短序列 90% 以上、长序列 85% 以上（字幕）；固定 8K 预算最高约 3.5 倍加速，88K 长度端到端比 FlashMLA 实现约 1.6 倍（字幕，讲者自陈对比实现未充分优化）；把 DeepSeek V3.2 的 DSA 无训练换成 HSA 能基本维持效果，GLM-5 上甚至略高（字幕），而纯 block 稀疏会掉很多。讲者也给了稀疏方法的表达力排序：同样 KV 开销下，静态稀疏弱于线性（低秩 memory）、弱于动态稀疏，所以他押注动态稀疏、并把 HSA 定位成 block 与 token 之间的平衡点。

Q&A 散点

  • compute-bound 就一定好吗：不是。需要的计算超出硬件能力很多倍时会被算力「蚌住」、速度不再提升；换 GQA 形态把算力降下来，带宽能力才被释放。
  • 与标准 GQA 的延迟差异：拐点位置相同，但 GQLA 多 RoPE 维度、单步计算访存略大而略慢，换来的是跨硬件适配与更强的可训练容量。
  • 转换的工程性：所有层可独立转换，大模型（如 600B 级）可用 offload 以很少显存完成，只是慢；逐层分布式会快很多但代码还没写。
  • 与 IndexCache 的区别：那是跨层复用同一份 token 选择；HSA 假设的是长文本里重要 token 成块连续出现，两者正交。
  • 国产卡：HSA 已适配、GQLA 未适配；讲者判断国产卡浮点不弱、主要卡在 HBM 带宽，可能反而适合 MQA 形态，但未实测。
  • 为什么不做线性模型：旗舰模型上效果优先于速度，动态稀疏表达力最强且其效率平衡还没做完，这是他当前押注。

5可迁移

  • 选注意力结构先算计算强度、再对目标硬件的 roofline 拐点：同一个权重在不同卡上该走吸收形态还是分组形态，是部署期可切换的决策，不必在训练期一次定死；做推理框架时把「形态切换」做成配置项，比为每种卡各训一个模型便宜得多。
  • 结构转换的通用配方可迁移到其他压缩任务：先找严格等价的变换（头合并、顺序重排），再把不可避免的有损压缩集中到一处，并用「按相似度分组 + 按 loss 影响定压缩方向」压损失——比直接 SVD / PCA 掉点小得多。
  • 稀疏注意力的 indexer 本身可能比 attention 更贵：长上下文优化要先测 indexer 占比；「粗筛成固定候选集再精选」把 $O(N^2)$ 选 token 变成常数规模精选，是可套到任何 top-k 选择模块上的分层套路。
