2一句话总结

长上下文推理里先撑爆的不是算力而是 KV cache；TriAttention 发现 RoPE 之前（pre-RoPE）的 Q/K 在绝大多数 attention head 上高度聚集，于是用离线校准的聚集中心作探针、提前预测每个位置的 K 将来会拿到多少 attention——这一近似展开后恰是一个三角级数打分函数，再混入按聚集度加权的 K 范数项兜底 retrieval head；最终在精度与 full attention 持平下做到 KV 显存约 1/10.7 、解码吞吐 2.5 倍，training-free、即插即用。

问题：上下文一长，先死的是 KV cache

长 CoT、long-horizon agent、长视频生成都在把上下文推长。讲者给了一个很具体的账：Qwen3-32B 跑在 RTX 5090（32GB 显存）上，权重先占约 18GB，只剩约 12GB 给 KV cache；16K–32K token 还够用，一旦到 64K、128K 就直接 OOM。KV cache 随上下文长度线性增长，显存而不是算力成为长推理的第一瓶颈。

压缩 KV cache 大体四条路线：量化、驱逐（直接删不重要的 KV）、表示压缩、架构级改进（GQA / MLA / linear attention）。本工作走驱逐路线，其核心难题只有一个：重要性打分函数怎么估准。推理是一条逻辑链，当前步可能依赖过去某个关键节点；重要性估错、提前删掉它，后面就会跑偏。

旧方法三派与观察派的反直觉瓶颈

  • 规则派（StreamingLLM 为代表）：观察到 attention sink 现象，强制保留开头几个 token + 最近窗口（如 2048），其余全删。简单粗暴。
  • 观察派（当前主流、性能最好）：拿最近若干个 query 与全部历史 K 做 attention，谁拿到的 attention score 高谁重要，如 R-KV。共同瓶颈是一个超参——观察窗用多少个 query。有工作（字幕作 easy eviction）发现用约 25 个 query 最好，太少太多了都不行。
  • 范数派：直接以 K 的模长作重要性分数，方法最少。

反直觉点在于：把 query 的 attention score 看作带噪声的观测，按理观测越多、估计越准，但实测是观察窗越大性能越差。讲者团队的可视化找到了原因：RoPE 让 Q/K 随位置持续旋转，旧 query 的旋转位置与当前 query 已经不同，根本不代表当前状态——只有最近的 query 才有代表性。这是观察派结构性的上限，不是调参能解决的。

核心观察：pre-RoPE 空间里 Q/K 高度聚集

既然 post-RoPE 的分布被旋转搅乱，那就看 RoPE 之前：pre-RoPE 空间里，无论什么 token、什么上下文，Q 与 K 都高度集中在同一小片区域。讲者用聚集度指标 $R$ （越接近 1 越聚集）对 Qwen3 做了统计：绝大多数 attention head 的 $R$ 都趋近于 1，只有少数不聚集——这是一个普遍现象而非个别 head 的特性。

由此得到 TriAttention 的基本做法：用语料离线校准出每个 head 的 Q/K 聚集中心，作为一对「探针 Q / 探针 K」代表所有 token，再走一遍正常 attention 流程（探针 K 被 RoPE 旋转到各历史位置、探针 Q 旋转到未来解码位置、做点积），得到的 attention logits 直接当重要性分数。这个近似展开写出来恰好是一个三角级数——方法名由此而来。可视化验证：近似打分曲线与真实 attention 的相对位置偏好曲线几乎重合；在 Qwen3、Llama、Qwen2 等多个模型上，近似与真实的相关性峰值约在 0.7 左右（字幕口径）。讲者顺带给出一个可解释性层面的推论：如果这个近似成立，说明模型本身就是靠这组三角级数实现「偏好回看前面第 10 个 / 第 100 个 key」这类相对位置偏好。

两个与观察派的本质区别：观察派在 post-RoPE 空间「回看过去」，TriAttention 在 pre-RoPE 空间「计算未来」；且它用的是离线统计出的虚拟 query，不依赖最近真实 query 的随机样本，因而是 query-agnostic 的。

两处工程改进与执行机制

  1. 用真实缓存的 K 替代探针 K：做 KV 压缩时真实 K 本来就躺在显存里，没必要用探针近似它，直接拿真实 K 打分更准。
  2. 给不聚集的 head 兜底：聚集度分布的长尾里藏着 retrieval head——数量少但对最终性能影响很大，必须单独照顾。做法是把 K 的范数作为附加打分项，按 $(1-R)$ 加权混入。其中 $R$ 越接近 1 的 head，范数项权重越趋于 0、完全由三角级数打分决定； $R$ 约 0.5 的 head，范数项权重约 0.5 。

执行是标准的驱逐循环，但触发节奏是关键：每解码 128 个 token 才做一次压缩（打分 → 取 top-k 保留 → 其余永久驱逐），而不是每个 token 都压。打分开销本身很低，真正的成本是把历史 KV 从显存读一遍——这和 attention 本身的瓶颈一样在访存而不在计算，粗估额外开销约 1/128 量级（字幕口径）。探针是离线校准的，在线打分无需再校准。方法 training-free，不动模型参数。

实验：数字全部按字幕口径

  • 主结果（AIME25 长推理）：精度与 full attention 持平的设置下，解码吞吐快 2.5 倍、KV 显存小 10.7 倍（论文口径：AIME25 精度 40.8 vs 40.8）。对照的旧方法（R-KV）在这条权衡曲线上明显落后。
  • 极小预算下差距更大：KV 预算很紧时，旧方法的精度只有 TriAttention 的一半多一点。
  • 能超过 full attention：某些预算下压缩后精度反而高于 full attention——讲者对此同样困惑，给出一个猜测：Q/K 只有 128 维，KV 太多时这个空间会被塞满、产生「碰撞」，提前剔除不重要的 token 反而减少碰撞。这不是孤例，其他 KV 压缩论文也报告过同类现象，但机制未证实（讲者明示是个人猜测）。
  • 其他基准：RULER 检索基准比 R-KV 高 10.5 点（字幕口径）；LongBench 16 项子任务中 11 项胜出，均分甚至略超 full attention。在 Qwen3、Llama、Qwen2、GPT-OSS 等模型上趋势一致。
  • 两项关键消融：去掉三角级数、只用范数打分，分数跌到 8.88 ——三角级数是出效果的主项；用代码数据校准探针、拿到数学任务上测，不掉点——pre-RoPE 聚集是跨数据分布鲁棒的现象，校准集分布不必与推理任务同类。
  • 落地：已 merge 进 NVIDIA TensorRT-LLM；在 B200 上实测吞吐 1.6 倍、可用 context 长度增至 2.63 倍（字幕口径）；agent 场景 demo 中，不开 TriAttention 的长任务跑到一半爆显存，开了能执行完；LongLife 长视频生成里把 KV 压到原来的 50% ，观感无明显质量下降（讲者甚至觉得个别细节更好）。

局限与下一步（讲者自列）

驱逐本质上仍是有损压缩，预算紧时损失不可避免。讲者心中的理想形态是无损压缩且与现有推理 infra 完全兼容——这一步还没做到，但已有工作在往这个方向走（如结合投机解码）。无损化也是它能否进入训练/后训练场景的前提：压缩改变 rollout 的输出分布，会带来训推不一致，后训练里直接用有损压缩目前不成立。

AMA 要点（含讲者最坦白的边界）

  • 压缩比的经验边界：上下文长度最好别超过预算的约 20 倍，超过后性能明显下降、甚至重复吐词；10 倍左右（即实测 10.7 倍）是体感合理的区间（字幕口径）。在 4090 上同理：理论上可无限拉长，实际上按「显存能承受的预算 × 20」封顶。
  • 效果取决于记忆压力而非任务难度：论文里另有一个递归实验——控制递归深度模拟任务的记忆压力（返回时必须记住每一层中间结果）；浅层（14–16 层）各方法接近，到 18–20 层时 TriAttention 与 full attention 彻底拉开、旧方法（R-KV）掉得更厉害。一个任务需要记住的内容越多，对压缩算法越难。
  • 永久驱逐的风险自认：被驱逐的 KV 永远回不来；确实存在「某个 K 现在没用、将来某个 query 又需要它」的情形（相对位置偏好曲线并非都单调）。补救思路是把驱逐的 KV 放到 CPU 内存、需要时再取回——只是展望，未实现。
  • pre-RoPE 为什么聚集：只有猜测——模型为了「看最近的 token」这类相对位置偏好，必须利用三角级数机制，而能被三角级数近似的前提正是 Q/K 高度聚集；即聚集是模型学出来的、为 RoPE 服务的结构（讲者明示是个人看法，未证实）。
  • 与推理 infra 的兼容性摩擦（两处，都是真问题）：
  • prefix cache 天然冲突：两个共享前缀的请求，一个跑得远一个跑得近，各自该保留的 KV 重点不同，压缩结果互相串扰；复用前缀时必须校验当前解码位置一致，否则不能复用。讲者认为这可能是所有驱逐式方法的共性问题。
  • PagedAttention 需要额外技巧：驱逐会在 page 里打出空洞，他们的做法是把后续 page 的 token 回填进空洞、让 page 始终填满，避免额外整理开销（实现细节跟随 vLLM 默认设置，字幕作 BRM）。
  • 少 KV head 的架构：如混合线性注意力的模型（字幕举例某 5B 级模型只有 2 个 KV head，他们实测过另一混合架构模型）方法仍能用，但可达压缩率只有约 30% ，达不到纯 attention 模型压到约 10% 的水平。
  • 与已压缩架构叠加未探索：和 DeepSeek 的 SWA 没必要叠（本身 KV 就少）；CSA/HCA 这类再压一层理论上可行，但还剩多少可压空间没试过。
  • 重复吐词的原因：讲者直说没搞明白，猜测是重要性识别偶有误杀、长到一定程度后才出现；方法本身 training-free，不是微调引入的。

5可迁移

  • 先问「pre 还是 post RoPE」再谈 attention 打分：post-RoPE 空间里位置旋转会污染任何基于 attention 分数的统计量；观察窗越大越差这类反直觉现象，根源在表示空间选错。对做 attention 分析、探针实验、KV 重要性估计的人，这是一个先决检查项。
  • 「预测而非观察」的低开销打分模式：离线校准一个虚拟探针 + 每 128 个 token 批量触发一次压缩，把在线成本压到约 1/128 量级——这种「离线统计先验 + 周期性批量执行」是推理 infra 里可复用的降本结构，不限于 KV 压缩。
  • 给长尾 head 单独兜底：绝大多数 head 服从简单规律，但对性能影响最大的恰是少数不服从的 retrieval head；用聚集度这类连续指标做加权混合（而非一刀切换方法），是处理「主规律 + 关键长尾」的通用手法。
  • 后训练场景的红线：有损 KV 压缩会改变 rollout 分布，训推不一致之下不能直接塞进 RL rollout；要用，先解决无损化或分布对齐——这条边界对做 RL infra 的人是直接的避坑提示。

6疑问 / 下一步

  • 「超过 full attention」的碰撞假说没有验证：128 维 Q/K 空间的容量与碰撞如何量化、剔除哪些 token 能减碰撞，目前只有直觉，没有实验设计。
  • pre-RoPE 聚集的成因解释（模型为利用三角级数而学出聚集）仍是讲者个人猜测；如果成立，它应当能推出更多可检验的预测，值得深挖。
  • 被驱逐 KV 的 CPU offload + 按需复活机制只是展望；相对位置偏好曲线非单调的 head 占比多少、复活能挽回多少精度，未量化。
  • 与 prefix cache 的冲突被讲者判定为驱逐式方法的共性难题：在多请求共享前缀的生产推理里，怎么让「按解码位置定制的保留集」与前缀复用共存，是推理引擎层面的开放问题。
