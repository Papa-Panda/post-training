## 一句话总结

Mobile-Agent 证明了一条「只靠截图操作手机」的纯视觉路线：V1 用单个多模态大模型加 OCR/SAM 两个 grounding 工具补齐坐标定位短板、靠反思机制纠错；V2 因长图文交错序列和单一 agent 职责过载，拆成规划 / 决策 / 反思三 agent 分工，并用外部操作知识（说明书）注入补模型没见过的 APP 场景。

## 核心

### 问题定义：为什么手机 agent 必须同时会感知、规划、反思

讲者先给大模型智能体的通用定义（能观察环境、做出行动以达成目标的自主实体，具备 profile / memory / planning 能力），再收窄到手机场景。手机 UI 与通用界面不同：要知道哪里能点、哪里要滑、搜索框在哪。完成一句指令往往需要 5–15 步连续操作，中间点错一步就会卡死。因此手机 agent 需要三种能力各就其位：**感知**（理解 UI、定位坐标）、**规划**（多步任务的全局安排）、**反思**（判断这一步是否做错、整体任务是否完成）。这三件事后来恰好对应了 V2 的三个 agent。

纯视觉是刻意的路线选择：只依赖手机截屏，不依赖 XML 等系统级数据，因为后者「不灵活并且权限要求比较高」。讲者在 Q&A 里把这条路线类比为类似特斯拉的纯视觉路线：能力上限在模型本身，模型持续变强，路线就持续受益（字幕 45:51–46:27）。

### V1：单 agent + grounding 工具补短板

V1（讲者称 2024 年 1 月发布，早于苹果 6 月的 Siri 升级发布；苹果多篇手机 UI 工作引用了 Mobile-Agent）是单个多模态大模型的观察—思考—行动循环：输入历史操作截图、全局指令与当前截图，先描述界面，再思考下一步，最后调用工具执行。动作空间只有 7 个：点击文本、点击图标、打字、上滑、下滑、返回上一界面、返回桌面 / 结束（具体枚举以开源框架为准，讲者称可自行扩展）。

关键工程判断是**当时的多模态大模型（包括 GPT-4V）grounding 能力都很弱**——知道该点哪个按钮，但给不出准确坐标。解法是外挂两个工具：带 bounding box 坐标的 OCR、图标分割工具（SAM）。流程是模型先描述界面可能要点的区域，再按指令调 OCR / SAM 拿到候选坐标，最后由模型裁决出精确点击点。反思能力在 V1 里已内建：showcase 中第 2 步点错后，agent 判断出当前这步做错、重新决策，才最终完成六步任务（字幕 16:05–16:43）。这说明在这种设定里，「能判断自己错了」不是锦上添花，而是任务能否完成的分界线。

### V2：为什么拆成三个 agent

V2 的核心变化是把单 agent 扩展为多 agent 架构，动机有二（字幕 21:17–22:59）：

1. **序列太长**。单 agent 要把全部历史记在上下文里，历史是图文交错格式；讲者给的 case 是七步操作后上下文已约 12K 图文交错 token，多模态长序列对模型压力很大。
2. **职责过载**。一个 agent 同时做 planning、决策、反思和记忆，步数越多压力越大。

拆分后的三 agent 各司其职：**规划 agent** 记录已完成哪些步骤、记住关键信息（跨 APP 操作要带的 key information），并给出当前步应该做什么操作；**决策 agent** 把规划给出的意图落到具体动作（点哪个坐标、还是滑动）；**反思 agent** 对照操作前后的截图与全局指令，判断这一步是否正确——错了就退回上一步，对了就继续，或判定全局指令已完成则结束。讲者强调拆分后每个 agent 的压力大大减小，长序列下性能保持稳定，而 V1 随序列变长性能明显衰减（ablation 中三个 agent 逐个去掉都会掉性能，讲者只给定性结论）。

配套的还有一条很实用的能力：**knowledge 注入**。模型没见过的新 APP、复杂 APP，靠预训练知识覆盖不了，可以把操作指南、说明书类专家知识放进 instruction 帮它完成任务；评测中加 knowledge 后性能进一步提升（字幕 26:08–27:01）。Q&A 里这也是答「图标没文字找不到」的官方解法——人工干预 / 说明书注入（字幕 41:40–42:11）。

### 评测与骨干选型

评测是真机动态评测（非静态截图评判）：基于安卓模拟器（暂只支持安卓与鸿蒙，讲者公开招募 iOS 同学），含 5 个系统级应用 + 5 个第三方应用，中文、英文两种设定。指标三类：完成率（0/1）、步级完成度（如十步完成七步记 0.7）、决策与反思 accuracy。结论口径（讲者只说定性）：V2 相比 V1 提升明显；对序列长度更稳；骨干对比中「效果最好的还是 GPT-4V」，showcase 均出自 GPT-4V。讲者明确承认与 GPT-4V 的差距是当前最大约束之一——成本高、传输慢，正因如此在做 V3。

### 边界与下一步

- **纯视觉路线的上限系于骨干模型**：讲者自承其他通用开源模型与 GPT-4V「差距还是比较明显的」。V3 的做法是基于 mPLUG-Owl2 做手机场景预训练数据 + SFT，目标是一个 7B 量级、自研开源、可与 GPT-4V comparable 的专用模型（字幕 38:20–38:44、44:17–44:34）。
- **部署形态**：连电脑只是为了用安卓模拟器这一体验方式；本质只需要拿到截屏与操作权限（安卓端 App 已做 demo），模型可端可云（字幕 44:41–45:28）。仅支持安卓 / 鸿蒙，iOS 能力待补。
- **动态评测 vs 静态评测**：动态评测能考反思（做错能续走），静态截图评测考不了；V3 可能会加静态评测只看每步操作准确率（字幕 50:08–50:53）。
- 同一套纯视觉方案已往 PC 场景迁（论文搜索下载、钉钉发新闻、编辑 Word），但讲者判断 PC 难度更大（键鼠操作 + 更大的图）。

## 可迁移

- **grounding 短板用工具补而不是等模型变强**：先让模型说出「大概要点哪些区域」，再用 OCR / 分割工具给候选坐标让模型裁决——这套「模型出意图、工具出坐标」的分工，今天做任何 GUI agent 都能直接复用，且工具可替换（Q&A 确认 OCR 工具可自选）。
- **长程 agent 的上下文账要先算**：七步就约 12K 图文交错 token，逼出了「规划 / 决策 / 反思拆 agent + 只留关键信息进 memory」的设计。做多步 agent 前先估单步上下文成本与步数上限，再决定单 agent 还是拆分。
- **反思是完成率的分界线不是装饰**：反思 agent 只做一件事——比对前后截图 + 全局指令，判对 / 判错 / 判完成。把它设成独立、便宜的一步，比让主 agent 顺带反思更可靠。
- **未见场景靠知识注入别靠换模型**：新 APP 先给操作说明书进 instruction，是当场可用的兜底手段。
