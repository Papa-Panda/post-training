2一句话总结

讲者认为长上下文和 RAG 都不等于记忆：前者有二次复杂度与 context rot，后者有检索噪声与压缩损失，参数化记忆（LoRA / 权重编辑）又太静态。δ-mem 的方案是维护一个只有 $8 \times 8$ （64 个浮点数）的在线联想记忆状态，用 DeltaNet 式的预测误差驱动更新（旧状态预测得越准、写得越少），读出一个 memory signal 后以低秩修正的方式注入 attention 的 $Q$ 与 $O$ ——不改骨干、不回传梯度、前向即可更新。仅用 2000 条 QA 数据、冻结骨干训练 6–7 分钟、新增参数约 0.12% ，在 LoCoMo 等记忆基准上拿到 1.2 倍以上的相对提升（字幕口径）。

3核心

问题：为什么长上下文与 RAG 还不算记忆

讲者从 personal agent 的真实场景切入：长期助手要记住历史偏好、犯过的错误与经验，交互量可以到每天上亿 token ，同时还要低延迟、低成本、可复用。现行三条路线各有硬伤：

  1. 直接扩上下文窗口：标准 attention 是序列长度的二次复杂度，越用越慢；且上下文过长会出现 context degradation / rot——模型记不住早先的结论、甚至做出错误决策。
  2. 文本记忆（textual memory）：把经验存成文档 / skills，检索后塞回上下文。灵活、无需改模型、闭源 API 也能用；但吃 context budget，检索错了等于把错误记忆贴进当前问题（retrieval noise），压缩又必然丢信息、且可能恰好丢掉关键点。
  3. 外部 latent 通道（outside-channel）：把 KV cache 一类 latent 存到外部再读回融合。多一笔检索开销，还可能与当前 token 存在模态不对齐，花了力气提升却不大。
  4. 参数化记忆（parametric memory）：prefix tuning、LoRA、权重编辑。推理高效，但静态：新任务、新交互进来就得重训。

讲者由此把记忆拆成两个正交问题：memory state（记忆以什么形式存：文本条目、外部 latent、参数）与 memory 如何影响当前推理（拼 prompt、检索后融合、或直接调制计算）。δ-mem 选的是「状态存为一个小矩阵、影响方式是直接调制 attention 计算」这个组合。

方法：一个 8×8 状态 + 对 Q/O 的低秩修正

整体结构（讲者口述，还原口径）：输入 embedding 经小矩阵投影得到 memory 侧的 $k$ 、 $v$ ，连同遗忘门与写入门迭代维护状态 $S$ ；当前 query 与 $S$ 作用得到读出 signal，再经两个矩阵分别产生对 attention 中 $Q$ 与 $O$ 的 low-rank correction，类 LoRA 地加回去。

为什么修正 $Q$ 与 $O$ 而不碰 $K$ 、 $V$ ——讲者的解释偏直觉： $Q$ 决定「问题问得准不准」（读什么）， $O$ 决定「得出的结果有没有问题」（怎么写出），这两处调控性价比最高；消融里 $Q$ 、 $K$ 、 $V$ 、 $O$ 全注入效果最好但参数更多，他们最终取 $Q$ 与 $O$ 。早期他们试过把压缩状态直接拼回上下文（cross-attention 式），发现模态不对齐、效果不好而放弃——这是他们从「影响分数」而非「影响内容」这一设计转向的由来：attention 本质在算分数，只需要调一小部分分数。

状态更新是全套机制的核心，借自 DeltaNet 一系的思路：把 $S$ 看作以 $k$ 为键的联想记忆，更新量由预测误差驱动。旧状态若已能很好地预测当前 $v$ ，更新就小；预测错了，说明新旧任务差异大，沿 $k$ 方向写入更多误差信息。具体形式包含三部分：遗忘门控制的旧状态保留、对当前 $k$ 方向上旧预测分量的移除（对角化的门控矩阵）、以及新 $k$ - $v$ 关联的写入。讲者把这比作认知心理学里的纠错式记忆 / 工作记忆，并类比为一个 PID 控制器：每步前向都在纠偏，且不需要反向传播。

实现细节刻意做简单以便验证机制本身：键 $k$ 经 tanh 稳定尺度、特征限制在 -1 到 1 之间，值 $v$ 不做变换，写入门就是一个 sigmoid，遗忘门取其一减。状态大小在实验中固定为 $8 \times 8$ ，即 64 个浮点数，「还远没有一个 token 占的大」。

三种写入粒度

  1. Token-level：每个 token 写一次。最细，但逗号句号等格式符号会带来噪声，相同 token 重复表达。
  2. Sequence-level：按 message（有 chat template 时）或句子把 embedding 平均后写一次。减冗余，但高精度任务的细节会被平均掉。
  3. Multi-head state：仿多头注意力把状态拆成多个子状态，各存不同信息分量，最后拼接。

训练：冻结骨干，只训 δ-mem，6–7 分钟

训练目标就用普通 SFT loss：把完整历史上下文写进状态，输入里只留当前 question 与 answer 来训练 δ-mem 参数，骨干全冻结。讲者说他们试过更复杂的 loss、效果更好，但考虑到真实接入的效率，SFT loss 是当前选择；也试过打开骨干一起训、略有提升，但那种设定下记忆的边际价值反而变小。

实验设置克制：仅 2000 条 QA 对数据（字幕口径），训练 6–7 分钟即可在多个基准上见效（字幕口径）。新增参数约占骨干的 0.12% ，推理速度（讲者自陈未特别优化）已接近 LoRA 水平、峰值显存与 base model 基本相当。

实验结果（字幕口径）

  • 记忆类基准：在 MemoryAgentBench（字幕作「memory agent bench」）、LoCoMo 等测试上明显优于文本记忆、RAG 类与外部通道类方法；LoCoMo 上相对提升超过 1.2 倍，另一记忆基准上超过 1.3 倍（字幕中基准名识别不清），所有基准平均分 4.87 。
  • 通用基准也有涨点：GPQA、HotpotQA 一类 QA 上同样有提升，讲者据此强调只用 2000 条克制数据不是只过拟合记忆任务。
  • 跨骨干：换不同模型都有不同程度提升，其中 4B 模型提升最好，讲者归因于模型规模与数据量匹配。
  • 状态不是装饰：推理时移除上下文、只注入压缩后的状态，模型仍能答题（HotpotQA 上尤其明显）；把不同基准下的状态 embedding 取出来看，分布位置明显不同，说明状态里存的是可被 query 激活的历史信号。
  • 注入层位置：以 36 层模型为例，注入中间层效果最好——能结合浅层信息又不缺乏深度、且来得及影响后面的输出。

与 RAG 的关系与未来工作

讲者明确说 δ-mem 与 RAG 生态位不重合、可以叠加：δ-mem 提供低成本的 attention 调制，RAG 提供可验证、可追溯的文本记忆。未来工作他列了三件：自适应记忆（按任务调 rank、多层级记忆）、mixture-of-memory（仿 MoE 把不同信息分发到不同状态）、以及与既有记忆方法（RAG 等）的组合。固定 8×8 容量在长 agent rollout 下够不够，他承认是当前最明显的一条 limitation ，大模型可能需要更大的状态，未来想做按信息熵自适应的 rank 。

Q&A 要点

  • 更新机制本质是什么？ 讲者：是在线学习 / PID 控制器式纠偏，只有前向、没有反向传播；被问及是否等价于持续 PCA 式低秩 attention adapter、理论上能否互推，他坦承不清楚、未研究。
  • 固定小状态在长上下文下会不会漂移？ 承认可能存在 drift，但长程评测下表现反而更好；记忆能持续多长，他明确说「不太好衡量」。
  • 会不会 memory overfitting？ 他认为没有特别过拟合：只用 2000 条数据、在多个通用基准上也有提升是主要证据。
  • 收敛性保证？ 讲者认为多虑了：更重要的信息一定会被保留（未给证明或量化）。
  • Memory poisoning 攻击？ 尚未尝试，列为有意思的未来方向。
  • 几种记忆谁会胜出？ 讲者不认为会有单一胜出者：外部文件 / 工具灵活、参数记忆对定向任务高效，业界（如 GPT 系）也是隔段时间重训 + 外部工具并用，应是共存组合。
  • 增益会不会只是 test-time adaptive bias、并非新记忆机制？ 讲者回应：这本来就是一种 test-time 计算机制，且与替换原架构的 test-time training 路线不同，走的是低成本部署路线（未完全正面拆解提问者的质疑）。
  • 长 session 下状态会线性增长吗、要不要 reset？ 状态固定大小不增长；开源 demo 里提供了显式 reset 开关，但自适应调控还没做。

5可迁移

  • 「影响分数而非影响内容」是一条可复用的注入设计原则：与其把外部信息拼回上下文或做跨模态融合（他们实测模态不对齐、效果差），不如对 attention 的 $Q$ / $O$ 做小幅低秩调制。做 agent 记忆、上下文压缩、条件注入时，这条比 RAG 式拼接多一个选项，且推理时零检索开销。
  • 预测误差驱动的写入门控：旧状态能预测新信息时少写、预测失败时多写——这个「纠错式遗忘」规则与流式系统里的增量更新、自适应缓存是同一个结构，可迁移到在线状态维护类 infra 设计中，先验地控制状态污染。
  • 克制数据的验证姿势：只用 2000 条数据、冻结骨干、几分钟训练就能测出机制是否有效，再谈 scale；对记忆 / adapter 类新机制，这是个体面的最小验证闭环模板。

6疑问 / 下一步

  • 8×8 固定状态的容量上界没有任何定量分析：讲者对「能记多长」「互信息上界」「不可逆混叠与任务性能的关系」几个问题都明确表示没测或不理解问题所指，长 rollout 下的状态漂移只给了定性安抚。
  • 关键数字几乎全部来自讲授口径且多个基准名在字幕中识别不清（1.3 倍那个基准、平均分 4.87 的评分构成），需回论文核对基线与绝对值后才能引用。
  • 「只注入状态、移除上下文仍能答题」只举了 HotpotQA 一个明显例子，状态到底存的是可检索的事实还是任务风格偏置，讲者给的 embedding 可视化证据是定性的。
  • 与 LoRA 的对照只谈了速度接近，未谈同一参数量下「静态 LoRA 适配」vs「在线状态」的任务表现对照；企业场景里两者如何选型仍开放。
