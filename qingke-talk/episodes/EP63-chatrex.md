## 一句话总结

这一讲沿一条主线推进：把目标检测从「回归坐标」改造成「语言模型做理解与指认」。ChatRex 用 proposal 模型出框、多模态大模型只输出框的 index，把坐标回归换成检索；RexSeek 用人工标注的 HumanRef 数据解决 referring 任务里「一句描述对应多个框」的数据缺失；RexThinker 再给 referring 加上 grounded 思维链（planning—逐物判断—summarization）并用 F1 作 reward 做 GRPO 后训练。讲者最后的判断很直白：检索式只是过渡，豆包 Seed 1.5 VL 证明直接自回归预测坐标 + 大规模混合数据才是检测的下一步。

## 核心

### 困境：检测模型有感知没理解，大模型有理解没感知

讲者先立问题。检测的发展史是从闭集（YOLO/DETR 一类固定类别）、开放词表（Grounding DINO/DINO-X，给任意文本提示）、到视觉提示（给样例图）一路放开，但他指出一个被忽略的事实：现有开放词表模型其实没有语言理解能力——让它检「黄色的头盔」「成熟的西红柿」，它仍然把所有头盔、所有西红柿都检出来，属性修饰被直接忽略。而真实落地场景（摔倒的人、戴安全帽的人、抽烟的人、入侵事件）几乎全是语言可描述的实体与事件。

另一边，多模态大模型语言理解强，但让它直接把坐标当 text token 自回归预测，密集与小物体上召回很差、容易漏检。讲者把直接预测坐标的难点拆成五条（字幕口径）：

1. **优化目标错位**：检测训练是回归（L1/GIoU 一类几何 loss），框与真值重叠已很高时 loss 很小；而 next-token prediction 算的是坐标数值的交叉熵，每个数值对不上就是高 loss，与几何重叠度脱钩。
2. **错误累积**：第一个框的坐标错了，后续框跟着错。
3. **顺序问题**：检测是并行出框，自回归必须先决定从左到右还是从右到左这类人为顺序。
4. **量化误差**：坐标量化到 0–1000 后，每个 token 至多表示一个像素，分辨率大于 1000 就有量化下限。
5. 结论：大模型擅长的是理解，不是感知；让他直接预测坐标本身就是把任务放错了位置。

### ChatRex：把检测改成检索——出框交给 proposal，理解交给大模型

ChatRex 的设计是把上面的任务换位：输入图片先过一个 proposal 模型（基于 DINO 结构，讲者称由 T-Rex2 改造），把图中所有物体先框出来；再从高分辨率特征上抽这些框的 ROI feature，连同 image feature 一起送入多模态大模型；大模型要表达检测结果时不再输出坐标，只输出对应框的 object index（例如「第 2 号和第 4 号框是狗」）。

proposal 模型本身有两个特殊 token 分别触发两种粒度的框：一路用 SAM 数据构造的细粒度框，一路汇集 COCO、Objects365、Open Images 等检测数据的粗粒度类别（字幕口径）。这样做的收益是绕开坐标回归的全部难点：讲者报告 ChatRex 在 COCO 上做到 48.2 AP，与传统检测/开放词表模型相当，在长尾的 LVIS 上比基于回归的模型更好（字幕口径，未给 LVIS 精确值）。同一套输入输出格式还能顺带做 region QA（问「0 号框的人在做什么」）与 grounded conversation（输出 caption 的同时把提到的物体指回原图）。

但这个解法的上限同样清楚：输入框数有上限（讲者称 ChatRex 设最多 100 个框），且大模型的检测能力被 proposal 的召回锁死——proposal 漏掉的框，index 集合里根本不存在，语言模型永远输出不出来。这一点讲者在 Q&A 里给了最坦白的自我否定，见下文「讲者的路线修正」。

### RexSeek：referring 的真问题在数据——一句描述应对应多个框

第二个工作把任务从 detection 推进到 referring（指代物体检测）：输入不再是类别名，而是带属性、方位、动作的描述（「手上拿着两个足球的人」）。讲者的核心观察是 benchmark 与真实能力脱节：现有模型在 RefCOCO 系列上分数接近刷满，实际却只出一两个框。根因在训练数据——RefCOCO 类数据集里每句 referring 只对应一个框，模型被训成无论什么 prompt 都只出少量框。

RexSeek 的解法先行于数据：人工标注 HumanRef（只标人，讲者称标人最简单）。流程是：开放词表检测模型先检出图中所有 person，标注员写属性（穿搭、年龄、交互、方位等），再把每个属性分配给对应的若干框，得到「一句 referring 对应多个框」的样本，最后用大模型把短语改写成符合语法的完整 referring 语句。模型侧仍沿用 ChatRex 的检索式：开放词表模型检出全部 person（示例图 7 个），框与视觉特征送入 Qwen2.5-VL（字幕作「千万2.5」），模型输出符合描述的 index 集合。

值得记的是泛化现象：只在「人」的数据上训练，模型对任意物体也能做 referring（只检未成熟的西红柿、不检成熟的；工业场景里检有缺陷的苹果）。讲者把这归因于多模态大模型本身的泛化能力被 HumanRef 这种训练格式激活，而不是数据覆盖了这些类别。

### RexThinker：给 referring 加 grounded 思维链，再用 GRPO 收尾

第三个工作回答「黑盒直接出 index 不可控」的问题：模型在给答案前先输出 reasoning，而且 reasoning 的形态是为 referring 任务定制的——不是数学题式的推导，而是对每个候选物体逐一判断。讲者定义的 grounded reasoning 三段式：

1. **Planning**：把 referring 语句拆解成判断步骤（简单任务一步，如逐个判断西红柿颜色；复杂任务多步）。
2. **Action**：对每一个输入框逐一判断是否符合描述，且 reasoning 中提到的物体序号与输入框序号一一对应——这是「grounded」的关键：推理里的每个物体都能对应回原图上的框。
3. **Summarization**：汇总判断，输出最终框的 index 序列。

训练分两阶段。第一阶段数据构造：仍只做 person，在 HumanRef 上改造出 CoT 数据——用 Set-of-Mark 式标记（绿 Mark 为真值、红 Mark 为非真值）把图、referring 语句、正确答案与物体顺序一并给教师模型（字幕口径为 GPT-4o 一类），让它「根据答案说原因」，生成符合三段式格式的 reasoning；再自动校验教师输出的最终答案与真值是否一致来过滤，不用人工 check（Q&A 口径）。第二阶段训练：在 Qwen2.5-VL 上先做 CoT SFT 冷启动（CE loss 逐 token 监督），再用 GRPO 后训练——reward 直接由最终输出的框算 F1（同时考虑 precision 与 recall；示例：两个真值框全对 reward 为 1，只对一个为 0.5）。

字幕给出的结论（幻灯被遮挡，精确数值未念出，只记方向）：

- **CoT 本身提升性能**：引入 CoT 后 F1 有明确提升；GRPO 在 CoT 模型之上进一步提升。
- **CoT 显著提升 rejection（拒答）能力**：referring 语句在图中不存在时，模型能逐物分析后输出「图中没有这样的东西」，而不是随便出一个框——讲者把这直接称作减少幻觉。
- **冷启动不可省**：这是本讲对 RL 实践最有价值的一条。直接拿 Qwen2.5-VL 做 GRPO（不做 CoT SFT），模型的思维过程非常短、不按 grounded 格式走，且思维与答案不一致（说「有一个人拿着小球」却输出三个框），答案也是错的。讲者的解释：referring 这类任务需要先用数据教会模型「按什么格式思考」，SFT 冷启动教的是 reasoning 模板本身，随后 GRPO 才有可优化的对象。

### 外部对照与讲者的路线修正：Seed 1.5 VL 把问题推翻重来

正片最后，讲者测了豆包 Seed 1.5 VL（字幕作「Seed VO 1.5」，原生多模态大模型）：它不用检索式，就是很「粗暴」地直接自回归预测坐标，密集物体（传统检测模型都吃力的场景）也做得很好，还能无类别提示地自动检测+识别全图物体，referring 也基本检对（示例中漏了一个 6 号人物）。讲者判断其定位精度与语言理解都已超过传统回归式检测模型与开放词表模型。

Q&A 里他把结论推到底，并公开修正自己三篇工作的路线：

- **检索式不用再做了**：proposal 给不出框，语言模型就永远做不了；正确方法应回到 next-token prediction 直接预测坐标，Seed 一系已经验证走得通。
- **Seed 检测做得好的原因不是检测数据**：其论文口径约 3 亿条数据（字幕：「300 个 million」），大部分由 Grounding DINO 打标——这种数据的质量只够让出框精确，带不来语言理解（Grounding DINO 本身就分不清红苹果绿苹果）。真正的理解来自混训的 image caption、QA 等通用数据。所以配方是：检测数据教「怎么出框」，通用理解数据教「理解什么」，混在一起训。
- **CE loss 的坐标错位问题在大规模下可被 scaling 吃掉**：数据量足够大、框分布足够广，0–999 的坐标 token 被频繁学习，模型自己就能把坐标出准，不必额外设计 loss；loss 的影响只在小数据/小模型时显著（字幕口径，讲者明确说这是猜测，未做对照实验）。

延伸问答里还有三条工程口径：分割可以两条路走——LISA 式输出 token 触发 SAM 的外挂 decoder，或把 mask 边缘表示成多边形、让模型多预测点（32/64 个点）走 Seed 式自回归；3D 检测用大模型在原理上可做（已有 SpatialLM 一类工作），瓶颈是 3D 数据匮乏与多模态训练数据量需求的矛盾；低资源做检测+大模型，讲者建议小基座（3B 级）+ 单卡 24GB（4090/3090）可跑，框架用 LLaMA-Factory 或手搓均可。

## 可迁移

- **「先用 SFT 教会输出格式与思考模板，再用可验证 reward 做 GRPO」在这期得到了一个视觉版复证**：referring 的 reward 是解析框后算 F1，天然可验证；但没有 CoT 冷启动时 GRPO 直接训不动（思维短、与答案脱节）。做任何「格式即能力」的任务时，冷启动数据教的是模板，不是答案分布，这笔预算省不掉。
- **reward 设计可以薄到只有一个标量**：RexThinker 的 GRPO 不对中间 reasoning 给任何监督，只验最终框的 F1。这与「中间过程不可监督时，把监督压到可解析的最终产物上」是同一条经验，适用于代码、结构化抽取等一切可机检任务。
- **benchmark 高分与真实能力的脱节，先查训练数据的结构性偏置**：RefCOCO「一句一框」把模型训成少出框，是数据构造方式直接写进了模型行为。评测异常时先审计数据生成规则，再怀疑模型。
- Infra 视角：检索式（proposal + index）与自回归坐标式是两种成本结构——前者把感知成本外置给专用检测器、上限被其召回锁死；后者把全部成本压进大模型训练与推理 token 数。讲者的路线修正提示：在数据与模型规模足够时，后者的总成本反而更低且没有外置上限，这个判断对自研多模态 infra 的选型有直接参考。
- 给最终产物留「拒答」出口并把它做成可测指标：rejection 不是附带功能，CoT 对它的提升比对 F1 的提升更显著——凡是「不存在就该说不存在」的落地任务，都值得把拒答率单列成 benchmark。

## 疑问 / 下一步

- RexThinker 的 F1 与 rejection 精确数值在字幕中被幻灯遮挡挡住，未能记录；需要查 RexThinker 论文原文补齐三组模型（plain / CoT / CoT+GRPO）的对照表。
