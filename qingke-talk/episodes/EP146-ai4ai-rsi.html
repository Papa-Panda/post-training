讲者先把「AI4AI / 进化 / 自进化 / 元进化 / RSI」这组正在被产业热炒的概念逐层拆开——AI4AI 回答「谁在改进谁」（任务关系），进化是「提出修改→执行→评价→筛选回滚」的机制闭环，自进化要求进化产生的经验回流并改变未来系统，元进化则要求改进器本身被改进（系统学会如何进化）；随后把这套概念落到自家全栈开源系统上：以机器学习工程（MLE）为可执行、可评价、可溯源的试验场，构造 Nature Gym 与大规模 Kaggle 任务环境，用「四种原子操作在训练与搜索两侧严格对齐」的方式把改进轨迹分别沉淀为 test-time 经验卡（OpenMLEvo）与模型参数（OpenMLEvoRL 的 SFT+RL，训出 35B 的 Frontis-MA1），在 MLE-bench Lite 上超过 GPT-5.5 + Codex，并把「投入的智能量小于产出的智能量」作为 RSI 是否成立的操作性判据。

概念辨析：五个词回答的是五个不同的问题

讲者把整场 talk 的第一半用于概念分层，核心区分如下：

  1. AI4AI 是一种任务关系，不是机制。只要 AI 参与构建或改进了某个 AI 系统（可以改进模型、算法，也可以只改进 harness、工具与工作流），即属 AI4AI。介入的 AI 与被改进的 AI 可以是同一个系统，也可以不是——这与「自」无关。
  2. 进化是一种机制：最小闭环是「提出修改→实现执行→外部评价→筛选/回滚→迭代」。讲者用四个代表工作点出共同点：AlphaEvolve 把算法与训练基础设施变成可评估的进化对象（数据中心调度、Gemini kernel 加速、训练提速）；Karpathy 的 autoresearch 把一次 nanoGPT 训练压成单个 train.py、给定固定 5 分钟预算，「跑一晚上」即得到可观的训练能力；DGM（Darwin Gödel Machine）不改基座模型、只改写 agent 的 harness（工具、工作流），在 SWE-bench 与 Polyglot 上维护树状结构逐代变强；AIDE² 在任务内层做树搜索（内循环）之外再包一层、外层重写自己的 harness，经 100 次 agent 迭代、7 个版本，不仅在见过的 MLE-bench 上变好，在 weather bench、kernel bench 等域外任务上也更好，且 reward hacking 水平下降。四者的共性：改进对象不同，但闭环相同，且评价必须来自可验证的外部环境（或独立的评价 agent）。
  3. 自进化 = 进化 + 经验回流。普通进化每换一个任务就从初始解重新开始（讲者图中「蓝线」）；自进化则要求进化产出的不只是 solution，还留有可复用经验，且这些经验回到系统里改变未来的起点（「紫线」）。讲者按经验落点分三类资产：内容资产（如 Voyager 在 Minecraft 中积累的 skill 库——讲者称这是 skill 一词可考的最早出处）、机制资产（从交互成败中提炼策略与执行结构，如 ReAct 一类把策略本身沉淀下来的工作）、参数资产（经验多到可直接训练/微调模型，如 SkillRL 把轨迹整理为 memory→skill 再与基座联合训练）。这也解释了「养龙虾（Clawdbot/OpenClaw 一类个人 agent）」为何成立：今天的 agent 已是「参数化模型 + harness」的经验系统，越用越聪明是自进化在产品层的自然结果。
  4. 元进化（meta-evolution）= 学习如何进化。类比元学习「学习如何学习」：系统沉淀的不再是任务经验，而是「关于改进的经验」——起始状态、改了什么、结果如何、为何如此。元进化层可以内置于 task agent 自身（如 Meta Agent 把元进化能力放在做事的 agent 里），也可以是独立于 task agent 的外部 meta layer（task agent 只做任务、不自指，如他们自己的系统）；更进一步是 HyperAgents：连「改进策略」本身也成为进化对象，形成套娃式嵌套（在 DGM 之上再套一层）。
  5. RSI 是元进化之上的极限形态，判据是复利。讲者坦言学界没有统一定义，他给出的操作性版本是：升级后的改进器要接管下一轮 AI 进化、持续产生更强的后继，且按他在 Q&A 中展开的判据——「投入的算力（智能量）小于最终产出的智能量」，才算真正进入持续复利。talk 中引用了某公司（字幕作 VICO，以公开资料为准）的 L0–L3 分级：L0 进化慢于人类，L1/L2 快于人类，L3 才是上述复利循环；这与 OpenAI 的五级 AI 能力分级不是同一个概念。

一条贯穿全篇的警戒（Q&A 中被反复回到）：只有 loop、没有经验沉淀的系统，连自进化都算不上——AlphaEvolve 只基于搜索树、若不维护 memory，就只是在刷题而没有错题本；但若把搜索树上「父节点→改了什么→子节点效果」这条边记录并积累下来，它学到的就是「如何改进」，那就是元进化的经验。

为什么选 MLE 做试验场：先有可执行证据，才有进化经验

讲者的工程主张是：元进化要研究「什么是一条好的改进经验」，就必须选一个高价值、可执行、可评价、修改可溯源的任务域。自动化机器学习（Machine Learning Engineering）恰好满足：给 agent 一个比赛描述与数据，它自己训模型、测模型，产出一张可与人类排行榜对比的量化表格，整个「改了什么→分数如何变」的轨迹天然可记录。两条任务线：

  • Nature Gym：从近 10 本 Nature 系列子刊出发，粗筛 5000 多个候选任务，经前沿 agent 能力测试与大量人工筛选，留下 90 个忠于原文的前沿科学任务（覆盖细胞组学、蛋白质等 6 个科学领域）；关键设计是把原论文方法隐藏且禁止联网检索，防止 agent「查答案」，测的是面对未知问题能否超过人类科学家。
  • 大规模 Kaggle 任务线（OpenMLE-Gym）：把 Kaggle 全部数据集与比赛下载筛选，并挑少量高质量 anchor 任务，统一为「带训练/测试数据、可评分」的任务包；模态与任务类型跨度大。讲者强调任务量与既有工作「不在一个数量级」（论文口径：三源合计 5,758 个过质量门的任务——156 个手工 anchor、3,362 个 Kaggle 数据集任务、2,240 个 Kaggle 竞赛任务），数据与任务包已开源至 Hugging Face。

三条既有路线在讲者框架里是同一问题链的三个环节：可获得（构造沙箱/任务、产出可验证的改进轨迹）、可使用（test-time 用搜索与经验组织复用旧经验）、可内化（把改进能力训进模型参数）。他们的 Frontis-MA1 系统主张把三条打通并全栈开源。

系统：训练与搜索共用同一组原子操作，是整个设计的枢纽

系统三层共享同一个底座——所有反馈都来自 MLE 任务在沙箱中的真实执行，不做模拟、不让 LLM 自评：

  1. OpenMLE-Gym（环境层）：统一任务形式 + 开源沙箱构造方法，给出可执行、可评测的环境。
  2. OpenMLEvo（test-time 层）：把训练好的模型放进进化搜索。每个算法节点挂一张经验卡（experience card），存分数、相对父节点的改进幅度、novelty 等元信息。经验卡有两处用途：其一决定节点被采样的概率（分数、改进、novelty 加权）；其二在生成新节点时，把被选节点的兄弟与祖先节点经验卡按重要性加权采样若干张、由模型自行总结后注入上下文（memory injection），再产生新节点。效果（字幕口径）：相比参考工作 AIRA，每次调用 token 更少、同等 token 预算下效果更好，「进化的效率不断提升」。
  3. OpenMLEvoRL（参数层）：把经验训回模型。四种原子操作（论文口径：Draft / Improve / Debug / Crossover）是关键设计——这类操作在 test-time scaling 文献里并不新，讲者的主张是训练时模型见到的操作必须与搜索时完全一致：好处一是上下文短（每步只是一次「从一个算法改进到另一个算法」的单步转移，而非完整改进轨迹）；好处二是搜索能力随训练直接变强，且搜索产物又能反哺参数训练，闭环成立。

参数训练的具体 recipe（讲授部分信息密度最高的一段）：

  • SFT 数据（2.6 万余条）：不只采高质量最终解，还先跑一遍进化式搜索采出整棵树，专门挑「debug 节点」——父节点是错的、子节点改对且改得更好——这类父→子边正是「改进经验」的原子单位。
  • RL 在树上进行：policy 的每一步是从树上采一个节点、产出一个新算法，评价后按组收集，用 GRPO 回传。
  • Reward 归一化：不同任务指标量级、方向（越高越好还是越低越好）都不同，统一映射到固定区间：有排行榜的任务用人类最高分/最低分作上下界；无排行榜的先用理论上下界，随采样推进再用模型实际能达到的分数动态估计。
  • 截断与指数放大：每个 group 内中下游的分数直接截断为 0（只鼓励模型产出自己能做到的中上游）；同时借用「entropic advantage」式的指数型 advantage 把 group 内最高分大幅放大——best candidate 的 advantage 是传统算法的好几倍，效果明显：训练中每组的最好解持续变高，最终模型也更强。

实验结果（按字幕口径，论文口径附注）

  • MLE-bench Lite：训练出的模型 + 自家进化算法，得牌率超过 GPT-5.5，甚至超过 GPT-5.5 + Codex（灰线）；再在此基础上加保持总计算量一致的并发优化，得牌率进一步提高。讲者的概括是「35B 的模型参数获得很大模型才能达到的效果，在所有对比的 agent 系统中达到 Pareto 最优」（论文口径：Medal Average 从基座 39.39% 提到 60.61%，配 OpenMLE-Evo-Max 达 71.21%）。
  • 消融：固定进化算法换不同改进者模型，自家模型最强；固定模型换算法，该进化策略对其他模型也有提升（但对自家模型提升最大——训练与搜索同构的收益在此可见）。
  • 泛化：同一套模型 + 搜索在 Nature Gym 上达到与 GPT-5.4 + Codex 相当的效果（字幕口径）——讲者据此主张「改进 AI 算法」的能力可以从 MLE 域迁移到科学问题域。
  • 讲者对现状的定位克制：这只是一条「通往 RSI 的可执行路径」，下一步要证明的是被改进的系统能接管自己的改进并持续产生更强后继，而不只是在一个 benchmark 上刷高分。

Q&A 要点

  • 元进化是否等同于 code agent？ 目前 AI 系统本身由代码构成，改自己必然需要很强的 coding 能力，code agent 是当下的实践路径；但已有团队把硬件优化做成进化循环，未来可能与物理世界交互，不必局限于代码。
  • 经验知识库无限增长、检索错误与知识冲突如何处理？ 这正是需要元进化的原因：淘汰/更新机制不应由人手写策略，而应让 AI 自己学会判断什么样的经验对自己有用、如何设计沉淀机制。
  • 没有在线 RL、只靠搜索树，算不算元进化？ 只靠每轮从零开始的搜索不算；但若记录并积累父→子边的改进轨迹（改了什么、效果如何），那就是在学习如何改进，可以算。AlphaEvolve 若维护 memory 同理。
  • 学界算力有限如何验证 scaling？ 挑高价值、可检验的任务验证进化/自进化/元进化机制本身，且不必用大厂模型——他们用 4B 模型在 MLE 上也训出明显提升；大厂做的是自家大模型的进化，学界做的是机制验证，分工不同（字幕口径）。
  • 科学垂类问题上，harness 与垂类模型能否一起做 RSI？ 可以：垂类模型套上带特殊工具/接口的垂类 harness 收集科研经验，再用经验训垂类模型，循环转起来即是自进化乃至元进化。
  • 如何评价「越改越好」、如何防评价指标被 hack？ 看版本间增量（第 1 版相对第 0 版的增长是否小于第 2 版相对第 1 版的增长，用以判断越改越快还是越改越收敛）；单个任务指标容易被 hack，任务足够多、足够真实、跨多轮汇聚的指标很难 hack，且进化轮数上去后 hacking 反而下降（引用了 AIDE 侧的观察）；主观指标则需人工设计跨任务 rubric，目前缓解有限（字幕口径）。
  • RSI 的判据：投入的智能量（算力）小于产出的智能量，即是复利的开始；真正部署后进化的评价还可看 Continual Learning Bench 一类序列化任务中经验是否在积累（字幕口径）。

5可迁移

  • 「训练时见到的操作 = 搜索时使用的操作」是一条可直接搬到 agentic RL 数据构造的原则：若推理期用 Draft/Improve/Debug/Crossover 式原子步做 test-time 搜索，SFT/RL 阶段就应按同一原子步切分轨迹（单步转移、短上下文），而不是喂完整长轨迹——讲者给出的两个收益（上下文变短、搜索产物可反哺训练）都与 rollout 数据管线设计直接相关。
  • 「经验卡」是对 agent memory 的一种具体落法：记忆单元不存任务轨迹本身，而存「父方案 → 做了何种修改 → 效果与相对改进」这条边，附分数/改进量/novelty 作为采样权重——对 coding data 的轨迹筛选与回放排序同样适用：存 diff 及其执行结果，而非只存成功全文。
  • Reward 归一化的两件套（排行榜上下界 + 无排行榜时「理论界初始化、运行中动态估计」；group 内中下游截断为零）是把异构任务塞进同一个 GRPO 训练时的现成配方，尤其适合多任务混合奖励尺度不一致的 RL infra。
  • 评价防 hack 的经验法则：先把任务做多、做真，再谈指标；以及把「版本间增量是否放大」作为进化是否真实加速的度量——可用于自建自进化系统的验收，而非只看单点分数。

6疑问 / 下一步

  • Frontis-MA1 的「改进器接管下一轮进化」尚未闭环：论文口径全程只训到 generation 1、权重更新发生在部署前的离线阶段，talk 中也只演示了一代训练 + 一代搜索；讲者主张的 RSI 复利（改进者越改越快）在本系统内还没有多代实验支撑。
  • 元进化的收益目前主要用 MLE-bench Lite 与 Nature Gym 两个域验收；讲者称已向科学问题泛化，但「改进经验」在代码/数学证明/硬件等其他可验证域上的可迁移性，只有 Q&A 层面的论证，没有数据。
  • 经验卡的采样权重（分数、相对改进、novelty 的加权方式）与经验淘汰机制讲者未给细节，而这正是他自己列出的元进化核心问题；开源 repo 中 OpenMLE-Evo 的实现细节值得对照。
