4核心

1. 背景/问题：熵崩塌是 RL scaling 的拦路虎

OpenAI 的技术报告宣称 RL 可以用更多训练算力换更好性能，但开源复现普遍训几百步就饱和。讲者在 11 个开源模型（4 个模型家族，含 Qwen、Llama、DeepSeek 等，字幕 [11:20]–[11:33]）上复现实验，发现一个共同现象：训练中策略熵（entropy）迅速趋近于零，性能提升同步到达瓶颈——两者不是巧合，而是强耦合。数据点很刺眼：前 200 步熵已消耗 73%（只剩 27%），而性能已完成总提升的 76%；到 600 步熵只剩 6%，性能完成 93%（字幕 [11:58]–[12:12] 起）。换句话说，RL 的「有效训练」几乎全发生在熵耗尽之前，之后再堆步数基本是空转。

2. 经验定律：性能上限在训练前就被熵决定

讲者拟合出熵 $H$ 与性能 $R$ 的经验关系：

$$R = -A e^{H} + B$$

其中 $A$ 、 $B$ 为拟合常数。含义是：性能随熵下降而上升，但熵耗尽（ $H \to 0$ ）时的性能上限在训练开始前就由初始条件决定。更实用的一点：只用前 15% 训练步的数据拟合这条曲线，就能预测最终性能，数学任务平均误差 0.9%、代码任务 1.2%（字幕口径）。这给 RL 训练提供了一个早期止损/调参的量化工具——不用训完就知道这轮配置的天花板。

3. 机制：谁在杀死熵？——log-prob 与 advantage 的协方差

为什么熵会单调崩塌？讲者从策略梯度的更新式出发推导出：每一步熵的变化量，与该步各 token 处 log-probability（或 probability）与 advantage 的协方差正相关。直觉是：

  • 「高概率 token + 高 advantage」：模型反复强化已经很确信的 token，分布更尖锐 → 熵下降；
  • 「低概率 token 意外拿到高 advantage」：冷门 token 被抬起来，分布被摊平 → 熵上升。

正常训练里前者占绝对主导，所以熵一路向下。讲者还用题目难度验证了这条机制：rollout 8 次正确率分别为 0.125、0.5、0.875 的题目上，测得的协方差随难度变化与理论预测吻合（难度越大、协方差越低）。熵不是玄学指标，而是可以被 advantage 分布定量解释的量。

4. 传统方法为何失效

  • 熵正则：系数极度敏感。字幕口径下，系数从 0.001 降到 0.0001 几乎无变化，再调大熵直接冲过初始值且不带任何性能收益——没有可用的甜点区。
  • 与 reference policy 的 KL 惩罚：能把熵保住，但代价是性能下降。讲者称之为「假阳性」：它只是限制了策略更新幅度，熵高是因为模型没怎么动，而不是探索得更好。

结论：熵要「对症」维持，而不是靠全局正则硬撑。

5. 方法：盯住极少数极端 token——Clip-Cov 与 KL-Cov

机制分析给出关键洞察：熵的变化被极少数高协方差 token 主导。字幕数据：占 0.02% 的极端 token，其协方差均值达 5.6，而全体 token 的均值只有 0.003，相差数千倍（字幕 [27:54]–[28:05]）。也就是说，不是所有 token 在杀熵，是极少数离群 token 在主导。于是两种干预都只动这些 token：

  • Clip-Cov：在协方差处于极端区间（字幕口径约 1–5）的 token 中，随机抽取一小部分（字幕口径约 0.02%–0.2%），直接 clip 掉它们的梯度、不参与更新（字幕 [30:47]–[31:13]）。
  • KL-Cov：对高协方差位置施加 rollout policy 与待更新 policy 之间的 KL 惩罚，讲者称其在实验中更稳定有效（字幕 [31:17] 起）。

两种方法改动量都只有约十行代码，已合入 verl，切换 loss_mode 即可启用，默认参数即论文参数（论文发出约一个月后合入，字幕口径）。

6. 实验结果

干预后 response length 显著变长、熵被维持在可控高位而不再崩塌。规模效应明显：32B 上的增益远大于 7B（讲者解释为大模型探索空间更大、更受益于熵维持）。字幕给出的 32B 数字：AIME24 提升约 15%，AIME25 提升字幕作「10% 4.6」、口径含糊，此处记为约 10% 并存疑（字幕 [34:38]–[34:47]）。对比参照是 DAPO 的 Clip-Higher 技巧（字幕作「double」，即把 clip 区间从 0.8–1.2 放宽到 0.8–1.28）——那是全局放宽，Clip-Cov/KL-Cov 是按协方差定点干预，粒度完全不同。

7. 结论/观点（含 Q&A）

  • 「健康的熵」没有绝对数值标准，但经验上不应超过初始熵；熵是训练状态的仪表盘，不是越高越好。
  • 与 Qwen 团队 forking tokens 工作的区别：协方差是概率与 advantage 的联合量，不能只看 token 自身的熵；且高协方差的主力其实是低概率、低 advantage 的 token（讲者在 Q&A 中自我修正了早先表述，字幕 [40:41]–[40:53]）。
  • 熵不能简单用训练 step 代替做性能预测——不同配置下熵的消耗速度不同，这正是经验定律要用 $H$ 而非步数做自变量的原因。
  • 对 pass@k 定义的能力上限，讲者本人持保留意见：pass@k 测的是采样覆盖，不等同于模型能力的真实边界。

6可迁移

  • 给自己的 GRPO/RL 训练加一条监控：逐步记录策略熵与「log-prob × advantage 协方差」的分布，熵崩塌前先看到的是协方差极端值的累积；用前 15% 步拟合 $R = -A e^{H} + B$ 做早期天花板预测，决定是否值得继续烧算力。
  • Infra 视角：Clip-Cov/KL-Cov 已在 verl 里以 loss_mode 形式提供，接入成本约等于改一行配置；做 RL 框架选型/二次开发时，熵与协方差应作为一等公民指标进 tracing，而非只看 reward 曲线。
