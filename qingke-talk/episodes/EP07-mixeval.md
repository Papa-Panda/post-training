## 一句话总结

这期解决的是「用什么尺子量模型」的问题：讲者先用数据证明现有 benchmark 的 query 分布普遍又偏又窄、与人类偏好的排名相关度普遍低于 0.8，再提出 MixEval——从互联网爬取约一百万条真实用户 query，据此去已有 benchmark 题库里逐条匹配最像的题目重组评测集，并用模型错误率构造更难的 MixEval-Hard、用动态刷新防污染，最终得到与 Chatbot Arena 人类排名相关度最高（字幕口径：居各评测集前二）、成本却低一两个数量级的 ground-truth 评测；附带一个有意思的结论：人类偏好主要由预训练能力决定，后训练的影响远小于通常想象。

## 核心

### 引入：评测的三难

讲者把现状摆成三组矛盾。**标准答案型 benchmark**（MMLU、GSM8K、GPQA 等）可复现、可重跑，但题目容易被塞进训练集刷分，且 query 分布与真实用户需求对不上。**Chatbot Arena 式人类评测**靠实时用户交互投票，很难 hack，是社区最信赖的尺子，但不可复现、且贵——两个版本测一个模型都要约 \$3,000（字幕口径），分数稳定要 3–5 天、5–6 万张人类投票。**LLM-as-judge 型**（Arena-Hard、MT-Bench）省了人力，但抽出的 query 子集本身有偏（专挑难的），裁判模型又有已被反复证明的倾向性。MixEval 的立题就是：能不能用有标准答案、可复现的评测，逼近人类偏好的排名？

### 先诊断：现有 benchmark 的分布有多偏

讲者对 29 个数据集的 query 做了降维可视化（字幕口径），三条发现构成本文的经验地基：

1. **分布位置揭示来源**：真实用户数据（ShareGPT、WildChat、Arena conversations、自爬 web query）分布广，标准答案型 benchmark 大多挤在很窄的区域；连 DROP、WinoGrande 这类号称多领域的数据集，其 query 分布都只落在一个小角落，甚至比 GSM8K 这类单领域数据集还窄——「多领域」名不副实。
2. **用户群体决定偏差**：query 在图上越靠上越技术化（写代码、数学、物理），靠下是生活、娱乐、语法类。Arena 类平台的技术用户占比明显更高，所以在它上面测出的排名天然偏向技术问题表现；真实世界的大多数用户问题其实集中在中间偏左——不是直接写代码或解数学题。
3. **分布广度与人类相关度正相关**：大多数数据集与 Chatbot Arena 的 Spearman 排名相关低于 0.8；多领域数据集中 13 个里有 10 个相关度大于 0.5，单领域数据集 8 个里只有 1 个。结论：query 覆盖面越广、分布越接近真实用户，排名越接近人类偏好。

### 方法：三步造出 MixEval

**第一步，按真实分布重组题库。** 先从互联网爬取用户 instruction（约一百万条量级，字幕口径；自建内部 benchmark 校验其抽取准确率，回归 / 精准度约 98%–99%，字幕 ASR 此处不清晰、按上下文读作此数），并验证爬到的 web query 分布与 ShareGPT 等真实用户数据相对象。然后对每条用户 query，从汇总的 benchmark 池子里检索最相似的一条已有题目，构成新评测集——题目自带标准答案，所以可复现；分布由真实用户决定，所以贴近人类需求。实际只需几千条用户 query 就能组出评测集。

**第二步，用错误率造难题版。** 初版 MixEval 上 GPT-4、Claude 一级模型已能到约 88 分（字幕口径），区分度将耗尽。于是按「一道题被多少模型做错」给题目打难度分，抽难題子集，同时用拒绝采样保持原分布，得到 MixEval-Hard：分布还是正的，难度提上去了，与人类评测的相关度反而更高——讲者强调难度本身就是与人类排名相关度的关键变量。

**第三步，动态刷新防污染。** 静态集迟早被塞进训练集，MixEval 定期换掉 query 重新匹配；两个版本之间模型分数方差只有约 0.36–0.37（0–100 尺度），一般不超过 0.5 分，足够稳定；更新可在一分钟内完成（Hard 版要先测几个模型估难度，稍慢但可接受）。

### 为什么粗放混合没用：关键消融

讲者特意做了一个反面对照（字幕口径）：把各数据集**按数据量混合**或**均匀混合**，与人类评测的相关度基本没有提升，按量混合甚至不比均匀混合好（那点分数还是被体量大的 MMLU、GSM8K 拉起来的）。有效的是**逐条 query 级的匹配**——让每条评测题都对应一个真实用户需求的位置。这条消融是 MixEval 区别于「把几个 benchmark 拼盘」的核心论证。

### 结果与两个附带发现

- **有效性**：拆开看每个源 benchmark，用 MixEval 匹配重组后，与 Arena（多语言版与英文版两个口径）的相关度都有非常明显的提升；MixEval 与 MixEval-Hard 居所有评测集与人类相关度的前两位（字幕口径）。
- **模型性价比曲线**：在 MixEval-Hard 上，最好的 GPT-4 与 Claude 也只有约 63–64 分，Llama-3 约 55–56 分（字幕口径），提升空间还很大；开源模型（横轴激活参数量）与闭源模型（横轴 API 价格）的分数都呈 log-linear 饱和曲线，闭源更明显；Llama-3 是开源里的异类，性价比已可与部分闭源模型相比。
- **base model 也能测，且预训练说了算**（讲者认为最有意思的分析）：Chatbot Arena 上只有 chat model，没法直接验 base model；但在 MixEval 上，base 与 chat 的排名相关高达 0.95（字幕口径），例外只是被重度后训练过的小模型（Llama-3 8B、Llama-2、Gemma 2B 一档）。由此推出：**人类偏好主要来自预训练决定的能力，后训练影响相对小、小模型上才明显**；「Arena 排名只反映会不会聊天」这个流行质疑不成立——问题都解决不了的模型，人类不会给高偏好。这对模型内测的直接价值是：后训练之前就能用 MixEval 较准地预估人类偏好排名。

### 成本口径

讲者把评测成本拆成 inference cost（按 query 数与平均生成 token、GPT-3.5 Turbo 价格估算）与 judge cost（统一用 GPT-3.5 做 model-based parsing，比规则解析更稳、不会系统性压低某些模型的排名）两部分，再与 Arena 按 MTurk 人力价折算的投票成本对比。结论：MixEval 测一个模型只需数分钟级时间（字幕作「34 分钟」，按上下文与论文口径应为 3–4 分钟量级，此处以字幕标注为准）、约 MMLU 评测时间的 6% 量级（论文口径），对 Arena 的 \$3,000 是数量级碾压。

### Q&A 要点

- **数据泄露了 benchmark 还有说服力吗**：讲者区分对外排名与内部开发——泄露影响的是外界对排名的认知，但开发者自己知道有没有作弊，内测时这些数据集照样有意义、照样该用；说服力变小不等于归零。
- **chat 与 base 评测的实际差异**：主要在输出格式——base model 不会按格式输出，需要 few-shot in-context learning 教它格式再解析结果，除此之外差距不大；这也是 Arena 测不了 base model、而 MixEval 可以的原因。
- **跨数据集公平性怎么保证**：他们不在每个数据集上自测，而是只从 Open LLM Leaderboard、OpenCompass、Chatbot Arena 三个官方榜单取分数、同一数据集只用一个来源，保证 setting 一致；实际判分统一用 GPT-3.5 parsing 消除解析偏差。
- **想自己设计评测集怎么办**：讲者的回答很直接——这套方法「过段时间就会放出来，可以直接抄作业」；讲授时论文刚投 NeurIPS（字幕作「MIPS」），代码约一周后公开。

## 可迁移

- **评测集先做分布体检，再看分数**：把自家 eval 的 query 做一次主题 / 难度分布画像，与真实用户（或线上流量）的分布对象，是比多跑几个 benchmark 更优先的事。DROP 式「号称多领域、实际窄分布」的坑，在内部评测集里同样常见。
- **判分通道要统一且抗格式偏差**：统一用一个 model-based parser 判分、不用各数据集自带的规则解析，避免系统性压低某些输出风格的模型——这条对 RL 训练里的自动 verifier / reward 打分同样成立：解析偏差会被 policy 直接学成风格偏置。
- **防污染靠动态刷新而非藏题**：留 test set 不公开的老办法已被「拿 GPT-4 生成答案再训练」绕过；定期换 query 并实测版本间方差（小于 0.5 分才算稳），是一套可直接搬到内部基准维护的协议。

## 疑问 / 下一步

- MixEval 的相关度是在 chat model 上对 Arena 校准的；讲者用 base/chat 排名相关 0.95 论证可测 base model，但 base model 的「人类偏好」本身没有直接的人类标注可对照，这条外推的强度取决于那个 0.95 是否在新一代模型上保持，值得用论文后续版本核对。
- query 匹配依赖 benchmark 池子的覆盖面：真实用户 query 里若有一大片在现有题库中找不到近似题（讲授未展开这部分占比），重组后的分布正不正会被题库上限反噬；这是把该方法搬到垂直领域（如代码、agent 轨迹评测）时要先测的量。
- 难度用「模型错误率」定义会随模型代际漂移：今天的 Hard 难题在下一代模型上变易，动态刷新能换 query，但难度标尺本身需要周期性重标定，讲授没有给出重标定的频率建议。
