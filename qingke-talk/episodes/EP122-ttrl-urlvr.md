## 一句话总结

讲者把无监督 RL 的奖励来源拆成「内在奖励」（模型自身置信度 / 多次采样一致性）与「外在奖励」（利用生成—验证不对称性或无标注语料构造可验证信号）两类，并用理论推导加多模型实验论证：内在奖励的优化本质是「锐化」模型初始分布——先验（置信度与正确性的相关性）对就走捷径快速涨点、先验错就放大偏见，宏观上呈「先升后降」直至崩溃，调参和换方法都救不回来；它安全可用的场景主要是小规模 test-time training；真正可能 scale 的方向是外在奖励（以自验证为代表）。附带产出一个实用指标：模型在内在奖励训练下「撑到崩溃的步数」能预测它在有监督 RL 中的可训练性。

## 核心

### 分类框架：先把「无监督」定义清楚

讲者先给边界：本期讨论的是**可验证任务**上的无监督 RL，即不需要人类标注 ground truth、但任务本身有对错。它和 2024 年 RLHF 阶段的 self-rewarding（模型同时当 actor 和 reward model 打分）要区分开。

奖励分两大类：

1. **内在奖励（intrinsic）**：信号完全来自模型自身，不与环境交互。再细分为：
   - **Certainty-based**：由输出的置信度定义奖励。实现形式五花八门——与均匀分布的 KL 散度、token 概率连乘、序列熵、最大与次大概率之差——但讲者指出它们本质都是对 logits 的某种变换，都在做同一件事：最大化高置信预测。
   - **Example-based**：由多次 rollout 的聚合定义奖励，代表是 TTRL 的 majority voting：采样 $N$ 次，把多数答案当作伪标签，与之一致给 1 分、否则 0 分。前提是「多次采样的一致性与正确率相关」。
2. **外在奖励（extrinsic）**：通过外部机制构造可验证信号。一是把无标注语料上的 next-token prediction 本身当作 RL 任务（用 RL 手段做语言建模，讲者提到微软有较多后续工作）；二是利用**生成—验证不对称性**：很多任务生成答案比验证答案难得多，于是可以让模型（或外部工具，如计算器、代码执行）给自己的答案做验证。

### 锐化机制：内在奖励在数学上到底在优化什么

讲者用 KL 约束下的奖励最大化框架（即 DPO 推导里那个最优策略形式）代入 TTRL 的 0/1 多数投票奖励，定义了「第 $k$ 轮迭代时模型对自身多数投票答案的概率之和」这一指标，并推导出它随迭代单调不减：

直白地说，每一步更新都在把「模型原本就高概率相信的东西」推得更高概率，分布越来越尖锐，终点是一个完全确定的策略。因最优策略里概率按 $\exp(\beta^{-1} r)$ 的因子被放大，本来略占优的答案会被拉得更快。这就是讲者命名的 **sharpening（锐化）机制**。

它像一个回音室：先验对，优化让你在对的路上更坚定；先验错，优化只会放大偏见。决定成败的变量因此被讲者定义为**模型先验**——模型初始置信度与正确性之间的相关性。这也顺带解释了社区早有的观察（Qwen 系比 Llama 系更「适合 RL」）：先验强弱不同，同一套内在奖励的命运就不同（Q&A 中讲者进一步把 Qwen 的强先验与预训练数据污染的讨论挂上了钩）。

### 实证一：先升后降是普适 pattern，换方法救不回来

讲者在 Qwen 小模型 + 数学数据集上复现 TTRL 并与真实奖励训练对比（字幕口径）：真实奖励曲线正常上升，TTRL 曲线**先升后降**。同看的几个指标里，多数投票一致性确实在涨，但多数投票奖励的准确率（伪标签和真标签的吻合度）持续下降，模型熵下降得比有监督训练更快——它在走「优化自己自信」的捷径。

再横向比 5 种内在奖励方法：一个 epoch 内就有 3 种先后崩掉，剩下 majority voting 与 self-certainty 两种能撑久些，但多训一个 epoch 基本也都崩。讲者 Q&A 中补充：他们对每种方法调了 4 个超参取最稳配置，训 1000 步、每步 64 条（6 万多条样本）后依然崩溃；且从最优策略的推导看，偏离量随训练只会越滚越大，所以在他们考虑的 horizon 上崩溃是「必然发生」，与用 GRPO 还是 PPO 无关（奖励最大化到置信度顶点这一目标本身决定的）。

细粒度看 in-distribution 行为：在同一道题上反复训练、同一道题上评测，大部分题只是初始分布被锐化（初始对就一直对且越来越确信，初始错就越来越确信地错），真正发生「由错变对 / 由对变错」相变的只是少数。有趣的是 OOD 上常能看到「A 任务训练、B 任务变对」的泛化——讲者给这个泛化打了引号：那往往不是学到了新能力，而是 B 任务上模型先验本来就强，一锐化就撞对了。

### 实证二：小规模 / test-time 是内在奖励的安全区

把训练集规模当变量（32 / 128 / 512 条直至全量）后出现分界：32、128 条这种小规模下，真实奖励保持高位不崩，KL 偏移也明显更小。讲者的解释是：小规模训练只造成**局部过拟合**而非全局策略偏移，所以不伤 OOD。极端验证：哪怕 32 条训练数据的初始多数投票答案**全是错的**，模型在这 32 条上确实一路往错里优化，但在 AMC 等留出评测上仍能看到正向提升、也不崩——这从侧面解释了文献里「错误奖励、随机奖励也能训出效果」的怪现象：锐化撞对题而已。

因此 test-time training（如在 AMC23 这种 40 道题的测试集上做 TTRL）是内在奖励最实在的应用：帮有监督 RL 走完「最后一公里」。但同一实验也给出警告：在大数据集上做同样的事，多数投票奖励能涨到 1.0（模型对每道题只会输出一个答案）而真实准确率趋于 0——这是教科书式的 reward hacking。

### 实证三：「崩溃步数」可以预测有监督 RL 的可训练性

既然先验决定命运，能否不开完整 RL 就先验地判断一个 checkpoint 适不适合 RL？讲者提出的代理指标是**模型崩溃 step**：在内在奖励无监督训练下，奖励准确率跌破 1% 所需的步数。在 3 个家族、7 个模型上的结果（字幕口径）：Llama 系（base 与 SFT）三四十步就崩，Qwen 系能撑得久得多，且 SFT 后的比 base 更能撑；而「撑得越久」的模型，在有监督 RL 里训前训后的提升也越大。对比之下，社区常用的 pass@k 也有类似趋势但预测没这么准。这个指标的卖点是便宜：不用跑完整个 RL 训练，就能筛 SFT checkpoint。

### 外在奖励：自验证的初步证据

最后讲者给出他们认为能 scale 的方向的初步实验：**self-verification**——让模型验证自己生成的答案，前提是任务有生成—验证不对称性。三条曲线对比（字幕口径）：有监督 RL 涨得最猛；纯内在奖励（trajectory entropy 一类）先升后降、最终归零；自验证早期有一段较长的探索期（分析 case 发现它在学指令遵循），之后能涨到一定程度且奖励准确率维持在中间位置、不塌到零。讲者强调这只是初步探索：把任务的生成—验证难度差人为可控地构造出来再 scale 自验证，是他们想做而未做完的方向（并举了可扩展可验证环境一类工作为例）。

### Q&A 要点

- **无监督 RL 能否复刻预训练的 scaling 奇迹？** 讲者的回答即全篇结论：纯内在奖励不行（左脚踩右脚），奖励来源能随数据与算力同步 scale 的外在奖励才有可能。
- **崩溃是必然还是大概率？** 在他们调参、换方法、训到 6 万多样本的设定下必然发生，且有最优策略推导背书；但他们只试了 GRPO 一类算法，跨算法普适性未验。
- **行业是否应转向 environment-grounded RL？** 讲者区分狭义 self-play（纯自身信号，本篇批判的对象）与广义 self-evolving（有环境反馈，如代码执行的 OJ 反馈）：后者本质就是 RL 该有的样子，也落在他定义的外在奖励里，是更可能 scale 的。
- **TTRL 的一致性 reward hacking 与原论文的 lucky hit 解释**：讲者认可 hacking 真实存在——训练集上多数投票奖励到 1.0 就是模型只会说一个答案；样本少时不伤测试集，样本多时灾难性。
- **RL 还能给现有大模型带来大跃升吗？** 讲者自陈没有大规模 RL 实践经验，给出的是判断：当前 RL 多在「利用」而非「探索」，action space 太大导致没法 from scratch 训、必须从强先验模型起步，SFT 与 RL 的算力分配与探索—利用跷跷板远未解决；他相信 RL 潜力未被真正发挥，但大厂现实中仍先吃 SFT / 蒸馏的收益。
- **KL 上涨是好是坏？** 讲者只认相关性不下因果：大数据集上 KL 偏离大且最终崩溃，但 KL 惩罚本身是「没法精细做 reward shaping 时的粗糙妥协」，他个人近期实践里加 KL 不一定好。
- **OPD / 自蒸馏算不算 URLVR？** 按「不需要人类劳力产出 ground truth」的定义可以算，且讲者认为现行 OPD 与 RL 区别不大，本质是 token-level reward 的 on-policy RL。

## 可迁移

- **给无监督 / 自训练类 RL 立一条验收纪律**：同时监控「代理奖励」与「代理奖励准确率」（伪标签与真标签的吻合度，哪怕只在一个小标注探针集上算）。本期最有操作性的信号是两者背离——一致性涨、准确率跌——出现即是锐化在放大偏见，比等评测崩了再发现早得多。
- **Checkpoint 筛选可以借「崩溃步数」做廉价探针**：在候选 SFT checkpoint 上跑小规模内在奖励训练，记录撑到奖励准确率跌破阈值的步数，作为是否值得投入完整 RL 的先验排序信号；这比只看 pass@k 多了一个「分布锐化下是否稳定」的信息维度。
- **Test-time training 的使用边界**：小测试集上做 TTRL 式最后一公里是被本篇背书的用法，但必须限制步数与数据规模，并用留出集盯真实准确率；把同一套做法放大到全量训练集，就是讲者实测的 reward hacking 路径。
- **Infra 视角**：majority voting 类方法的主要成本在每个 prompt 的多次 rollout 采样；若要工程化，先验探针（置信度—正确性相关性、崩溃步数）都是采样端的小开销前置检查，适合做成 RL 训练前的 gate。

## 疑问 / 下一步

- 锐化机制的推导基于 KL 约束最优策略的单步更新，讲者未展开多步、带熵正则与 clip 的 GRPO 实际更新下单调性还差多少；Q&A 里他也承认只试了 GRPO 一类算法，「与算法无关」是他的判断而非实证。
- 「崩溃步数」只在 7 个模型、数学任务上验证，与有监督 RL 收益的相关是定性趋势；换任务域（代码、agent）是否成立、阈值（1%）怎么定，讲者未给出。
- Qwen 先验强与数据污染的因果在 Q&A 里被听众直接提出，讲者顺着讲但未给定量剥离方法；用污染程度未知的模型测「先验」，指标本身会被污染程度混杂。
- 自验证实验只给了「不归零、能涨一段」的存在性证据，生成—验证难度差如何人为构造并 scale，讲者明确说是未完成的方向。
