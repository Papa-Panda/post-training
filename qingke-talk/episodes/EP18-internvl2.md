## 一句话总结

讲者复盘了书生·万象从一代到 2.0 的整条路线，核心方法论只有一句：渐进式扩展——先把视觉基础模型做大（InternViT 从架构搜索定型、扩到 6B），再让它的表征与越来越大的 LLM（10B → 100B 级）分阶段对齐，最后用持续迭代的高质量 SFT 数据把能力一项项补齐；靠这套「基础模型渐进变强、数据渐进变优」的打法，InternVL 2.0 的 76B 在多数基准上追平或超过 GPT-4o，且从 1B 到 76B 全开源。讲授后半段还交代了 VisionLLM v2 如何用 embedding 连接外部解码器把检测/生成/编辑等 100 多种任务接进同一个对话模型，以及团队在数据工程上的一批坦率经验（数据准备占 80% 时间、SFT 是一锅迭代的老汤、很多「结构问题」本质是数据没堆够）。

## 核心

### 背景：从专用模型到通用多模态对话系统

讲者的叙事起点是成本结构：传统深度学习是「一个任务采一份数据、设计一个模型」，边际推广成本高；ChatGPT 把成本压到预训练一次、用户用文字表达任意需求，边际成本近零。但现实世界不只有语言模态——视觉、3D、语音、动作指令都得处理——目标就是做「ChatGPT 式的通用多模态模型」。语言侧的可行路径已经收敛到 decoder-only + 开源 LLM（LLaMA、Qwen、DeepSeek 一类）；模态扩展主流有三条路线：BLIP-2 式 Q-Former 汇总、MLP 直接投影、LLM 旁挂 visual expert。讲者的判断是三条路线上限接近，MLP 最简单好用，InternVL 走 MLP 路线：把视觉能力在强 LLM 基础上做好、做强、开源。

### 第一步：视觉基础模型必须先「大」起来

讲者认为多模态的瓶颈首先在视觉编码器，它要同时表征互联网图像、文档、医疗、遥感等各种 domain 并与语言空间对齐。CLIP 只擅长互联网图像、参数量与 LLM 差一个量级，小编码器会出现「这个 domain 训好、那个 domain 掉下去」的跷跷板。一代 InternViT 因此定为 6B（当时算力约束下的上限）。没有现成可用模型，就自己做架构搜索：固定参数量，枚举深度 32–80、head 维度 64/128、MLP ratio 4/8 等组合，用 CLIP 做代理任务短训，再以 zero-shot ImageNet 精度与收敛稳定性（训练速度、loss 平稳性）挑型。

配对经验（Q&A 给出口径）：LLM 小于 7B 接 300M 的 ViT 即可，7B 以上接 6B ViT。讲者确认视觉编码器从 300M 扩到 6B 收益很大（domain 覆盖能力与编码器规模直接挂钩）；是否继续往上扩，团队还在探索。

### 第二步：渐进式对齐——表征跟着 LLM 一起长大

InternViT 的对齐对象不是一次定死的：从 10B 级 LLM 起步，逐步换到 20B、70B、100B 级。讲者的理由是各家 LLM 的表征空间基本一致（都用全互联网语料训练），与小模型对齐好之后再往上换并不难。训练分三阶段，动机是不能把海量低质数据与稀少高质数据一锅混（高质数据会被埋没）：

1. **对比学习阶段**：在筛选前的大规模图文对上用 contrastive loss 做初步对齐——全局平均池化对局部噪声有抑制，适合在脏数据上打底；
2. **生成式 caption 阶段**：换上筛选过的高质量数据，用 cross-attention 连接 + 生成 loss 训 caption。数据筛选维度讲者列了：CLIP 分数、水印概率、黄暴概率、美学指标、分辨率、caption 长度；
3. **高质量 SFT 阶段**：把学术界/开源能找到的图像描述、物体检测、OCR、科学图表、数学、常识、文档等 VQA/caption 数据全收拢，当作高质 SFT 集继续加强，同时逐步扩充 domain 覆盖。

成果是 InternViT 一个模型同时能做 ViT-22B 式的分类/分割（不到其 1/3 参数量，分割甚至更好）、CLIP 式的图文检索（当时最好，且支持中英日等多语零样本分类），乃至 VQA；其配套的生成模型只用英文数据训练就能迁移到中文、表情包等图文生成（多语表征在 CLIP 阶段已基本对齐）。

### 第三步：拼成对话模型 + 分辨率按任务分配

把 InternViT 与社区好用的 LLM（讲者举例 InternLM2 20B）用 MLP 接起来，处理好高分辨率、SFT 数据足够强，就能得到对话模型。InternVL 1.5 的 26B 在 xAI Grok-1.5V 宣传用的七个指标上拿到其中四个最好。分辨率是讲者给出的一个很实用的经验坐标（tile 为 $448 \times 448$ 切图）：通用问答约 6 个 tile 就够；图表尤其文档问答需要约 24 个 tile，字看不清分辨率再高也白搭（2.0 技术报告里 Document VQA 用的是 18 个 tile，线上 demo 固定 12 个 tile；细节多的图把 tile 拉到 40 是经验最优）。动态分辨率 vs 大图直输对比过，结论是相差不大，他们实际用固定分辨率、按任务调最优值。

### InternVL 2.0：渐进式扩展的完整形态

2.0 就是把上述路线整体放大：模型从百亿扩到千亿级、数据质量持续迭代，用「比较低的资源」换性能。开源 76B 已与 GPT-4o 非常接近：多学科问答（MMMU）是 62 对 GPT-4o 的 69，其余如数学问答、科学图表、文档/信息图表问答、OCR、MMBench 通用视觉问答都更好或同级。系列覆盖 1B–76B；8B 版本相比 1.5 全面提升且硬件门槛降到 4090/3090 可训（不再需要 A100）。千亿级 Pro 版通过 API 供学术标注/评测申请。新发布的语音版用 Whisper 编码器 + 简单 MLP 接入，输出端暂时接火山 TTS API，后续再做端到端语音生成。

### VisionLLM v2：用 embedding 把「只能输出语言」的限制拆掉

讲授最后一节：现实任务不只有文本输出。做法是提示符 + 向量连接：模型输出一个任务表征向量，与各类外部解码器结合——检测把表征送进 Grounding DINO 当类别条件，生成送进 Stable Diffusion，图像生成/编辑同理。任务冲突用 query 分流解决：检测用 8 个 query、生成用 64 个 query，提示符先分流、每个任务用自己的 query 抽信息。100 多种任务接进同一系统后，性能基本保持在接入前的专用水平；开放性也变强（可指令检测没见过的新类别、工业/农业/生物图像、各种 pose 与编辑）。

### Q&A 要点（讲者最有信息量的部分）

- **embedding 为什么用 conv2d**：与 linear 等价（无 overlap 时就是全连接），只是实现方式不同；
- **OCR 训练细节**：预训练阶段 OCR 的 loss 就是 next-token prediction；grounding 不预测框坐标回归，而是对文字内容做 NTP；OCR 数据量讲者估计约 100M；没有准备负样本（试过不大）；OCR 读序靠在 GT 里定死顺序、模型学着跟；
- **幻觉怎么解**：目前最直接有效的方法仍是仔细的高质量 caption 数据硬修；更系统的办法团队也还在研究；
- **SFT 数据规模**：讲者坦言已经记不清总共叠了多少——「SFT 叠 SFT，一锅老汤熬过来的」；能力差了就生成新数据、回炉老数据继续训；纯文本数据只占很小一部分（随机配空白图/不配图/随机图），纯粹为保住普通问答能力；
- **RLHF/DPO**：后面肯定会试，目前仍以 SFT 对齐为主；1.5 的数据混合配比暂不公开；
- **垂直领域微调**：GitHub 有微调文档与医学图像例子；新 domain 拿通用问答数据 + 新数据混训、比例可调高，旧问答能力不会掉太多；ViT 不用重训（300M 与 6B 都做过多 patch 训练）；
- **密集检测为什么做不好**：next-token prediction 是顺序输出，而一图 100 个框是无序集合，自回归回归不了——能做好框很少的 grounding（甚至比专用模型好），COCO 式密集检测/人脸检测不要指望；
- **代码生成**：没专门做过优化，用市面开源数据、能力基本是底座 LLM（如 InternLM2 20B）自带的；数据构造建议看 Codeforces 一类在线编程站点的代码截图；
- **图文交错数据**：在试，判断有用，但还没在最强模型上起作用；
- **prompt 工程**：标数据前正经花一天把 prompt 设计好，GPT-4o 对 prompt 的 follow 很好，后面省很多事；这类「固定场景 + GPT-4o 生成数据」的做法团队有专门论文（字幕作「M-Instruct」）讨论；
- **表格看串行答错怎么办**：本质不是能力缺失，是这类指令见得太少、没被激活——拿 arXiv 的 LaTeX 表构造问答数据叠上去就能解；
- **数据质量的教训**（被问「1 万条自生成数据没提升」）：1 万条量够，问题在质量与复杂度——GPT-4o 简单 prompt 批量生成的 1 万条不如人工认真修好的 1000 条复杂数据。

## 可迁移

- **渐进式扩展是一条可复用的 post-training 路线**：先把「感知/表征」部件单独做强，再与逐步变大的主干分阶段对齐、最后用高质 SFT 收口——避免了「大脏数据埋没小高质数据」的经典坑。这与 RL 训练里先做强 base/rollout 再上 RL 的分工是同构的；分阶段换数据的纪律（对比学习打底 → 生成式对齐 → 任务 SFT）可以直接搬到多阶段训练配比设计。
- **分辨率/tile 数的任务标定表很工程**：通用问答 6、文档 24、报告 18、demo 12、细节 40——本质是「按任务的信息密度分配输入 token 预算」。做 agentic RL 的上下文管理时同理：不同任务步的 observation 分辨率（截断长度、压缩率）值得按任务实测标定，而不是全局一个窗口。
- **「能力没激活」优先于「能力不存在」**：表格看串行、竖排 OCR、印章文字，讲者的统一解法都是补对应形态的数据叠训，而非改结构。这对评测后的数据飞轮是直接的工作方法：先判定是分布没见过还是真不会，前者只堆数据（但要堆对复杂度，人工修 1000 条 > 机器生成 10000 条简单的）。
- **多任务冲突用「分流 + 专属 query」而非共享硬挤**：提示符分流 + 每任务不同数量的 query 抽取，是轻量版的任务路由；对照 MoE / 多任务 RL 的梯度冲突问题，这个「便宜的隔离」思路值得借鉴。
- **next-token prediction 的结构性边界要认清**：无序集合输出（密集检测框）自回归天然做不好——在设计 agent 的结构化输出（多目标、无序集合）时，别指望靠数据把序列模型的这个短板训没。

## 疑问 / 下一步

- 渐进对齐中「换更大的 LLM 后补训多少步能追平从头训」，讲者只说不难、未给数据；InternVL 2.0 技术报告当时尚在撰写，细节（各阶段配比、tile 策略的最终版）以报告为准。
- 视觉编码器 6B 往上扩的收益曲线未定（团队自称探索中）；与之对照，LM 从 20B → 34B 涨幅大、34B → 76B 收益收窄的现象，讲者主要归因于 34B 底座（Yi-34B 的再训版本）本身特别强——即表观 scaling 里混着底座质量差异，解读时要小心。
- CoT/推理能力是明确短板：讲者承认 InternVL 用了 CoT 反而比不用差，推理能力怎么提「还是比较难的一件事」；这正是后续多模态 RL 的主战场。
- 语音版当时的输出端仍是外部 TTS API 拼接，端到端语音生成未落地；图文交错数据未在最强模型上验证。
