2一句话总结

7B
上 AIME

SFT 与 RL 不是两种对立范式，而是同一个策略梯度估计器在不同数据分布假设与偏差-方差取舍下的两个实例。论文把这个估计器（UPGE）拆成四个可互换部件——稳定化掩码、参考策略分母、优势估计、对数似然梯度——并证明 SFT 只是"优势恒为 1、参考策略取当前策略"的特例。在这个统一视角上长出的算法 HPT 做法极简：按每道题的实时 rollout 正确率逐题门控，做对了就继续 RL 探索、全军覆没才切 SFT 喂示范，在 Qwen2.5-Math-7B 上 AIME 2024 比最强基线高出约 7 个点（论文口径）。

3核心

引入：三类范式与三类混合系数方案

讲者先梳理后训练的三类范式：RL（效果好、泛化强，但依赖初始模型性能，弱模型上可能越训越差）、SFT（快速拟合目标分布、学领域知识，但限制探索、跨任务易掉分）、SFT→RL 串行流水线（闭源模型标配，但资源消耗大、阶段衔接要精细调参）。由此自然引出问题：既然两者各有优劣，能否结合？讲者指出今年上半年起的混合方法（mix-policy）大体都是把 SFT loss 与 RL objective 加权求和，区别只在系数怎么定，分三类：

  1. 固定系数：训练全程不变，代表作 LUFFY；
  2. 预定 schedule：系数按预设曲线变化，讲者举阿里 CHORD 为例（融合系数 $\mu$ 随训练推进按预设形式变化）；
  3. 按指标动态调整：如 SRFT 按 entropy 动态调权重。

讲者顺手补了 on-policy / off-policy 的划分：待训练模型与采样模型是否同一个。SFT 是经典 off-policy（数据由外部模型生成）。真正待回答的问题是：SFT loss 与 RL loss 形式差异这么大，为什么能放进同一个优化过程而不打架？ 这是全场的主问题。

梯度视角：把三类算法逐一求导

讲者换视角——不看 loss，看 policy gradient。对 SFT 的交叉熵 loss 求导，得到 $\nabla \log \pi_\theta$ 乘以 $1 / \pi_\theta$ 的形式（loss gradient 与 policy gradient 只差符号）；对简化后的 PPO loss（先略去 KL 约束与熵项，讲者说明这些项最终都可并入 advantage）求导，参数只出现在重要性采样比的分子里，得到带 clip 的同类形式。第三个样本是 mix-policy 方法的 off-policy 部分（以 SRFT 的 loss 为例，LUFFY 形式相近但多一个 policy shaping 修正）：

  • off-policy 部分的重要性采样分母 $\pi_\beta$ 是外部强模型（如 DeepSeek-R1）的概率，实践中从不真正计算，而是直接置 1。讲者给了两个理由（字幕口径）：其一，开源社区的现成高质量数据只有文本、没有生成时概率，算不了；其二，待训练模型与数据生成模型往往不是同一系列，tokenizer 不对齐，token 无法一一对应，比值根本无从算起。置 1 的合理性在于：这些外部模型输出的本就是其高概率 token，概率天然接近 1。Q&A 中讲者补了他们自己的预实验支撑（字幕口径）：离线数据里 99.8% 的 token 概率大于 0.92、约 80% 大于 0.95，所以置 1 "虽然有点近似，但不是不准确"。

三种梯度并排后，规律浮现：第一项都是对 $\pi_\theta$ 的求导项，后面都挂着一个类 advantage 项，且都出现一个分母项——SFT 是 $\pi_\theta$ ，PPO 是 $\pi_{\theta_{\text{old}}}$ ，SRFT 是 1。统一框架由此呼之欲出。

UPGE：四部件统一估计器

把上节的大表整理、严谨化，讲者得到统一的梯度形式，由四个部件组成：

  1. 稳定化掩码（stabilization mask）：由 clip 操作求导而来——clip 区间内函数是 $y = x$ 、导数为 1，区间外是常数、导数为 0，所以 clip 在梯度里等价于一个 0/1 掩码，作用是忽略掉"不安全"的更新、让训练稳定。讲者举例：PPO 的掩码边界恰为 $1 - \epsilon$ 与 $1 + \epsilon$ ；但 DAPO 等工作发现被裁掉的 token 里也有对正确率与熵有益的，于是把上界放大。
  2. 参考策略分母（reference policy denominator）：讲者特别说明这是一个泛化定义，不同于通常所说的 reference policy（RLHF 里防偏离的初始模型）：凡是出现在分母、对梯度起修正/重加权作用的策略都算。取值决定各算法的性格——SFT 与 REINFORCE 取当前策略 $\pi_\theta$ ，效果是模型对低概率的示范 token 给出 $1 / \pi_\theta$ 的大更新、快速学会不熟的 token；PPO 取 $\pi_{\theta_{\text{old}}}$ ，作用是重要性采样修正。
  3. 优势估计（advantage estimate）：PPO 用 GAE，GRPO 用组内奖励减均值除标准差；SFT 恒为 1（示范无条件全盘接受）。
  4. 对数似然梯度（likelihood gradient）：各方法共享的骨架，把当前动作与参数更新关联起来。

统一不止是归纳：讲者从一个 common objective 出发做了正向推导——所有后训练算法其实都在做同一件事：提高想要的回复的概率、压低不想要的回复，同时让当前策略接近 behavior policy。把这个目标（success rate 项 + KL 衡量的分布接近项）求导、再把采样分布换到参考策略下（等价于引入重要性采样项），即得 UPGE；推导出的 advantage 天然包含两部分：一部分与 RL 相连（实践中被替换为 advantage 以压方差），另一部分与 SFT 相连（带一个判断参考策略是否等于 behavior policy 的指示项）。最后再把 clip 带来的掩码并回去，四部件齐备。

两个结论（区分事实与判断）：

  • 事实：SFT 与 RL 优化的是同一个 common objective，loss 形式只是这个目标的子项表达，所以两者在优化时不冲突——这从理论上解释了 LUFFY、SRFT 这类混合方法为什么能 work。
  • 判断：目标相同不等于算法相同；从 UPGE 看，各算法的差异本质是偏差-方差取舍（SFT 低方差但有分布偏置，RL 无偏但高方差）。启示是算法设计不应全程用同一种方法，而应依据当前情形动态选择——这直接引出 HPT。

HPT：按逐题实时表现二值门控

HPT（Hybrid Post-Training）的流程（字幕口径）：对每道题 $q$ ，先用当前模型采样 $N$ 次，把每条回复送进 rule-based verifier 打分（对/错），取平均得该题的实时表现 $P$ ；再用阈值 $\gamma$ 门控系数： $P > \gamma$ 时 $(\alpha, \beta) = (1, 0)$ 纯 RL， $P \le \gamma$ 时 $(\alpha, \beta) = (0, 1)$ 纯 SFT；最终 loss 为 $\mathcal{L} = \alpha \mathcal{L}_{\text{RL}} + \beta \mathcal{L}_{\text{SFT}}$ 。

几个实现口径（字幕）：

  • 门控是逐题的，不是逐 batch 的（Q&A 确认）：实验 batch size 128，一个 batch 里可以一部分题走 SFT、另一部分走 RL。
  • RL 侧采用 LUFFY 同款的 DAPO-GRPO 变体（舍弃 sequence 的 token-level 平均；字幕作「DOTA 加 GRPO」，按上下文应为 DAPO-GRPO）。
  • 直觉：RL 在"全军覆没"的题目上组内优势恒为 0、梯度为空转，此时 SFT 注入新知识恰好补上探索前置条件；已能做对的题目继续 RL 自我探索，避免 SFT 拉低熵、压制探索。门控即"按题难度自适应课程"。
  • Q&A 中讲者强调门控几乎不引入额外开销：算 $P$ 用的采样与 reward 计算本来就是 GRPO 训练的必经步骤，额外只有求均值与系数判断的逻辑计算；且切到 SFT 的题不需要 rollout，"反而甚至会有一个更高的效率"。

实验：设置与主结果

设置（字幕口径）：Qwen2.5-Math-1.5B/7B、LLaMA3.1-8B 三个模型；评测为 6 个数学基准（AIME 2024/2025、AMC、MATH-500、Minerva、OlympiadBench）+ 2 个 OOD 套件（ARC-c、GPQA-Diamond）；最长回复 8192；AIME/AMC 等小数据集汇报 avg@32，其余 avg@1。训练数据 follow LUFFY：由 Lumina 数据集筛选难度、再用 DeepSeek-R1 蒸馏思考过程得到的约 46K 条（Q&A 口径）；SFT→GRPO 基线的 SFT 与 RL 数据是不同子集（48K / 46K）。其余细节如每题采样 8 条（温度 1.0）、8×A800 80GB 为论文口径。

主结果的具体数字讲者在 talk 中只给图表与定性结论（"基本上都要比 baseline 高""比全量先 SFT 后 GRPO 高出不少"），下表沿用旧版论文口径并标注来源：Qwen2.5-Math-7B 分布内平均 HPT 52.7（LUFFY 49.8、SFT→GRPO 46.5、SFT 44.5、GRPO 43.1），AIME 2024 单项 33.0（LUFFY 26.1、SRFT 18.4），OOD 平均 62.3 同样第一；小模型差距更大——1.5B 平均 41.9（LUFFY 34.7、SFT 36.9），LLaMA3.1-8B 平均 18.2（LUFFY 13.2、GRPO 9.6）。讲者的定性解读（字幕口径）：先全量 SFT 再全量 GRPO 这种"死板安排"的 schedule 本身并不有效。

分析实验：四个有信息量的观察

  1. Pass@k 不缩水：讲者对比 RLVR 的 "Limits of RLVR" 式质疑（RL 后模型在大 $k$ 下与 RL 前打平，即 RL 不提升能力上限），测了 Pass@1 到 Pass@1024（每题采样 2048 条）：先 SFT 的曲线始终高于纯 GRPO，说明 SFT 引入的外部数据确实能抬升能力上限；HPT（红线）在三张图上基本全程最高，AIME 2025 上起步最低但 Pass@1024 反超——HPT 同时提升 Pass@1 与 Pass@k。
  2. 难题上新解更多、遗忘更少：MATH-500 五难度等级独占解题分析，HPT 相对 GRPO 额外做对 58 题、做错 15 题，且额外做对数随难度等级升高而增多。逐题轨迹研究（字幕新增细节）：从 MATH 的 L3/L4/L5 各取 85 题共 255 题、训 50 个 epoch 逐题画正确率热图——纯 GRPO 在难题上出现整行白色（8 次采样全错、始终学不会）的连线；HPT 相对 SFT→GRPO 的差值图随训练推进由蓝转红、最终超越，L5 上最明显。
  3. 训练动态自洽：off-policy 数据占比随训练自动下降（初期模型弱、更多题触发 SFT，后期转 RL），且模型越强拐点越早、占比越低；对照 LUFFY 的占比恒定在 1/8（1 条 off-policy + 7 条 on-policy）。熵全程高于 GRPO（外部数据带来更多可能性）；回复长度先明显上升（SFT 数据最长 8K、长回复占比高）后趋稳，后期以 RL 为主时长度不掉——SFT 学到的长链 pattern 在 RL 阶段被保留、不遗忘。
  4. 消融：把 HPT 的 SFT 部分换成 off-policy RL 项（或两者并存），1.5B 上纯 SFT 切换最好，7B 上三者差别不大（字幕口径）——讲者据此判断 SFT 与 off-policy RL 在此起的作用相近，最终只保留收敛更快的 SFT 与 on-policy RL 切换。阈值消融： $\gamma$ 越大 SFT 比例越高，但 Qwen 上 $\gamma = 0$ （8 次采样全错才切 SFT）效果最好，即"SFT 不是越多越好"。

讲者自陈的边界与未来讨论

讲者用三点收尾（字幕口径，区分事实与判断）：

  1. 与产业界的 gap：mix-policy 方法自今年 3 月起层出不穷、实验上普遍优于 SFT→RL，但主流厂商并未采用。讲者自诊原因（除产业惯性与大规模验证成本外）：这类方法在应用条件上同时受制于 SFT 与 RL——既要求有外来的高质量采样数据，又要求有明确的打分机制（verifier 或 reward model），两个条件同时满足才能用。未来方向：在没有高质量思维链、也没有明确监督信号的场景里做类似处理。
  2. 统一框架的真正作用：不只是把已有方法归纳成一张表，而是提供"把任意方法拆成四个子模块来分析"的视角，看清每个算法适合什么情形，从而有的放矢地设计新方法。
  3. mix-policy 后续：让方法更能被产业界采用、更高效，以及向蒸馏与理论分析方向延伸。

4Q&A 要点

  • 门控粒度：逐题（单条数据）选择 SFT 或 RL；batch 128 内两种数据并存（字幕 64:19 起）。
  • 额外开销：可忽略—— $P$ 的计算复用 RL 本就要做的采样与 reward 计算；SFT 步省 rollout，整体甚至比纯 RL 快（但比纯 SFT 慢，讲者明说）。
  • 骨架可替换：把 GRPO 换成 PPO 也做过实验，SFT+PPO 组合同样有效；主实验用 GRPO/DAPO-GRPO 只是为了与基线同口径。
  • 与 CHORD 的区别：CHORD 是预定 schedule（融合系数 $\mu$ 按预设形式变化）；HPT 是按逐题实时表现做 0/1 选择，且有 UPGE 的统一视角打底；讲者认为效率上 HPT 略好。
  • 对 Thinking Machines on-policy distillation 的看法：讲者称分享当天才粗读，"做得非常扎实、非常实用、值得在实际应用时适配"，但认为创新性有限、此前已有类似工作；承诺把该文的分析整理进 PPT 后续分享（对应本仓库 EP125 与 EP154 的 OPD 线）。
  • 未做的基线：听众提出"按阈值先全量 SFT 再全量 RL""先 RL 收集错题再 SFT"两种分段方案，讲者均认可为有价值、值得补实验，并给出直观判断：逐题交错切换比整段切换更灵活、更有的放矢，但分段方案在硬件效率上可能有优势。
  • 实现：基于 verl 改造——在 RL pipeline 中插入 SFT 数据引入与 $\alpha / \beta$ 判断，实现 SFT 与 RL 的同时更新（代码已开源）。
  • MoE 适用性：本工作只测 dense 模型；讲者认为 MoE 训练不稳定主要源于架构本身（训推不一致等），配上常用稳定 trick 后本算法应可稳定，但未实测。
  • DPO 能否替代 SFT：讲者认为不行——DPO 需要成对偏好数据、条件更苛刻，而此处需要的是让模型获得解难题的基础模仿能力，SFT 足够。
  • 数据细节：训练数据 follow LUFFY 的 OpenMath 系列（Lumina 按难度筛选 + DeepSeek-R1 蒸馏思考过程），约 46K 条。
  • Pass@1024 是否过大：讲者认为不大—— $k$ 越大越能检验 RL 是否真的提升能力上限，且沿袭了 "Limits of RLVR" 的设置。

6可迁移

  • 对 coding data / RL infra 工作的 1-2 个直接可试的点：
  • 把 SFT 数据当"救援通道"而不是第一阶段：训练中按题/任务统计 rollout 通过率，全失败的样本自动路由到示范学习——这对 coding data 尤其直接（单元测试通过率就是现成的 $P$ ）。讲者的效率论证也成立：门控信号复用 RL 已有的采样与 verifier 结果，几乎零额外成本，SFT 步还省 rollout。
  • 混合训练的旋钮优先级重排：先试逐样本动态门控，最后才考虑全局固定混合比例；UPGE 框架提示，调 mask/分母/优势的取舍本质是偏差-方差工程。与 CHORD 式预定 schedule 相比，逐题实时门控是讲者验证过的更优默认。
  • Infra 视角（扩展性 / 成本 / 评测自动化）的启发：HPT 的门控信号来自训练内已有的 verifier 结果，不需要额外评测管线；工程实现就是在 verl 的 RL pipeline 里插入 SFT 数据通道与系数判断——"用在线表现调度离线数据"是便宜的自适应。注意讲者自陈的应用前提：高质量外部数据与明确打分机制缺一不可。

7疑问 / 下一步

  • UPGE 是梯度形式的归约，但 SFT 与 RL 的数据分布差异（示范分布 vs 当前策略分布）在这套估计器里只体现在分母与优势上——分布偏移本身（如示范质量参差）如何进入同一框架？值得对照 LUFFY 的 policy shaping 再看。
  • 讲者认可但未做的两个基线（按阈值整段 SFT→RL、先 RL 后 SFT 收集错题）值得留意后续版本是否补上——这关系到"逐题交错"相对"分段"的增益到底有多大。
  • 本期只测了 dense 模型与数学任务；coding / agent 场景（轨迹长、rollout 贵）下逐题门控的采样成本与收益比如何，讲者未展开，是直接可试的迁移点。
