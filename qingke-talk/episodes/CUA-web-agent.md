## 一句话总结

讲者把 web agent 的数据路线分成「合成环境」与「真实环境采集」两条，并各给一个解法：WebFactory 在建站时同步沉淀网站蓝图（导航图、页面语义、规范流程），用这份 knowledge 驱动任务合成、轨迹收集与训练，使合成任务从不可靠生成变成可执行、可验证的确定性过程，其上做 offline RL 的效果可媲美真实人工轨迹；WebChain 则用约 40 名标注员、近半年时间攒出 3 万多条真实轨迹（30 万条数据），带视觉上下文、结构快照与动作对齐三维监督，实验显示数据规模越大 grounding 与长程 planning 能力越强且未见饱和，最佳配方是「grounding RL → 思维链 SFT → planning RL」的三段式。

## 核心

### 两条数据路线与各自的坑

讲者先立框架：CUA 的数据供给目前主要两条路线。路线一，合成环境：生成大量可扩展环境，在其中采数据或做 online RL——可扩展、环境干净、低成本，但泛化存疑，合成环境上效果好放到真实环境可能出问题。路线二，真实环境采集：在亚马逊等真实网站上人工操作存轨迹，做微调或 offline 学习——真实，但贵，且真实在线环境有验证码、登录、网络噪声，数据不干净。两篇工作一一对应：WebFactory 解路线一，WebChain 解路线二。

### WebFactory：先有蓝图，再建网站

核心洞察是顺序问题：合成环境与环境训练通常解耦，但建站的人手里本来就有网站的蓝图，这份 knowledge 不该扔掉。它包含三部分：**导航图**（网站有哪些页面、页面间如何切换）、**页面语义**（每个页面有哪些功能与元素）、**规范流程**（如购物站的搜索 → 详情页 → 加购物车这类标准链路）。

有了蓝图，任务合成从「让大模型相对不可靠地编任务」变成确定性过程：任务分操作类（改变网页状态、执行某个任务）与信息检索类（在网页中搜索并返回答案）两类，合成的任务更可执行、可验证，也能生成更复杂的任务。实验结论（字幕口径，讲者指着表格口述）：有网站 knowledge 时合成任务的复杂度与质量明显提升；在合成网站上收集轨迹做 offline RL 后，性能可以媲美真实人工轨迹——「证明了合成环境这条路走得通，并且用 knowledge 驱动效果更好」。

还有一个更高维度的用法：整条 pipeline 本身可以当作模型「具身能力」的测度——让两个不同版本的 Claude（字幕作「两个版本的 cloud」）分别驱动建站、任务合成、轨迹执行全流程，再在公开 benchmark 上测产出的开源模型，不同模型的成绩差异就反映了其驱动全流程的能力。这相当于把 WebFactory 用成一个 embodiment benchmark。

### WebChain：30 万条真实轨迹与三维监督

动机是真实轨迹数据的公开供给严重不足、大量研究依赖私有数据集。WebChain 的规模（字幕口径）：一共收集 30 万条数据、3 万多条轨迹，平均每条轨迹十步以上；约 40 位数据标注员、做了大约小半年。

它存的不只是「截图 + 动作」，而是三维监督信号：**视觉上下文**（视口截图、交互元素标注）、**结构生态**（HTML 快照、无障碍树、DOM 路径）、**动作对齐**（click 的像素坐标、元素边界框、CSS 选择器定位）。讲者强调，正因为多存了这些维度，这份数据还能做很多轨迹本身之外的事（比如 grounding 增强）。

### 实验：规模没到顶，配方有讲究

验证分 grounding（精确找到交互元素）与 planning（完成多步复杂任务）两种能力。结论是数据规模与长程规划能力正相关：自有 benchmark 与公开 benchmark 上曲线一直往上、没有出现临界点——「现在的数据规模还远远没有达到足够多的情况」。

训练范式上探索了两个增强点。其一，grounding 数据增强：一条轨迹里用户点了一个按钮，但页面上其他九个按钮的坐标同样可从已收集数据里拿到，可据此合成更多 grounding 样本。其二，planning 的三段式配方效果最好（字幕中为橙色曲线）：先做 grounding 的 RL，再做思维链 SFT，最后做 planning 的 RL。这条「先定位、再推理、后规划」的顺序结论，比单看数据规模更有操作价值。

## 可迁移

- **建环境时把蓝图当资产留下**：导航图、页面语义、规范流程这类「建站 knowledge」能把任务合成从概率生成改成确定性构造，且天然带可验证性。自建任何 agent 环境（不止 web）时，生成环境的副产品规格说明应与环境一起版本化保存，它是后续任务合成与评测的 cheapest 杠杆。
- **轨迹数据多存维度**：存轨迹时把结构快照（DOM/a11y 树）与动作对齐（坐标、bbox、选择器）一并落盘，单份数据就能同时供 grounding 增强、planning 训练与离线评测复用，避免日后为每个用途重采一遍。
- **三段式配方**：grounding RL → CoT SFT → planning RL 的顺序可直接借鉴到任何「先定位、后多步执行」的 agent 后训练里；先把低层感知用 RL 打稳，再上思维链与规划。
