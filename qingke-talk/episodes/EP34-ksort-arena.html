2一句话总结

针对视觉生成模型的人类偏好评估，讲者团队把 Chatbot Arena 式的一对一比较改造成四路自由混战：用 $K$ 路比较提高单次投票的信息量，用「能力正态分布 + 表现噪声」的双重随机概率建模加贝叶斯更新替代 Elo 数值分以抗人类偏好噪声，再用 UCB 探索-利用匹配策略决定每轮让哪几个模型交手；仿真中给 50 个模型排名从 Elo 所需的 1 万多次比较降到平均 716 次（16.3 倍效率提升），新模型加入榜单不到 30 次投票即可定位。

3核心

背景：Arena 机制搬到视觉生成模型上，卡在效率与噪声

讲者先按 Chatbot Arena 论文的分类法铺垫：benchmark 可按「评估指标」（ground-truth 对照 vs 人类偏好）和「问题来源」（静态 vs 动态）分四象限，Arena 的优势是开放式 prompt + 实时平台，能跟上快速迭代的新模型与新玩法。但直接照搬到视觉生成模型有三个待解问题：

  1. 效率：人类投票成本高昂且不可再生，如何让每次投票的信息量最大化、不浪费人力；
  2. 可靠性：同一输入输出、不同评估者打分不一致是固有的人类偏好噪声，排行榜要在噪声下仍可信；
  3. 模态特性：图像/视频比文本更具感官直观性（扫两三秒即可整体判断），这个特性应当被利用来放大单次投票的信息量。

方法一： $K$ 路比较模式（本场实现取 $K = 4$ ）

不再一对一，而是 $K$ 个模型同题竞技、投票者给出全序（如 A > C > B > D）。近似相同的投票时间里，一次投票包含的成对信息远多于一对一。讲者给的生物学依据是视觉信息的直观性：评文本要逐字看对错、结构、关键词，评图像/视频则可快速形成整体与细节认知。 $K$ 的取值做过消融： $K = 2$ 收敛慢， $K = 6$ 初期下降快但后期震荡、且更新更难，最终系统取 $K = 4$ 。

方法二：概率建模 + 贝叶斯更新，得分取保守下限

Elo 的数值分对偏好噪声敏感，讲者改用概率建模，且叠了两层随机性：

  • 模型能力 $\theta$ 用正态分布 $N(\mu, \sigma^2)$ 表示（ $\mu$ 是能力均值， $\sigma$ 是不确定性）；
  • 在能力之上再叠一层「实际表现」的随机性（选手有超常/失常发挥），使建模对噪声与扰动鲁棒；
  • 最终得分不用均值，而用保守分估计，即按下限 $\mu - 3\sigma$ 排序，避免不确定性大的模型虚高。

更新走贝叶斯路线：以当前能力分布为先验、本轮比较结果为观测，按 $P(\theta \mid D) \propto P(D \mid \theta) P(\theta)$ 求联合后验，再对单个模型边缘化、代入期望与方差公式得到新的 $\mu$ 与 $\sigma$ 。先以 $K = 2$ 推导，再推广到 $K$ 路：一组 $K = 4$ 的投票等价于单个模型与其余 3 个模型并行各比一次，沿用同一更新公式。初始化统一取 $\mu = 0$ 、 $\sigma = 1$ 。Q&A 里讲者补充了噪声自适应性质：若新投票与先验矛盾， $\sigma$ 反而增大（不确定性上升、需要更多投票），与先验一致则 $\sigma$ 收缩——恶意投票主要拖慢收敛，不改变最终结果。

方法三：UCB 匹配策略，每轮投票先算「打谁最划算」

随机匹配会浪费投票（例如榜单已稳定时还让第一名打最后一名，收益趋零）。讲者把模型对之间的关系建模成多臂老虎机的一条臂，用 UCB 同时做两件事：

  • 探索：成对比较次数少的模型对，优先促成其交手；
  • 利用：能力越接近的模型越值得打（区分度最高，避免强弱悬殊的无效比较）。

组局方式是贪心的：先选一个「枢纽模型」——即参与比较总次数最少的模型——再按 UCB 得分贪心挑 $K-1$ 个对手组成一组。枢纽取最少参与者带来两个天然好处：从零排 50 个模型时各模型参与次数自动均衡、不会评估不足或过度；新模型加入时其参与次数天然最少，会在最初几十轮频繁当枢纽，快速追平老模型的比较量，实现新模型的实时评估。

实验：仿真四组消融 + 已上线的双榜单

仿真设定：给每个模型预设一个隐藏的「无序标签」当真实能力，投票结果由标签生成（可另加偏好噪声），榜单与标签算 MSE 看收敛；两种场景——50 个模型从头排名、向已有 50 模型榜单加 1 个新模型。

  1. 端到端对比：Elo 系统（ $K = 2$ 、数值建模、随机匹配）给 50 个模型排名需要 1 万多次比较；K-Sort Arena（ $K = 4$ 、概率建模、UCB 匹配）平均 716 次比较即收敛，效率提升 16.3 倍。
  2. 建模方式消融（固定 $K = 2$ + UCB 匹配）：无噪声时 Elo 在 3400 次比较时仍剧烈震荡，概率建模约 1500 次即稳定收敛（MSE 降为零）；加入 5% 偏好噪声后收敛变慢，但约 2000 多次仍收敛，Elo 继续震荡。
  3. 匹配策略消融（固定 $K = 4$ + 概率建模）：随机匹配在 3400 次时仍震荡；TrueSkill 式按能力相近匹配（只有利用、没有探索）同样严重震荡（很多模型没被充分比较）；UCB 在 700–800 次比较即收敛。
  4. 新模型评估：全随机选枢纽时新模型只有约 1/50 概率被选中、收敛极慢；枢纽随机 + UCB 匹配有改善（探索项会照顾比较次数少的新模型）；最终方案（新模型当枢纽 + UCB 匹配）在无噪声理想情况下，不到 30 次投票即可完成对新模型的评估。

线上系统：已在 Hugging Face Space 运行数月，投票界面给出明确标尺（50% 文本对齐程度 + 50% 图像真实性），支持全序投票与只选最佳两种模式，并备有预生成样例免去等待生成。截至讲授时：文生图榜单收录 34 个模型、收集 1530 张投票；文生视频榜单收录 13 个模型、收集 577 张投票（均为字幕口径）；讲者特别提到榜单上已有国内开源模型超越商业模型的结果。此外平台公开前经历了近 4 个月内测（邀请伯克利、新加坡国立、CMU、斯坦福、普林斯顿、北大等同行反馈），并设了投票贡献者排行榜。

Q&A 要点

  • 公平性/权威性：投票全程匿名、无名称与顺序先验；权威性靠算法可靠性 + 持续纳入最新模型积累。
  • 闭源模型怎么测：实时评估只支持开源权重或有 API 的模型；闭源模型只能人工逐个收集其输出做成缓存再投票，无法实时生成。
  • 平衡系数 $\alpha$ 怎么定：简单 grid search 定死后全场景通用，不追求逐场景最优。
  • 偏好随场景漂移：当前榜单是对齐与真实性各半的宏观口径；讲者表示后续可能拆出只看对齐或只看真实性的细分榜单。
  • 自有模型想上榜：可联系团队或在 Hugging Face 提 issue，最好提供开源权重或可调用 API。

5可迁移

  • 「比较次数少的当枢纽 + UCB 选对手」是一套通用的评估调度：任何靠两两/多路比较攒排行榜的场景（模型评测、prompt/策略 A/B、数据配比筛选）都可先按参与次数定枢纽、再按「不确定性 + 能力接近度」选对照组，把预算花在区分度最高的比较上，而不是随机配对。
  • 概率建模 + 保守分（ $\mu - 3\sigma$ ）排序的思路可直接迁移到内部 benchmark 榜单：带不确定性的分数比点估计更抗标注噪声，新模型/新 checkpoint 用很少样本就能给出可信的保守名次，适合做快速准入评估。
  • 投票标尺先行（把「对齐 50% + 真实性 50%」写在投票界面顶部）是低成本降噪手段：任何众包或内部标注任务，先把评估维度与权重显性化，比事后清洗更划算。

6疑问 / 下一步

  • 5% 偏好噪声下约 2000 多次收敛的数字是在「噪声即与真实标签相反」的简化仿真下得到的；真实众包噪声（系统性偏好、恶意投票、评估者水平差异）下收敛性与榜单稳定性的实测曲线，讲授未展开。
  • $K = 4$ 的全序投票在模型水平两极分化时，后段名次的判别精度是否退化（一眼能分出最好，但第 3 与第 4 名常难分），以及只选最佳模式与全序模式的票数如何统一进同一套贝叶斯更新，讲授未细讲。
  • 榜单票数（文生图 1530 张）相对 34 个模型的规模仍然不大；保守分 $\mu - 3\sigma$ 在票数稀疏时是否会系统性压低新模型名次、影响「不到 30 次定位新模型」的实际体验，值得看论文的真实数据部分核对。
