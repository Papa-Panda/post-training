2一句话总结

讲者沿一条主线串起自己的四件工作：先为 3D 世界建一个「可增量构建、可 attend、可回传梯度」的内部表征（neural field），再让大语言模型在这个表征上做开放词表推理与规划（3D LLM），进而让模型通过触觉、听觉、温度等交互通道主动向环境取信息（MultiPLY），最后用 diffusion 式世界模型先想象未来状态、再反推当前动作（3D-VLA）。核心判断是：2D 视觉语言模型缺的不是识别能力，而是没有 grounded 在 3D 物理世界上的表征，物理常识、功能可供性（affordance）与 3D 空间关系都无法从 2D 图片里长出来。

3核心

为什么必须有 3D 内部表征

讲者先复盘人类的做法：探索环境、收集观察、在脑中压缩出一个 internal representation（心理学家所说的 mental model），之后所有推理、规划、动力学预测都在这个内部模型里进行。由此他给 3D 表征定了四条硬要求：

  1. 增量构建：像人一样走一步看一步，而不是一次性把整个场景吐出来；
  2. 编码整个场景，不是停留在单个物体的表示；
  3. 可交互：需要时能 attend 到某个具体物体甚至某个局部（如椅子腿的底部）取出特征；
  4. 连续可导：后续推理、规划、动力学预测的 loss 能回传来修正表征本身。

传统表示（point cloud、voxel grid、3D mesh）四条全不满足：它们是显式的一次性整体表示、以物体级为主、取不出局部特征、下游 loss 也回传不回去。

第一件工作：用 neural field 做内部表征

讲者在 NeurIPS 2022 的工作中用 neural descriptor field 承载这个表征：空间中每一点都有一个 descriptor vector，想了解哪里就 query 哪里的特征。他类比说，这就像用手去摸某一点、把触觉特征取回来——query 机制本身就是「人与环境交互」的数学形式。因为每点的特征可导，concept grounding、推理等下游任务的 loss 能回传 refine 这个 field，感知模块不再是与任务无关的前置黑盒。

这直接对治了 neuro-symbolic 路线的老毛病：先感知分割、再符号推理的流水线里，推理出错（比如说某个物体「有三条腿」）的信息回传不到感知模块，感知也不知道当前任务需要它看什么。

到 CVPR 2023，讲者把这条线推向开放世界：agent 先探索环境收集多视图观察，用 CLIP 特征经 2D-3D 对齐 loss 投影进 3D，得到一个开放词表的 3D field，再用语言做 grounding / attention 把 3D 语义分割出来。

第二件工作：3D LLM——在 3D 表征上做推理与规划

神经符号方法虽然透明、错误可定位，但 operator 要人为定义，问题一旦 parse 不进预定义算子集就答不了。3D LLM 的目标是换成更灵活、更开放的推理：把多视图特征经 CLIP embedding 投影成 3D 内部表征，再用 Perceiver 框架通过 MLP 把 3D 特征与语言模型对接。

当时没有现成的 3D 语言数据，讲者用三路 prompting 造数据：

  1. 把场景 bounding box 喂给 ChatGPT 配 few-shot 示例，让它生成问答对；
  2. caption-based：让 BLIP 就某个角度提问作答，再把各角度信息整合成整个场景的描述；
  3. 把已有 captioning 数据改写成问答对。

在这个底座上 3D LLM 能做 3D detection、3D 空间中的规划（比如「打扫房间该做什么」）、房间探索（一步步增量建表征、判断沙发不在当前房间、经走廊继续找）、具身对话、grounding 问答与 3D captioning。

但 3D LLM 是黑盒，可能幻觉；神经符号透明却死板。讲者的折中是让大模型在推理过程中把中间步骤显式 decode 出来：先框出面包的 bounding box，再框出它右边的物体，最后回答那是沙拉——既保留神经符号的可解释与组合性，又保留大模型的灵活性。

第三件工作：MultiPLY——让模型主动向环境取信息

MultiPLY 针对的是多感官交互：视觉之外，人还有触觉、听觉（环境声与敲击声）、温度等通道。现有做法（如 ImageBind 式）把所有模态都映射到 image 上，讲者认为这不合理：两个长得一模一样的杯子，一个塑料一个陶瓷，只有摸一下、敲一下才能分辨材质。

MultiPLY 的两个关键设计：

  • 交互式数据引擎：仍用 ChatGPT 从房间 bounding box 生成任务并拆解成步骤，但每一步都放一个真正的具身 agent 进模拟器（Habitat 框架，自研触觉与音频模拟器）执行，由环境返回真实 feedback 作为下一步的 ground truth 输入。讲者强调这一步的验证过程正是 MultiPLY 的 prompting 优于 3D LLM 与 LLaVA 的地方——ChatGPT 生成的内容对不对，不靠人工核查，靠 agent 实跑验证。通过这种方式收集了 50 万条数据，覆盖 captioning、QA、具身对话、导航、物体操作、工具使用等任务。
  • Concept graph 表征：整个点云作为输入太占空间；人对房间先只有粗略表征，被要求细看时才走近细看，触觉、声音也都是交互时才获得。于是 MultiPLY 把环境组织成动态图：每个物体是一个 node，带各类属性（讲者举例含声音等信息），模型与 node 交互时才把更多信息取回来。

运行时 MultiPLY 以 concept graph 编码的对象表示、环境声音与问题为输入，逐步输出推理步骤或动作：听到微波炉响就走过去、找到后进一步观察、伸手摸、把感官数据 append 回大模型，再结合全部历史判断「这个东西还很热，不能吃」。讲者举例：模型可以通过敲击杯子判断材质，再把符合条件的杯子取回来；也可以做导航、重排、QA 与工具使用。

第四件工作：3D-VLA——世界模型先想象，再行动

最后一部分把 dynamics 接进来。讲者心目中的世界模型有三要素：对 3D 环境的内部表征、预测并模拟未来发生什么、用预测的未来指导当下的推理与规划。3D-VLA 的结构是：取 3D 表征输入，用 diffusion model 设想一个目标状态（把设想出的未来图像 / 点云放回大模型），最后生成控制动作。训练上 diffusion model 先单独预训练学会「联想未来」，再把它的 decoder 与大模型接起来；大模型带类似 RT-2 的 action token 输出机器人动作变化。

讲者给出三类验证：模拟中做 manipulation、真实世界中预测未来状态（如先模拟出「抽屉关上后应该是什么样」再执行）、以及长时程任务（先把易拉罐拿到百事可乐旁边，再把它放倒）。Q&A 中他补充：3D-VLA 在真实数据上 fine-tune 以弥合 sim-to-real gap；在 rebuttal 阶段加的消融显示，加世界模型比不加在任务执行上高出「几十个点」（字幕口径，讲者未给出精确数值，本纪要不精化）。

未来：生成式的大世界 + 生成式 agent

收尾展望是：用 diffusion 生成非常大的 3D 场景乃至 virtual community，同时生成其中的人物、动画与人-环境交互，得到近乎无限的 3D 世界数据，并把多感官数据包含进去，进而研究社会智能（social intelligence）。

Q&A 要点

  • 3D LLM 的输入到底是什么：用的是 voxel-based neural field，实际以点云形式输入——在环境中采样约 10000 个点（字幕口径），取每个点 query 到的 NeRF feature 作为输入。
  • 从 2D LMM 到 3D LMM 的瓶颈：多一个维度后信息量暴涨，位置信息尤其难学：2D 只需几百个 location token，3D 可能需要几万个，整个预测过程更难。
  • 目前能生成的空间尺度：主要是室内环境，一个房间或两到三个房间拼起来；应对更复杂机理的两条路——借长上下文把复杂信息全 encode 进去，或借 MultiPLY 式「增量探索 + 按需取回」的 ReAct 式检索。
  • 具身大模型的根本难点不在模型：各家对具身智能的定义、环境、机械臂形态、动作空间全不统一（他举 Google RT-2 在自家旧办公室采的数据换到新办公室就不能用为例），如何统一所有数据集是当前最难解的问题。
  • 世界模型里的物理一致性怎么保证：讲者认为当前 Sora 一类视频生成模型很难做到真正物理一致；两条办法——喂足够多物理正确的数据让模型自己学，或注入物理先验约束（如不碰撞、不穿模），乃至把经典物理模型嵌入生成过程。
  • 真实世界具身数据集该采什么：移动小车载机械臂进房间探索，可同时拿到导航、高层 planning 数据与低层 control 示范；他提到 Open X-Embodiment 一类工作已经在做类似的事。

5可迁移

  • 对后训练 / 数据工作的直接启发：MultiPLY 的数据引擎本质上是「LLM 造任务、agent 在环境里实跑、环境 feedback 当标签」的自验证数据飞轮——任务正确性不靠人工标注，靠可执行性验证。这与 coding data 里「生成题目 + 沙箱执行 + 用执行结果当监督」是同构的，且讲者明确说这正是它比纯 ChatGPT prompting 数据更可靠的原因。
  • Infra 视角看「表征四要求」：增量构建、可局部 attend、可导回传、可扩展到全场景——这组约束放在任何要承载下游 RL / 规划的状态表示上都成立；尤其「下游 loss 能回传修正表征」一条，等价于要求感知与策略不要做成不可微的硬流水线。
  • 3D-VLA 的「先想象目标状态、再出动作」与生成式规划（先采样目标、再反推动作）在结构上互通；讲者补充的世界模型消融收益（字幕口径约几十个点）提示：给 agent 加一个廉价的未来预测头，收益可能先于换更大的策略模型出现。

6疑问 / 下一步

  • 讲者对 sim-to-real 的处理是「在真实数据上 fine-tune 弥合一部分 gap」，但真实多模态数据（触觉、声音）的采集成本与模拟器保真度之间的账没有展开；他自己也判断未来真实世界多模态数据会更多，这个比例拐点在哪值得追踪。
  • Concept graph 以物体为 node 的组织方式在物体数量大、关系稠密的真实场景里如何扩展，讲授中没有给出复杂度口径；与长上下文路线（把一切 encode 成超长 token）的取舍，他列为开放问题。
  • 3D LLM 用 ChatGPT 造数据的三路 prompting 里，问答对的正确性在 MultiPLY 之前没有验证环节；这批数据的错误率与对最终模型的污染程度，讲授中未量化（这正是他后来在 MultiPLY 里补上 agent 验证的动机）。
