2一句话总结

BridgeData V2 把"机器人数据规模化"做成一个 \$4,000 买得起的配方：单台 WidowX 250 廉价臂、VR 遥操作，在 24 个玩具厨房/桌面环境里按"每场景多任务可行"的协议采集 60,096 条轨迹（50,365 条人工演示 + 9,731 条脚本化 pick-and-place），全部带事后众包语言标注；然后用同一套数据跑通 6 种 offline 方法（目标条件/语言条件的 IL + 目标条件 RL），证明三件事：模型容量上升带来单调增益、数据量上升带来增益、技能多样性 13 vs 3 在数据量相当时把未见 pick-and-place 从 0.30 拉到 0.65——覆盖轴的第三条边（skill 轴）被钉死了。

3大纲

  • 问题：单环境单任务数据换个实验室就失效，私有机器人数据别人复现不起
  • 采集：廉价臂加 VR 遥操作，24 个环境里多任务可行且不重置
  • 组成：50365 条人工演示加 9731 条脚本轨迹，事后众包语言标注
  • 评测：六种离线方法同台，已见与未见与跨机构三档分开记账
  • 证据：等量对照下 13 技能胜过 3 技能，未见任务 0.30 到 0.65
  • 边界：四路视角并非每条都有，跨机构只测 3 个任务且每任务 10 次

7今天的 3 问

  1. 采集协议刻意让每个场景"多任务可行"（不 reset、随时换任务），迫使策略必须看任务条件 $c$ 而不是从观测 $o$ 推断任务。用互信息怎么形式化这个设计？旧 Bridge（单场景任务少）的数据分布里 $I(\text{task}; o) \approx H(\text{task})$ 会导致什么捷径？（见数学视角 §2：策略学 $\pi(a \mid o)$ 捷径，条件 $c$ 的梯度约等于 0；Bridge V2 用高 $H(\text{task} \mid o)$ 逼出 $I(c; a \mid o) > 0$ 。）
  2. 13 skills vs 3 skills、数据量相当（28k vs 27k），未见 pick-and-place 从 0.30 升到 0.65——sweeping、folding 这些"看起来不相关"的技能为什么能帮到 pick-and-place？是共享表征（视觉编码器、抓取几何）还是状态覆盖？（见数学视角 §3：共享编码器 $\varphi$ 的训练支撑被撑大，未见任务的观测落进已见支撑——"轴扩张 > 点加密"在 skill 轴上的版本。）
  3. 16% 的脚本化次优数据对 BC 是噪声、对 CRL（offline RL）是礼物。从"分布覆盖 vs 分布匹配"的角度，次优数据到底补了什么？为什么 offline RL 需要它而 BC 不需要？（见数学视角 §4：BC 要 $p_{\text{expert}}(a \mid o, c)$ 的分布匹配，offline RL 要 $\text{supp}(p_{\text{data}})$ 的分布覆盖以约束 value 外推。）

8问答补充（2026-09-08）

以下 4 组问答来自 2026-09-08 当晚用户对今日卡片第 1 问（互信息视角下的任务注意力协议）与技能多样性消融的追问，原样归档。

Q1： $H(\text{task} \mid o)$ 是啥？任务条件是啥？

问题原文："完全没有思路啊 $H(\text{task} \mid o)$ 是啥？任务条件是啥"

核心答案（字母表先行）： - $\text{task}$ ：采集员当时在干哪件事（如"把勺子放进杯子"、"叠毛巾"）；每条轨迹有一个 task 标签。 - $o$ ：观测，一张 128×128 的 RGB 图像（机器人看到的画面）。 - $c$ ：任务条件——额外告诉策略"这次要干什么"的输入，一张目标图像（"最后要长这样"）或一句语言指令（"叠毛巾"）。 - $H(\text{task})$ ：熵，任务种类越多越均匀则越大。 - $H(\text{task} \mid o)$ ：条件熵——已经看到图像 $o$ 了，还剩多少"在干哪个任务"的不确定性。 - $I(\text{task}; o) = H(\text{task}) - H(\text{task} \mid o)$ ：互信息，图像告诉了你多少关于任务的信息。 - $\pi(a \mid o, c)$ ：策略，看到图像 $o$ 和条件 $c$ 输出动作 $a$ 。 - $I(c; a \mid o)$ ：给定图像后，条件 $c$ 还能给动作提供多少额外信息——衡量"模型到底有没有在用 $c$ "。

例子：旧 Bridge 是单一场景单一任务， $H(\text{task} \mid o) \approx 0$ ，策略学捷径 $\pi(a \mid o)$ 即可，语言指令只是摆设（ $c$ 通路的梯度 $\approx 0$ ）。Bridge V2 同场景多任务、随时切换不 reset， $H(\text{task} \mid o)$ 很大，策略必须读 $c$ 才知道干嘛—— $I(c; a \mid o) > 0$ 。

结论：V2 是在用数据分布做"loss 设计"——让任务条件变得不可或缺，模型才被迫学会用它。迁移到 agent RL：想让 agent 听指令，就要保证"同一观测下，指令不同、正确行为也不同"——指令必须携带观测里没有的信息。很多 instruction-following 数据集训出的模型"不听话"，根子常在这里：不是模型不行，是 $H(\text{task} \mid o)$ 太小，模型走了捷径。

Q2： $I(c; a \mid o) = H(c \mid o) - H(c \mid a, o)$ ？

问题原文：" $I(c;a \mid o) = H(c \mid o) − H(c \mid a,o)$ ?"

核心答案：完全正确，且有对称写法：

$$I(c;a \mid o)=H(c \mid o)-H(c \mid a,o)=H(a \mid o)-H(a \mid c,o)$$

  • $H(c \mid o)$ 大：只看图像猜不出给了哪条指令——V2 采集协议故意让它大（旧 Bridge 里它 $\approx 0$ ）。
  • $H(c \mid a, o)$ 小：看到图像加动作，就能反推出指令（看到叠毛巾的动作，指令肯定是"叠毛巾"）。
  • 差值 $> 0$ ：指令携带了图像里没有的信息，而且这部分信息必须流进动作，策略才学得好。

第二个写法 $H(a \mid o) - H(a \mid c, o)$ 是训练视角：走捷径的策略 $\pi(a \mid o)$ （不用 $c$ ）的动作不确定性，永远比把 $o$ 和 $c$ 都作为输入的最优策略高，差的就是这个 gap——在 V2 数据上，不读指令注定吃亏。

Q3：第一个等式为啥成立？

问题原文："第一个等式为啥成立？"

核心答案：从条件互信息的 KL 定义出发一步代数。条件版本 = 先固定 $o = o$ 算普通互信息，再对 $o$ 取期望：

$$I(c;a \mid o)=\sum_o p(o)\sum_{c,a}p(c,a \mid o)\log\frac{p(c,a \mid o)}{p(c \mid o)\,p(a \mid o)}$$

关键一步：分子按链式法则拆开， $p(c,a \mid o)=p(c \mid a,o)\,p(a \mid o)$ ，代入后 $p(a \mid o)$ 上下约掉：

$$\frac{p(c,a \mid o)}{p(c \mid o)\,p(a \mid o)}=\frac{p(c \mid a,o)}{p(c \mid o)}$$

于是对数拆成两项：

$$I(c;a \mid o)=\underbrace{\sum_{o,a,c}p(o,a,c)\log p(c \mid a,o)}_{-H(c \mid a,o)}\;-\;\underbrace{\sum_{o,c}p(o,c)\log p(c \mid o)}_{-H(c \mid o)}$$

$$=H(c \mid o)-H(c \mid a,o)$$

证毕。对称写法同理：把比值改写成 $p(a \mid c,o)/p(a \mid o)$ ，即得 $H(a \mid o)-H(a \mid c,o)$ 。

Q4：13 skills vs 3 skills、数据量相当（28k vs 27k）啥意思？

问题原文："13 skills vs 3 skills、数据量相当（28k vs 27k） 啥意思？"

核心答案：论文里一个干净的对照实验设计： - 从 BridgeData V2 切出两个子集：子集 A = 28k 条轨迹、仅 3 种技能；子集 B = 27k 条轨迹、13 种技能（pick-and-place、sweeping、folding、擦桌子、开抽屉……）。 - 数据量 $N$ 基本钉死，唯一的差别是技能多样性。 - 同样方法在两个子集上各训一个策略，都在没见过的 pick-and-place 任务上评测：0.30 → 0.65。

为什么要"数据量相当"：如果直接拿"60k 多样数据 vs 10k 单一数据"比，涨点分不清是数据多了还是种类多了。把 $N$ 钉死、多样性作为唯一变量，超 2 倍的增益就只能归因于多样性本身——这是 Day15（OXE 没公开混合权重）和 Day16（DROID 没做等量消融）都没做干净的事。

直觉：sweeping 并没有"教会" pick-and-place 扫地，而是 13 个技能合起来把共享视觉-运动表征的训练支撑铺得更宽，未见任务的观测落进了已见支撑里——"支撑扩张 > 单点加密"在 skill 轴上的版本。

Bridge 是数据论文，数学就是 offline 学习的目标函数 + 覆盖轴的泛化直觉。统一框架：条件行为克隆 $\pi(a \mid o, c)$ 及其 value 形式。

1) State / observation / action / objective

  • Observation $o$ ：128×128 RGB 过肩主视角图像（训练只用这一路；RT-1 用 320×256 + 观测历史）。原始采集是 640×480，另有两路随机位姿 RGB + 腕部 RGB + RGBD 深度（多数轨迹只有主视角）。
  • Action $a$ ： $a = (\Delta x, \Delta y, \Delta z, \Delta r_x, \Delta r_y, \Delta r_z, g)$ ，前 6 维是末端执行器笛卡尔相对位姿变化（连续）， $g \in \{0, 1\}$ 是夹爪开合（离散）；控制频率 5 Hz，平均轨迹 38 步（约 7.6 秒）。
  • Condition $c$ ：目标图像 $g_{\text{img}}$ （GCBC / D-GCBC / ACT / CRL）或语言指令 $\ell$ （LCBC / RT-1）。
  • 六种方法，一个目标家族（全部在学 $p(a \mid o, c)$ 或其 value 形式； $\theta$ 是参数， $\mathcal{D}$ 是 BridgeData V2 离线数据集）：
  • GCBC： $\mathcal{L}_{\text{BC}}(\theta) = -\mathbb{E}_{(o,a,c) \sim \mathcal{D}}[\log \pi_\theta(a \mid o, c)]$ ， $o$ 经 ResNet-34 编码的朴素目标条件 BC。
  • D-GCBC： $\mathcal{L}_{\text{diff}}(\theta) = \mathbb{E}_{k,\epsilon}[\|\epsilon - \epsilon_\theta(a^k, o, c, k)\|_2^2]$ ， $a^k$ 是第 $k$ 步加噪后的动作， $k = 1..K$ 是扩散步， $\epsilon \sim \mathcal{N}(0, I)$ ——Day12 的 DDPM 数学，加了条件 $c$ 。
  • ACT：预测动作块 $A = (a_t, \dots, a_{t+H-1})$ ， $H$ 是块长度；CVAE 的 ELBO 为 $\mathbb{E}_{q(z \mid A,o,c)}[\log \pi_\theta(A \mid o, c, z)] - \mathrm{KL}(q(z \mid A,o,c) \| p(z))$ ， $z$ 是捕捉演示多峰性的隐风格变量，transformer 做编码。
  • CRL：目标条件 value 函数 $Q(o, a, g)$ 参数化为对比表示的 log-linear 形式，把 goal-conditioned RL 写成表示学习问题。
  • LCBC： $\ell$ 经 MUSE 句向量编码，ResNet-34 + FiLM 条件注入视觉特征，MLP 策略头输出动作；FiLM 即用语言向量对视觉特征做缩放/平移调制。
  • RT-1：每维动作离散成 256 个 bin， $p_\theta(t_{1:7} \mid o_{\text{hist}}, \ell) = \prod_{j=1}^{7} p_\theta(t_j \mid t_{<j}, o_{\text{hist}}, \ell)$ ，EfficientNet token + decoder-only transformer——Day09 RT-2 数学的直接复用， $o_{\text{hist}}$ 是观测历史。
  • 对应到实现：官方 Jax 仓库 rail-berkeley/bridge_data_v2 提供 GCBC / D-GCBC / GC-IQL / CRL / LCBC 五套训练代码与预训练 checkpoint，experiments/train.py 一键切换 --config ...:METHOD。

2) 任务注意力协议的互信息形式化：用数据分布设计代替 loss 设计

旧 Bridge：每个场景只有少数预设任务， $I(\text{task}; o) \approx H(\text{task})$ ——从观测几乎能确定任务，策略学到捷径 $\pi(a \mid o)$ ，条件 $c$ 的梯度约等于 0，语言/目标条件形同虚设。

Bridge V2 的采集协议（三件套：每场景多任务可行、不 reset 连续采集、每 50 条随机化相机/物体/工作区）把 $H(\text{task} \mid o)$ 推高：同一张观测可能对应"把勺子放进碗里""擦桌子""开抽屉"中的任意一个。要降低 $\mathcal{L}_{\text{BC}}$ ，策略必须让 $I(c; a \mid o) > 0$ ，即真正使用条件。这是"数据集设计 ⇒ 归纳偏置"的干净例子：不是改 loss，而是改数据分布让捷径消失。

工程对应：语言标注是事后众包的（标注员根据轨迹首末帧描述"物体最终位置"，部分由 Microsoft Research 协助标注）——所以 $\ell$ 是对轨迹的后验描述而非采集意图。这解释了评测现象：语言方法在未见物体上吃亏（物体名在训练分布里没被 ground 过， $p(\ell_{\text{new}})$ 落在 MUSE 嵌入空间的未见区域）。

3) 技能多样性的 scaling：覆盖三轴的第三条边

统一框架（串联 Day15/16/17）：泛化误差 $\lesssim d(P_{\text{test}}, \text{supp}(P_{\text{train}}))$ ， $P_{\text{test}}$ 是部署分布， $\text{supp}(P_{\text{train}})$ 是训练混合的支撑。三篇各扩张一条轴：

  • Day15 OXE：embodiment 轴（22 种身体，场景基本固定在实验室）；
  • Day16 DROID：scene 轴（564 真实场景，固定 Franka 身体）；
  • Day17 Bridge：skill 轴（13 技能、24 环境，固定 WidowX 身体）。

Bridge 的关键消融把"多样性"和"数据量"解耦：28k 轨迹 / 3 skills vs 27k 轨迹 / 13 skills， $N$ 相当，未见 pick-and-place 成功率 0.30 → 0.65。注意这比"加数据"更强： $N$ 固定时，多样性本身带来超过 2 倍增益。

机制解释（多任务表示学习）：设共享编码器 $\varphi: o \mapsto z$ ， $z$ 是视觉-运动表征，策略 $\pi(a \mid z, c)$ 。13 个技能共享 $\varphi$ 和底层原语（抓取几何、接触前对齐、手眼协调）；sweeping / folding 的数据虽然任务不同，但它们把 $\varphi$ 的训练支撑撑大，让未见 pick-and-place 的观测 $o'$ 落进已见支撑——于是 $d(P_{\text{test}}, \text{supp}(P_{\text{train}}))$ 缩小。这是 Q2 的答案：不是"sweeping 教会了 pick-and-place 扫地"，而是"所有技能合起来把表征的支撑铺得更宽"；也是 Day16"支撑扩张 > 单点加密"在 skill 轴上的版本。

4) 次优数据的双面性：BC 要分布匹配，offline RL 要分布覆盖

16% 脚本化 pick-and-place 数据（高随机、常失败）：对 BC 是标签噪声—— $\mathcal{L}_{\text{BC}}$ 会把它当专家拟合，稀释 $p_{\text{expert}}(a \mid o, c)$ ；对 CRL 这类 offline RL 是覆盖礼物—— $Q(o, a, g)$ 的估计需要在 $(o, a)$ 空间有支撑，随机策略的宽覆盖缓解了 value 外推高估。形式化：BC 要的是分布匹配（mode 越干净越好），offline RL 要的是分布覆盖（ $\text{supp}(p_{\text{data}})$ 越宽，value 在越宽的动作上被约束）。论文明说次优数据可被 offline RL 利用——数据论文里少见的诚实：同一批数据对不同算法家族价值符号相反，采集时就想好"这批数据是给谁吃的"。

5) 和系统实现的对应

  • 硬件 infra：WidowX 250 六自由度臂 + VR 遥操作，整套约 \$4,000、全公开采购、两周到货——"把数据采集变成本科生 lab 也能复现的事"；这是 Bridge 路线相对 DROID（Franka 贵臂 + 52 栋建筑物流）的根本 infra 差异。
  • 采集 infra：不 reset 连续采集（省掉 reset 的人力/时间税）；每 50 条随机化相机位姿 + 物体 + 工作区位置；事后众包语言标注。
  • 数据 infra：JPEG/PNG + pkl 原始包；转换链 raw → numpy → TFRecord（data_processing/）；TFDS RLDS 版（256×256 下采样）+ 推荐 Octo 的 data loader——直接喂给 Day13 Octo 那套生态；CC-BY 4.0。
  • 评测：10 trials/任务（scaling 消融 20 trials），seen / unseen / 跨机构三档；RT-1 在跨机构 zero-shot 退化最小（平均 0.47 → 0.40），语言方法退化最大——容量和离散化带来鲁棒性。

6) 假设与数学没有覆盖的真实误差

  • 任务全是低精度操作（论文 Discussion 自认）：无大力/动态/高精度插入——泛化结论的外推边界是"玩具厨房级"任务； $\mathcal{L}_{\text{BC}}$ 在这套数据上可解，不代表在精细操作上可解。
  • 全部数据单机构采集（Berkeley），"跨机构"评测只是 Lab1 → Lab2 的一次验证——环境多样性的真实上限不如 DROID 的 52 栋建筑。
  • 语言标注是事后众包：标注员没看采集意图，只能从首末帧推断—— $\ell$ 与真实意图的对齐有噪声；未见物体名直接 OOV，这是语言方法 unseen 任务拉胯的结构性原因，数学上即 $p(\ell)$ 的支撑缺口。
  • 单一 embodiment（WidowX）：论文自己说下一步是 multi-robot 数据集——这正是 Day15 OXE 回答的问题，Bridge 是 OXE 的"上游原料"之一。
  • 平均轨迹 38 步 @5Hz ≈ 7.6 秒：全是短时程技能，长程任务组合不在验证范围（Day14 π₀.₅ 的子任务分层是另一条线）。

10核心

  1. Motivation: CV/NLP 靠"大数据 + 大模型"拿到泛化，机器人学想抄这条路，但已有数据集要么单环境（换个 lab 就用不了）、要么私有机器人（学术界复现不起）、要么单任务（策略从观测猜任务、不看任务条件）。问题：能不能用 \$4,000 的公开硬件，做出一个"别的 lab 拿去就能用"的多任务数据集？和 Physical AGI 的关系：这是数据飞轮里"规模化采集"那一环的平民化方案。
  2. System / Method: WidowX 250 + VR 遥操作 + 四路相机（RGBD 过肩 + 两路随机位姿 RGB + 腕部 RGB，640×480，5 Hz）；采集协议三件套：每场景多任务可行、不 reset 连续采、每 50 条随机化；50,365 条人工演示 + 9,731 条脚本化 pick-and-place；全部事后众包语言标注；7 维动作（6D 笛卡尔相对 + 夹爪离散）。
  3. Training / Data Details: 60,096 轨迹 / 24 环境 / 13 技能 / 100+ 物体；CC-BY 4.0；TFRecord + TFDS RLDS 双格式；评测 6 种方法（GCBC、D-GCBC、ACT、CRL、LCBC、RT-1），10 trials/任务；Sim 数据：无；Reward：纯 BC / 对比 RL，无外部 reward。
  4. Key Tricks（3个最值得抄的）:
  5. "多任务可行"采集协议：不预设任务清单、不 reset，让采集员在场景里做任何可行的事——用数据分布设计（ $H(\text{task} \mid o)$ 高）代替 loss 设计，逼策略真正使用任务条件。这是数据 infra 里最便宜的归纳偏置。
  6. 脚本化次优数据当 RL 的覆盖礼物：9,731 条高随机 pick-and-place 对 BC 是噪声、对 offline RL 是 $(o, a)$ 覆盖——采集时就想好"这批数据是给谁吃的"，一种数据、两种算法价值。
  7. 等量消融钉死多样性因果：28k/3-skills vs 27k/13-skills， $N$ 相当时多样性带来 0.30 → 0.65——数据论文的 claim 就该这么做对照（对比 Day15 OXE 没公开混合权重、Day16 DROID 没做等量消融）。
  8. Results: seen 任务上目标条件方法相当（平均约 0.41–0.49）、RT-1 碾压 LCBC（0.49 vs 0.23）；未见物体/环境非零成功，语言方法在未见物体名上吃亏；跨机构 zero-shot 全部非零，RT-1 退化最小（0.47 → 0.40）；模型容量上升严格单调增益；数据量上升 seen + unseen 都增益；技能多样性 13 vs 3：未见 pick-and-place 0.30 → 0.65。

11可迁移 / Transfer

  • 方法在 held-out 上是否 transfer？是——unseen 物体/环境/机构三档都是 held-out；技能多样性的 0.30 → 0.65 是跨技能泛化的直接证据。模型 vs 框架贡献：框架（数据）贡献主导——6 种方法同一套数据，增益与排序主要由数据多样性解释；RT-1 的架构增益是例外（0.49 vs 0.23 说明容量 + 离散化 + 观测历史也是真东西）。
  • 对你 Infra → Post-training → Physical AI 迁移的 1-2 个直接启发：
  • Post-training 数据配方的"三轴覆盖"思维：embodiment（OXE）× scene（DROID）× skill（Bridge）——做 agent RL 数据时先问"我的三轴分别覆盖到哪"，一次扩张一轴，别三轴一起铺；评测按"与训练支撑的距离"分桶。
  • "采集协议即归纳偏置"：Bridge 证明不用改 loss，改数据分布（多任务可行、不 reset）就能逼模型用条件——做 SFT/RL 数据时，prompt 与任务的可辨识性设计和 loss 设计同等重要；先检查 $I(\text{task}; o)$ 是不是已经把任务泄露了。
  • Infra 视角：\$4,000 公开硬件 + VR 遥操作 + 不 reset 采集 + 事后众包标注 = 低成本真实数据采集的 infra 四件套；TFRecord + TFDS RLDS 双格式 + 5 个方法的预训练 checkpoint 是数据集发布的黄金标准（对比 OXE 没公开混合权重）；评测成本锚点：seen/unseen/跨机构三档 × 10 trials/任务是"数据论文"eval 预算的参考线。

12疑问 / 下一步

  • 没看懂的 / 想深挖的 1 个问题：CRL（对比 RL）的 log-linear value 参数化在 Bridge 数据上和 GCBC 成功率相当（平均 0.42 vs 0.49）——offline RL 的理论优势（stitching、次优数据利用）在这套评测里没兑现，是任务太简单（短时程、BC 可解）还是 CRL 的实现没吃到脚本数据的红利？值得翻附录 B 的实现细节和 GC-IQL 的 checkpoint 对比。
  • 如果要复现 / 小规模试，第一个实验做什么？拿 Bridge 开源 TFDS 子集（只取 3 个技能 vs 13 个技能、等量轨迹），在仿真或真机 WidowX 上训 GCBC，复现 0.30 → 0.65 的技能多样性增益曲线——验证"轴扩张 > 点加密"在 skill 轴上成立，顺手验证 $H(\text{task} \mid o)$ 协议是否真让策略用上了语言条件（mask 掉 $\ell$ 看成功率掉多少）。

元信息修正

  1. 四路视角是硬件上限，不是每条轨迹的标配：附录 A 的传感器分布图写明，采集过程中相机是逐步加上去的，多数轨迹只有固定的过肩主视角，带齐全部 4 路视角的数据非常少。初读「核心」里写的四路相机并列，容易读成每条都有四路。训练口径更窄：§4 写明所有方法只用过肩视角，图像为 128×128 ，只有 RT-1 用 320×256 并带观测历史。数据集口径与策略口径必须分开，与 Day16 复习里相机口径收紧是同一类错误。
  2. 技能与任务是两个定义，13 的计数有规则：§3.3 定义，技能指运动相似的轨迹组，任务指语言指令相似的轨迹组；同一种运动换物体仍是同一技能、不同任务。表 1 脚注的计数规则是：pick-and-place 只算一个技能，正反运动如开抽屉与关抽屉合算一个技能。附录表 5 的 13 个技能完整清单还包括开合纸箱盖、拧旋钮、翻开关、拉拉链与转杠杆，初读的举例清单并不完整。以后引用 13 时要连计数规则一起引，否则与别的数据集的技能数不可比。
  3. 已见与未见两张表的平均数不可直接比：表 2 是 8 个已见任务、每任务 10 次，平均为 GCBC 0.49 、D-GCBC 0.49 、ACT 0.41 、CRL 0.42 、LCBC 0.23 、RT-1 0.49 。表 3 是另外 6 个未见任务，平均为 GCBC 0.60 、D-GCBC 0.55 、ACT 0.28 、CRL 0.52 、LCBC 0.08 、RT-1 0.50 。两组任务不同，所以 GCBC 未见平均高于已见平均不说明未见更容易泛化，只说明任务集合不同。真正可读的是同表内的塌陷：语言条件的 LCBC 从已见 0.23 掉到未见 0.08 ，论文给的原因是未见物体名在数据里没有被锚定。
  4. 跨机构的 0.47 到 0.40 只是 3 个任务的子集平均：表 4 只评了 3 个已见任务、每任务 10 次，RT-1 在这个子集上从 Lab 1 的 0.47 掉到 Lab 2 的 0.40 。它不是全部已见任务上的退化幅度。同一张表里 ACT 的平均从 0.03 升到 0.10 、CRL 从 0.13 升到 0.20 ，在每格 10 次的规模下这种反向波动就是噪声量级；论文的原话只是目标条件方法退化更多、所有方法在 Lab 2 仍有非零成功。初读写的「RT-1 退化最小」只能在这个 3 任务子集内成立。
  5. 技能多样性实验的范围比标题窄：§5.3 的等量实验只用 GCBC 一个方法、每策略 20 次试验、只测一个未见 pick-and-place 任务。3 技能子集具体是 pick-and-place 、pushing 与 wiping ，不是任意 3 个技能；13 技能一侧是 27k 条、3 技能一侧是 28k 条。结论应写成「在这一个方法与这一个未见任务上，多样性带来 0.30 到 0.65」，不能直接外推成所有方法与所有未见任务的定律。
  6. 文中有两个不同的 0.65，不能混引：图 5 的 0.65 是技能多样性实验里 13 技能 GCBC 在未见 pick-and-place 上的成功率。附录表 6 还有另一个 0.65 ：GCBC 从旧 Bridge 加 PTR 的组合换到 BridgeData V2 后，在 put marker in bowl 这一未见任务上从 0.05 升到 0.65 ，两任务平均从 0.08 升到 0.70 。后者同时变了数据量、环境数与技能数，是规模与多样性的联合效应，不是纯多样性证据。两个 0.65 端点相同、实验完全不同，引错一个就会把联合效应冒充成单变量因果。另外补版本口径：arXiv 2308.12952 的 v3 修订于 2024-01-17 ，初读只记了 CoRL 2023 与编号。

一句话总结

三十多天后回看，Day17 的耐久贡献不是便宜本身，而是技能层的两个设计：第一，采集协议让同一观测下有多个可行任务，策略不读任务条件就做不对；第二，等量对照证明在总量钉死时，技能多样性本身就能抬高未见任务表现。便宜的 WidowX 只是让这两件事能被别的实验室买回去复现的前提。

  • vs Day16 DROID（直接对比，同专题相邻篇）：等量对照的同门。Day16 复习已经查明 DROID 的 §V-C 做了 7362 条等量对照，在场景轴上拆开了覆盖与总量；Bridge 的 §5.3 在技能轴上做同一件事。初读 Day17 时写的「DROID 没做等量消融」是错的，本轮收回。两篇合起来的规则才是完整的：场景轴与技能轴各自都过了等量门，但没有任何一篇替第三条轴背书。体量取舍仍正交：DROID 把预算花在 564 个真实场景，Bridge 花在 24 个环境内的 13 个技能与低价硬件。
  • vs Day15 OXE（直接对比，同专题上游）：Bridge 是 OXE 混合里被消融验证过的关键成分——Day15 复习里去掉 Bridge 后 emergent skills 大幅下降，与本篇的技能多样性结果互相印证：OXE 吃到的泛化有一部分正是 Bridge 提供的技能覆盖。但不对称也要记：OXE 至今没有公开各成分的混合权重，而 Bridge 的等量实验恰好说明权重与构成不入账，多样性结论就无法在聚合层复现。
  • vs Day12 Diffusion Policy 与 Day09 RT-1（直接对比，分专题上游）：Bridge 评测里的 D-GCBC 是 Day12 扩散数学的目标条件版，它出现 jerky 行为的原因论文写得很具体：没有观测历史、也没有动作块，在多峰分布的模态之间振荡。ACT 在附录 B.3 里把动作块长度从原版的 100 改到 5 ，理由是控制频率只有 5 Hz 且轨迹只有约 50 到 100 步——动作块长度是频率与时程的函数，不是可照抄的常数，这正是 Day12 三个 horizon 合同在别人评测栈里的回声。RT-1 则是唯一带历史与更高分辨率的方法，它的优势不能只记在容量上。
  • 跨阶段 vs Day20 RLPD（RL 与 sim2real 段）：初读最看重的「脚本数据是 offline RL 的礼物」在本文里其实没有被隔离验证。9731 条脚本轨迹占 16% ，论文只说受益于次优数据的方法可以利用它、使用者也可以排除它，没有报告开与关脚本数据的对照。而 CRL 这个唯一的 offline RL 方法在已见表上是 0.42 、未见表上是 0.52 ，都没有超过 GCBC 的 0.49 与 0.60 。Day20 RLPD 的教训在这里适用：离线数据要兑现成在线或离线 RL 的优势，需要采样与正则等整套机制配合，光有覆盖不够。
  • 跨阶段 vs Day30 数据飞轮与 Day34 π0.7（评测与最新进展段）：Bridge 的低价加可复现是飞轮的入口成本问题——别的实验室能用约 \$4,000 在两周内买齐同一套硬件，跨机构评测才做得成；飞轮的第一环不是采得多，是别人采的能与你的对齐。Day34 π0.7 的组合泛化可以看成技能层的问题升级版：Bridge 只证明多技能共训能帮到一个未见的同族任务，π0.7 问的是没教过的任务组合能不能做出来，两者之间隔着的正是本篇没有测的组合评测。

核心

  1. 动机重读：便宜是实验设计，不是省钱：初读把 \$4,000 读成成本优势，本轮改读成可复现设计。私有贵硬件的数据集即使公开，别人也无法在自己的实验室复现同一身体与同一评测；WidowX 公开可买，才使表 4 的跨机构零样本评测成为可能。便宜在这里买到的是外部效度，不是折扣。
  2. 机制深挖一：稀释悖论让技能迁移的证据更硬：等量对照里，13 技能一侧总量还略少，是 27k 对 28k ，而且 pick-and-place 在 13 技能中的占比远低于在 3 技能中的占比。也就是说，多样一侧的目标技能密度被稀释了，未见 pick-and-place 反而从 0.30 升到 0.65 。若增益只来自目标技能练得多，这个结果不可能出现；它支持的解释是共享表征与运动原语的迁移——抓取前的对齐、接触与重定向这些原语被其他技能反复练到。初读的表示学习解释方向对，但没有注意到稀释这一点，证据其实比初读写的更强。
  3. 机制深挖二：目标条件方法的目标是事后采样出来的：附录 B 写明，目标条件方法训练时，目标是从同一轨迹的未来时刻里均匀采样的一帧观测。于是目标条件本质上是一种事后重标记：一条轨迹天然提供多个可达目标，数据利用率被放大，但目标分布也被轨迹自身的未来限制住——策略学到的是「到达这条轨迹后来到过的地方」，不是任意语言指定的目标。这解释了为什么目标条件方法在已见任务上整齐，却在需要区分锅的朝向这类目标细节上吃亏，论文在跨机构一节也专门点了 flip the pot upright 这一例。
  4. 机制深挖三： scaling 结论的方法范围很窄：容量与数据量的 scaling 图测的都是 GCBC ，容量实验只用 moving a spoon 一个任务，数据量实验用分层抽样保住多样性只减条数。论文标题级的「随数据与容量上升而变好」严格说只在这一个方法上被系统地测过；其余 5 个方法是兼容性展示，不是 scaling 证据。把兼容性评测与 scaling 评测分开记账，是这篇最容易被综述文章混淆的地方。

边界

  1. 统计规模：主表每任务只有 10 次试验，技能对照每策略 20 次，单格成功率的噪声足以解释跨机构表里 ACT 与 CRL 的反向上升。0.30 到 0.65 是 20 次量级的差，方向可信，但把 0.65 当成可复现的点估计去做决策仍然危险。
  2. 环境口径：24 个环境里多数数据来自 7 个玩具厨房，其余是桌面、玩具水槽与玩具洗衣机等。环境多样性远小于 Day16 的 564 个真实场景，「跨环境」在本篇里主要是跨玩具厨房与桌面，不是跨真实家庭。
  3. 任务边界：论文讨论部分自认任务总体低精度，不需要大力、动态或低容差插入。技能多样性的结论外推到精密装配或力控任务没有证据；平均轨迹只有几十步，长程组合任务不在验证范围内，那是 Day14 的分层路线要回答的。
  4. 语言条件的结构性缺口：语言是采集后众包补标的，标注员只看轨迹描述最终位置，未见物体名没有在训练里被锚定，所以 LCBC 在未见任务掉到 0.08 是数据构成的结果，不全是模型能力问题。用本篇比较语言条件与目标条件时必须带上这一条。
  5. 何时失效：当新任务的运动原语与 13 个技能几乎不相交时，多技能共训只会稀释目标技能密度，稀释悖论会反过来咬人；当评测任务需要精确力控或长程组合时，本篇的覆盖结论整体不适用。

迁移到 post-training / Agentic RL Infra

可执行的一条主映射：把 Bridge 的等量技能门与条件泄漏审计做成 agent 数据配方的两道入训检查。一，等量多样性门：任何「加技能种类能涨泛化」的宣称，先固定总轨迹数或总 token 数，只换构成——窄技能集与宽技能集各训一版，只比未见任务桶，试验次数要足够区分噪声；过门后才批准扩量，过不了门说明涨的是总量不是多样性。二，目标技能密度入账：每次混合都要记录目标技能在混合中的实际占比，像本篇 27k 对 28k 那样把稀释量写明；若宽混合在稀释后仍赢，记为迁移证据，若靠加密目标技能才赢，记为拟合证据，两类证据不许混报。三，条件泄漏审计：定期做遮掉指令的消融——把语言指令或目标条件置空后成功率掉多少，就是策略实际使用条件的量；掉得很少说明数据里观测已经泄漏了任务，要改采集协议让同一观测对应多个任务，而不是改 loss。四，低价复现包：评测环境要像 WidowX 一样给出可买齐或可一键复现的同款配置与成本上限，外部团队复现不了的评测不算数。判读规则：未见桶不涨而已见桶涨时，下一笔预算投给技能构成与评测分桶，不投给总量扩张。

思考题（综合 Day15 / Day16 / Day17 / Day20 / Day34）

  • (a) 稀释悖论的边界在哪：Bridge 的 13 技能一侧把目标技能密度稀释了却在未见 pick-and-place 上从 0.30 升到 0.65 ，Day16 的场景轴也有同样的支撑扩张逻辑。请设计一个实验把稀释从有益推到有害：逐步加入与目标任务原语越来越不相交的技能，保持总量钉死，预判未见任务成功率随「技能与目标的原语重叠度」变化的曲线形状，并说明曲线拐点出现时，你会用哪个观测量先察觉——共享表征的探针表现、目标技能的已见成功率，还是未见桶与已见桶的差？
  • (b) 两个 0.65 该信哪个：图 5 的技能多样性 0.65 是单变量等量对照，附录表 6 的 0.65 是数据量、环境与技能一起变的联合效应，两任务平均 0.08 到 0.70 。若只能选一个数字写进 Day15 OXE 的混合决策依据，你选哪个，为什么？再为表 6 设计一个补对照，把联合效应拆成数据量与构成两部分，写清每个对照子集的条数、环境数与技能数如何钉死，以及拆完后哪种结果会改变你对 OXE 混合权重的用法。
  • (c) 脚本数据的礼物到底送到没有：本文断言 9731 条脚本次优数据对 offline RL 有用却没有做开与关的对照，CRL 也没有跑赢 GCBC 。请借 Day20 RLPD 的机制清单设计一个能真正检验这句断言的实验：同一批数据、同一骨干，只变脚本数据开与关以及 RL 侧的关键机制，预判 GCBC 与 CRL 在两种开关下的排序变化，并给出判据——什么样的结果说明问题在数据构成，什么样的结果说明问题在算法机制没配齐？
