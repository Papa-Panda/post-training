2一句话总结

DROID 把"机器人数据规模化"从 OXE 的跨身体聚合转向跨场景覆盖：18 台统一 Franka 硬件、50 个采集员在 52 栋建筑的 564 个真实场景采集 76k 条轨迹（350 小时、86 个任务），每条带 3 路同步 RGB + 深度 + 相机标定 + 语言标注；用 diffusion policy 做 co-training（少量本域数据 + DROID），在 6 个任务 × 4 个地点（实验室→办公室→真实家庭）的评测里，相对已有大规模机器人数据集的 SOTA 做法平均提升约 20%——证明场景多样性本身就是可量化的泛化增益。

3大纲

  • 问题：通用策略训在少数实验室场景，训练分布的支撑只是几个点
  • 采集：18 台统一 Franka、50 名采集员、13 个机构，564 个场景采得 76k 条成功轨迹
  • 协议：每场景约 20 分钟就轮换、任务随机抽题、成功标记与采集员 ID 全程记录
  • 证据：50/50 共训相对 OXE 共训分布内 +22 个百分点、分布外 +17 个百分点
  • 对照：7362 条等量实验把场景多样性与数据总量拆开
  • 边界：86 是去重动词数；评测每格仅 10 次 rollout；跨身体不在验证范围内

所以 DROID 在 repo 里其实是个"复古"的选择：回到 RT-1/RT-2 时代固定硬件的老路——一次只扩张一个多样性轴：OXE 是固定场景、扩张身体多样性；DROID 反其道而行，固定身体、扩张场景多样性。

术语定义：embodiment = 机器人身体配置（关节数、末端执行器、相机布局）；固定硬件 = 训练数据全部来自同一种身体，动作接口天然对齐，省下跨身体对齐成本；跨 embodiment = 数据来自多种身体，需要统一接口（Octo 的 mask/tokenizer）或数据配方（π₀.₅ 的 heterogeneous co-training）来吃进去。

9数学视角：分布覆盖 × 混合权重——in-the-wild 数据为什么能提高泛化

DROID 是数据论文，没有新模型；它的数学就是数据混合与分布覆盖的数学。统一框架：行为克隆的数据混合目标 + 场景覆盖的泛化界直觉。

1) State / observation / action / objective

  • Observation： $O=(I^{(1:3)}_{t-T_o+1:t},\,q_t)$ ——3 路同步 RGB（两路外部立体相机 + 一路腕部相机，带外参标定）共 $T_o$ 帧历史 + 本体感知 $q_t$ （Franka 关节角/末端位姿）+ 语言指令 $\ell$ 。
  • Action：Franka 7 自由度关节或末端位姿命令的动作块 $A=(a_t,\dots,a_{t+T_p-1})$ ——因为硬件栈全网统一，DROID 不需要 OXE 式的 per-dataset 归一化/离散化对齐算子，动作接口天然对齐。
  • 训练目标（co-training 混合，沿用 Day12 diffusion loss，算法固定）：

$$\mathcal{L}(\theta)=\alpha\,\mathbb{E}_{(O,A)\sim\mathcal{D}_{in}}\!\big[\|\epsilon-\epsilon_\theta(O,A^k,k)\|_2^2\big]+(1-\alpha)\,\mathbb{E}_{(O,A)\sim\mathcal{D}_{droid}}\!\big[\|\epsilon-\epsilon_\theta(O,A^k,k)\|_2^2\big].$$

符号： $\mathcal{D}_{in}$ 是评测任务的少量本域数据（task-relevant 但场景窄）； $\mathcal{D}_{droid}$ 是 76k 条 in-the-wild 数据（task-irrelevant 居多但场景宽）； $\alpha\in(0,1)$ 是混合权重； $k$ 是扩散时间步； $\epsilon_\theta$ 是 Day12 的噪声预测器。对应到实现：训练 batch 按比例从两个数据源采样，网络结构与 Day12 完全相同——数据是唯一的自变量。

2) 场景覆盖的泛化直觉：混合支撑越宽，测试点离得越近

把每个场景 $s$ 看成一个观测-动作联合分布 $P_s(o,a)$ 。DROID 的训练分布是 564 个场景的混合：

$$P_{train}=\sum_{s=1}^{564} w_s\,P_s,\qquad w_s\propto n_s\;(\text{该场景轨迹数}).$$

部署场景 $s^{\prime}$ 的泛化误差可以直觉地拆成：

$$\mathrm{err}(s')\;\lesssim\;\underbrace{d\big(P_{s'},\,\mathrm{supp}(P_{train})\big)}_{\text{分布外推距离}}+\underbrace{\lambda_{s'}}_{\text{场景内在难度}}+\text{有限样本方差}}.$$

DROID 的赌注是第一项主导：实验室数据 $P_{train}^{lab}$ 的支撑是几个桌面，真实家庭场景 $s^{\prime}$ 离这个支撑很远；而 564 场景的混合把支撑铺开（52 栋建筑、家庭/办公室/实验室），让未见场景 $s^{\prime}$ 更可能落在"某个已见场景的邻域"里。实验验证：在 4 个地点（lab → office → 真实家庭）的 6 个任务上，本域小数据 + DROID 相对已有大机器人数据集的 SOTA 做法平均 +20%——增益随部署场景与 lab 的距离单调变大，正是"外推距离缩小"的预测。

数量 vs 多样性的取舍：76k 条 / 564 场景 ⇒ 平均每场景约 135 条轨迹——DROID 选择了支撑扩张而非单点加密。直觉：把第 136 条轨迹加进已见场景，只能降低该场景的估计方差（ $\propto 1/n_s$ ）；而把这条轨迹放到一个新场景，是在支撑上新增一个点，直接缩小最坏情况下的 $d(P_{s'},\mathrm{supp})$ 。这是 Q2 的答案：策略从每个场景学到的不是该场景的精细动力学，而是"场景可变"的不变性——背景、光照、桌面纹理在 564 个场景里被随机化掉了。

3) 去伪相关：场景随机化打破背景捷径

单场景数据里，背景特征 $B$ （桌面颜色、光照）与正确动作 $A$ 高度相关，策略会学捷径 $B\to A$ 。564 个场景下，背景与任务的联合分布被随机化：

$$\mathrm{Cov}_{s\sim\{1..564\}}(B_s,\,A)\approx 0,$$

捷径失效，模型被迫用真正因果的视觉特征（物体位姿、抓取点）。这是 DROID "robustness" 增益的数学实质，也是 Day21 domain randomization（仿真端随机化）的真实数据版本——DROID = 物理世界里的 domain randomization，只是随机化的是真实场景而不是仿真参数。

4) 采集员方差与多峰行为分布：为什么配 diffusion policy

50 个采集员、free-form 任务 ⇒ 同一 $(O,\ell)$ 下的行为分布 $p(A\mid O,\ell)$ 天然多峰（不同人的抓取习惯、路径偏好）。单峰回归（MSE）会学到多峰的均值——均值动作往往是非法动作（比如两条绕行路径的平均穿过障碍物）；而 Day12 的 diffusion head 直接拟合完整条件分布 $p_\theta(A\mid O)$ ，多峰是它的舒适区。这是 Q3 的答案：数据分布的形状决定了算法的归纳偏置需求——DROID 的采集协议（多样性优先）与 diffusion policy（多峰表达）是互相成就的一对；反过来，如果数据是单采集员精修的，MSE 回归可能更 sample-efficient。

5) 和系统实现的对应

  • 硬件 infra：18 台 Franka Panda 全网统一硬件栈 + 开源复现指南——用"固定身体"换"数据可比性"，这是和 OXE 最根本的 infra 哲学分歧。
  • 数据 infra：3 路同步 RGB + 深度 + 相机外参标定 + 语言标注；全量 CC-BY 4.0 开源；带交互式可视化浏览器；跨 52 栋建筑的自动相机标定流程（附录 G，质量评估 + 自动重标定）——分布式采集的标定 infra 是论文最被低估的工程贡献。
  • 采集协议：50 个采集员、12 个月、free-form 任务 prompt + 语言标注；场景类型分类（附录 C）与去重（附录 D）保证 564 场景的"场景"是真实不同的物理地点。
  • 评测：6 个任务 × 4 个地点，diffusion policy，batch 按 $\alpha$ 混合采样（附录 F-B）；口径是"本域小数据 + DROID" vs "本域小数据 + 其他大机器人数据集"——加法式归因。

6) 假设与数学没有覆盖的真实误差

  • 50 个采集员的风格方差是双刃剑：带来多峰覆盖，也带来质量长尾——demo 里混入次优/失败片段，行为克隆会原样复制（BC 没有 reward 过滤）；论文未量化采集员间的质量分布。
  • 跨 52 栋建筑的自动标定（附录 G）有残差：外参误差直接污染"图像 → 动作"的几何对应，而 diffusion policy 没有显式的几何一致性约束来吸收它。
  • 564 场景的"多样性"用的是元数据分类（场景类型、建筑 ID），不是视觉分布散度的度量——两个"不同建筑"的厨房可能视觉上很接近，真实的有效覆盖可能小于 564。
  • +20% 是 6 个任务的平均：全是短时程桌面操作；embodiment 仍是单一 Franka，跨身体泛化不在验证范围内（OXE 的地盘）；长程/移动操作未覆盖。
  • 长尾的另一面：平均每场景 135 条轨迹里，86 个任务的分布也不均匀——稀有任务的 per-task 样本可能不足以支撑可靠的条件分布估计。

  1. Motivation: 最通用的机器人策略仍训在少数实验室环境里，场景/任务多样性不足；采集真实场景数据有物流、安全、人力成本三重门槛。问题：能不能组织一次跨机构的分布式采集，把"真实世界"本身变成数据集？和 Physical AGI 的关系：这是"数据飞轮"里最贵的一环——真实世界交互数据的规模化采集方法论。
  2. System / Method: 统一 Franka 硬件栈 + 开源复现指南；50 采集员 × 18 台机器人 × 13 机构 × 12 个月；每条轨迹 3 路同步 RGB + 深度 + 相机外参 + 语言标注；场景去重与类型分类保证 564 场景真实不同；策略端零创新——全部实验用 Day12 diffusion policy，数据是唯一变量。
  3. Training / Data Details: 76k 轨迹 / 350 小时 / 564 场景 / 86 任务 / 52 栋建筑；CC-BY 4.0 全开源 + 可视化 + 训练代码 + 预训练 checkpoint；训练 = 本域小数据 + DROID 按权重 $\alpha$ 混合采 batch；Sim 数据：无；Reward：纯行为克隆。
  4. Key Tricks（3个最值得抄的）:
  5. 固定身体、扩张场景：和 OXE 反向的取舍——18 台统一 Franka 让动作接口天然对齐，省掉跨 embodiment 对齐算子，把全部复杂度预算花在场景覆盖上。做数据 infra 时先想清楚：你要的多样性是哪个轴的？一次只扩张一个轴。
  6. 分布式采集的标定 infra：52 栋建筑的自动相机-机器人外参标定 + 质量评估（附录 G）——真实世界数据规模化的瓶颈不在采集员，在标定和质检的自动化。
  7. 加法式归因的评测设计：固定算法（diffusion policy）、固定本域小数据，唯一变量是"加不加 DROID"、"加的是 DROID 还是别的大数据集"——把数据论文的 claim 做成干净的对照实验。
  8. Results: 6 个任务 × 4 个地点（lab → office → 真实家庭）；本域小数据 + DROID 相对"本域小数据 + 已有大规模机器人数据集"的 SOTA 做法，性能/鲁棒性/泛化性平均 +20%；增益随部署场景与实验室的距离增大而变大。

11可迁移 / Transfer

  • 方法在 held-out 上是否 transfer？是——4 个评测地点里有办公室和真实家庭，本来就是 held-out 场景；+20% 是跨场景泛化的直接证据。模型 vs 框架贡献：框架（数据）贡献 100%——算法与 baseline 完全相同，增益全部来自数据混合。
  • 对你 Infra → Post-training → Physical AI 迁移的 1-2 个直接启发：
  • Post-training 数据配方的"覆盖轴"思维：DROID 证明支撑扩张 > 单点加密——做 agent RL 数据时，与其把同一任务刷 10k 遍，不如把任务×环境的笛卡尔积铺开；评测也要按"与训练分布的距离"分桶，而不是只报平均成功率。
  • "数据分布形状 → 算法归纳偏置"的匹配意识：多采集员 free-form 数据天然多峰，配 diffusion/flow 这类分布拟合器；单采集员精修数据配 MSE 回归更省样本。选算法前先看数据的模态结构——这是 Day12 数学在数据侧的回声。
  • Infra 视角：统一硬件栈 + 开源复现指南 + 自动标定 + 场景去重 = 分布式真实数据采集的 infra 四件套；CC-BY 4.0 + 可视化浏览器 + 预训练 checkpoint 是数据集发布的黄金标准（对比 OXE 没公开混合权重 $w_k$ 的短板）；评测成本锚点：6 任务 × 4 地点的真机评测是"数据论文"的 eval 预算下限。

12疑问 / 下一步

  • 没看懂的 / 想深挖的 1 个问题：混合权重 $\alpha$ （本域小数据 vs DROID 的 batch 比例）到底怎么定的？附录 F-B 给了 batch 构造但没给 $\alpha$ 的搜索过程—— $\alpha$ 太大 DROID 被稀释、太小本域任务信号被淹没，这个 trade-off 的 scaling 规律值得挖（和 Day15 的 $w_k$ 问题是同一个：数据混合论文都不爱公开权重）。
  • 如果要复现 / 小规模试，第一个实验做什么？拿 DROID 开源数据里 2–3 个场景子集 + 一个本地 Franka（或仿真）小任务：固定 diffusion policy，对比"本域数据 only" vs "本域 + DROID 子集（按场景数递增：10 / 50 / 200 场景）"的成功率曲线——验证"增益随场景数单调增、随单场景条数快速饱和"的预测，复现"支撑扩张 > 单点加密"。

16第二轮复习（2026-10-27）

本轮做六处口径修正（86 是动词数不是任务数、76k 只计成功轨迹、混合比 $\alpha$ 揭晓且实际只训了 40k 子集、+20% 的精确口径、策略只吃两路外部相机、场景类型是 GPT-4V 标注）＋补大纲与流程图（初读缺失，本轮补齐）。核心收获：把 Day16 从「场景多样性可量化」重读为覆盖层的确立——DROID 真正的发明不是 76k 条数据，而是一套用采集协议制造覆盖的方法：多样性是协议的输出，不是采集的副产品；而它的旗舰证据（§V-C 等量对照）恰恰是初读漏掉、还误以为要自己补做的那一个。

元信息修正

  1. 「86 个任务」实为 86 个去重动词：§II 脚注与 §IV 写明，task diversity 的计数口径是从语言指令里语义解析抽取动词、再用 GPT-4 去掉同义词与拼写变体后的唯一动词数。它不是 86 个预先定义的任务，更不是动词 × 物体的组合数（那个数大得多）。初读全篇把动词数当任务数用，今后应写「86 类动词行为」；这也意味着 DROID 的「任务多样性」是一个可扩展的代理指标，不是任务清单的完备枚举。
  2. 76k 只计成功轨迹，失败另有约 16k 条：§III-B 原文是 “DROID consists of 76k successful episodes”，另有约 16k 条被采集员标记为 not successful 的轨迹随数据集一同发布、但不计入 76k。连带推翻初读数学节第 6 点的一半推测：失败片段并没有混进行为克隆——§V 的策略训练明确排除 not successful 的轨迹，初读担心的「BC 原样复制失败片段」对本论文的配方不成立；反过来，这 16k 条失败数据的价值在论文里零实验，只是发布了而已。
  3. 混合权重 $\alpha$ 揭晓，且实际训练量只有 40k：初读「疑问 / 下一步」问的 $\alpha$ 有答案——batch 在本域数据与 DROID 之间按 50/50 采样，原文只说 “we find to work well in practice”，没有报告任何搜索或敏感性分析。更重要的是附录口径：主实验实际用的是当时已有语言标注的前 40k 条成功轨迹，不是 76k 全量。发布规模（76k）与实验规模（40k 子集）必须分开引用——这正是 Day15 复习立的「三层记账」在 Day16 自己身上的复现。
  4. +20% 的精确口径与评测的统计规模：引言的 “20% on average” 是概括说法；Fig. 6 的可引用口径是相对次优方法（OXE 共训）分布内 +22 个百分点、分布外 +17 个百分点（absolute success rate，不是相对提升百分比）。同时钉死评测规模：每个任务 × setting × 方法只跑 10 次 rollout，6 个评测任务的本域示范每任务仅 50–150 条。单格二项标准误可达约 16 个百分点，+22/+17 是跨任务平均后的数——效应方向可信，任务级细节要看 Fig. 6/8 的分任务读数，不能只引平均。
  5. 策略口径收紧：只吃两路外部相机：数据集记录 3 路相机流，但 §V 的评测策略只用两路外部 Zed 2 的 RGB（腕部 Zed Mini 没进策略），下采样到 $128 \times 128$ ，ResNet-50（ImageNet 预训练）编码、拼接冻结的 DistilBERT 语言嵌入与本体感知；输出绝对末端位姿动作，生成 16 步、开环执行 8 步再重规划。初读数学节把观测写成 3 路 RGB，是把数据集口径当成了策略口径。另外初读说硬件是 “Franka Panda”，补全：末端是 Robotiq 2F-85 夹爪，遥操作用 Quest 2 手柄，控制与记录频率 15 Hz，动作同时以关节空间与末端空间记录。
  6. 场景类型是 GPT-4V 标注，「数量级领先」要限定对象：§IV 的 10 类场景类型由 GPT-4V 按附录 C 的 prompt 分类，不是初读所说的「元数据分类」；而「场景」本身的计数口径是工作空间发生实质变化（换房间或工位角落），只重排物体不算新场景。另补一条初读漏掉的对照：Table I 里 OXE 记 311 个场景，DROID 的 564 与之相比不到 2 倍——「比已有数据集多一个数量级」是对单个实验室数据集成立，不是对聚合后的 OXE 成立。

一句话总结

三十多天后回看，Day16 的耐久贡献不是 564 这个场景数，而是一条可复制的因果链：采集协议（强制轮换 + 随机抽题 + 扰动提示 + 成功标记）→ 分布覆盖 → 等量对照下可测的 OOD 增益。DROID 是整条路线里的覆盖层：Day15 解决「已有的异构数据怎么 pooled」，Day16 解决「新数据按什么分布去采」——前者是存量聚合，后者是增量设计。

和之前工作的关系

  • vs Day15 OXE（直接对比，同专题相邻篇）：聚合层 vs 覆盖层。最有分量的一条连接在方法论上：Day15 复习指出 OXE 的去 Bridge 消融缺一个等量替换对照、分不清内容效应与总量效应；DROID 的 §V-C 恰好把这个对照做在了场景轴上——固定 7362 条，只换采样覆盖（20 个高产场景 vs 全场景均匀采样），OOD 差异只能归因于覆盖。所以数据专题里第一个把「多样性 ≠ 总量」做干净的是 DROID，不是 OXE；但不对称也要记下：embodiment 轴至今没人补上同样的等量对照。
  • vs Day17 BridgeData V2（直接对比，同专题下游）：Bridge 的等量对照在技能轴（等量数据下 13 技能 vs 3 技能，未见 pick-and-place 0.30 → 0.65），DROID 的等量对照在场景轴（7362 条，20 场景 vs 全场景）。两篇合起来给出一条可执行的判读规则：多样性的每一个轴都要单独过等量门才能宣称增益，任何一轴的结论不能替其他轴背书。体量上 Bridge 是 24 个场景的玩具厨房，DROID 是 564 个真实场景——同一条「固定身体」路线，Bridge 把预算花在便宜与技能数，DROID 花在真实场景覆盖。
  • vs Day12 Diffusion Policy（直接对比，分专题上游）：DROID 的策略不是「沿用 DP」四个字那么松——16 步生成、8 步开环执行就是 Day12 三 horizon 合同里 $T_a = 8$ 的字面复现，反馈频率的结论（不是越密越好）在数据论文的评测栈里被默认继承。另一个连接在数据形状：成功过滤之后，多采集员 free-form 数据仍然天然多峰，这正是初读 Q3 说的 diffusion 舒适区；本轮补一句，过滤掉的是成败轴的多峰，保留的是风格轴的多峰——两者对 BC 的意义完全不同，初读把它们混在一起了。
  • 跨阶段 vs Day21 Domain Randomization（RL / sim2real 段）：初读说「DROID = 物理世界里的 DR」，本轮把差别说透。DR 的随机化分布 $p_\phi$ 是一个可调的采样器，可以按 ADR 那样自动扩边界；DROID 的覆盖是协议诱导出的经验分布，没有旋钮、不能事后重采样出没采过的场景。ADR 的边界扩张在真实采集里的对应物，是 GUI 定期提示的 scene augmentation（挪动底座、移动并重标定相机、改变光照、增减物品）——协议就是它的课程表。推论：真实覆盖的上限由协议设计决定，不由数据量决定；采 10 倍数据但不改协议，覆盖轴几乎不动。
  • 跨阶段 vs Day20 RLPD（RL / sim2real 段）：两个 50/50 的相遇值得单独记。RLPD 用离线 / 在线 50/50 对称采样防止任一分布独占梯度，DROID 用本域 / 广覆盖 50/50 做同一件事——结构直觉相同，但证据等级不同：RLPD 的比例嵌在 UTD、LayerNorm、Q 集成一整套机制里讨论，DROID 的 50/50 只有一句 “works well in practice”。把 50/50 当默认起点可以，当定律不行。
  • 跨阶段 vs Day30 数据飞轮 / Day33 Figure Index（评测与最新进展段）：DROID 的采集端（采集员 ID、成功标记、场景轮换配额、自动标定的事后精化——arXiv v2 还补了 36k / 24k 两档标定集）就是 Day30 飞轮在「采集」这一环的原型：飞轮转不转，先看每条数据进池子时带没带溯源与成败标记。Day33 的 Index 数据众包则是这套协议的商业放大版——众包解决量，协议解决分布，两者缺一不可。

核心

  1. 动机重读：病不在数据少，在于训练分布的支撑是几个点：初读把 DROID 的命题读成 scale，本轮改成 coverage。实验室数据的根本问题不是条数，是支撑集退化成少数桌面与灯光条件的并集，测试场景落在支撑外只能靠外推。DROID 的全部设计——固定身体省下的对齐预算、分布式机构、协议轮换——都只服务一件事：把混合分布的支撑铺开。这也解释了为什么它的对照实验要固定总量：命题本身就是关于支撑形状的，不是关于 $n$ 的。
  2. 机制深挖一：多样性是被协议制造出来的（本轮最核心的重读）：564 个场景不是「采着采着就有了」。协议里写死了四条：每场景至多约 100 条轨迹或约 20 分钟就换场；GUI 从该场景的任务列表里随机抽题给采集员（防止挑易题、挑近物）；GUI 定期随机提示 scene augmentation（挪底座、移相机、改光照、增减物品）；采集员 ID 与成功标记随每条轨迹记录。换句话说，覆盖是这套协议的输出。推论很硬：复制 DROID 要复制的是协议与 GUI，不是 76k 条数据本身；只买数据不建协议，下一次采集还会退化回少数场景。
  3. 机制深挖二：§V-C 等量对照是数据专题最干净的因果证据（本轮最反直觉）：初读完全漏了这一节，还把「按场景数递增做子集对照」写进了自己的「下一步」——论文其实已经做了。等量 7362 条：取演示最多的 20 个场景 vs 全场景均匀随机采样，同样的 50/50 共训，diverse 子集的 OOD 表现更高；而全量共训在所比的 3 个任务上不低于任一 7k 子集，说明多样性与总量不是互相替代——多样性抬 OOD 的地板，总量仍有边际。但对照有混杂要诚实记：演示最多的 20 个场景多半来自大机构、偏实验室型，「场景少」与「场景偏 lab」纠缠在一起，§V-C 拆出的严格说是「覆盖广度 + 场景类型构成」的联合效应，不是纯粹的场景计数效应。
  4. 机制深挖三：真正的配方比标题窄得多：把 §V 与附录拼起来，「DROID 效应」的实际成分是——成功过滤 × 前 40k 条子集 × 50/50 混合 × 每任务仅 50–150 条本域示范被反复重采样。在 50/50 下，本域样本的单条复用率比 DROID 样本高出约数百倍，本域数据本质上是被当作高权重锚点在用。所以 +22/+17 是这个组合的效应；「76k 原始池全量混训是否同样有效」论文没有测。以后引 DROID 的增益，必须连配方一起引，只引数据集规模是误引。
  5. 机制深挖四：场景数只是五轴里最显眼的代理变量：§IV 实际并列了五条多样性轴——任务（动词）、物体、场景、视角（1417 个相机视角）、交互位置（首次夹爪闭合点的 3D 分布）。§V-C 操纵的是场景采样，但视角与交互位置覆盖与场景数高度共变，增益记在「场景」名下是方便，不是归因完毕。这与 Day15 的教训同构：聚合平均数会洗掉结构，单一轴名会洗掉共变轴。做数据设计时，五轴要分别设预算、分别做对照，不能只数场景。

边界

  1. 评测的 OOD 比标题温和得多：OOD 变体是加干扰物、换未见物体实例、平移相机，全部在采过本域数据的同 4 个地点内做。论文没有测「零本域数据直接部署到全新家庭」——DROID 证明的是「少量本域 + 广覆盖共训 > 少量本域 + 窄覆盖共训」，不是零样本 in-the-wild 部署。标题里的 in-the-wild 描述的是训练数据的采集地，不是评测的部署难度。
  2. 统计功效：每格 10 次 rollout、6 个任务，任务级的涨跌被平均数盖住；且 Toasting 与 Close Waffle Maker 两任务共用一个多任务策略（附录口径），「6 个任务」也不是 6 个完全独立的实验单元。用 DROID 的数字做 gate 级决策时，要回到分任务读数。
  3. 单 embodiment 的账没有变：Franka + Robotiq 2F-85 + Quest 2 遥操作的固定栈，评测也用同一栈——硬件指纹与数据覆盖的贡献没有拆分，跨身体仍是 Day15 的地盘，DROID 对新身体零证据。
  4. 失败数据是发布姿态，不是证据：16k 条 not successful 已开源，但论文内没有任何一个实验用它们（连表示学习预训练都没测）。「失败数据值钱」在这篇里是开放姿态，其兑现要等 Day20 式在线 RL 或 Day30 飞轮的 verifier 路线，不能倒过来给 DROID 记功。
  5. 何时失效：目标任务的交互类型与 DROID 覆盖几乎不相交时，50/50 混合只会把本域梯度稀释一半；覆盖广但每场景成功示范过薄时，条件分布 $p(A \mid O, \ell)$ 在单场景内根本估不准——有效数据量是覆盖轴与质量轴的乘积，任一轴趋零，乘积趋零。

迁移到 post-training / Agentic RL Infra

可执行的一条主映射：把 DROID 的采集协议平移成 agent 轨迹池的四条硬规则，覆盖靠协议制造，不靠事后筛选补救。一，覆盖配额制：以（环境 × 任务模板）为格子设单格采集上限（对应每场景约 20 分钟 / 100 条），到顶强制轮换；任务由调度器随机抽取而不是生成策略自选（防挑易题），并定期注入环境扰动（页面布局、干扰元素、语言变体——对应 scene augmentation 提示）。二，溯源与成功标记必填：每条轨迹记生成者 ID（模型版本 / 教师 / 人工）、成功标记、环境指纹；SFT 类混合默认只用成功子集，失败轨迹单独入池供 verifier 与负样本使用——这是 DROID 配方（成功过滤后共训）的字面平移，不许把失败混进 BC 式训练再指望模型自己分辨。三，混合比与实际训练量入账：默认 50/50（目标域 : 广覆盖池）起步，但每次实验必须记录实际入训子集的大小与构成（学 Day15 三层记账 + DROID 的 40k 教训：池子总量不许冒充训练量），并对混合比做一次 25/50/75 扫描再锁定，不把 50/50 当定律。四，先等量对照，再扩采：任何「加覆盖涨点」的宣称先过 §V-C 式的等量门——固定总条数，集中采样 vs 广覆盖采样，只比 OOD 桶（未见环境 / 未见布局）；过门后才讨论扩量。判读规则：若 ID 涨而 OOD 不涨，涨的是拟合不是覆盖，下一笔预算不投采集、投评测分桶与目标域数据。

思考题（综合 Day12 / Day15 / Day16 / Day17 / Day20 / Day21）

  • (a) 把五轴拆开：§V-C 只操纵了场景采样，但视角与交互位置覆盖与场景数高度共变，增益被记在了「场景」名下。请设计一个能把「场景覆盖」与「视角覆盖」拆开的等量对照：用同一批场景的轨迹，构造「多场景少视角」与「少场景多视角」两个等量子集，其余配方（50/50、成功过滤、同一 diffusion policy）全固定，预判两者在 OOD 桶的排序，并说明每种排序分别支持哪种解释；若增益主要来自视角轴，Day21 的视觉 DR 处方与 DROID 的真实采集处方应该如何合并成一份数据预算？
  • (b) 两个 50/50 何时该动：DROID 的本域 / 广覆盖 50/50 与 Day20 RLPD 的离线 / 在线 50/50 是同一个结构直觉，但一个只有 “works well in practice”、一个嵌在整套机制里。设目标任务的本域数据从 100 条涨到 10k 条，预判最优混合比往哪边移，并给出你会盯的观测量（ID 与 OOD 的差、分桶成功率、梯度冲突的某种代理）与移动的触发条件；再说明为什么 Day15 的混合权重 $w_k$ 不公开，使这类问题在 OXE 上连事后复现都做不了——权重入账应该写进数据 infra 的哪一层？
  • (c) 16k 条失败轨迹的兑现路径：BC 配方把失败过滤掉，Day30 飞轮却说失败是最值钱的信号，两边都有道理。请给 DROID 的 16k 条 not successful 轨迹设计两条互斥的使用路线——(i) 训 success verifier / reward 模型，(ii) 按失败模式分桶后定向补采成功示范——各自写清验证实验与成功判据（注意每条路线都要避开「把失败混回 BC」这个已被配方排除的选项），并论证哪条更符合 DROID 自己的证据形态：它的全部增益都来自成功数据的覆盖，失败侧是零证据。
