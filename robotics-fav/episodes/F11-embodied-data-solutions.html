2一句话总结

具身智能「数据不够」的公开解法已经收敛成三件套：生成式 AI 造任务与场景（LLM 提议任务、生成 3D 资产与训练监督，把人的设计劳动也自动化）、仿真扩增造轨迹（少量真人演示经轨迹重组与程序化扰动放大成百万级数据）、域随机化保迁移（把物理、光照、相机等参数随机铺满，让真实世界成为训练分布的一个样本）。三者的分工是：生成解决组合多样性，扩增解决轨迹数量，随机化解决 sim-to-real 域差；反例同样重要——外观逼真不是充分条件，物理对不齐时画面再像也没用。

1. 背景/问题：真机数据的经济学困境

遥操数据的昂贵程度可以先看对照组：DROID 汇集 13 个机构也只攒到约 76,000 条遥操轨迹（约 350 小时人力）；Google RT-1 的 130,000 条 episode 花了 17 个月人工采集（Ai2 公开报道口径）。对想要「通用」机器人的实验室，更麻烦的是长尾：真正决定泛化能力的任务组合、物体摆放、失败情形永远不够。这一集把答案拆成三个正交问题——造什么（任务与场景）、造多少（轨迹数量）、怎么迁移（仿真到真实）——分别对应三件套。

2. 生成式 AI：把任务与场景设计也自动化

  • RoboGen（生成式仿真路线，公开论文口径）：让 GPT-4 负责「生成式仿真」的全部流水线——提议任务（采样机器人与物体、生成任务名与描述）→ 生成场景（文字描述组件、检索或生成 3D 资产）→ 生成训练监督（把任务分解为技能、选择训练方法）→ 技能学习，几乎不需要人力介入。关键机制是让生成式模型把「设计训练课程」这件事本身规模化：仿真的优势（并行、无限观测、零硬件损耗探索）才真正被释放。
  • 生成 3D 场景与资产（3D Generation for Embodied AI 综述口径）：可扩展的 3D 生成（程序化生成、NeRF/高斯泼溅场景重建、文本生成资产）正在把「搭场景」从人工美术工时变成生成问题，和 LLM 提任务合起来，才能供给通用策略需要的组合多样性。

3. 仿真扩增：少量演示 → 百万级轨迹

  • MimicGen（NVIDIA，arXiv:2310.17596）：相对位姿重组把少量真人演示（原论文演示量级约 200 条）自动扩增为数万至十万级带新物体构型的演示，正是 GR00T 等人形基础模型的官方合成数据管线：Vision Pro 遥操少许演示 → Isaac Sim 重放 → MimicGen 扩增 → 与真实数据混训。
  • Ai2 MolmoBot（纯合成极端路线，Ai2 公开报道口径）：完全不用真人遥操，在 MolmoSpaces 程序化环境里用 MuJoCo 并行物理 + 激进域随机化（物体、视角、光照、动力学全随机）生成 180 万条专家操作轨迹，训出的策略直接迁移真机——这是「数据经济模型」的另一端：人工数据的边际成本趋近于零，代价是任务分布的真实性要由程序化环境的设计来扛。

4. 域随机化：real 是训练分布的一个样本

sim-to-real 的标准叙事：与其把仿真修到和真实一模一样，不如把参数铺得足够宽，让真实世界落在分布内部。随机化的维度包括几何形状、质量与摩擦等动力学参数、光照与纹理等外观、相机位姿与传感器噪声。公开支持与反例都有：

  • 正例（3D 生成综述与 DR 文献一致口径）：域随机化是 Real-to-Sim-to-Real 管线的关键环节；近期工作进一步用可学习的随机化分布、贝叶斯参数推断与闭环范围自适应把「随机多宽」也数据驱动化。
  • 反例（物理精度决定下限）：接触、摩擦、变形这些物理过程仿得不准时，视觉域随机化救不了策略；MolmoBot 式纯合成路线成立的前提也是 MuJoCo 物理先要过关。排序上，物理对齐优先于渲染逼真，高保真仿真的价值在接触动力学而非像素。

5. 结论/观点（三条合成的公开叙事，非本场原话）

  • 数据合成不是「假数据骗模型」，而是用生成成本换采样成本：真人演示一条的钱，仿真能摇出成百上千条扰动版本；通用策略的长尾只能这样喂。
  • 三件套缺一不可：只有生成没有随机化，过拟合仿真外观；只有随机化没有生成，任务组合不够丰富学不到长尾技能；只有扩增没有物理，学到的轨迹本身就是错的。
  • 评估仍在真实世界验收：合成数据训出的策略最终要过真机评测一关（参见 F12 的评估闭环一脉）——数据合成的规模化只是把瓶颈从「采集」移到了「评测」。

5可迁移

  • 对 coding data / RL infra 工作可直接试的点：数据合成的三件套分工可直接类比 agent 数据工程——生成式任务提议 ≈ 程序化生成 prompt/任务变体；轨迹扩增 ≈ 从少数专家轨迹做扰动与重组（MimicGen 式相对位姿重组对应代码任务中的路径/参数替换）；域随机化 ≈ 训练分布扰动（工具版本、上下文噪声、约束抖动）。三者配比应分开管理、分开消融，而不是一锅「数据增强」。
  • Infra 视角的启发：合成数据的瓶颈会转移到评测——生成的算力便宜之后，真机/真实环境评测的吞吐成为闭环最短的板；在预算规划上应为「生成:评测」预留可比量级的资源，而不是把全部算力砸在生成侧。

6疑问 / 下一步

  • 纯合成路线（MolmoBot）在更长尾、更接触丰富的任务（如插入、变形物）上还能保持多少零样本迁移率？公开报道以拾放为主，更难的物理任务的合成-真实差距需要原始论文补数。
  • 程序化生成任务的分布真实性（生成的任务真的覆盖用户要做的事吗）是三件套里最难验证的一环；其分布漂移如何监控，目前公开做法不系统。
