## 一句话总结

Jason Ma 要破的是机器人行业对「演示成功率」的集体误读：演示视频里的 85% 成功率在生产环境等价于不可用，真正的基准是像折餐巾这种任务上的 99.4% 可靠性；而通往这种可靠性的路径不是更大的实验室演示集，而是「预训练 → 后训练 → 部署数据飞轮」的闭环——奖励模型把稀有失败自动转成可扩展的监督信号，真机 RL（人机在环）把策略练到超越示范者。

## 核心

### 1. 背景/问题：演示成功率是一场集体错觉

这是标题里「RL 迷思」的总纲，也是他近期公开演讲（如 AI Engineer 播客专场，公开报道口径）反复讲的开场。一段两分钟的演示视频看起来完美，但如果模型单次成功率只有 80%–90%，那它是一个「演示品」而不是「产品」。设单次成功率为 $p$ ，连续 $n$ 次全成功的概率为：

$$P = p^n$$

$p = 0.9$ 、 $n = 100$ 时， $P$ 只有约 $2.7 \times 10^{-5}$ 。餐厅折餐巾、洗衣房折毛巾、酒店处理布草这类任务要求的是整天连续运行， 80%–90% 的单次成功率在这种口径下是不可用的（nonstarter）。于是行业被夹在两个极端之间：**通用基础模型**能做很多任务、演示惊艳，但部署成功率上不去；**专用流水线**在单一任务上可靠，却无法迁移到新任务。Dyna 的立场（其创立命题）是：弥合这个鸿沟的唯一办法，是让商业部署本身成为研究流程的一部分，而不是研究做完之后的收尾环节。

### 2. 方法/设计之一：可靠性的来源是「失败信号」，不是更多成功演示

Dyna 的第一个公开结果 DYNA-1 正是为讲清这件事选的任务——折餐巾：商业上真实存在（餐厅后厨有专人手工折餐巾）、对并联夹爪的精度要求苛刻（必须从一摞里恰好拈出一张、第二道折缝偏差约一英寸即低于餐厅验收标准），且是可变形物体操作、状态空间近乎无限，无法穷举错误情形采集数据（讲者原话大意，公开报道口径）。

标准预训练 + 后训练配方只能到约 80% 成功率，且失败模式很典型：**模型在初始阶段表现正常，一旦出错就滑出训练分布、卡住、无法恢复**——大多数演示视频正是在这里剪辑结束的。Dyna 的技术核心是让一个**奖励/进度模型**看机器人视频、输出 0 到 1 的任务进度分数：机器人出错时进度曲线会出现非单调回落，这就给出了失败的自动检测信号。由此形成「可扩展监督」（scalable supervision）：不需要人盯着一台已经 90% 正确的机器人去捕捉稀有失败，奖励模型在自主 rollout 中后台运行、标记失败，研究者据此做靶向的错误恢复数据采集、微调、再部署，循环往复。多个主动学习周期之后，模型泛化出了未被训练过的恢复行为（报道中最出彩的例子：机器人意外把整摞餐巾带翻后，自行执行拉拽、展开动作恢复并继续），成功率推进到 **99.4%**（公开报道口径）。可靠性验证的方式也很「生产级」：让机器人连续跑 24 小时（他引用了四次独立的 24 小时运行，含环境光随清晨变化而模型继续工作的片段）。

### 3. 方法/设计之二：数据飞轮——部署数据是金字塔顶端

为什么实验室数据不够？因为实验室与客户现场（餐厅、洗衣房、酒店的真实光照、人流干扰、物体堆放方式）之间存在分布鸿沟，再多「摆拍式」演示也补不上。Dyna 的数据策略是一个三层金字塔（公开报道口径）：塔底是离体数据（穿戴相机的人体第一视角视频、公开数据集，部分仿真数据在考虑中）；中层是在机器人本体上多场景、多任务采集的数据；塔顶最稀少也最有价值的是**部署数据**——只有它与任务真实分布同分布，能直接闭合训练—部署的差距。配合的模型架构是「高层推理模型 + 低层世界动作模型（world action model）」双层：前者负责语义理解，后者输出精细、高频的灵巧动作，因为真实物理任务既需要知道「这是什么」，也需要在出错时即时恢复。金字塔的回报体现在样本效率：若干基准任务（清垃圾、开箱、折毛巾、折 T 恤）根本不在预训练数据里，用不到 1 小时的任务数据后训练就能「反复完成而不失败」（公开报道口径）。

飞轮闭环的极端演示是把机器人直接空运到没采集过数据的环境：CoRL 2025（韩国）展会现场，机器人抵达展位后连续折 T 恤三天，期间观众反复捣乱（甚至用 T 恤盖住摄像头）；以及与 Red Bull 合作在音乐节现场开罐（背景光照不断变化）。他给出的目标形态是：把机器人带到现场，它直接开始工作。

### 4. 结论/观点：几条「迷思」与对应的反命题

以下按讲者一贯公开论点重组，均非本场逐字原话：

- **迷思：成功率 80%–90% 就「基本解决了」**。反命题：按连续运行口径，生产级基准是 99%+；评估方式应该是 24 小时连续运行 + 多客户站点，而不是剪辑好的演示片段。
- **迷思：通用与专用是二选一**。反命题：预训练的「广度」恰恰是可靠性的来源——模型在上千个任务上见过的恢复行为能被插值迁移到新任务，在新任务上「按需执行」；从一开始就专用化，等于放弃这批物理经验，模型反而更脆弱。配方是**预训练（通用物理先验）→ 后训练（少量任务数据）→ 主动学习（失败驱动）**。
- **迷思：RL 在真机上不可行，要靠纯模仿**。反命题来自他自己的学术工作：HIL-SERL（人机在环 SERL）在真实机器人上 1–2.5 小时训练即达到近完美成功率（连接器装配、插 RAM、穿同步带等精密任务）；在相同人类数据量下，RL 策略的成功率平均比模仿学习高 101%、周期时间快 1.8 倍——因为 RL 不被示范者的水平锁死，还能学到示范里没有的快速闭环恢复策略。更早的 Eureka 则说明奖励这一环可以被规模化：LLM 生成的奖励函数在 29 个任务中 83% 胜过人类专家手写奖励（平均归一化提升 52%），并练出了 Shadow Hand 转笔。Dyna 的奖励模型做法是这条学术线（奖励设计自动化）在工业部署中的续篇。
- **迷思：数据质量是数据的固有属性**。他另一个反复讲的观点是「数据质量随机器人形态而变」：2020 年前后发布的四千小时量级第一视角数据集当年近乎无用，直到人形机器人形态足够接近人类才被盘活（公开报道口径）；因此数据管线应该能随硬件演进重新估值、持续接入新分布，而不是一次性清洗定稿。

## 可迁移

- 对 coding data / RL infra 工作的直接可试点：**把「失败自动检测」做成一等公民基础设施**。Dyna 的奖励进度模型（进度曲线非单调 ⇒ 失败）本质是轨迹级 verifier：对 agent 训练同理，逐步进度/回落信号比终局成败更适合做靶向数据采集——优先回灌「出错点附近」的恢复轨迹，而不是均匀加数据。这与 HIL-SERL「人在失败边界处纠偏」的数据分布是同一件事的自动化版本。
- Infra 视角的启发：**评测口径决定上限**。单次成功率是演示口径，连续运行成功率（ $p^n$ ）是产品口径；agent 评测若只报单 episode pass@1，会系统性高估长程任务的可用性，长程基准应报「连续 N 次全成功率」一类口径。
- 泛化不是可靠性的敌人：广预训练攒下的「恢复行为库」可被新任务插值调用——在后训练里保留任务多样性（而非过早收窄到目标分布），可能比极致专用化更鲁棒。

## 疑问 / 下一步

- 99.4% 是在「现场采集过数据」的部署里拿到的；CoRL/Red Bull 的零现场数据演示到底依赖多少隐性适配（标定、夹爪、任务选择），公开报道没有量化，这是判断「飞轮已转起来」还是「精心准备的演示」的关键。
- 奖励进度模型自身的误检率、以及它对新任务需要多少标注才能冷启动，没有公开数字；这是该配方能否横向复制到其他公司的决定性细节。
